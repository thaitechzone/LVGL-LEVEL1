# Level 1 / Lab 3 — WiFi Connecting (ตั้งค่า SSID/รหัสผ่านเอง + ไฟ RGB บอกสถานะ)

ต่อจาก [Lab 2](../Lab2_Template_ADC_LDR/README.md) โดยให้บอร์ด **เชื่อมต่อ WiFi** ด้วยชื่อและรหัสผ่านที่ **เรากำหนดเอง**
และรายงานทุกขั้นตอนทาง **Serial Monitor** พร้อมใช้ **RGB LED เป็นไฟสถานะ** ให้รู้ว่าเกิดอะไรขึ้นโดยไม่ต้องมองจอคอมพิวเตอร์

> **ใบงานฉบับละเอียด (ทฤษฎีเครือข่าย ขั้นตอน 9 ขั้น อ่านโค้ดทีละส่วน แบบฝึกหัด 8 ข้อ) อยู่ที่ [WORKSHEET.md](WORKSHEET.md)**
> เฉลยสำหรับผู้สอน: [WORKSHEET_ANSWERS.md](WORKSHEET_ANSWERS.md)

## ไฟ LED บอกอะไร

| สี / จังหวะ | สถานะ | ความหมาย | คุณต้องทำอะไร |
|---|---|---|---|
| 🔴 แดง **กะพริบเร็ว** | `NotConfigured` | ยังไม่ได้ตั้งชื่อ/รหัส WiFi | ทำตามหัวข้อ "ตั้งค่า WiFi ของคุณ" |
| 🔵 น้ำเงิน **กะพริบช้า** | `Scanning` | กำลังสแกนหา WiFi รอบตัว | รอสักครู่ (ราว 2–7 วินาที) |
| 🔵 น้ำเงิน **กะพริบเร็ว** | `Connecting` | กำลังเชื่อมต่อกับ WiFi ของคุณ | รอ (ไม่เกิน 15 วินาที) |
| 🟢 เขียว **ติดค้าง** | `Connected` | เชื่อมต่อสำเร็จ ได้ IP แล้ว | ใช้งานได้ |
| 🔴 แดง **ติดค้าง** | `Failed` | เชื่อมไม่สำเร็จ (รหัสผิด / หาไม่เจอ / หมดเวลา) | ดูสาเหตุใน Serial โปรแกรมจะลองใหม่เองใน 5 วินาที |
| 🔴 แดง **กะพริบช้า** | `Lost` | เคยต่อติดแล้วแต่สัญญาณหลุด | รอ โปรแกรมจะลองใหม่เอง |

จำง่ายๆ: **น้ำเงิน = กำลังทำงาน, เขียว = สำเร็จ, แดง = มีปัญหา** (ยิ่งกะพริบเร็ว ยิ่งเป็นช่วงที่ต้องการให้คุณสังเกต)
และทุกครั้งที่สถานะเปลี่ยน Serial จะพิมพ์บอกว่า LED ตอนนี้ควรเป็นอย่างไร จึงตรวจเทียบกับสีที่เห็นได้ทันที

> ตอนเปิดเครื่อง LED จะทดสอบตัวเองก่อน (แดง → เขียว → น้ำเงิน สีละ 0.3 วินาที) เพื่อให้รู้ว่าไฟทั้ง 3 สีปกติ

## ตั้งค่า WiFi ของคุณ (ทำครั้งเดียว)

ชื่อ WiFi และรหัสผ่าน **ไม่ได้เขียนไว้ในโค้ด** แต่เก็บในไฟล์ `include/secrets.h` ที่ git ไม่เก็บ (รหัสผ่านจึงไม่หลุดขึ้น GitHub)

1. คัดลอกไฟล์ `include/secrets.h.example` เป็น **`include/secrets.h`** (ชื่อต้องเป็น `secrets.h` ตรงตัว)
2. เปิด `secrets.h` แก้ 2 บรรทัดนี้ให้เป็นของคุณ

```cpp
inline constexpr char WIFI_SSID[] = "MyHomeWiFi";        // ชื่อ WiFi (พิมพ์ให้ตรงทุกตัวอักษร)
inline constexpr char WIFI_PASSWORD[] = "mypassword123"; // รหัสผ่าน (เครือข่ายเปิดไม่มีรหัส ให้เว้นว่างเป็น "")
```

3. บันทึกไฟล์ แล้ว build และ upload

ข้อควรรู้ก่อนตั้งค่า

| เรื่อง | รายละเอียด |
|---|---|
| ต้องเป็น **2.4 GHz** | ESP32 ไม่รองรับ WiFi 5 GHz ถ้า router ปล่อยชื่อเดียวกันทั้งสองย่าน ปกติบอร์ดจะต่อย่าน 2.4 GHz ให้เอง ถ้ามีแยกชื่อ ให้ใช้ชื่อของย่าน 2.4 GHz |
| ชื่อต้องตรงเป๊ะ | แยกตัวพิมพ์ใหญ่-เล็ก และรวมช่องว่างด้วย (`MyWiFi` ≠ `mywifi` ≠ `MyWiFi `) |
| รหัสผ่านอย่างน้อย 8 ตัว | ถ้ารหัสสั้นกว่า 8 ตัว (แต่ไม่ว่าง) โปรแกรมจะเตือนใน Serial |
| อย่าแก้ `.example` | ไฟล์ `.example` ถูกเก็บใน git ห้ามใส่รหัสจริงลงไป |
| ห้ามอัปโหลด `secrets.h` | อย่าลบ `.gitignore` หรือใช้ `git add -f` กับไฟล์นี้ |
| WiFi ที่ซ่อนชื่อ (hidden SSID) | โปรแกรมนี้หาเครือข่ายด้วยการสแกนก่อน จึงไม่เจอเครือข่ายที่ซ่อนชื่อ (ใช้ชื่อที่ broadcast ปกติ) |

ถ้าไม่ได้สร้าง `secrets.h` โปรแกรมก็ยัง build และรันได้ แต่ LED จะเป็นแดงกะพริบเร็ว และ Serial จะบอกให้ตั้งค่า (ตั้งใจให้เห็นกรณีนี้ได้เลย)

## การทำงาน (state machine)

```
                 ┌──────────────── SSID ว่าง ────────────────┐
   เปิดเครื่อง → Boot ─┤                                      ▼
                       └─ มี SSID ─► Scanning ─► เจอชื่อ ─► Connecting ─► Connected
                                        │                      │              │
                                  ไม่เจอชื่อ              ล้มเหลว/หมดเวลา   สัญญาณหลุด
                                        ▼                      ▼              ▼
                                      Failed ◄─────────────────┘            Lost
                                        │   รอ 5 วินาที                       │ รอ 5 วินาที
                                        └──────────► Scanning ◄───────────────┘
```

| ขั้นตอน | โปรแกรมทำอะไร |
|---|---|
| **Scanning** | สั่งสแกนแบบ async (ไม่หยุดรอ) แล้วพิมพ์รายการ WiFi ที่เจอพร้อมความแรงสัญญาณ และตรวจว่ามีชื่อของคุณหรือไม่ ถ้าไม่เจอจะบอกทันทีโดยไม่เสียเวลาลองต่อ 15 วินาที |
| **Connecting** | เรียก `WiFi.begin(ssid, password)` แล้วเช็ค `WiFi.status()` ทุกรอบ พิมพ์ความคืบหน้าทุกวินาที หมดเวลา 15 วินาทีถือว่าล้มเหลว |
| **Connected** | พิมพ์ IP, Gateway, Subnet, DNS, MAC, ช่องสัญญาณ, ความแรงสัญญาณ (RSSI) แล้วคอยตรวจว่ายังต่ออยู่ พิมพ์ RSSI ทุก 5 วินาที |
| **Failed / Lost** | พิมพ์สาเหตุ (จาก reason code ของ ESP32) แล้วรอ 5 วินาทีก่อนสแกนใหม่ วนไปเรื่อยๆ |

## ความรู้ที่ได้ใน Lab นี้

| เรื่อง | อธิบายสั้นๆ |
|---|---|
| **SSID / รหัสผ่าน** | SSID คือชื่อ WiFi รหัสผ่านคือกุญแจเข้าเครือข่าย |
| **โหมด Station (STA)** | บอร์ดเป็น "ลูกข่าย" ที่ไปต่อกับ router (`WiFi.mode(WIFI_STA)`) |
| **DHCP และ IP** | router แจกที่อยู่ IP ให้บอร์ดอัตโนมัติหลังต่อสำเร็จ |
| **Gateway / Subnet / DNS** | Gateway = ทางออกไปอินเทอร์เน็ต (มักเป็น router), Subnet = ขอบเขตวงแลนเดียวกัน, DNS = ตัวแปลงชื่อเว็บเป็น IP |
| **MAC address** | หมายเลขประจำตัวของการ์ด WiFi บอร์ดนี้ (ไม่ซ้ำกับใคร) |
| **RSSI (dBm)** | ความแรงสัญญาณ ติดลบ ยิ่งใกล้ 0 ยิ่งแรง: ≥ −55 แรง, ≥ −70 ดี, ≥ −80 อ่อน, ต่ำกว่านั้นอ่อนมาก (ค่าประมาณ) |
| **Async scan** | สั่งสแกนแล้วไม่รอ ถามผลทีหลัง ทำให้ LED ยังกะพริบได้ระหว่างสแกน (เหมือนแนวคิด `millis()` แทน `delay()`) |
| **Event callback** | ฟังก์ชันที่ระบบเรียกให้เมื่อเกิดเหตุการณ์ (เช่น WiFi หลุด) ใช้จดรหัสสาเหตุ ตัวแปรที่แชร์ข้าม task ต้องเป็น `volatile` |
| **การเก็บความลับ** | แยกรหัสผ่านไว้ใน `secrets.h` ที่ git ไม่เก็บ ไม่เขียนรหัสผ่านลงโค้ดหลัก และไม่พิมพ์รหัสผ่านออก Serial (พิมพ์แค่ความยาว) |

## วิธีรันและทดสอบ

```powershell
pio run -t upload --upload-port COM3
pio device monitor -b 115200 --port COM3
```

(ปิด Serial Monitor ก่อน upload ทุกครั้ง, ถ้าไม่เห็นข้อความตอนเปิดเครื่องให้กดปุ่ม EN/RESET)

### ทดลองที่ 1 — ยังไม่ตั้งค่า (ทำได้ทันที)

ยังไม่ต้องสร้าง `secrets.h` เห็นสถานะ `NotConfigured` และ LED แดงกะพริบเร็ว

### ทดลองที่ 2 — ตั้งค่าถูกต้อง

สร้าง `secrets.h` ด้วยชื่อ/รหัสที่ถูก → เห็นน้ำเงินกะพริบช้า → น้ำเงินกะพริบเร็ว → **เขียวติดค้าง** และ Serial พิมพ์ IP

### ทดลองที่ 3 — ตั้งชื่อ WiFi ผิด

แก้ `WIFI_SSID` ให้พิมพ์ผิดหนึ่งตัวอักษร → สแกนแล้วไม่เจอชื่อ → **แดงติดค้าง** Serial บอกว่า `SSID not found` และลองใหม่ทุก 5 วินาที

### ทดลองที่ 4 — ตั้งรหัสผ่านผิด

แก้ `WIFI_PASSWORD` ให้ผิด → ต่อไม่ติด → **แดงติดค้าง** Serial พิมพ์รหัสสาเหตุ เช่น `AUTH_FAIL` หรือ `HANDSHAKE_TIMEOUT` (รหัสผ่านผิดมักขึ้นสองอย่างนี้)

### ทดลองที่ 5 — ให้ WiFi หลุด

ตอนเขียวติดค้างอยู่ ลองปิด router (หรือปิด hotspot มือถือ) → แดงกะพริบช้า (`Lost`) → เปิดคืน → น้ำเงิน → เขียว

### ส่วนที่ทดสอบกับบอร์ดจริงแล้ว

กรณียังไม่มี `secrets.h`

```
==========================================
Hello World from ESP32-2432S028 (CYD)!
Level 1 / Lab 3 : WiFi Connecting
==========================================
LED legend:
  BLUE  blinking slow = scanning for WiFi networks
  BLUE  blinking fast = connecting to your WiFi
  GREEN steady        = connected (got an IP address)
  RED   steady        = failed (will retry)
  RED   blinking slow = connection lost (will retry)
  RED   blinking fast = WiFi name/password not set in include/secrets.h

LED self-test: RED -> GREEN -> BLUE
[STATE] Boot -> NotConfigured   (LED: RED blinking fast)

กรณีตั้งชื่อ WiFi ที่ไม่มีอยู่จริง (ทดสอบด้วยชื่อสมมติ) บอร์ดสแกนเจอ WiFi รอบตัวและแจ้งว่าหาชื่อไม่เจอ (ชื่อ `YourRouter_2.4G` ด้านล่างคือชื่อสมมติแทนเครือข่ายที่สแกนเจอจริง)

```

[WiFi] attempt #1: scanning for networks ...
[STATE] Boot -> Scanning   (LED: BLUE blinking slow)
[SCAN] found 1 network(s):
        #  SSID                      CH   RSSI  signal       security
        1  YourRouter_2.4G            6   -44  [#######---]  secured
[WiFi] "Lab3_NoSuchNetwork_Test" was NOT found in the scan. Check the spelling (upper/lower case, spaces) and that the router uses 2.4 GHz.
[WiFi] FAILED: SSID not found
[WiFi] will retry in 5 s ...

[WiFi] attempt #2: scanning for networks ...

(ทดสอบ 6 รอบติดต่อกัน สแกนสำเร็จทุกรอบ ใช้เวลารอบละราว 1–6 วินาที ขึ้นกับสภาพคลื่นรอบตัว)

### เส้นทางเชื่อมต่อสำเร็จ (ผู้ใช้ทดสอบกับ WiFi จริงแล้วว่าใช้งานได้)

ผู้พัฒนาทดสอบกับ WiFi จริงแล้วและยืนยันว่าทำงานได้ดี ข้อความด้านล่างเป็น **ตัวอย่างประกอบ** ที่เขียนตามโค้ด (ตัวเลข IP, MAC และเวลา)
ค่าจริงของคุณจะต่างตามเครือข่ายของคุณเอง

[WiFi] CONNECTED in 2.3 s
       SSID    : MyHomeWiFi
       IP      : 192.168.1.45
       Gateway : 192.168.1.1
       Subnet  : 255.255.255.0
       DNS     : 192.168.1.1
       MAC     : AA:BB:CC:DD:EE:FF
       Channel : 6
       RSSI    : -48 dBm [#######---] strong

## ค่าที่ปรับได้ใน `app_config.h`

| ค่า | ค่าเริ่มต้น | ผลเมื่อปรับ |
|---|---|---|
| `CONNECT_TIMEOUT_MS` | 15000 | รอการเชื่อมต่อนานแค่ไหนก่อนถือว่าล้มเหลว |
| `RETRY_DELAY_MS` | 5000 | พักกี่ ms ก่อนลองใหม่ |
| `SCAN_TIMEOUT_MS` | 15000 | รอผลสแกนนานสุดกี่ ms |
| `STATUS_PRINT_MS` | 5000 | พิมพ์ RSSI ตอนเชื่อมแล้วทุกกี่ ms |
| `CONNECTING_PRINT_MS` | 1000 | พิมพ์ความคืบหน้าตอนกำลังเชื่อมทุกกี่ ms |
| `MAX_SCAN_RESULTS_PRINTED` | 15 | โชว์รายชื่อ WiFi สูงสุดกี่รายการ |
| `BLINK_FAST_MS` / `BLINK_SLOW_MS` | 150 / 500 | จังหวะกะพริบเร็ว / ช้า |
| `SELF_TEST_STEP_MS` | 300 | เวลาทดสอบ LED ต่อสีตอนเปิดเครื่อง |

## แบบฝึกหัด

1. **ดูข้อความผิดพลาดให้ครบ:** ทำทดลองที่ 3 และ 4 แล้วเทียบสิ่งที่ Serial พิมพ์ว่ากรณี "ชื่อผิด" กับ "รหัสผิด" ต่างกันอย่างไร
2. **เปลี่ยนความหมายของสี:** แก้ฟังก์ชัน `patternFor()` ให้สถานะ `Connected` เป็นสีฟ้าอมเขียว (เขียว + น้ำเงิน) แทนเขียว แล้วทดสอบ
3. **ปรับจังหวะ:** ลองตั้ง `BLINK_FAST_MS = 60` และ `BLINK_SLOW_MS = 1000` เทียบความรู้สึกของสถานะ `Connecting` กับ `Scanning`
4. **ปรับเวลา:** ตั้ง `CONNECT_TIMEOUT_MS = 3000` แล้วลองต่อ WiFi ที่สัญญาณอ่อน ผลเป็นอย่างไร ทำไมการตั้งน้อยเกินไปจึงไม่ดี
5. **ท้าทาย:** พิมพ์ RSSI ตอนเชื่อมแล้วเฉพาะเมื่อค่าเปลี่ยนจากที่พิมพ์ล่าสุดตั้งแต่ 5 dBm ขึ้นไป (แนวคิดเดียวกับ Lab 2)
6. **ท้าทาย:** จำกัดจำนวนครั้งที่ลองใหม่ที่ 3 ครั้ง หลังจากนั้นค้างที่สถานะ `Failed` (แดงติดค้าง) และพิมพ์บอกให้ตรวจ `secrets.h` (คำใบ้: ใช้ตัวแปร `attempt` ที่มีอยู่แล้ว)

| แดงกะพริบเร็ว ตลอด | ยังไม่มี `include/secrets.h` หรือ `WIFI_SSID` ว่าง ให้ทำตามหัวข้อ "ตั้งค่า WiFi ของคุณ" แล้ว upload ใหม่ |

| `SSID not found` ทั้งที่ชื่อถูก | router ปล่อยเฉพาะ 5 GHz / อยู่ไกล / ชื่อซ่อน (hidden) / ตัวพิมพ์ใหญ่-เล็กหรือช่องว่างไม่ตรง ลองดูรายการที่สแกนเจอว่าชื่ออยู่ในนั้นไหม |
| ขึ้น `AUTH_FAIL` หรือ `HANDSHAKE_TIMEOUT` | รหัสผ่านผิด (ตรวจตัวพิมพ์ใหญ่-เล็ก ช่องว่างหน้า-หลัง) |
| ต่อ hotspot มือถือไม่ติด | เปิดโหมด 2.4 GHz ใน hotspot (iPhone: เปิด "เพิ่มความเข้ากันได้สูงสุด") |
| ต่อได้บ้างไม่ได้บ้าง | สัญญาณอ่อน (ดู RSSI ต่ำกว่า −80 dBm) ขยับเข้าใกล้ router |
| upload ไม่ผ่าน `Access is denied` | ปิด Serial Monitor ก่อน upload |
| ข้อความ Serial เป็นตัวอักษรเพี้ยน | ตั้ง baud 115200 |
