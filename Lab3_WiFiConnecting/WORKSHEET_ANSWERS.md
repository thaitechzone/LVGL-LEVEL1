| รายการ | สถานะ |

| กรณีไม่มี `secrets.h` (`NotConfigured`, ข้อความเตือนซ้ำทุก 5 วินาที, LED legend, self-test) | ตรวจจากบอร์ดจริงแล้ว |

| โค้ดเฉลยข้อ 2, 5, 6, 7 | **build ผ่าน** (รวมกันในโปรเจกต์ทดสอบ) ยังไม่ได้รันบนบอร์ดกับ WiFi จริง |

ผู้สอนควรทดสอบ Lab นี้เองครบทั้ง 3 กรณี (ต่อสำเร็จ / ชื่อผิด / รหัสผิด) ก่อนสอน เพื่อจดค่าจริงของห้องเรียนไว้ใช้ตรวจงาน

## ตารางสรุป LED (หัวข้อ 2)

| สถานะ | LED |
|---|---|
| `NotConfigured` | แดงกะพริบเร็ว (150 ms) |
| `Scanning` | น้ำเงินกะพริบช้า (500 ms) |
| `Connecting` | น้ำเงินกะพริบเร็ว (150 ms) |
| `Connected` | เขียวติดค้าง |
| `Failed` | แดงติดค้าง |
| `Lost` | แดงกะพริบช้า (500 ms) |

## ผลที่ตรวจจากบอร์ดจริง (ขั้นที่ 3)

ข้อความ `[WiFi] include/secrets.h not found ...` ซ้ำทุก **5 วินาที** และ LED เป็นแดงกะพริบเร็ว

## แบบฝึกหัด

### ข้อ 1 — เทียบ 3 กรณี

| กรณี | LED สุดท้าย | ข้อความสำคัญ | เวลารู้ผล |
|---|---|---|---|
| ต่อสำเร็จ | เขียวติดค้าง | `[WiFi] CONNECTED in x s`, `Connecting -> Connected` | สแกน 1–6 วินาที + ต่อ ~2–5 วินาที (ขึ้นกับเครือข่าย) |
| ชื่อผิด | แดงติดค้าง | `was NOT found in the scan`, `FAILED: SSID not found` | เท่ากับเวลาสแกนเท่านั้น (1–6 วินาที) |
| รหัสผ่านผิด | แดงติดค้าง | `FAILED: ...` + `reason code ... ->` (ผู้สอนจดค่าจริง) | ช้าที่สุด: ต้องเข้า `Connecting` และรออีกสูงสุด 15 วินาที |

คำตอบ: **ชื่อผิด** รู้ผลเร็วที่สุด เพราะการสแกนไม่เจอชื่อ โปรแกรมจึงไม่เข้าสถานะ `Connecting` เลย ส่วนรหัสผ่านผิด ระบบต้องลองพิสูจน์ตัวตนกับ router ก่อน
จึงรู้ผลเมื่อได้รหัสสาเหตุหรือครบ 15 วินาที

### ข้อ 2 — Connected เป็นสีฟ้าอมเขียว
ใน `patternFor()`
```cpp
case WifiState::Connected: return {false, true, true, 0, "CYAN steady"};
```
(build ผ่านแล้ว) ค่าที่ 2 และ 3 คือ green และ blue เป็น true

### ข้อ 3 — จังหวะกะพริบ
`BLINK_FAST_MS = 60` จะกะพริบเร็วจนตาแทบจับไม่ทัน ส่วน `BLINK_SLOW_MS = 1000` ช้าจนดูเหมือนหยุดชะงัก ผู้เรียนควรสรุปได้ว่าต้องเลือกให้ **ต่างกันชัดเจนแต่ยังเห็นเป็นการกะพริบ**
ค่าเริ่มต้น 150/500 ms ออกแบบให้แยกสองสถานะออกจากกันได้ง่าย

### ข้อ 4 — CONNECT_TIMEOUT_MS = 3000
การต่อ WiFi ผ่านหลายขั้น (หัวข้อ 3.2: หาเครือข่าย → พิสูจน์ตัวตน → เข้าร่วม → ขอ IP) มักใช้เวลาหลายวินาทีแม้รหัสถูก (ตัวอย่างในใบงานใช้ ~2.3 วินาที)
ถ้าตั้ง 3 วินาที อาจหมดเวลาก่อนต่อสำเร็จ ทำให้ล้มเหลวทั้งที่ทุกอย่างถูก แล้ววนลองใหม่ไม่รู้จบ (false failure) จึงควรตั้งให้มีเผื่อ (ค่าเริ่มต้น 15 วินาที)

### ข้อ 5 — พิมพ์ RSSI เฉพาะเมื่อเปลี่ยน ≥ 5 dBm
เพิ่มตัวแปรโกลบอลและเก็บค่าตอนเชื่อมต่อ
```cpp
int lastPrintedRssi = 0;                      // ไว้ข้างตัวแปรอื่นใน namespace ไม่มีชื่อ

// ใน onConnected() ก่อน setState(WifiState::Connected):
lastPrintedRssi = WiFi.RSSI();

// ใน loop() สถานะ Connected แทนบล็อกที่พิมพ์ทุก STATUS_PRINT_MS:
} else if (now - lastPrintAt >= app::STATUS_PRINT_MS) {
    lastPrintAt = now;
    const int rssi = WiFi.RSSI();
    if (abs(rssi - lastPrintedRssi) >= 5) {
        lastPrintedRssi = rssi;
        char bar[11];
        makeRssiBar(rssi, bar);
        Serial.printf("[WiFi] online  IP %s   RSSI %d dBm [%s] %s\n", WiFi.localIP().toString().c_str(), rssi,
                      bar, rssiQuality(rssi));
    }
}
```
(build ผ่านแล้ว) ตอนสัญญาณนิ่งจะไม่มีบรรทัด `online` ใหม่ มีเฉพาะเมื่อ RSSI เปลี่ยนมากพอ

### ข้อ 6 — จำกัดการลองใหม่ 3 รอบ
เพิ่มใน `app_config.h`: `constexpr uint8_t MAX_ATTEMPTS = 3;` และตัวแปรโกลบอล `bool gaveUp = false;` แล้วแก้ case `Failed`/`Lost`
```cpp
case WifiState::Failed:
case WifiState::Lost:
    if (attempt >= app::MAX_ATTEMPTS) {
        if (!gaveUp) {
            gaveUp = true;
            Serial.printf("[WiFi] gave up after %u attempts. Check include/secrets.h, then press EN/RESET.\n",
                          static_cast<unsigned>(attempt));
        }
        break;
    }
    if (now - stateSince >= app::RETRY_DELAY_MS) {
        startScan();
    }
    break;
```
(build ผ่านแล้ว) `attempt` เพิ่มทุกครั้งที่ `startScan()` ทำงาน จึงนับรอบการลอง LED ค้างแดงติดค้างต่อไป
หมายเหตุ: ข้อความ `will retry in 5 s` จากรอบสุดท้ายยังพิมพ์ออกมาตามโค้ดเดิม (ผู้เรียนที่ละเอียดอาจปรับให้ไม่พิมพ์เมื่อถึงขีดจำกัด)

```cpp
if (pattern.blinkMs == 0) {
    ...
```
(build ผ่านแล้ว) ถ้าสัญญาณแรงกว่า −75 ยังเป็นเขียวตามเดิม ข้อควรสังเกต: `WiFi.RSSI()` ถูกเรียกทุกรอบ `loop()` ซึ่งไม่ถี่เกินไปสำหรับงานนี้
แต่ถ้ากลัวสิ้นเปลือง ให้อ่านทุก 500 ms แล้วเก็บไว้ในตัวแปร (เป็นแนวทางต่อยอดได้)

### ข้อ 8 — ข้อดี/ข้อเสียของการสแกนก่อนเชื่อมต่อ
ข้อดี (ตอบได้ 2 ข้อขึ้นไป)
1. ได้ข้อมูลรอบตัว (ช่องสัญญาณ, RSSI, ชนิดความปลอดภัย) ช่วยวินิจฉัยปัญหา เช่นเห็นว่ามีแต่ 2.4 GHz
2. รู้ทันทีว่า "ชื่อผิด/ไม่เจอ" โดยไม่ต้องรอ timeout 15 วินาทีของการเชื่อมต่อ
3. แยกสาเหตุได้ชัด: ชื่อไม่เจอ (ที่สแกน) กับ รหัสผิด (ที่เชื่อมต่อ)
4. ผู้เรียนเห็นภาพเครือข่ายรอบตัว (สื่อการเรียนรู้ที่ดี)

ข้อเสีย
- เสียเวลาสแกน 1–6 วินาทีก่อนเชื่อมต่อทุกครั้ง
- ไม่เจอเครือข่ายที่ซ่อนชื่อ (hidden SSID) ทั้งที่การเรียก `WiFi.begin()` ตรงๆ อาจต่อได้

## คำถามทบทวน

1. SSID คือชื่อเครือข่าย WiFi ส่วนรหัสผ่านคือกุญแจเข้าเครือข่าย
2. ชิป ESP32 รองรับ WiFi ย่าน 2.4 GHz เท่านั้น ถ้า router ปล่อยสองย่าน ให้ใช้ชื่อของย่าน 2.4 GHz (หรือเปิดโหมดที่ให้ 2.4 GHz ใช้งานได้)
3. −45 dBm แรงกว่า (ยิ่งใกล้ 0 ยิ่งแรง) ตามเกณฑ์ของโปรแกรม −45 เป็น `strong` (≥ −55) และ −82 เป็น `very weak` (< −80)
4. IP = ที่อยู่ในเครือข่าย, Gateway = ทางออกสู่อินเทอร์เน็ต (มักคือ router), Subnet = ขอบเขตของวงเครือข่ายเดียวกัน, DNS = แปลงชื่อเว็บเป็น IP, MAC = หมายเลขประจำการ์ด WiFi
5. Station = บอร์ดเป็นลูกข่ายต่อเข้า router; Access Point = บอร์ดปล่อยสัญญาณ WiFi เอง
6. รหัสผ่านเป็นความลับ ไม่ควรอยู่ในโค้ดที่แชร์ได้ การแยกไว้ใน `secrets.h` และให้ `.gitignore` ละเว้นไฟล์นี้ ทำให้ git ไม่เก็บและไม่ขึ้น GitHub
7. ทำให้โปรแกรม build ได้แม้ยังไม่มี `secrets.h` (ใช้ค่าว่างแทน) แล้วแจ้งผู้ใช้ผ่าน Serial/LED แทนที่จะ build ล้มด้วยข้อความที่เข้าใจยาก
8. กันรหัสผ่านหลุดจากการแคปหน้าจอ/ส่ง log ให้ผู้อื่น พิมพ์แค่ความยาวก็พอช่วยตรวจเช่นรหัสสั้นเกินไปหรือมีช่องว่างเกิน
9. State machine คือการแยกงานเป็นสถานะ ที่แต่ละรอบ `loop()` ทำเฉพาะงานของสถานะนั้นแล้วออกทันที ไม่หยุดรอ จึงกะพริบ LED และรับเหตุการณ์ใหม่ได้ตลอด ต่างจาก `delay()` ที่หยุดทุกอย่าง
10. async สั่งสแกนแล้วไม่รอ ให้ถามผลทีหลังด้วย `scanComplete()` ผลดีคือ LED น้ำเงินยังกะพริบได้ตลอดระหว่างสแกน
11. ใช้กับตัวแปรที่ถูกเปลี่ยนจากที่อื่นนอกโค้ดที่กำลังอ่าน (เช่น callback/ต่าง task) เพื่อให้อ่านค่าล่าสุดเสมอ `lastDisconnectReason` ถูกเขียนจาก `onWifiEvent`
12. `Failed` = ยังต่อไม่สำเร็จเลย (ชื่อไม่เจอ รหัสผิด หมดเวลา) → แดงติดค้าง; `Lost` = เคยต่อสำเร็จแล้วหลุด → แดงกะพริบช้า ทั้งสองรอ 5 วินาทีแล้วเริ่มสแกนใหม่
13. ไลบรารีตัดสินว่าสแกน "ล้มเหลว" ถ้าเกินราว 6 วินาที ทั้งที่สแกนยังเดินต่อและเสร็จได้ (ห้องทดสอบสแกนใช้ 1–6 วินาที) ทำให้ผลเป็นล้มเหลวเป็นระยะ แก้โดยรอเองได้ถึง `SCAN_TIMEOUT_MS` (15 วินาที)
14. ดูข้อความ `[WiFi] FAILED: ...` และ `reason code`: `NO_AP_FOUND` = หาชื่อไม่เจอ, `AUTH_FAIL` = พิสูจน์ตัวตนไม่ผ่าน (รหัสผ่านผิด)
15. ต้อง upload ใหม่ เพราะค่าใน `secrets.h` ถูกคอมไพล์รวมเข้าโปรแกรมตอน build ไม่ได้ถูกอ่านตอนรัน

## แนวทางให้คะแนนและข้อควรระวัง

- **ห้ามขอรหัสผ่านจริงของผู้เรียน** ตรวจจากภาพ Serial ที่ไม่มีรหัส (โปรแกรมพิมพ์แค่ความยาว) และคำตอบ `git check-ignore`
- ผู้เรียนที่ต่อไม่ติด: ให้ตรวจตามลำดับ (1) ดูตารางสแกนว่ามีชื่อตัวเองไหม (2) ย่าน 2.4 GHz (3) ตัวพิมพ์ใหญ่-เล็ก/ช่องว่าง (4) รหัสผ่าน (5) ระยะห่าง/RSSI
- ถ้ามีผู้เรียนหลายคนใช้ hotspot มือถือเดียวกัน อาจต่อได้ไม่ครบ (จำนวนอุปกรณ์จำกัด) ให้แบ่งกลุ่มหรือใช้ router ห้องเรียน
- ข้อมูล MAC/IP ของผู้เรียนไม่ใช่ความลับสำคัญ แต่ไม่ควรบังคับให้ส่ง
- ถ้าผู้เรียนเผลอ commit `secrets.h` ให้ถือว่ารหัสหลุด ต้องเปลี่ยนรหัสผ่าน WiFi (ตามตารางปัญหาในใบงาน)
