## 1. เป้าหมายการเรียนรู้

เมื่อจบใบงานนี้ ผู้เรียนต้องทำได้ทุกข้อ

1. อธิบายความหมายของ SSID, รหัสผ่าน, WiFi 2.4 GHz, RSSI, IP, Gateway, Subnet, DNS และ MAC ได้
2. กำหนดชื่อ WiFi และรหัสผ่านด้วยตัวเองผ่านไฟล์ `secrets.h` โดยไม่เขียนรหัสผ่านลงในโค้ดหลัก และอธิบายเหตุผลได้
3. ทำให้บอร์ดเชื่อมต่อ WiFi สำเร็จ และอ่านผลจาก Serial Monitor ได้ทุกบรรทัด
4. บอกความหมายของไฟ LED ทุกสถานะ (สีและจังหวะกะพริบ) ได้ และเทียบกับข้อความใน Serial ได้
5. วิเคราะห์สาเหตุเมื่อเชื่อมต่อไม่สำเร็จ (ชื่อผิด, รหัสผิด, สัญญาณหลุด) จาก Serial และ LED ได้
6. อ่านโค้ด state machine ที่มีหลายสถานะและการสแกนแบบ async ได้ และปรับแก้ตามแบบฝึกหัดได้

## 2. ภาพรวมสิ่งที่จะสร้าง

```
   secrets.h (ชื่อ+รหัส WiFi ของคุณ)               บ้าน/ห้องเรียน
            │                                       ┌────────────┐
            ▼                                       │  Router    │──► อินเทอร์เน็ต
   ┌───────────────────┐   คลื่น WiFi 2.4 GHz         │ (SSID, รหัส)│
   │  บอร์ด ESP32 CYD   │ ◄──────────────────────────► └────────────┘
   │  state machine     │
   └───────┬─────┬─────┘
           │     │
   Serial Monitor  RGB LED   ← น้ำเงิน = กำลังทำงาน, เขียว = สำเร็จ, แดง = มีปัญหา
   (รายงานละเอียด)  (บอกสถานะ)
```

| LED | สถานะ | ความหมาย |
|---|---|---|
| 🔴 แดง **กะพริบเร็ว** | `NotConfigured` | ยังไม่ได้ตั้งชื่อ/รหัส WiFi |
| 🔵 น้ำเงิน **กะพริบช้า** | `Scanning` | กำลังสแกนหา WiFi รอบตัว |
| 🔵 น้ำเงิน **กะพริบเร็ว** | `Connecting` | กำลังเชื่อมต่อ |
| 🟢 เขียว **ติดค้าง** | `Connected` | เชื่อมต่อสำเร็จ ได้ IP |
| 🔴 แดง **ติดค้าง** | `Failed` | ล้มเหลว จะลองใหม่เองใน 5 วินาที |
| 🔴 แดง **กะพริบช้า** | `Lost` | เคยต่อได้แต่สัญญาณหลุด จะลองใหม่เอง |

## 3. ความรู้พื้นฐานที่ต้องเข้าใจก่อนลงมือ

### 3.1 เครือข่าย WiFi เบื้องต้น

| คำ | ความหมาย | ตัวอย่าง |
|---|---|---|
| **Router (เราเตอร์)** | อุปกรณ์ที่ปล่อยสัญญาณ WiFi และเชื่อมเครือข่ายในบ้านเข้ากับอินเทอร์เน็ต | กล่อง WiFi ที่บ้าน |
| **SSID** | ชื่อของเครือข่าย WiFi (ที่เห็นตอนเลือกเชื่อมต่อในมือถือ) | `MyHomeWiFi` |
| **รหัสผ่าน (Password / Passphrase)** | กุญแจเข้าเครือข่าย แบบ WPA2 ต้องยาว **อย่างน้อย 8 ตัวอักษร** | `mypassword123` |
| **2.4 GHz / 5 GHz** | ย่านความถี่ของ WiFi **ESP32 รองรับเฉพาะ 2.4 GHz** | |
| **ช่องสัญญาณ (Channel)** | ช่องความถี่ย่อยของ WiFi ย่าน 2.4 GHz (ช่อง 1–13) | `CH 6` |
| **RSSI** | ความแรงสัญญาณที่บอร์ดรับได้ หน่วย dBm เป็นเลขติดลบ **ยิ่งใกล้ 0 ยิ่งแรง** | −45 แรงกว่า −80 |

เกณฑ์คร่าวๆ ของ RSSI ที่โปรแกรมนี้ใช้ตัดสิน

| RSSI | คำที่แสดง |
|---|---|
| −55 dBm ขึ้นไป | `strong` |
| −70 ถึง −56 | `good` |
| −80 ถึง −71 | `weak` |
| ต่ำกว่า −80 | `very weak` |

### 3.2 การต่อ WiFi เกิดขึ้นเป็นขั้นๆ

เมื่อสั่ง `WiFi.begin(ssid, password)` เบื้องหลังเกิดลำดับนี้ และ **แต่ละขั้นล้มเหลวด้วยเหตุผลต่างกัน**

| ขั้น | เกิดอะไรขึ้น | ถ้าล้มเหลว มักเพราะ |
|---|---|---|
| 1. หาเครือข่าย | บอร์ดค้นหา router ชื่อ SSID นั้น | ชื่อผิด, อยู่ไกล, router ปล่อยแต่ 5 GHz |
| 2. พิสูจน์ตัวตน | แลกเปลี่ยนกุญแจจากรหัสผ่าน (WPA2 4-way handshake) | **รหัสผ่านผิด** |
| 3. เข้าร่วมเครือข่าย | router ยอมรับบอร์ดเข้าเครือข่าย | router จำกัดจำนวนอุปกรณ์/กรองอุปกรณ์ |
| 4. ขอ IP (DHCP) | router แจกที่อยู่ IP ให้บอร์ด | router ไม่ตอบ / IP หมด |

เมื่อผ่านครบ `WiFi.status()` จะเป็น `WL_CONNECTED`

### 3.3 IP, Gateway, Subnet, DNS, MAC

| คำ | ความหมาย |
|---|---|
| **IP address** | ที่อยู่ของบอร์ดในเครือข่าย เช่น `192.168.1.45` ได้มาจาก DHCP ของ router (เปลี่ยนได้เมื่อเชื่อมใหม่) |
| **Gateway** | ทางออกไปสู่อินเทอร์เน็ต ปกติคือ IP ของ router เช่น `192.168.1.1` |
| **Subnet mask** | บอกขอบเขตของวงเครือข่ายเดียวกัน เช่น `255.255.255.0` แปลว่า IP ที่ขึ้นต้น `192.168.1.` อยู่วงเดียวกัน |
| **DNS** | ตัวแปลงชื่อเว็บ (เช่น `example.com`) เป็นเลข IP |
| **MAC address** | หมายเลขประจำการ์ด WiFi ของบอร์ด ไม่เปลี่ยนตามเครือข่าย เช่น `AA:BB:CC:DD:EE:FF` |

### 3.4 โหมด Station (STA)

ESP32 ทำได้หลายโหมด ใน Lab นี้ใช้ **Station** คือบอร์ดเป็น "ลูกข่าย" ที่ไปต่อกับ router (เหมือนมือถือต่อ WiFi)
อีกโหมดคือ Access Point (บอร์ดปล่อย WiFi เอง) ยังไม่ใช้ใน Lab นี้ โค้ดสั่งด้วย `WiFi.mode(WIFI_STA)`

### 3.5 การเก็บรหัสผ่านอย่างปลอดภัย

| หลักการ | ในโปรเจกต์นี้ |
|---|---|
| ไม่เขียนรหัสผ่านลงในโค้ดหลัก | เก็บใน `include/secrets.h` แยกไฟล์ |
| ไฟล์ลับต้องไม่ขึ้น git/GitHub | `.gitignore` มีบรรทัด `include/secrets.h` จึงถูกละเว้น |
| มีไฟล์ตัวอย่างให้คัดลอก | `secrets.h.example` (ไม่มีรหัสจริง ขึ้น git ได้) |
| ไม่พิมพ์รหัสผ่านออก Serial | โปรแกรมพิมพ์แค่ความยาวของรหัส (`password length: 13`) |
| โปรแกรมยัง build ได้แม้ไม่มี `secrets.h` | ใช้ `#if __has_include("secrets.h")` เลือกใช้ค่าสำรองที่ว่างเปล่า แล้วแจ้งผู้ใช้ผ่าน Serial/LED |

### 3.6 State machine ของ WiFi

โปรแกรมมี 7 สถานะ (`enum class WifiState`) แต่ละสถานะรู้ว่า "ต้องทำอะไร" และ "ไปสถานะไหนต่อเมื่อไร"

| สถานะ | ทำอะไร | ไปต่อ |
|---|---|---|
| `Boot` | ช่วงเริ่มต้นสั้นๆ | → `NotConfigured` (ถ้า SSID ว่าง) หรือ `Scanning` |
| `NotConfigured` | เตือนผู้ใช้ทุก 5 วินาที | (ค้างอยู่จนกว่าจะแก้ `secrets.h` แล้ว upload ใหม่) |
| `Scanning` | รอผลสแกน | → `Connecting` (เจอชื่อ) หรือ `Failed` (ไม่เจอ/สแกนไม่เสร็จใน 15 วินาที) |
| `Connecting` | รอ `WL_CONNECTED` | → `Connected` / `Failed` (รหัสผิดหรือหมดเวลา 15 วินาที) |
| `Connected` | ตรวจว่ายังต่ออยู่ พิมพ์ RSSI ทุก 5 วินาที | → `Lost` (สถานะไม่ใช่ connected แล้ว) |
| `Failed` / `Lost` | รอ 5 วินาที | → `Scanning` (ลองใหม่) |

**ทำไมใช้ state machine?** เพราะแต่ละช่วงใช้เวลาไม่แน่นอน (สแกน 1–6 วินาที, เชื่อมต่อ 2–15 วินาที) ถ้าเขียนแบบ `delay()` รอทีละขั้น
LED จะกะพริบไม่ได้ และโปรแกรมจะตอบสนองต่อเหตุการณ์ใหม่ไม่ได้ แต่ state machine ทำให้ `loop()` วนเร็วตลอด เช็คสถานะทีละนิดและไม่เคยหยุดรอ

### 3.7 Async, Event และ `volatile`

- **การสแกนแบบ async:** `WiFi.scanNetworks(true)` สั่งสแกนแล้ว **ไม่รอผล** ใน `loop()` เราถามผลด้วย `WiFi.scanComplete()` ทุกรอบ
  ระหว่างรอ LED น้ำเงินยังกะพริบได้ (ถ้าสแกนแบบรอ จะค้างหลายวินาที)
- **Event callback:** ระบบ WiFi เรียกฟังก์ชัน `onWifiEvent` ให้เมื่อเกิดเหตุการณ์ เช่นหลุดการเชื่อมต่อ เราใช้จด "รหัสสาเหตุ" ไว้
- **`volatile`:** callback ทำงานคนละ task กับ `loop()` ตัวแปรที่แชร์กัน (`lastDisconnectReason`) จึงต้องมี `volatile`
  เพื่อบอกคอมไพเลอร์ว่าค่าอาจถูกเปลี่ยนจากที่อื่น ให้อ่านค่าล่าสุดเสมอ

### 3.8 ข้อสังเกตจากการทดสอบจริง: ไลบรารีตัดสินว่าสแกนล้มเหลวเร็วเกินไป

ขณะทดสอบ พบว่าการสแกนเป็นระยะรายงานว่า "ล้มเหลว" ทั้งที่ไม่ได้เสีย เพราะไลบรารี Arduino-ESP32 ตัดสินว่าล้มเหลวถ้าสแกนนานเกิน
ประมาณ 6 วินาที ซึ่งการสแกนในห้องทดสอบใช้เวลา 1–6 วินาที (ใกล้ขีดจำกัดนั้นมาก) ผลคือบางรอบถูกตัดทิ้งทั้งที่สแกนเดินต่อและเสร็จได้ทีหลัง
วิธีแก้คือไม่เชื่อค่า `WIFI_SCAN_FAILED` ทันที แต่ **รอเองได้นานถึง `SCAN_TIMEOUT_MS` (15 วินาที)** ก่อนถือว่าล้มเหลว
หลังแก้แล้วทดสอบสแกน 6 รอบติดกันผ่านทุกรอบ
บทเรียน: ไลบรารีที่ใช้อาจมีข้อจำกัดซ่อนอยู่ ถ้าผลที่ได้แปลก ให้ลองอ่านซอร์สของไลบรารี

### 3.9 การกะพริบ LED แบบไม่ใช้ `delay()`

`updateLed()` ทำงานทุกรอบ `loop()` สถานะที่ต้องกะพริบจะมีค่า `blinkMs` (ms ต่อครึ่งรอบ) และตัวแปร `blinkOn`
เมื่อเวลาผ่านไปครบ `blinkMs` ให้สลับ `blinkOn` แล้วสั่ง LED เป็น `blinkOn && สีนั้น` หลักการเดียวกับตัวจับเวลา `millis()` ใน Lab 1–2

## 4. ขั้นตอนปฏิบัติ

### ขั้นที่ 1 — เปิดโปรเจกต์

เปิด VS Code → **File → Open Folder** → `Level1/Lab3_WiFiConnecting` (โฟลเดอร์ต้องมี `platformio.ini`)
เปิดไฟล์ `include/app_config.h`, `include/secrets.h.example` และ `src/main.cpp` ดูโครงสร้างคร่าวๆ

### ขั้นที่ 2 — Build และ upload โดยยังไม่สร้าง `secrets.h`

```powershell
pio run -t upload --upload-port COM3
```

(เปลี่ยน `COM3` เป็นเลขของคุณ ดูได้จาก `pio device list` และปิด Serial Monitor ก่อน upload ทุกครั้ง)
โปรแกรม **ต้อง build ผ่านแม้ไม่มี `secrets.h`** (ตั้งใจออกแบบไว้) ท้ายสุดต้องขึ้น `[SUCCESS]`

### ขั้นที่ 3 — ดูสถานะ `NotConfigured`

```powershell
pio device monitor -b 115200 --port COM3 --filter time
```

(กดปุ่ม EN/RESET บนบอร์ดถ้าไม่เห็นข้อความตอนเปิดเครื่อง) ผลที่ตรวจจากบอร์ดจริง

```
LED self-test: RED -> GREEN -> BLUE
[STATE] Boot -> NotConfigured   (LED: RED blinking fast)
[WiFi] include/secrets.h not found. Copy include/secrets.h.example to include/secrets.h, ...
```

บันทึก: LED ที่เห็นคือ ☐ แดงกะพริบเร็ว  ข้อความ `[WiFi] ... not found` ซ้ำทุกกี่วินาที: ____ (ดูเวลาหน้าบรรทัด)

### ขั้นที่ 4 — สร้าง `secrets.h` ของคุณ

ใน Terminal (PowerShell) ที่โฟลเดอร์โปรเจกต์

```powershell
Copy-Item include\secrets.h.example include\secrets.h
```

เปิด `include/secrets.h` แล้วแก้ 2 บรรทัดให้เป็นของคุณ (พิมพ์ให้ตรงทุกตัวอักษร รวมตัวพิมพ์ใหญ่-เล็กและช่องว่าง)

```cpp
inline constexpr char WIFI_SSID[] = "ชื่อ WiFi ของคุณ";
inline constexpr char WIFI_PASSWORD[] = "รหัสผ่านของคุณ";
```

ตรวจสอบก่อนไปต่อ

- [ ] ไฟล์ชื่อ `secrets.h` ตรงตัว (ไม่ใช่ `secrets.h.txt`)
- [ ] เป็น WiFi ย่าน **2.4 GHz**
- [ ] รหัสผ่านยาวอย่างน้อย 8 ตัว
- [ ] ยังไม่ได้แก้ไฟล์ `secrets.h.example`

ตรวจว่า git ไม่เก็บไฟล์นี้ (ต้องเห็นว่าถูกละเว้น)

```powershell
git check-ignore -v include/secrets.h
```

ต้องขึ้นบรรทัดที่อ้างถึง `.gitignore` ถ้าไม่ขึ้นอะไร แปลว่าไฟล์ **ไม่ถูกละเว้น ห้าม commit ไฟล์นี้**

### ขั้นที่ 5 — Upload และดูการเชื่อมต่อสำเร็จ

upload ใหม่ (ค่าใน `secrets.h` ถูก build เข้าโปรแกรม จึงต้อง upload ทุกครั้งที่แก้) แล้วเปิด monitor

ลำดับที่ควรเห็น (ตัวเลขเป็นตัวอย่างประกอบ)

```
[WiFi] target SSID: "MyHomeWiFi"   MAC of this board: AA:BB:CC:DD:EE:FF
[WiFi] attempt #1: scanning for networks ...
[STATE] Boot -> Scanning   (LED: BLUE blinking slow)
```

### 5.3 `enum class WifiState`, `LedPattern` และ `patternFor()`

```cpp
enum class WifiState : uint8_t { Boot, NotConfigured, Scanning, Connecting, Connected, Failed, Lost };

struct LedPattern { bool red; bool green; bool blue; uint32_t blinkMs; const char *text; };
```

`patternFor(state)` คือ "ตารางแปลสถานะเป็นไฟ" ใช้ `switch` ส่งค่ากลับ เช่น

```cpp
case WifiState::Connected: return {false, true, false, 0, "GREEN steady"};          // เขียว ติดค้าง (blinkMs = 0)
case WifiState::Connecting: return {false, false, true, app::BLINK_FAST_MS, "BLUE blinking fast"};
```

ข้อดีของการแยกตารางนี้ออกมา: อยากเปลี่ยนสีหรือจังหวะของสถานะใด แก้จุดเดียวที่นี่ ไม่ต้องไล่แก้ทั้งโปรแกรม (แบบฝึกหัดข้อ 2)

### 5.4 ตัวแปรสถานะ

| ตัวแปร | เก็บอะไร |
|---|---|
| `state` | สถานะปัจจุบัน |
| `stateSince` | เวลา (ms) ที่เข้าสถานะนี้ ใช้คำนวณ timeout/รอลองใหม่ |
| `lastBlinkAt`, `blinkOn` | จังหวะกะพริบ LED |
| `lastPrintAt` | เวลาที่พิมพ์ Serial ล่าสุด (กันพิมพ์ถี่เกินไป) |
| `connectStartedAt` | เวลาเริ่มเชื่อมต่อ ใช้คำนวณ "CONNECTED in x s" |
| `attempt` | นับว่าลองมากี่รอบ |
| `lastDisconnectReason` | รหัสสาเหตุล่าสุดที่หลุด (เขียนจาก event callback จึงเป็น `volatile`) |

### 5.5 `reasonText()` และ `onWifiEvent()`

`reasonText(code)` แปลรหัสสาเหตุของ ESP32 เป็นข้อความที่คนอ่านรู้เรื่อง

| รหัส | ชื่อ | ความหมาย |
|---|---|---|
| 201 | `NO_AP_FOUND` | หา SSID ไม่เจอ |
| 202 | `AUTH_FAIL` | พิสูจน์ตัวตนไม่ผ่าน (รหัสผ่านผิด) |
| 15, 204 | `4WAY_HANDSHAKE_TIMEOUT`, `HANDSHAKE_TIMEOUT` | แลกกุญแจไม่สำเร็จ ส่วนใหญ่รหัสผ่านผิด |
| 203 | `ASSOC_FAIL` | router ปฏิเสธการเข้าร่วม |
| 200 | `BEACON_TIMEOUT` | ขาดการติดต่อกับ router |
| 2 | `AUTH_EXPIRE` | การพิสูจน์ตัวตนหมดอายุ |

`onWifiEvent` ถูกระบบเรียกเมื่อเกิดเหตุการณ์ ถ้าเป็น `ARDUINO_EVENT_WIFI_STA_DISCONNECTED` ให้จดรหัสสาเหตุไว้ใน `lastDisconnectReason`

### 5.6 `makeRssiBar()` — แปลง RSSI เป็นแถบ 10 ช่อง

```cpp
const int filled = constrain(map(rssi, -90, -30, 0, 10), 0L, 10L);
```

`map` แปลงช่วง −90…−30 dBm เป็น 0…10 ช่อง (คำนวณจำนวนเต็ม ปัดเศษทิ้ง) ส่วน `constrain` กันค่าหลุดช่วง

| RSSI (dBm) | จำนวน `#` |
|---|---|
| −90 หรือต่ำกว่า | 0 |
| −75 | 2 |
| −70 | 3 |
| −60 | 5 |
| −50 | 6 |
| −44 | 7 |
| −40 | 8 |
| −30 หรือสูงกว่า | 10 |

### 5.7 `setState()` และ `updateLed()`

`setState(next)` พิมพ์บรรทัด `[STATE] เก่า -> ใหม่   (LED: ...)` แล้วอัปเดต `state`, `stateSince` และรีเซ็ตตัวจับเวลากะพริบ
จึงเห็นความเชื่อมโยงของสถานะกับสีไฟทุกครั้งที่เปลี่ยน

`updateLed(now)` อ่าน `patternFor(state)` แล้ว ถ้า `blinkMs == 0` ให้ติดค้าง ถ้ามากกว่า 0 ให้สลับ `blinkOn` เมื่อครบเวลา (หัวข้อ 3.9)

### 5.8 ฟังก์ชันขั้นตอน WiFi

| ฟังก์ชัน | ทำอะไร |
|---|---|
| `startScan()` | เพิ่ม `attempt`, สั่งสแกน async (`WiFi.scanNetworks(true)`), เข้า `Scanning` |
| `printScanResults(count)` | พิมพ์ตารางเครือข่ายที่เจอ ทำเครื่องหมาย `<== YOUR NETWORK` ที่ชื่อตรงกับ `WIFI_SSID` และคืนค่า `true` ถ้าเจอ |
| `beginConnect()` | ล้างรหัสสาเหตุ จดเวลาเริ่ม เรียก `WiFi.begin(ssid, password)` เข้า `Connecting` |
| `onConnected()` | พิมพ์ SSID/IP/Gateway/Subnet/DNS/MAC/Channel/RSSI เข้า `Connected` |
| `failConnect(why, showReason)` | พิมพ์สาเหตุ (และรหัสสาเหตุถ้าบอกให้โชว์) ตัดการเชื่อมต่อ เข้า `Failed` |
| `ledSelfTest()` | ไล่ R→G→B ตอนเปิดเครื่อง (ใช้ `delay()` ได้เพราะอยู่ใน `setup()` ครั้งเดียว) |

รูปแบบข้อความใน `printScanResults` ที่ควรรู้

| รูปแบบ | ความหมาย |
|---|---|
| `%2d` | จำนวนเต็ม กว้างอย่างน้อย 2 ช่อง (เลขลำดับ) |
| `%-24.24s` | ข้อความ ชิดซ้าย กว้าง 24 ช่อง และตัดที่ 24 ตัวอักษร (SSID ยาวสุด 32) |
| `%3d` / `%4d` | จำนวนเต็มความกว้าง 3 / 4 ช่อง (ช่องสัญญาณ / RSSI) |
| `%s` | ข้อความ เช่น `open` หรือ `secured` |

### 5.9 `setup()`

```cpp
Serial.begin(...); ... printLedLegend(); cyd::ledInit(); ledSelfTest();

WiFi.persistent(false);        // ไม่บันทึกชื่อ/รหัส WiFi ลงหน่วยความจำถาวรของชิป
WiFi.mode(WIFI_STA);           // โหมด Station
WiFi.setAutoReconnect(false);  // เราคุมการต่อใหม่เองใน state machine
WiFi.onEvent(onWifiEvent);     // ลงทะเบียน callback

if (strlen(WIFI_SSID) == 0) setState(WifiState::NotConfigured);
else { ... startScan(); }
```

### 5.10 `loop()` — หัวใจของโปรแกรม

```
loop()
 ├─ updateLed(now)                       ← กะพริบ/ติดตามสถานะ ทุกรอบ ไม่เคยหยุดรอ
 └─ switch (state)
      ├─ NotConfigured : พิมพ์เตือนทุก 5 วินาที
      ├─ Scanning      : scanComplete()  ┬─ ยังไม่เสร็จ → รอต่อ (ถึง SCAN_TIMEOUT_MS ถึงยอมแพ้)
      │                                  └─ เสร็จ → พิมพ์ตาราง → เจอชื่อ ? beginConnect() : failConnect()
      ├─ Connecting    : status()        ┬─ WL_CONNECTED → onConnected()
      │                                  ├─ WL_CONNECT_FAILED → failConnect()
      │                                  ├─ ครบ 15 วินาที → failConnect()
      │                                  └─ ทุก 1 วินาที → พิมพ์ความคืบหน้า
      ├─ Connected     : ไม่ใช่ WL_CONNECTED → Lost  /  ทุก 5 วินาที → พิมพ์ RSSI
      └─ Failed, Lost  : ครบ 5 วินาที → startScan()
```

## 6. แบบฝึกหัด

กลับโค้ดเดิมได้ด้วย `git restore src/main.cpp include/app_config.h` (ไม่กระทบ `secrets.h` ของคุณ เพราะ git ไม่ติดตามไฟล์นั้น)

### ระดับ 1

**ข้อ 1 — เทียบข้อความ 3 กรณี:** ใช้ผลจากขั้นที่ 5, 6, 7 เติมตาราง

| กรณี | LED สุดท้ายที่เห็น | บรรทัด `[WiFi] FAILED:` / `[STATE]` สำคัญ | เสียเวลากว่าจะรู้ผล |
|---|---|---|---|
| ต่อสำเร็จ | | | |
| ชื่อผิด | | | |
| รหัสผ่านผิด | | | |

ตอบ: กรณีไหนโปรแกรมรู้ผลเร็วที่สุด และเพราะอะไร (คำใบ้: ดูว่าไปถึงสถานะ `Connecting` หรือไม่)

**ข้อ 2 — เปลี่ยนสี Connected:** แก้ `patternFor()` ให้ `Connected` เป็นสีฟ้าอมเขียว (เขียว + น้ำเงิน ติดค้าง) แล้ว upload ดู

**ข้อ 3 — ปรับจังหวะกะพริบ:** ตั้ง `BLINK_FAST_MS = 60` และ `BLINK_SLOW_MS = 1000` เทียบความรู้สึกของ `Connecting` กับ `Scanning` ว่าแยกออกง่ายขึ้นหรือยากขึ้น เพราะอะไร

### ระดับ 2

**ข้อ 4 — ปรับ timeout:** ตั้ง `CONNECT_TIMEOUT_MS = 3000` แล้วลองต่อ ผลเป็นอย่างไร ทำไมการตั้งน้อยเกินไปจึงไม่ดี (คิดถึงขั้นตอนในหัวข้อ 3.2)

**ข้อ 5 — พิมพ์ RSSI เฉพาะเมื่อเปลี่ยน:** ตอนเชื่อมต่อแล้ว พิมพ์บรรทัด `online ...` เฉพาะเมื่อ RSSI ต่างจากที่พิมพ์ครั้งล่าสุดอย่างน้อย 5 dBm
คำใบ้: ต้องมีตัวแปรเก็บ RSSI ล่าสุดที่พิมพ์ และเมื่อเชื่อมต่อสำเร็จให้ตั้งค่าเริ่มต้น

**ข้อ 6 — จำกัดจำนวนครั้งที่ลองใหม่:** ลองสูงสุด 3 รอบ (ใช้ตัวแปร `attempt` ที่มีอยู่แล้ว) หลังจากนั้นค้างที่ `Failed` (แดงติดค้าง)
และพิมพ์ข้อความบอกให้ตรวจ `secrets.h` แล้วกด EN/RESET (พิมพ์ครั้งเดียวพอ)

### ระดับ 3 (ท้าทาย)

**ข้อ 7 — ไฟเตือนสัญญาณอ่อน:** ตอน `Connected` ถ้า RSSI ต่ำกว่า −75 dBm ให้ LED เป็นสีเหลือง (แดง + เขียว) ติดค้างแทนเขียว
คำใบ้: แก้ใน `updateLed()` หลังเรียก `patternFor(state)` (ต้องเปลี่ยน `const LedPattern` เป็นตัวแปรที่แก้ได้)
ทดสอบโดยถือบอร์ดเดินห่างจาก router (หรือเอามือครอบบอร์ด) แล้วสังเกตสี

**ข้อ 8 — ตอบเชิงออกแบบ:** โปรแกรมนี้สแกนก่อนเชื่อมต่อเสมอ ทั้งที่เรียก `WiFi.begin()` ตรงๆ ก็ได้ จงเขียนข้อดีอย่างน้อย 2 ข้อ และข้อเสีย 1 ข้อของการสแกนก่อน
(คำใบ้: ดูข้อมูลที่ได้, เวลาที่ใช้ตอนชื่อผิด, และเครือข่ายแบบซ่อนชื่อ)

## 7. คำถามทบทวน

1. SSID คืออะไร และต่างจากรหัสผ่านอย่างไร
2. ทำไม ESP32 ต่อ WiFi 5 GHz ไม่ได้ และถ้า router ปล่อยทั้งสองย่านควรทำอย่างไร
3. RSSI −45 dBm กับ −82 dBm อันไหนสัญญาณแรงกว่า และโปรแกรมนี้จัดอันไหนเป็น `strong` / `very weak`
4. IP, Gateway, Subnet, DNS, MAC แต่ละตัวบอกอะไร
5. โหมด Station ต่างจาก Access Point อย่างไร
6. ทำไมต้องเก็บรหัสผ่านใน `secrets.h` แทนที่จะเขียนในโค้ดหลัก และไฟล์นี้ไม่ขึ้น GitHub ได้อย่างไร
7. `#if __has_include("secrets.h")` ช่วยแก้ปัญหาอะไร
8. ทำไมโปรแกรมไม่พิมพ์รหัสผ่านออก Serial แต่พิมพ์ความยาวรหัสแทน
9. State machine คืออะไร และทำไม Lab นี้ใช้แทนการเขียน `delay()` รอทีละขั้น
10. การสแกนแบบ async ต่างจากแบบรอผลอย่างไร ผลดีต่อ LED คืออะไร
11. `volatile` ใช้เมื่อไร และทำไม `lastDisconnectReason` ต้องมี
12. สถานะ `Failed` กับ `Lost` ต่างกันอย่างไร และต่างกันที่ LED อย่างไร
13. จากการทดสอบพบปัญหาอะไรกับการสแกนของไลบรารี และแก้อย่างไร
14. ถ้า LED แดงติดค้าง ต้องดูอะไรใน Serial เป็นอย่างแรก และข้อความ `AUTH_FAIL` / `NO_AP_FOUND` บอกอะไร
15. ถ้าแก้ `secrets.h` แล้วต้องทำอะไรจึงจะเห็นผล เพราะอะไร

## 9. ปัญหาที่พบบ่อย

| อาการ | สาเหตุที่เป็นไปได้ | วิธีแก้ |
|---|---|---|
| แดงกะพริบเร็วตลอด | ไม่มี `secrets.h` หรือ `WIFI_SSID` ว่าง | ทำขั้นที่ 4 แล้ว upload ใหม่ |
| แก้ `secrets.h` แล้วไม่มีอะไรเปลี่ยน | ยังไม่ได้ upload ใหม่ | upload ทุกครั้งที่แก้ |
| `SSID not found` ทั้งที่ชื่อถูก | router ปล่อยแต่ 5 GHz / ชื่อซ่อน / อยู่ไกล / ตัวพิมพ์หรือช่องว่างไม่ตรง | ดูตารางสแกนว่ามีชื่อนั้นไหม ขยับเข้าใกล้ router |
| `AUTH_FAIL` หรือ `HANDSHAKE_TIMEOUT` | รหัสผ่านผิด | ตรวจตัวพิมพ์ใหญ่-เล็ก และช่องว่างหน้า-หลัง |
| ต่อ hotspot มือถือไม่ติด | hotspot เปิดเฉพาะ 5 GHz | เปิดโหมด 2.4 GHz (iPhone: "เพิ่มความเข้ากันได้สูงสุด") |
| สแกนเจอน้อยกว่าที่มือถือเห็น | มือถือเห็นย่าน 5 GHz แต่ ESP32 เห็นเฉพาะ 2.4 GHz | ปกติ |
| ต่อได้บ้างไม่ได้บ้าง | สัญญาณอ่อน (RSSI ต่ำกว่า −80) | เข้าใกล้ router |
| build ฟ้อง `secrets.h` ไม่เจอ | (ไม่ควรเกิด ใช้ `__has_include` อยู่) | ตรวจชื่อไฟล์ และว่าอยู่ในโฟลเดอร์ `include/` |
| upload ไม่ผ่าน `Access is denied` | Serial Monitor เปิดค้าง | ปิด monitor แล้ว upload ใหม่ |
| ข้อความ Serial เป็นตัวอักษรเพี้ยน | baud ไม่ตรง | ใช้ `-b 115200` |
| เผลอ commit `secrets.h` | `.gitignore` ถูกลบ หรือใช้ `git add -f` | ลบออกจาก git ทันที **และเปลี่ยนรหัสผ่าน WiFi** เพราะรหัสเดิมถือว่าหลุดแล้ว |
