# เฉลยใบงาน Level 1 / Lab 2 — ADC + LDR (สำหรับผู้สอนเท่านั้น)

> อย่าแจกก่อนผู้เรียนทำเสร็จ ใบงานฉบับนักเรียนอยู่ที่ [WORKSHEET.md](WORKSHEET.md)

## สถานะการตรวจสอบเฉลย (อ่านก่อนใช้)

| รายการ | สถานะ |
|---|---|
| โปรแกรมหลักของ Lab 2 | build ผ่านโดยไม่มี warning และอัปโหลดขึ้นบอร์ดจริงแล้ว |
| ช่วง Calibration ใน Serial (นับถอยหลัง, สรุปผล, ข้อความ `Range too small`) | ตรวจจากบอร์ดจริงแล้ว ตรงตามใบงาน |
| บรรทัด `[LDR] ...` ในสภาพมืด/ค่าสำรอง (raw ≈ 120–124, light 0%, step 100 ms, `DARK -> FAST`) | ตรวจจากบอร์ดจริงแล้ว |
| ตัวอย่างคำนวณ (ตาราง 3.7, ข้อ 6, ข้อ 4 ของคำถามทบทวน) | คำนวณซ้ำด้วยสูตร `map` แบบจำนวนเต็มแล้ว |
| โค้ดเฉลยข้อ 4, 5, 7 | **build ผ่าน** แต่ยังไม่ได้รันบนบอร์ด (พอร์ต COM3 ถูก Serial Monitor จองอยู่ตอนตรวจ) |
| ข้อ 1, 2, 3 (แก้เฉพาะค่าใน `app_config.h`) | อนุมานจากโค้ด ยังไม่ได้รันบนบอร์ด |
| ข้อ 8 (hysteresis) | เป็นแนวคิด ไม่มีโค้ดสำเร็จรูปที่ทดสอบ |
| **ค่า raw ตอนมีแสงสว่าง** และการ calibrate สำเร็จ (`OK: using the range ...`) | **ยังไม่ได้ยืนยัน** ต้องให้ผู้สอนทดสอบเอง (ครอบมือแล้วเปิดมือ + ส่องไฟฉาย) |
| ลักษณะ LED ที่เห็นด้วยตา (เร็ว/ช้าชัดเจนแค่ไหน) | ยังไม่ได้ยืนยัน ให้ผู้สอนดูเอง |

ผู้สอนควรทดสอบ Lab นี้เองหนึ่งรอบ (ขั้นที่ 5–6 ของใบงาน) ก่อนนำไปสอน เพราะค่าที่ได้ขึ้นกับแสงในห้อง

## ตารางในหัวข้อ 3.5 (EMA)

| รอบ | ค่าใหม่ |
|---|---|
| 1 | 100 + (120 − 100) × 0.25 = 105 |
| 2 | 105 + (120 − 105) × 0.25 = 108.75 |
| 3 | 108.75 + (120 − 108.75) × 0.25 = 111.5625 ≈ 111.56 |

## ตารางในหัวข้อ 3.7 (ค่าสำรอง bright = 0, dark = 120; FAST = 100, SLOW = 1200)

| raw | ความสว่าง % | ระยะเวลาต่อสี |
|---|---|---|
| 120 | `(120−120)×100 ÷ (0−120)` = 0 | 100 ms |
| 90 | `(−30×100) ÷ (−120)` = 25 | 25×1100÷100+100 = 375 ms |
| 60 | `(−60×100) ÷ (−120)` = 50 | 650 ms |
| 30 | `(−90×100) ÷ (−120)` = 75 | 925 ms |
| 0 | 100 | 1200 ms |

## แบบฝึกหัด

### ข้อ 1 — กลับพฤติกรรม (แก้เฉพาะ `app_config.h`)
สลับค่ากัน: `FAST_STEP_MS = 1200;` และ `SLOW_STEP_MS = 100;`
เหตุผล: `stepIntervalMs()` แปลง 0% (มืด) เป็นค่า `FAST_STEP_MS` และ 100% (สว่าง) เป็น `SLOW_STEP_MS` เมื่อสลับตัวเลข
ตอนมืด `step` จะเป็น **1200 ms** (ช้า) และตอนสว่างเป็น **100 ms** (เร็ว) (`map` รองรับช่วงขาออกที่ลดลงได้)
หมายเหตุ: หลังสลับ ชื่อ `FAST`/`SLOW` จะสื่อความหมายกลับกับพฤติกรรมจริง ถ้าถามผู้เรียนที่เก่ง ให้ชี้ว่าควรเปลี่ยนชื่อเป็น `DARK_STEP_MS` / `BRIGHT_STEP_MS`

### ข้อ 2 — ความไวของตัวกรอง
ค่าตัวกรองอัปเดตทุก `SAMPLE_MS = 50` ms ค่าคงที่เวลาโดยประมาณของ EMA คือ `SAMPLE_MS ÷ alpha`

| alpha | ค่าคงที่เวลาโดยประมาณ | พฤติกรรม |
|---|---|---|
| 0.9 | ≈ 55 ms | `smooth` เกือบเท่า `raw` ตอบไว แต่รับ noise ไปเต็มๆ LED อาจกระตุก |
| 0.25 (ค่าเริ่มต้น) | ≈ 200 ms | สมดุล |
| 0.05 | ≈ 1 วินาที | นิ่งมาก แต่ตามแสงช้าชัดเจน LED ปรับความเร็วช้ากว่าที่มือเปลี่ยนแสง |

### ข้อ 3 — ลดเวลา calibrate เป็น 2000 ms
ข้อความจะขึ้น `For 2 s` และสรุปผลหลัง 2 วินาที ต้องครอบมือเร็วและตรงจังหวะ จึงมีโอกาสได้ `Range too small` มากขึ้น (ตั้งใจให้ผู้เรียนเห็นว่าเวลา calibrate สั้นไปทำให้ไม่สำเร็จง่าย)

### ข้อ 4 — พิมพ์ทุกครั้งที่ LED เปลี่ยนสี
ใน `showStep()`
```cpp
void showStep(const LedStep &step)
{
    cyd::ledSet(step.red, step.green, step.blue);
    Serial.printf("[LED] %s (GPIO%u)\n", step.name, step.pin);
}
```
(build ผ่านแล้ว) ผลที่คาด: ระยะห่างระหว่างบรรทัด `[LED]` ใกล้เคียงค่า `step=` ที่เห็นในบรรทัด `[LDR]` ช่วงนั้น โดยคลาดเคลื่อนได้เล็กน้อย
เพราะค่า `step` ที่พิมพ์เป็นค่า ณ ขณะพิมพ์ แต่การตัดสินใจเปลี่ยนสีใช้ค่า ณ ขณะที่ `loop()` เช็ค ถ้าแสงกำลังเปลี่ยนอยู่ ตัวเลขจะไม่ตรงเป๊ะ
(ผู้สอนควรทดสอบกับบอร์ดจริงเพื่อดูตัวเลขที่ได้ ยังไม่ได้ยืนยัน)

### ข้อ 5 — พิมพ์เฉพาะเมื่อแสงเปลี่ยน ≥ 5 จุด
```cpp
int lastPrintedPercent = -100;       // ตัวแปรโกลบอล (เริ่มค่าที่ไม่มีทางเท่ากับ 0-100 เพื่อให้พิมพ์ครั้งแรกเสมอ)

// ใน loop() ช่วง Running ที่เดิมพิมพ์ทุก PRINT_MS:
if (now - lastPrintAt >= app::PRINT_MS) {
    lastPrintAt = now;
    if (abs(percent - lastPrintedPercent) >= 5) {
        lastPrintedPercent = percent;
        printRunningLine();
    }
}
```
(`percent` คือผลของ `lightPercent()` ที่คำนวณไว้ก่อนหน้าในรอบ `loop()` เดียวกัน build ผ่านแล้ว) ตอนแสงนิ่งจะไม่มีบรรทัดใหม่ มีเฉพาะบรรทัดแรกหลังเข้าช่วง Running

### ข้อ 6 — คำนวณด้วยมือ (smooth = 45)
- (ก) `map(45, 120, 0, 0, 100)` = `(45−120) × 100 ÷ (0−120)` = `(−7500) ÷ (−120)` = 62.5 → ปัดทิ้งเป็นจำนวนเต็ม = **62 %**
- (ข) `map(62, 0, 100, 100, 1200)` = `62 × 1100 ÷ 100 + 100` = 682 + 100 = **782 ms**
- (ค) 62 ไม่ต่ำกว่า 35 และไม่สูงกว่า 65 → **`MID`**

### ข้อ 7 — ไฟกลางคืน (< 15%)
เพิ่มตัวแปรโกลบอล `bool nightOn = false;` และ `constexpr int NIGHT_PERCENT = 15;` แล้วแทนบล็อก "เปลี่ยนสี" ในช่วง Running ด้วย
```cpp
const int percent = lightPercent();
if (percent < NIGHT_PERCENT) {
    if (!nightOn) {
        nightOn = true;
        cyd::ledSet(true, true, true);
        Serial.println("[NIGHT] too dark -> white night light ON");
    }
} else {
    if (nightOn) {
        nightOn = false;
        lastStepAt = now;                 // เริ่มนับเวลาของสีปัจจุบันใหม่
        showStep(steps[currentStep]);
        Serial.println("[NIGHT] OFF -> back to R-G-B");
    }
    if (now - lastStepAt >= stepIntervalMs(percent)) {
        lastStepAt = now;
        currentStep = (currentStep + 1) % STEP_COUNT;
        showStep(steps[currentStep]);
    }
}
```
(รวมกับข้อ 5 แล้ว build ผ่าน) โครงนี้ทำให้ LED ไม่วิ่งขณะ `nightOn` เป็นจริง เพราะส่วนเปลี่ยนสีอยู่ในกิ่ง `else`
ข้อสังเกตเมื่อวัดจริง: ถ้าแสงอยู่แถว 15% พอดี สถานะอาจสลับถี่ ซึ่งนำไปสู่ข้อ 8

### ข้อ 8 — Hysteresis
แนวคิดคือใช้ **สองเกณฑ์ต่างกัน** แทนเกณฑ์เดียว
```
ถ้ายังไม่เปิดไฟกลางคืน และ percent < 15  -> เปิด
ถ้าเปิดอยู่แล้ว          และ percent > 25  -> ปิด
นอกนั้น คงสถานะเดิม
```
ช่วง 15–25% เป็น "โซนกันสั่น" ค่าที่แกว่งเล็กน้อยรอบ 15% จะไม่ทำให้สถานะสลับไปมา เหมือนหลักการ anti-swing ใน Smart Farm
(เป็นแนวคิด ผู้เรียนต้องเขียนโค้ดเอง ไม่มีเฉลยที่ทดสอบบนบอร์ด)

## คำถามทบทวน

1. ADC แปลงแรงดันไฟ (analog) เป็นตัวเลข ESP32 ให้ค่า 12 บิต = **0–4095**
2. **มืด** (บนบอร์ดนี้ raw แปรผกผันกับแสง: raw สูง = มืด, raw ต่ำ = สว่าง)
3. ค่า ADC สั่นเล็กน้อยเสมอ (noise) การเฉลี่ยหลายครั้งทำให้ค่านิ่งกว่า ลดการกระตุกของ LED
4. `ค่าใหม่ = ค่าเก่า + (ค่าที่อ่าน − ค่าเก่า) × alpha`; alpha 0.5, เก่า 100, อ่าน 120 → 100 + 20 × 0.5 = **110**
5. ปรับให้ตรงกับช่วงมืด–สว่างจริงของห้อง/บอร์ดนั้น ถ้าไม่ทำ ค่าสำรองที่ตายตัวอาจไม่ตรงกับห้องใหม่ ทำให้เปอร์เซ็นต์ค้างที่ปลายใดปลายหนึ่ง (เช่นสว่างแค่ไหนก็ไม่เลย 30%)
6. โปรแกรมแจ้งเตือน (`Range too small`) และใช้ค่าสำรอง (bright = 0, dark = 120) ผู้ใช้ควรกด EN/RESET แล้วครอบมือ–เปิดมือภายในช่วง calibrate
7. เพราะ raw สูง = มืด ต้องการให้มืดแปลงเป็น 0% และสว่างเป็น 100% จึงใส่มืด (`rawDark`) เป็นปลายแรกของช่วงขาเข้า `map` ที่รองรับช่วงกลับด้าน
8. กันไม่ให้เปอร์เซ็นต์หลุดจาก 0–100 เมื่อค่า raw มืดหรือสว่างกว่าช่วงที่ calibrate ไว้
9. 50% → `50 × 1100 ÷ 100 + 100` = **650 ms**
10. 4 ตัว (ในช่วง Running ใช้ 3 ตัวจริง): อ่าน LDR ทุก 50 ms, เปลี่ยนสีตามความเร็วที่คำนวณได้, พิมพ์ Serial ทุก 250 ms และตัวกะพริบ LED ขาวทุก 250 ms (ใช้เฉพาะช่วง Calibrating)
    ใช้ `delay()` ไม่ได้ เพราะมันหยุดทั้งโปรแกรม ทำให้จังหวะอื่นๆ ที่ต่างกันทำพร้อมกันไม่ได้
11. `Phase::Calibrating` และ `Phase::Running` ใช้บอกว่าตอนนี้ทำงานช่วงไหน เพื่อให้ `loop()` เลือกทำงานต่างกันตามช่วง
12. เขียน `%%`

## แนวทางให้คะแนนและข้อควรระวัง

- ผู้เรียนที่ calibrate ไม่สำเร็จแล้วบอกว่า "บังแสงแล้วไม่เปลี่ยน" ให้ถามก่อนว่าครอบเซนเซอร์ตรงตำแหน่งและภายใน 6 วินาทีแรกหรือไม่
- ตารางทดลอง 3 สภาพแสง ไม่มีค่าที่ "ถูกตัวเลขเดียว" ให้ตรวจ **ทิศทาง** (มืดแล้ว `light` ต่ำและ `step` น้อย / สว่างแล้ว `light` สูงและ `step` มาก) และความสอดคล้องกับสิ่งที่เห็น
- ถ้าผู้เรียนเปลี่ยน `FAST_STEP_MS` ต่ำมาก (< 50) LED จะวิ่งเร็วจนตามองเห็นเป็นสีผสม ไม่ใช่ข้อผิดพลาดของโค้ด
- ผู้เรียนที่ทำข้อ 1 โดยแก้ `main.cpp` แทน `app_config.h` ให้คะแนนบางส่วน เพราะโจทย์ต้องการให้เห็นประโยชน์ของการแยกไฟล์ตั้งค่า
