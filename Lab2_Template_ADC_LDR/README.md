# Level 1 / Lab 2 — Template ADC + LDR (แสงควบคุมความเร็ว RGB LED)

ต่อจาก [Lab 1](../Lab1_Template_Demo/README.md) (Hello World + RGB LED) โดยเพิ่ม **ประสาทสัมผัสด้านแสง** ให้บอร์ด

1. อ่านค่าแสงจาก **LDR** บนบอร์ด (GPIO34) ด้วย ADC แล้วพิมพ์ **Raw Data** ออก Serial Monitor
2. เอาค่าแสงไปควบคุม **ความเร็วที่ RGB LED วิ่ง แดง → เขียว → น้ำเงิน**
   - **บังแสง (มืด)** → LED วิ่ง **เร็ว**
   - **มีแสง (สว่าง)** → LED วิ่ง **ช้าๆ**

> **ใบงานฉบับละเอียด (ทฤษฎี อ่านโค้ดทีละส่วน แบบฝึกหัด 8 ข้อ) อยู่ที่ [WORKSHEET.md](WORKSHEET.md)**
> เฉลยสำหรับผู้สอน: [WORKSHEET_ANSWERS.md](WORKSHEET_ANSWERS.md)

## ที่ทำให้น่าสนใจกว่าการอ่านค่าธรรมดา

| ฟีเจอร์ | ทำไมต้องมี |
|---|---|
| **Calibration ตอนเปิดเครื่อง** (6 วินาที, LED ขาวกะพริบ) | ห้องแต่ละห้อง/บอร์ดแต่ละตัวมีช่วงค่าแสงต่างกัน ให้ครอบมือแล้วเปิดมือ โปรแกรมจะเรียนรู้ช่วง "มืด–สว่าง" ของคุณเอง |
| **Oversampling + ตัวกรอง (smoothing)** | ค่า ADC สั่นเล็กน้อยเสมอ ถ้าไม่กรอง LED จะกระตุก |
| **แถบความสว่าง `[#######---]` + เปอร์เซ็นต์** ใน Serial | เห็นภาพว่าแสงมากน้อยแค่ไหนโดยไม่ต้องตีความตัวเลขดิบ |
| **ความเร็วเปลี่ยนต่อเนื่อง** (100–1200 ms ต่อสี) | ไม่ใช่แค่ "เร็ว/ช้า" 2 โหมด แต่ไล่ระดับตามแสงจริง |
| **สำรองอัตโนมัติ** ถ้า calibrate ไม่สำเร็จ | ไม่ครอบมือก็ยังใช้งานได้ด้วยค่าเริ่มต้น |

## การทำงาน (ไหลของข้อมูล)

```
 LDR ──► ADC (GPIO34) ──► อ่าน 8 ครั้งเฉลี่ย ──► ตัวกรอง smoothing ──► raw ที่นิ่ง
                                                                          │
   calibration (min/max ของห้องคุณ) ──────────────────► แปลงเป็น 0-100% (map + constrain)
                                                                          │
              มืด 0%  ───────────────►  ช้า/เร็ว  ◄───────────────  สว่าง 100%
                          FAST_STEP_MS = 100 ms        SLOW_STEP_MS = 1200 ms
                                                                          │
                                                           ระยะเวลาต่อ 1 สี ► RGB LED  R → G → B → R ...
```

โปรแกรมมี 2 ช่วง (**state machine** อย่างง่าย)

| ช่วง | ทำอะไร | LED |
|---|---|---|
| `Calibrating` (6 วินาทีแรก) | จดค่า raw ต่ำสุด (สว่างสุด) และสูงสุด (มืดสุด) | ขาวกะพริบ |
| `Running` | แปลงแสงเป็นความเร็ว แล้ววิ่ง R→G→B | แดง/เขียว/น้ำเงินทีละสี |

และใน `loop()` มี **ตัวจับเวลา `millis()` 3 ตัว** ทำงานพร้อมกัน ไม่มี `delay()` เลย:
อ่าน LDR ทุก 50 ms, เปลี่ยนสีตามความเร็วที่คำนวณได้ และพิมพ์ Serial ทุก 250 ms

## ความรู้ใหม่ใน Lab นี้

**ADC (Analog-to-Digital Converter)** แปลงแรงดันไฟ (analog) เป็นตัวเลข ESP32 ให้ค่า 12 บิต = **0–4095**
อ่านด้วย `analogRead(pin)` ไม่ต้อง `pinMode()` และ GPIO34 เป็นขา input-only ซึ่งเหมาะกับการอ่านค่า

**LDR** คือตัวต้านทานที่ความต้านทานเปลี่ยนตามแสง บนบอร์ดต่อเป็นวงจรแบ่งแรงดัน ทำให้แรงดันที่ ADC อ่านเปลี่ยนตามแสง
สิ่งที่ทดสอบพบบนบอร์ดนี้: **ค่า raw แปรผกผันกับแสง** (raw ต่ำ = สว่าง, raw สูง = มืด) และช่วงค่าแคบมาก
(ที่ตั้งค่า ADC เริ่มต้น สว่าง ≈ 0, บังแสง ≈ 50 จาก 4095 เต็ม) โปรแกรมจึงทำ 3 อย่างช่วย

- `analogSetPinAttenuation(LDR_PIN, ADC_0db)` ลดช่วงวัดเหลือ ~1.1 V ให้ค่า raw กว้างขึ้นและแยกมืด/สว่างได้ชัดขึ้น
- **Oversampling:** อ่านซ้ำ 8 ครั้งแล้วเฉลี่ย (`OVERSAMPLE_COUNT`)
- **ตัวกรอง exponential moving average:** `ค่าใหม่ = ค่าเก่า + (ค่าที่อ่าน − ค่าเก่า) × alpha` (alpha = `SMOOTH_ALPHA` = 0.25)
  alpha มาก = ตอบสนองไวแต่สั่น, alpha น้อย = นิ่งแต่ช้า

**`map()` และ `constrain()`** `map(x, in_min, in_max, out_min, out_max)` แปลงค่าจากช่วงหนึ่งเป็นอีกช่วงแบบเส้นตรง
ที่นี่ใส่ช่วงขาเข้า "กลับด้าน" (มืดก่อน สว่างทีหลัง) เพื่อให้มืด = 0% และสว่าง = 100% ส่วน `constrain(x, 0, 100)` กันค่าหลุดช่วง

## วิธีรันและทดสอบ

```powershell
pio run -t upload --upload-port COM3
pio device monitor -b 115200 --port COM3
```

(เปลี่ยน `COM3` ตามเครื่องคุณ, ปิด Serial Monitor ก่อน upload ทุกครั้ง, ถ้าไม่เห็นข้อความตอนเปิดเครื่องให้กดปุ่ม EN/RESET)

1. **ช่วง Calibration (6 วินาที):** เห็น LED ขาวกะพริบ ให้ **ครอบมือบังเซนเซอร์ LDR สักครู่ แล้วเปิดมือ** (LDR คือตัวเล็กๆ มุมขวาบนของจอ ป้าย R21)
2. ดูผล calibration ใน Serial ว่า `range` ที่วัดได้มากกว่า 8 หรือไม่
3. **ช่วงใช้งาน:** ทดลอง
   - ครอบมือ → ค่า `light` ลดลงเข้าใกล้ 0% และ LED วิ่งเร็ว (`DARK -> FAST`)
   - เปิดมือ/ส่องไฟฉายโทรศัพท์ → ค่า `light` เพิ่มเข้าใกล้ 100% และ LED วิ่งช้า (`BRIGHT -> SLOW`)

### ตัวอย่าง Serial จริงจากบอร์ดต้นแบบ

กรณี **ไม่ได้ครอบมือตอน calibrate** (ช่วงแคบ โปรแกรมจึงใช้ค่าสำรองและแจ้งเตือน)

```
---------------- CALIBRATION ----------------
For 6 s: COVER the LDR with your hand for a moment, then UNCOVER it.
LED blinks WHITE during calibration.
[CAL] 5 s left  raw= 120  smooth= 119.7  min= 119  max= 121
[CAL] 4 s left  raw= 121  smooth= 120.4  min= 119  max= 121
...
---------------- CALIBRATION RESULT ----------------
raw min (brightest) = 119, raw max (darkest) = 122, range = 3
Range too small (< 8): did you cover the sensor? Using defaults bright=0 dark=120.
Press the EN/RESET button on the board to calibrate again.
Running: DARK -> LED runs FAST,  BRIGHT -> LED runs SLOW.
[LDR] raw= 122  smooth= 122.0  light=  0% [----------]  step= 100 ms  LED=RED    DARK -> FAST
[LDR] raw= 123  smooth= 122.3  light=  0% [----------]  step= 100 ms  LED=BLUE   DARK -> FAST
```

บอร์ดต้นแบบอ่านได้ราว 120 ตอนเซนเซอร์อยู่ในที่มืด/ถูกบัง (0 dB) ซึ่งเป็นด้านมืดของช่วง จึงได้ `light = 0%` และวิ่งเร็วสุดตามที่ออกแบบ
เมื่อ calibrate สำเร็จ บรรทัดสรุปจะขึ้น `OK: using the range measured in this room.` และค่าเปอร์เซ็นต์จะไล่ขึ้นลงตามแสงจริง
ค่า raw ของห้องคุณจะต่างจากตัวอย่าง เป็นเรื่องปกติ

## ค่าที่ปรับได้ใน `app_config.h`

| ค่า | ค่าเริ่มต้น | ผลเมื่อปรับ |
|---|---|---|
| `FAST_STEP_MS` | 100 | เวลาต่อสีตอน "มืด" (น้อย = เร็วขึ้น) |
| `SLOW_STEP_MS` | 1200 | เวลาต่อสีตอน "สว่าง" (มาก = ช้าลง) |
| `SMOOTH_ALPHA` | 0.25 | ความไวของตัวกรอง (0.0–1.0) |
| `OVERSAMPLE_COUNT` | 8 | จำนวนครั้งที่อ่านเฉลี่ยต่อตัวอย่าง |
| `SAMPLE_MS` / `PRINT_MS` | 50 / 250 | ความถี่อ่านค่า / ความถี่พิมพ์ Serial |
| `CALIBRATION_MS` | 6000 | เวลา calibrate ตอนเปิดเครื่อง |
| `MIN_CALIBRATION_RANGE` | 8 | ช่วงขั้นต่ำที่ถือว่า calibrate สำเร็จ |
| `DEFAULT_RAW_BRIGHT` / `DEFAULT_RAW_DARK` | 0 / 120 | ค่าสำรอง (เป็นค่าประมาณ ปรับตามบอร์ดคุณได้) |

## แบบฝึกหัด

1. **กลับพฤติกรรม:** สลับค่า `FAST_STEP_MS` กับ `SLOW_STEP_MS` (เช่น `FAST_STEP_MS = 1200`, `SLOW_STEP_MS = 100`) ให้ "มีแสง = เร็ว, บังแสง = ช้า" ทดสอบแล้วบันทึกผล
2. **ความไวของตัวกรอง:** ลอง `SMOOTH_ALPHA` เป็น `0.05` และ `0.9` เทียบกัน ค่า `smooth=` ใน Serial และการตอบสนองของ LED ต่างกันอย่างไร
3. **ดู raw เฉยๆ:** เปลี่ยน `PRINT_MS` เป็น `1000` และ `FAST_STEP_MS` เป็น `300` แล้วสังเกตว่าอ่านผลง่ายขึ้นไหม เพราะเหตุใด
4. **ทดลองไม่ calibrate:** ตั้ง `CALIBRATION_MS = 1000` แล้วลอง calibrate ให้สั้นๆ ดูว่าผลต่างจาก 6 วินาทีอย่างไร
5. **ท้าทาย (night light):** เพิ่มเงื่อนไขว่าถ้า `light` ต่ำกว่า 15% ให้ LED เป็นสีขาวค้าง ไม่วิ่ง (คำใบ้: เช็คใน `loop()` ก่อนบล็อก "เปลี่ยนสี" แล้วใช้ `cyd::ledSet(true, true, true)`)

## ปัญหาที่พบบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| ขึ้น `Range too small` ตอน calibrate | ไม่ได้ครอบเซนเซอร์ หรือครอบไม่ทัน ให้กด EN/RESET แล้วครอบมือ-เปิดมือภายใน 6 วินาที |
| ค่า `light` ไม่เปลี่ยนเมื่อบังแสง | ครอบผิดตำแหน่ง (LDR = ตัวเล็กมุมขวาบนใกล้ขอบจอ, ป้าย R21) หรือ calibrate มาจากสภาพที่ไม่ต่างกัน |
| ค่าเปอร์เซ็นต์กลับทิศ (บังแสงแล้วขึ้น) | ลำดับ `DEFAULT_RAW_BRIGHT`/`DEFAULT_RAW_DARK` ผิด หรือ calibrate สลับ ให้ calibrate ใหม่ |
| LED วิ่งเร็วเกินกว่าจะเห็นสี | เพิ่ม `FAST_STEP_MS` (เช่น 250) |
| ข้อความ Serial เป็นตัวอักษรเพี้ยน | ตั้ง baud 115200 |
| upload ไม่ผ่าน `Access is denied` | ปิด Serial Monitor ก่อน upload |
