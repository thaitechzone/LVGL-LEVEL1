## 1. เป้าหมายการเรียนรู้

เมื่อจบใบงานนี้ ผู้เรียนต้องทำได้ทุกข้อ

1. อธิบายได้ว่า ADC คืออะไร และอ่านค่าแสงจาก LDR ด้วย `analogRead()` ได้
2. อ่านและอธิบายความหมายของข้อความ Raw Data ที่โปรแกรมพิมพ์ใน Serial Monitor ได้ครบทุกช่อง
3. อธิบายได้ว่าทำไมต้องมี **oversampling**, **ตัวกรอง (smoothing)** และ **calibration**
4. แปลงค่า raw เป็นเปอร์เซ็นต์ความสว่างด้วย `map()` และ `constrain()` ได้ และคำนวณด้วยมือได้
5. ทำให้ LED วิ่ง R → G → B เร็วขึ้นเมื่อมืด และช้าลงเมื่อสว่าง แล้วสังเกตและบันทึกผลได้
6. อ่านโค้ดที่มีการทำงานหลายอย่างพร้อมกันด้วย `millis()` หลายตัวและ state machine แบบง่ายได้
7. ปรับค่าใน `app_config.h` และแก้โค้ดตามแบบฝึกหัดแล้วเห็นผลที่คาดไว้ได้

## 2. ภาพรวมสิ่งที่จะสร้าง

```
 แสงรอบตัว ──► LDR ──► แรงดัน ──► ADC (GPIO34) ──► ตัวเลข raw (0-4095)
                                                        │
        อ่าน 8 ครั้งแล้วเฉลี่ย  ◄───── oversampling ─────┘
                │
        ตัวกรอง smoothing (EMA)  ──►  raw ที่นิ่ง
                │
   calibration (ช่วงมืด–สว่างของห้อง) ──► map + constrain ──► ความสว่าง 0–100 %
                                                                   │
                       มืด 0 %  ──►  100 ms ต่อสี (เร็ว)            │
                       สว่าง 100 % ──► 1200 ms ต่อสี (ช้า)  ◄───────┘
                                                                   │
                                         RGB LED:  แดง → เขียว → น้ำเงิน → แดง ...
                                                                   │
                                  Serial Monitor: พิมพ์ Raw Data ทุก 250 ms
```

โปรแกรมมี 2 ช่วง

| ช่วง | เวลา | ทำอะไร | LED |
|---|---|---|---|
| **Calibrating** | 6 วินาทีแรกหลังเปิดเครื่อง | จดค่า raw ต่ำสุดและสูงสุดที่เจอ | ขาวกะพริบ |
| **Running** | หลังจากนั้น | แปลงแสงเป็นความเร็ว แล้ววิ่ง R→G→B | แดง/เขียว/น้ำเงิน ทีละสี |

## 3. ความรู้ที่ต้องเข้าใจก่อนลงมือ

### 3.1 ADC (Analog-to-Digital Converter)

ปกติ GPIO ที่เราใช้ใน Lab 1 รู้แค่ "สูง/ต่ำ" (HIGH/LOW) แต่แสงมีได้ตั้งแต่มืดสนิทถึงสว่างจ้า ต้องการค่า "ระหว่างกลาง"
**ADC** แปลง **แรงดันไฟ (analog)** เป็น **ตัวเลข** ESP32 แปลงเป็น 12 บิต แปลว่าได้ค่า **0 ถึง 4095**
(2¹² = 4096 ระดับ) ยิ่งแรงดันสูง ตัวเลขยิ่งมาก

- อ่านค่าด้วย `analogRead(pin)` (ไม่ต้องเรียก `pinMode` ก่อน)
- GPIO34 ที่ต่อกับ LDR เป็นขา **input-only** คือรับค่าเข้าได้อย่างเดียว ซึ่งเหมาะกับงานอ่านเซนเซอร์

### 3.2 LDR และวงจรแบ่งแรงดัน

**LDR (Light Dependent Resistor)** คือตัวต้านทานที่ **ความต้านทานเปลี่ยนตามแสง** ยิ่งสว่าง ความต้านทานยิ่งต่ำ
เมื่อต่อกับตัวต้านทานอีกตัวในวงจรแบ่งแรงดัน ความต้านทานที่เปลี่ยนจึงกลายเป็น **แรงดันที่เปลี่ยน** ซึ่ง ADC อ่านได้

สิ่งที่ **ทดสอบแล้วบนบอร์ดนี้** (ไม่ใช่ทฤษฎีทั่วไป) คือ

| แสง | ค่า raw ที่อ่านได้ |
|---|---|
| สว่าง | **ต่ำ** (ใกล้ 0) |
| มืด / บังแสง | **สูง** |

คือ **raw แปรผกผันกับแสง** (ต่างจากที่หลายคนคาดว่า "สว่าง = ตัวเลขมาก") และช่วงค่าที่เปลี่ยนแคบมากเมื่อเทียบกับ 4095 เต็ม
สองข้อนี้คือเหตุผลที่โปรแกรมต้องมีขั้นตอนพิเศษหลายอย่าง (ดูหัวข้อ 3.3–3.6)

### 3.3 Attenuation (ปรับช่วงการวัดของ ADC)

ค่าเริ่มต้น ADC วัดแรงดันได้ราว 0–3.3 V เทียบเป็น 0–4095 แต่ LDR บนบอร์ดให้แรงดันเปลี่ยนเพียงช่วงเล็กๆ ใกล้ 0 V
เราจึงสั่ง `analogSetPinAttenuation(LDR_PIN, ADC_0db)` เพื่อให้ ADC วัดช่วงที่ **แคบลงเหลือราว 1.1 V** เมื่อแรงดันเดิมเปลี่ยนเท่าเดิม
ค่า raw จะเปลี่ยนมากขึ้น แยกมืดกับสว่างได้ชัดขึ้น (เหมือนซูมเข้าไปในช่วงที่สนใจ)

### 3.4 Noise และ Oversampling

ค่า ADC สั่นเล็กน้อยเสมอ แม้แสงไม่เปลี่ยน (เรียกว่า noise) ถ้านำค่าตรงๆ ไปใช้ LED จะกระตุก
วิธีแรกคือ **oversampling**: อ่านซ้ำหลายครั้งแล้วเฉลี่ย โปรแกรมอ่าน **8 ครั้ง** (`OVERSAMPLE_COUNT`) ต่อ 1 ตัวอย่าง

### 3.5 ตัวกรอง Exponential Moving Average (smoothing)

วิธีที่สองคือกรองให้ค่าเปลี่ยนแบบนุ่มนวล โดยไม่กระโดดทันที

```
ค่าใหม่ = ค่าเก่า + (ค่าที่อ่านได้ − ค่าเก่า) × alpha        (alpha = 0.25)
```

ตัวอย่าง: ค่าเก่า (`smooth`) = 100 แล้วมีการบังแสงทำให้อ่านได้ 120 ต่อเนื่อง

| รอบที่ | ค่าเก่า | อ่านได้ | ค่าใหม่ |
|---|---|---|---|
| 1 | 100 | 120 | 100 + (120 − 100) × 0.25 = **105** |
| 2 | 105 | 120 | 105 + (120 − 105) × 0.25 = **108.75** |
| 3 | 108.75 | 120 | 108.75 + (120 − 108.75) × 0.25 = **111.56** |

ค่าค่อยๆ ไต่เข้าหา 120 ยิ่ง alpha **น้อย** ยิ่งนิ่งแต่ตามช้า ยิ่ง alpha **มาก** ยิ่งตามไวแต่สั่นมากขึ้น

### 3.6 Calibration (เรียนรู้ช่วงมืด–สว่างของห้องคุณ)

ห้องสว่างไม่เท่ากัน บอร์ดแต่ละตัวก็ต่างกันเล็กน้อย ค่า raw "มืดสุด/สว่างสุด" ของคุณจึงไม่เหมือนคนอื่น
ช่วง 6 วินาทีแรกโปรแกรมจึงให้คุณ **ครอบมือแล้วเปิดมือ** โดยจดค่า raw **ต่ำสุด** (`calMin` = สว่างสุด) และ **สูงสุด** (`calMax` = มืดสุด)
หลังจากนั้นถือว่า "ช่วงมืด–สว่าง" ที่ใช้คือ calMax ↔ calMin ถ้าช่วงที่ได้ **แคบกว่า 8** (`MIN_CALIBRATION_RANGE`)
แปลว่าไม่ได้ครอบเซนเซอร์ โปรแกรมจะแจ้งเตือนและใช้ค่าสำรอง (สว่าง = 0, มืด = 120)

### 3.7 `map()` และ `constrain()`

`map(x, in_min, in_max, out_min, out_max)` แปลงค่า x จากช่วงหนึ่งเป็นอีกช่วงหนึ่ง แบบเส้นตรง

```
ผลลัพธ์ = (x − in_min) × (out_max − out_min) ÷ (in_max − in_min) + out_min      (คำนวณด้วยจำนวนเต็ม ปัดเศษทิ้ง)
```

โปรแกรมใช้ `map` สองครั้ง

1. **raw → ความสว่าง %:** `map(raw, rawDark, rawBright, 0, 100)` ใส่ **มืดก่อน สว่างทีหลัง** เพราะ raw สูง = มืด
   จึงได้ มืด = 0% และ สว่าง = 100% (ช่วงขาเข้ากลับด้านได้ `map` รองรับ)
2. **ความสว่าง % → ระยะเวลาต่อสี:** `map(percent, 0, 100, FAST_STEP_MS, SLOW_STEP_MS)` = `map(percent, 0, 100, 100, 1200)`

ส่วน `constrain(x, 0, 100)` ตัดค่าที่หลุดช่วง (เช่น ค่าที่มืด/สว่างกว่าตอน calibrate) ให้อยู่ใน 0–100 เสมอ

ตัวอย่างคำนวณด้วยค่าสำรอง (`rawBright = 0`, `rawDark = 120`)

| raw ที่ผ่านตัวกรอง | ความสว่าง % | ระยะเวลาต่อสี | สรุป |
|---|---|---|---|
| 120 | 0 % | 100 ms | มืดสุด วิ่งเร็วสุด |
| 90 | 25 % | 375 ms | |
| 60 | 50 % | 650 ms | |
| 30 | 75 % | 925 ms | |
| 0 | 100 % | 1200 ms | สว่างสุด วิ่งช้าสุด |

### 3.8 State machine แบบง่าย

โปรแกรมมีตัวแปร `phase` ที่บอกว่า "ตอนนี้อยู่ช่วงไหน" (`Calibrating` หรือ `Running`) แล้ว `loop()` ทำงานต่างกันตามช่วงนั้น
ข้อดีคือแยกงานแต่ละช่วงชัดเจน ไม่ต้องใช้ `delay()` รอให้ calibrate เสร็จ

### 3.9 `millis()` หลายตัวพร้อมกัน

ใน Lab 1 มีตัวจับเวลาตัวเดียว ใน Lab นี้มีหลายตัว ทำงานอิสระในรอบ `loop()` เดียวกัน

| ตัวจับเวลา | ทุกกี่ ms | ทำอะไร |
|---|---|---|
| `lastSampleAt` | 50 | อ่าน LDR |
| `lastStepAt` | 100–1200 (เปลี่ยนตามแสง) | เปลี่ยนสี LED |
| `lastPrintAt` | 250 | พิมพ์ Raw Data ใน Serial |
| `lastBlinkAt` | 250 | กะพริบ LED ขาว (เฉพาะช่วง calibrate) |

ถ้าใช้ `delay()` จะทำพร้อมกันแบบนี้ไม่ได้ เพราะ `delay()` หยุดทุกอย่าง

### 3.10 รูปแบบข้อความใน `Serial.printf` ที่เพิ่มจาก Lab 1

| รูปแบบ | ความหมาย | ตัวอย่าง |
|---|---|---|
| `%4d` | จำนวนเต็ม กว้างอย่างน้อย 4 ช่อง (เว้นหน้า) | `  12` |
| `%6.1f` | ทศนิยม 1 ตำแหน่ง กว้างอย่างน้อย 6 ช่อง | ` 122.0` |
| `%3d%%` | จำนวนเต็ม 3 ช่อง ตามด้วยเครื่องหมาย % (ต้องเขียน `%%`) | ` 78%` |
| `%-5s` | ข้อความ ชิดซ้าย กว้าง 5 ช่อง | `RED  ` |
| `%lu` | จำนวนเต็มบวกขนาดยาว | `975` |

## 4. ขั้นตอนปฏิบัติ

### ขั้นที่ 1 — เปิดโปรเจกต์และดูไฟล์

1. เปิด VS Code → **File → Open Folder** → เลือก `Level1/Lab2_Template_ADC_LDR` (ต้องเป็นโฟลเดอร์ที่มี `platformio.ini`)
2. เปิดไฟล์ `include/app_config.h` ดูค่าที่ปรับได้ แล้วเปิด `src/main.cpp` ดูโครงสร้างคร่าวๆ
3. หาตำแหน่ง LDR บนบอร์ด: ตัวเล็กๆ ใกล้มุมของจอ มีป้าย **R21** ตามเอกสารของบอร์ด

### ขั้นที่ 2 — Build

```powershell
pio run
```

ต้องขึ้น `[SUCCESS]` (ถ้าสั่ง `pio` ไม่ได้ใช้ `python -m platformio ...` แทน)

### ขั้นที่ 3 — Upload

ปิด Serial Monitor ที่เปิดค้างอยู่ก่อน แล้วสั่ง (เปลี่ยน COM3 เป็นเลขของคุณ ดูได้จาก `pio device list`)

```powershell
pio run -t upload --upload-port COM3
```

### ขั้นที่ 4 — เปิด Serial Monitor

```powershell
pio device monitor -b 115200 --port COM3
```

ถ้าไม่เห็นข้อความตอนเปิดเครื่อง ให้กดปุ่ม **EN/RESET** บนบอร์ด 1 ครั้ง

### ขั้นที่ 5 — ฝึก Calibration

หลัง reset จะเห็นข้อความทำนองนี้ (จริงจากบอร์ดต้นแบบ)

```
---------------- CALIBRATION ----------------
For 6 s: COVER the LDR with your hand for a moment, then UNCOVER it.
(LDR = small sensor near the top-right corner of the screen, label R21)
LED blinks WHITE during calibration.
[CAL] 5 s left  raw= 120  smooth= 119.7  min= 119  max= 121
[CAL] 4 s left  raw= 121  smooth= 120.4  min= 119  max= 121
```

LED ขาวกะพริบอยู่ ภายใน 6 วินาทีนี้ให้ **ครอบมือบังเซนเซอร์สัก 2–3 วินาที แล้วเปิดมือ** ดูที่ `min=` และ `max=` ที่ห่างกันมากขึ้น

เมื่อครบเวลาจะขึ้นสรุป

| กรณี | ข้อความที่เห็น | ความหมาย |
|---|---|---|
| ครอบมือแล้ว (ช่วง ≥ 8) | `OK: using the range measured in this room.` | ใช้ช่วงที่วัดได้จริง |
| ไม่ได้ครอบ (ช่วง < 8) | `Range too small (< 8): did you cover the sensor? Using defaults ...` | ใช้ค่าสำรอง ให้กด EN/RESET ทำใหม่ |

บันทึกผล calibration ของคุณ: `raw min = ____`   `raw max = ____`   `range = ____`   ผล: ☐ OK  ☐ ใช้ค่าสำรอง

### ขั้นที่ 6 — ทดลองและบันทึกผล

หลัง calibrate จะเห็นบรรทัด Raw Data (ตัวอย่างจริงจากบอร์ดต้นแบบ)

```
[LDR] raw= 122  smooth= 122.0  light=  0% [----------]  step= 100 ms  LED=RED    DARK -> FAST
```

| ช่อง | ความหมาย |
|---|---|
| `raw` | ค่าดิบ (เฉลี่ย 8 ครั้งแล้ว) ช่วง 0–4095 |
| `smooth` | ค่าหลังผ่านตัวกรอง นิ่งกว่า raw |
| `light` และแถบ `[#####-----]` | ความสว่าง 0–100% (10 ช่อง = 100%) |
| `step` | ระยะเวลาที่ LED ค้างต่อ 1 สี ณ ตอนนี้ (ms) |
| `LED` | สีที่กำลังติดตอนพิมพ์ |
| ท้ายบรรทัด | `DARK -> FAST` (ต่ำกว่า 35%), `MID`, `BRIGHT -> SLOW` (สูงกว่า 65%) |

ทำการทดลอง 3 สภาพ รอให้ค่านิ่งประมาณ 2 วินาทีแล้วจดค่า

| สภาพแสง | `raw` | `light` % | `step` (ms) | LED วิ่งเร็วหรือช้า (สังเกตด้วยตา) |
|---|---|---|---|---|
| ครอบมือบังเซนเซอร์ให้มืดที่สุด | | | | |
| แสงห้องปกติ (ไม่บัง) | | | | |
| ส่องไฟฉายโทรศัพท์ใกล้ๆ เซนเซอร์ | | | | |

เกณฑ์ที่ควรเห็น: เมื่อมืด `light` เข้าใกล้ 0% และ `step` ใกล้ 100 ms (เร็ว) เมื่อสว่าง `light` เพิ่มและ `step` มากขึ้นถึงราว 1200 ms (ช้า)
ค่าของแต่ละห้องต่างกันเป็นเรื่องปกติ

> ถ้า calibrate ไม่สำเร็จ (ใช้ค่าสำรอง) ตัวเลขอาจไม่ตรงกับห้องคุณมากนัก ให้กด EN/RESET แล้ว calibrate ใหม่ให้สำเร็จก่อนทดลอง

| `SMOOTH_ALPHA` | 0.25 | ความไวของตัวกรอง |

| `CALIBRATION_MS` | 6000 | เวลา calibrate |
| `MIN_CALIBRATION_RANGE` | 8 | ช่วงขั้นต่ำที่ถือว่า calibrate สำเร็จ |
| `DEFAULT_RAW_BRIGHT` / `DEFAULT_RAW_DARK` | 0 / 120 | ค่าสำรอง (ประมาณ) |
| `FAST_STEP_MS` / `SLOW_STEP_MS` | 100 / 1200 | ระยะเวลาต่อสีตอนมืด / ตอนสว่าง |

### 5.2 `main.cpp` — ส่วนประกาศ

```cpp
enum class Phase { Calibrating, Running };    // ช่วงของโปรแกรม (state)
struct LedStep { const char *name; uint8_t pin; bool red; bool green; bool blue; };
const LedStep steps[] = { {"RED", ...}, {"GREEN", ...}, {"BLUE", ...} };
```

`enum class` คือชนิดข้อมูลที่มีค่าได้เฉพาะรายการที่ตั้งชื่อไว้ ส่วน `LedStep` และ `steps[]` เหมือน Lab 1

ตัวแปรสำคัญ

| ตัวแปร | เก็บอะไร |
|---|---|
| `phase` | ตอนนี้ Calibrating หรือ Running |
| `lastRaw` | ค่า raw ล่าสุด (เฉลี่ย 8 ครั้งแล้ว) |
| `smoothedRaw` | ค่าที่ผ่านตัวกรอง (ใช้จริงในการคำนวณ) |
| `calMin`, `calMax` | raw ต่ำสุด/สูงสุดที่เจอตอน calibrate |
| `rawBright`, `rawDark` | ช่วงที่ใช้จริงหลัง calibrate (หรือค่าสำรอง) |

### 5.3 `readLdrRaw()` และ `updateLdr()`

```cpp
int readLdrRaw() {
    uint32_t sum = 0;
    for (uint8_t i = 0; i < app::OVERSAMPLE_COUNT; i++) sum += analogRead(cyd::LDR_PIN);
    return sum / app::OVERSAMPLE_COUNT;        // เฉลี่ย 8 ครั้ง
}
void updateLdr() {
    lastRaw = readLdrRaw();
    if (!smoothedReady) { smoothedRaw = lastRaw; smoothedReady = true; }   // รอบแรกยังไม่มีค่าเก่า ใช้ค่าอ่านเลย
    else smoothedRaw += (lastRaw - smoothedRaw) * app::SMOOTH_ALPHA;       // สูตร EMA หัวข้อ 3.5
}
```

### 5.4 `lightPercent()` และ `stepIntervalMs()`

```cpp
int lightPercent() {
    const long pct = map(lroundf(smoothedRaw), rawDark, rawBright, 0, 100);   // มืด -> 0, สว่าง -> 100
    return constrain(pct, 0L, 100L);                                          // กันหลุดช่วง
}
uint32_t stepIntervalMs(int percent) {
    return map(percent, 0, 100, app::FAST_STEP_MS, app::SLOW_STEP_MS);        // 0% -> 100 ms, 100% -> 1200 ms
}
```

`lroundf` ปัดเศษทศนิยมเป็นจำนวนเต็มใกล้ที่สุดก่อนส่งให้ `map` (ซึ่งทำงานกับจำนวนเต็ม)

### 5.5 `makeBar()` และ `modeLabel()`

`makeBar` สร้างแถบ 10 ช่องจากเปอร์เซ็นต์: `filled = (percent + 5) / 10` (บวก 5 เพื่อปัดขึ้น) ช่องที่ i < filled เป็น `#` ที่เหลือเป็น `-`
เช่น 78% → (78+5)/10 = 8 → `[########--]`  ส่วน `modeLabel` คืนข้อความตามเกณฑ์ <35 / >65

### 5.6 `startCalibration()` และ `finishCalibration()`

- `startCalibration()` ตั้ง `phase = Calibrating`, เริ่มนับเวลา, ตั้ง calMin/calMax เป็นค่าปัจจุบัน, เปิด LED ขาว และพิมพ์คำแนะนำ
- `finishCalibration()` คำนวณ `range = calMax - calMin` ถ้า `range >= 8` ใช้ calMin/calMax เป็น `rawBright`/`rawDark`
  ไม่เช่นนั้นใช้ค่าสำรอง แล้วเปลี่ยน `phase = Running` และแสดงสีแรกทันที

### 5.7 `setup()`

```cpp
Serial.begin(...);   cyd::ledInit();
analogSetPinAttenuation(cyd::LDR_PIN, ADC_0db);   // ซูมช่วงวัดให้เห็นความต่างของแสงชัดขึ้น (หัวข้อ 3.3)
updateLdr();         // อ่านค่าแรกไว้เป็นค่าเริ่มของตัวกรอง
startCalibration();
```

### 5.8 `loop()` — ลำดับการทำงาน

```
loop()
 ├─ ทุก 50 ms : updateLdr()   (ถ้าอยู่ช่วง Calibrating ให้จด calMin / calMax ด้วย)
 │
 ├─ ถ้า phase == Calibrating
 │     ├─ ทุก 250 ms : สลับ LED ขาวติด/ดับ
 │     ├─ ทุก 1 s    : พิมพ์ [CAL] ...
 │     ├─ ครบ 6 s    : finishCalibration()
 │     └─ return  (ข้ามส่วนล่าง)
 │
 └─ ช่วง Running
       ├─ ถึงเวลา stepIntervalMs(lightPercent()) : เปลี่ยนสีถัดไป (% 3 วนกลับ)
       └─ ทุก 250 ms : printRunningLine()
```

จุดสำคัญ: เวลาที่ใช้เปรียบเทียบกับ `lastStepAt` **คำนวณใหม่ทุกรอบ `loop()`** จากแสงปัจจุบัน
จึงเห็น LED เร่ง/ผ่อนความเร็วตามแสงที่เปลี่ยนไปแบบต่อเนื่อง

## 6. แบบฝึกหัด

ทุกข้อ: **แก้ → upload → ดูผล** กลับโค้ดเดิมได้ด้วย `git restore src/main.cpp include/app_config.h`

### ระดับ 1 (ปรับค่า)

**ข้อ 1 — กลับพฤติกรรม:** ให้ "สว่าง = เร็ว, มืด = ช้า" โดยแก้ **เฉพาะ** `app_config.h` (ไม่แตะ `main.cpp`)
บอกว่าแก้ค่าอะไร และบันทึกค่า `step` ตอนมืด/สว่างหลังแก้

**ข้อ 2 — ความไวของตัวกรอง:** ลอง `SMOOTH_ALPHA = 0.05` และ `0.9` สลับกัน ครอบมือแล้วเปิดมือเร็วๆ ดูค่า `smooth=`
เทียบกับ `raw=` ตอบ: ค่าไหนตามแสงทันที ค่าไหนตามช้า เพราะเหตุใด (ดูหัวข้อ 3.5)

**ข้อ 3 — ลดเวลา calibrate:** ตั้ง `CALIBRATION_MS = 2000` แล้ว reset ลอง calibrate ให้ทันภายใน 2 วินาที ผลที่ได้ยากกว่าตอน 6 วินาทีหรือไม่

### ระดับ 2 (แก้โค้ดเล็กๆ)

**ข้อ 4 — พิมพ์ทุกครั้งที่ LED เปลี่ยนสี และวัดความเร็วจริง:** ใน `showStep()` เพิ่ม

```cpp
Serial.printf("[LED] %s (GPIO%u)\n", step.name, step.pin);
```

แล้วเปิด monitor ด้วย `pio device monitor -b 115200 --port COM3 --filter time` ดูเวลาหน้าบรรทัด `[LED]`
คำนวณระยะห่างระหว่างสองบรรทัดติดกัน เทียบกับค่า `step=` ที่พิมพ์ในบรรทัด `[LDR]` ตอบ: ตรงกันหรือไม่

**ข้อ 5 — พิมพ์เฉพาะเมื่อแสงเปลี่ยน:** ปรับให้พิมพ์บรรทัด `[LDR]` เฉพาะเมื่อ `light` ต่างจากที่พิมพ์ครั้งล่าสุดอย่างน้อย 5 จุด
คำใบ้: เก็บเปอร์เซ็นต์ที่พิมพ์ล่าสุดไว้ในตัวแปร และใช้ `abs(percent - ตัวแปรนั้น) >= 5` ผลที่ควรได้: ตอนแสงนิ่งแทบไม่มีบรรทัดใหม่

**ข้อ 6 — คำนวณด้วยมือ:** ใช้ค่าสำรอง (`rawBright = 0`, `rawDark = 120`) และ `FAST_STEP_MS = 100`, `SLOW_STEP_MS = 1200`
ถ้า `smooth = 45` จงหา (ก) ความสว่าง % (ข) ระยะเวลาต่อสี (ms) (ค) ป้ายโหมดที่ขึ้น (`DARK -> FAST` / `MID` / `BRIGHT -> SLOW`)
(ใช้สูตรหัวข้อ 3.7 ปัดเศษทิ้งตามการคำนวณจำนวนเต็ม)

### ระดับ 3 (ท้าทาย)

**ข้อ 7 — ไฟกลางคืน (night light):** ถ้า `light` ต่ำกว่า 15% ให้ LED เป็นสีขาวค้าง (ไม่วิ่ง R-G-B) พร้อมพิมพ์ข้อความ `[NIGHT] ...` ครั้งเดียวตอนเข้าโหมด
และกลับมาวิ่ง R-G-B เมื่อสว่างขึ้น คำใบ้: ต้องมีตัวแปร `bool` จำสถานะ และเมื่อกลับมาวิ่งให้รีเซ็ตตัวจับเวลา `lastStepAt`

**ข้อ 8 — กันไฟกลางคืนกะพริบ (hysteresis):** ถ้าแสงอยู่แถวๆ 15% พอดี ไฟกลางคืนอาจเปิด-ปิดสลับถี่ๆ
ออกแบบให้ "เปิดเมื่อต่ำกว่า 15%" แต่ "ปิดเมื่อสูงกว่า 25%" (ช่วงระหว่าง 15–25% คงสถานะเดิม)
อธิบายด้วยคำพูดของตัวเองว่าทำไมวิธีนี้ช่วยได้ (เชื่อมโยงกับ anti-swing ที่คุณอาจเคยเรียนใน Smart Farm)

## 7. คำถามทบทวน

1. ADC คืออะไร และ ESP32 ให้ค่าตั้งแต่เท่าไรถึงเท่าไร
2. บนบอร์ดนี้ ค่า raw "สูง" แปลว่าสว่างหรือมืด
3. เหตุใดต้องอ่าน LDR 8 ครั้งแล้วเฉลี่ย แทนที่จะอ่านครั้งเดียว
4. สูตร EMA คืออะไร ถ้า alpha เป็น 0.5, ค่าเก่า 100, ค่าที่อ่านได้ 120 ค่าใหม่คือเท่าไร
5. Calibration ช่วยแก้ปัญหาอะไร ถ้าไม่ทำ calibrate จะเกิดอะไรขึ้นเมื่อย้ายบอร์ดไปห้องที่สว่างต่างกันมาก
6. เมื่อ calibrate ไม่สำเร็จ (ช่วงแคบกว่า 8) โปรแกรมทำอย่างไร และผู้ใช้ควรทำอย่างไร
7. ทำไมจึงใส่ช่วงขาเข้าของ `map` เป็น `rawDark, rawBright` (มืดก่อน) ไม่ใช่ `rawBright, rawDark`
8. `constrain(pct, 0, 100)` มีไว้ป้องกันอะไร
9. ในช่วง Running ถ้าความสว่าง 50% ระยะเวลาต่อสีคือเท่าไร (ใช้ค่าเริ่มต้น)
10. ใน `loop()` มีตัวจับเวลา `millis()` กี่ตัวทำงานพร้อมกัน แต่ละตัวทำอะไร และทำไมใช้ `delay()` แทนไม่ได้
11. `phase` ใน state machine มีค่าอะไรได้บ้าง และใช้ทำอะไร
12. ถ้าใน `Serial.printf` ต้องการพิมพ์เครื่องหมาย `%` ต้องเขียนอย่างไร
