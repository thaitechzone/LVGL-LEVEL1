# Level 1 / Lab 8 — SD Logger: บันทึกข้อมูล DHT11 พร้อมเวลาจริงลง microSD card

Lab นี้ต่อยอดจาก Lab 7 (NTP Clock): บันทึก **อุณหภูมิ ความชื้น และสถานะพัดลม** ลงไฟล์ **CSV** บน microSD card ทุก 10 วินาที โดยติด **เวลาจริง** จาก NTP ให้ทุกแถว
เปิดไฟล์ใน Excel / Google Sheets ได้ทันที คอลัมน์ `source` บอกว่าค่าเป็น `REAL` (เซนเซอร์จริง) หรือ `SIM` (ค่าจำลอง) ไม่ให้ปนกัน

> **สถานะการตรวจสอบ (อ่านก่อน):** โปรแกรม build ผ่านและทดสอบบนบอร์ดจริงพร้อม microSD card แล้ว: เมาท์การ์ด, สร้างไฟล์ log ใหม่ทุกครั้ง, บันทึกแถวพร้อมเวลาจริง, คำสั่ง `i l p e r x y`,
> เส้นทาง "ไม่พบการ์ด" และเส้นทางไม่มี WiFi (เวลาเป็น `NOT_SYNCED`) ผู้พัฒนาเปิดไฟล์ log ใน Excel ได้ถูกต้อง และส่งภาพหน้าจอยืนยันแล้ว
> **ส่วนที่ยังไม่ได้ตรวจ:** ถอดการ์ดขณะกำลังบันทึกโดยไม่สั่ง `e`, การ์ดเต็ม, การ์ดชนิดอื่น (เช่น 32 GB ขึ้นไป หรือฟอร์แมตเป็น exFAT), LED เขียว, ปุ่ม BOOT ดูตาราง "สิ่งที่ยังไม่ได้ยืนยัน" ท้ายไฟล์
> ภาพ ASCII วาดประกอบ ข้อความ Serial ที่ระบุว่าเป็นของจริงมาจากบอร์ดต้นแบบ

## สิ่งที่จะได้เรียน

1. **microSD บน SPI ชุดแยก:** การ์ดใช้ขา CS/MOSI/SCK/MISO ของตัวเอง ไม่ชนกับจอ (จอใช้ HSPI การ์ดใช้ VSPI)
2. **ระบบไฟล์ FAT บนการ์ด:** เมาท์ (`SD.begin`), เปิด/เขียน/ต่อท้าย/ปิดไฟล์, อ่านรายชื่อไฟล์, ลบไฟล์
3. **การเขียนการ์ดช้า:** วัดเวลาที่ใช้เขียนจริง (ราว 14–17 ms ต่อแถวบนการ์ดที่ทดสอบ) จึงไม่เขียนถี่เกินไป และรู้ว่าเกิดอะไรกับ `loop()`
4. **ความทนทานของข้อมูล:** เปิด-เขียน-ปิดไฟล์ทุกครั้ง, ปล่อยการ์ด (`e`) ก่อนถอด, ไม่ฟอร์แมตการ์ดเอง, ลบเฉพาะไฟล์ที่โปรแกรมสร้าง
5. **จัดการอุปกรณ์ที่ถอดได้:** ไม่มีการ์ด/เขียนไม่สำเร็จ/สั่งถอดแล้ว โปรแกรมต้องไม่ค้างและกลับมาบันทึกต่อเองได้
6. **รูปแบบ CSV และการเปิดใน Excel**
7. **ใช้เวลาจริงจาก Lab 7 ติดข้อมูล** และรับมือเมื่อยังไม่ sync (`NOT_SYNCED`) ไม่เขียนเวลาปี 1970 ลงไฟล์

## ฮาร์ดแวร์

- **microSD card** ใส่ในสล็อตด้านหลังจอ (ไม่ต้องต่อสายเพิ่ม) ฟอร์แมตเป็น **FAT32** ความจุแนะนำไม่เกิน 32 GB (การ์ดที่ผู้เขียนทดสอบคือ SDHC 7.4 GB ฟอร์แมตด้วย Windows)
- ขาของการ์ด (จาก `board_config.h`): **CS = GPIO5, MOSI = GPIO23, SCK = GPIO18, MISO = GPIO19**
- DHT11 ต่อเหมือน Lab 6–7 (DATA → GPIO27) ถ้าไม่มีเซนเซอร์ ค่าจะเป็น SIM และคอลัมน์ `source` จะบอก
- WiFi 2.4 GHz และ `include/secrets.h` เหมือน Lab 7 (ถ้าไม่มี ก็บันทึกได้ แต่เวลาจะเป็น `NOT_SYNCED`)
- **ห้ามถอดการ์ดขณะกำลังเขียน** ให้พิมพ์ `e` ใน Serial ก่อน (ดูหัวข้อด้านล่าง) และอย่าฟอร์แมตการ์ดจากบอร์ด (โปรแกรมนี้ไม่ฟอร์แมต)

## ไฟล์ log

ทุกครั้งที่เปิดเครื่อง (หรือสั่ง `r`) โปรแกรมสร้างไฟล์ใหม่เลขถัดไป: `log_0001.csv`, `log_0002.csv`, … **ไม่เขียนทับไฟล์เก่า**

```
timestamp,uptime_s,source,temp_c,hum_pct,fan_duty_pct,mode
2026-10-09 20:14:19,11,REAL,27.4,93,0,AUTO
2026-10-09 20:14:29,21,REAL,27.5,93,0,AUTO
```

| คอลัมน์ | ความหมาย |
|---|---|
| `timestamp` | **เวลาจริง** (UTC+7) รูปแบบ `YYYY-MM-DD HH:MM:SS` หรือ `NOT_SYNCED` ถ้ายังไม่ได้เวลา |
| `uptime_s` | วินาทีตั้งแต่เปิดเครื่อง (มีเสมอ ใช้ดูลำดับแม้ยังไม่ sync) |
| `source` | `REAL` (DHT11 จริง) / `SIM-RANDOM` / `SIM-SWEEP` (ค่าจำลอง) |
| `temp_c` / `hum_pct` | อุณหภูมิ (°C ทศนิยม 1 ตำแหน่ง) / ความชื้น (%) |
| `fan_duty_pct` | duty ของพัดลมจำลอง (%) |
| `mode` | `AUTO` / `MANUAL` |

- ขนาดแถวละ **44 ไบต์** (รวมขึ้นบรรทัดใหม่แบบ Windows) บันทึกทุก 10 วินาที = 8,640 แถวต่อวัน = 380,160 ไบต์ ≈ **0.38 MB ต่อวัน** (คำนวณจากขนาดไฟล์ที่วัดได้)
- ยังไม่มีค่า (ยังอ่านเซนเซอร์ไม่ได้) จะ **ไม่บันทึกแถวว่าง**
- **เปิดใน Excel:** ใส่การ์ดเข้าคอมพิวเตอร์ เปิดไฟล์ `.csv` Excel จะรู้จักคอลัมน์ `timestamp` เป็นวันที่-เวลา (ภาพที่ผู้พัฒนาส่งมาแสดงถูกต้อง) โดยค่าเริ่มต้นแสดงแค่ชั่วโมง:นาที
  ถ้าอยากเห็นวินาที ให้จัดรูปแบบเซลล์เป็น `yyyy-mm-dd hh:mm:ss`

## วิธีควบคุม

| คำสั่ง Serial | ทำอะไร |
|---|---|
| `i` | ข้อมูลการ์ด: สถานะ, ชนิด, ขนาด, พื้นที่ใช้/ว่าง, ไฟล์ปัจจุบัน, จำนวนแถว, แถวที่ข้าม, ครั้งที่เขียนไม่สำเร็จ, เวลาเขียนล่าสุด/สูงสุด |
| `l` | แสดงรายชื่อไฟล์ในการ์ด (พร้อมขนาด) |
| `p` | แสดงท้ายไฟล์ log ปัจจุบัน (ประมาณ 360 ไบต์ท้ายสุด) |
| **`e`** | **หยุดบันทึกและปล่อยการ์ด = ถอดได้อย่างปลอดภัย** (สถานะเป็น `EJECTED`) |
| `r` | เมาท์การ์ดใหม่ แล้วเริ่มบันทึกต่อ **ในไฟล์ใหม่** (เลขถัดไป) |
| `x` แล้ว `y` | ลบไฟล์ `log_####.csv` ทั้งหมดที่ Lab นี้สร้าง (ต้องกด `y` ภายใน 10 วินาที ปุ่มอื่นยกเลิก) **ไม่แตะไฟล์อื่นในการ์ด** และสร้างไฟล์ใหม่ให้ |
| `m` `+` `-` `0`–`9` `s` `n` `t` `h` | เหมือน Lab 6–7 (พัดลม, ค่า REAL/SIM, ขอเวลา NTP, พิมพ์เวลา, วิธีใช้) |
| ปุ่ม BOOT | สลับพัดลม AUTO ↔ MANUAL |

## ความรู้ใหม่ใน Lab นี้

### ใช้การ์ดผ่านไลบรารี `SD`

```cpp
SPIClass sdSpi(VSPI);                                              // SPI ชุดที่สำหรับการ์ด (จอใช้ HSPI)
sdSpi.begin(cyd::SD_PIN_CLK, cyd::SD_PIN_MISO, cyd::SD_PIN_MOSI, cyd::SD_PIN_CS);
SD.begin(cyd::SD_PIN_CS, sdSpi, 4000000);                          // เมาท์ที่ 4 MHz (ถ้าไม่มีการ์ดจะคืน false)

File file = SD.open("/log_0001.csv", FILE_APPEND);                 // เปิดแบบต่อท้าย
file.println("...");                                               // เขียน 1 แถว
file.close();                                                      // ปิดทุกครั้ง
```

- `SD.begin(...)` **ไม่ฟอร์แมตการ์ด** (ค่าเริ่มต้นของพารามิเตอร์ `format_if_empty` คือ `false`) โปรแกรมไม่ฟอร์แมตการ์ดเด็ดขาด
- `FILE_WRITE` สร้าง/เขียนไฟล์ใหม่ (ใช้ตอนสร้างพร้อมหัวตาราง) ส่วน `FILE_APPEND` ต่อท้ายไฟล์เดิม (ใช้ตอนบันทึกแถวใหม่)
- ใช้ SPI ที่ 4 MHz ซึ่งช้าแต่เสถียร (ปรับที่ `SD_SPI_HZ` ได้)

### ทำไม "เปิด-เขียน-ปิด" ทุกครั้ง

ข้อมูลที่เขียนลงไฟล์อาจค้างอยู่ใน buffer ในหน่วยความจำ และตารางไฟล์ (FAT) ของการ์ดจะอัปเดตเมื่อปิดไฟล์ ถ้าไฟดับหรือถอดการ์ดก่อนปิดไฟล์ อาจเสียข้อมูลหรือไฟล์เสียหาย
การปิดไฟล์ทุกแถวจึงปลอดภัยกว่า แลกกับเวลาที่ช้ากว่า (**วัดจากบอร์ดจริง:** เขียนหนึ่งแถว ≈ **14.4–16.8 ms**) ที่ 1 แถวต่อ 10 วินาที ไม่กระทบอะไร
(แต่ถ้าบันทึกถี่ขึ้นมากๆ ต้องคิดใหม่ ดูแบบฝึกหัด) เมื่อต้องการถอดการ์ด ให้พิมพ์ `e` ก่อนทุกครั้ง

### ใช้เวลาเท่าไรในการเมาท์ และเมื่อไม่มีการ์ด

| เหตุการณ์ | เวลาที่วัดได้ |
|---|---|
| เมาท์การ์ดที่มีอยู่ (ครั้งแรกหลังเปิดเครื่อง) | ≈ 127–148 ms |
| เมาท์ซ้ำ (เช่น `r` หรือหลังรีเซ็ต) | ≈ 10–11 ms |
| **เมาท์ล้มเหลว (ไม่มีการ์ด)** | ≈ **625 ms** ต่อครั้ง และ **`loop()` หยุดรอตลอดช่วงนี้** |
| เขียน 1 แถว (เปิด-ต่อท้าย-ปิด) | ≈ 14.4–16.8 ms |

เมื่อไม่มีการ์ด โปรแกรมลองเมาท์ใหม่ทุก 5 วินาที (`SD_RETRY_MS`) จึงหยุดรอ ≈ 0.6 วินาทีทุก 5 วินาที (≈ 12% ของเวลา) ซึ่งทำให้นาฬิกา/จอสะดุดเล็กน้อย
ระหว่างนี้พัดลมและการอ่านเซนเซอร์ยังทำงานต่อ ถ้าอยากให้สะดุดน้อยลง ให้เพิ่ม `SD_RETRY_MS` (ดูแบบฝึกหัด)

### สถานะของ SD (`SdState`)

| สถานะ | ความหมาย | ไปสถานะถัดไปเมื่อ |
|---|---|---|
| `NoCard` | ไม่พบการ์ด/เมาท์ไม่สำเร็จ | ลองเมาท์ใหม่ทุก 5 วินาที สำเร็จ → `Ready` |
| `Ready` | บันทึกได้ | เขียนไม่สำเร็จ → `WriteError` / พิมพ์ `e` → `Ejected` |
| `WriteError` | เขียนไม่สำเร็จ (เช่นถอดการ์ดโดยไม่สั่ง `e`, การ์ดเต็ม) | ปล่อยการ์ด แล้วลองเมาท์ใหม่ทุก 5 วินาที |
| `Ejected` | ผู้ใช้สั่ง `e` แล้ว (ถอดได้) | พิมพ์ `r` → เมาท์ใหม่ |

แถวที่ถึงเวลาบันทึกแต่บันทึกไม่ได้ (ไม่มีการ์ด/ถอดแล้ว/ผิดพลาด) จะถูกนับใน `skipped` (ดูด้วย `i`) ไม่ใช่เขียนค้างไว้ภายหลัง

### เลือกชื่อไฟล์ใหม่โดยไม่ทับของเก่า

`highestLogNumber()` เปิดโฟลเดอร์หลักของการ์ดและอ่านรายชื่อไฟล์ทุกตัว หาเลขสูงสุดของไฟล์ที่ชื่อ `log_####.csv` แล้วใช้เลขถัดไป
ฟังก์ชัน `isLogFileName()` ตรวจรูปแบบชื่อให้ตรงเป๊ะ (ยาว 12 ตัวอักษร) ใช้ทั้งตอนหาเลขและตอนลบ ไฟล์อื่นในการ์ด (เช่นโฟลเดอร์ `System Volume Information` ที่ Windows สร้าง) จึงไม่ถูกแตะ

### `NOT_SYNCED` และหลักคิดเรื่อง "ไม่ใส่ข้อมูลที่เชื่อถือไม่ได้"

ช่วงเริ่มเครื่องก่อน NTP sync (หรือไม่มี WiFi) เวลาจริงยังใช้ไม่ได้ โปรแกรมเลือก **บันทึกแถวพร้อมคำว่า `NOT_SYNCED` ในคอลัมน์เวลา** แทนที่จะเขียนเวลาปี 1970
และมี `uptime_s` กำกับเสมอ ทำให้เรียงลำดับข้อมูลได้และรู้ว่าแถวไหนไม่มีเวลาจริง (ตรวจแล้วจากบอร์ดจริงตอนไม่มี `secrets.h`) ทางเลือกอื่นคือรอจน sync แล้วค่อยเริ่มบันทึก (ดูแบบฝึกหัด)

(เปลี่ยน `COM3` ตามเครื่องคุณ ปิด Serial Monitor ก่อน upload ถ้าไม่มีคำสั่ง `pio` ให้ใช้ `python -m platformio` ถ้า upload ไม่ผ่านด้วย `No serial data received` ให้กดปุ่ม BOOT ค้างตอน `Connecting......` หรือถอด/เสียบสาย USB ใหม่)

ลองตามลำดับนี้

1. **ใส่การ์ด FAT32 ก่อนเปิดเครื่อง** ดู Serial: `[SD] card OK: type SDHC ...` และ `[SD] created /log_0001.csv` จอแสดง `SD READY`
2. รอ 10 วินาที ดู `[LOG] #1 ...` และตัวนับ `rows` บนจอเพิ่ม พิมพ์ `p` ดูท้ายไฟล์ และ `l` ดูรายชื่อไฟล์
3. **ทดสอบถอดการ์ดอย่างปลอดภัย:** พิมพ์ `e` จอเป็น `EJECTED` ถอดการ์ดไปเปิดในคอมพิวเตอร์ (Excel) แล้วใส่กลับ พิมพ์ `r` เพื่อเริ่มบันทึกต่อในไฟล์ใหม่
4. **ทดสอบไม่มีการ์ด:** เปิดเครื่องโดยไม่ใส่การ์ด จอเป็น `NO CARD` พัดลม/เซนเซอร์/นาฬิกายังทำงาน (นาฬิกาสะดุดเล็กน้อยทุก 5 วินาทีตามที่วัดไว้) ใส่การ์ดแล้วรอ ≤ 5 วินาที ควรกลับมาเป็น `READY` (ยังไม่ได้ทดสอบกรณีใส่การ์ดภายหลังด้วยมือ)
5. **ทดสอบไม่มี WiFi:** ลบ/เปลี่ยนชื่อ `secrets.h` แล้ว upload ใหม่ ดูแถวใน log เป็น `NOT_SYNCED` (ตรวจแล้ว)
6. **เปิดไฟล์ใน Excel** ตรวจว่าคอลัมน์และค่าตรงกับที่แสดงใน Serial

## ค่าที่ปรับได้ใน `app_config.h`

| ค่า | ค่าเริ่มต้น | ผลเมื่อปรับ |
|---|---|---|
| `LOG_INTERVAL_MS` | 10000 | บันทึกทุกกี่ ms |
| `SD_SPI_HZ` | 4000000 | ความเร็ว SPI ของการ์ด (เพิ่มแล้วเขียนเร็วขึ้นถ้าการ์ดรองรับ) |
| `SD_RETRY_MS` | 5000 | ไม่พบการ์ด/ผิดพลาด แล้วลองเมาท์ใหม่ทุกกี่ ms |
| `SD_DELETE_CONFIRM_S` | 10 | ต้องกด `y` ยืนยันการลบภายในกี่วินาที |
| (ค่าของ Lab 6–7) | | เกณฑ์พัดลม, ค่า SIM, เซิร์ฟเวอร์ NTP ฯลฯ |

## แบบฝึกหัด

1. **เปลี่ยนช่วงบันทึก:** ตั้ง `LOG_INTERVAL_MS = 2000` แล้วดูขนาดไฟล์ที่โตเร็วขึ้น คำนวณขนาดต่อวัน (แถวละ 44 ไบต์)
2. **เพิ่มคอลัมน์:** เพิ่มคอลัมน์ `wifi_rssi` (ความแรงสัญญาณ) ในหัวตารางและทุกแถว (ต้องแก้ทั้งหัวตารางและ `snprintf`)
3. **รอ sync ก่อนบันทึก:** เปลี่ยนให้ไม่บันทึกแถวจนกว่า `timeValid()` เป็นจริง และนับแถวที่ข้ามไว้ในตัวแปร `skipped` เปรียบเทียบข้อดี/ข้อเสียกับการเขียน `NOT_SYNCED`
4. **ลด `loop()` สะดุดเมื่อไม่มีการ์ด:** เพิ่ม `SD_RETRY_MS` เป็น 30000 แล้วดูว่านาฬิกาลื่นขึ้นไหม เมื่อไม่ได้ใส่การ์ด แต่ต้องรอนานขึ้นกว่าจะกลับมาบันทึกเมื่อใส่การ์ด
5. **วัดผลของความเร็ว SPI:** ลอง `SD_SPI_HZ = 10000000` และ `20000000` ดู `write took` เปลี่ยนไหม และการ์ดยังเมาท์ได้ไหม (บางการ์ด/สายอาจไม่เสถียร ให้ย้อนกลับถ้าเมาท์ไม่ผ่าน)
6. **ไฟล์ใหม่ทุกวัน:** เมื่อวันที่เปลี่ยนให้ปิดไฟล์เดิมและสร้างไฟล์ใหม่ (คำใบ้: จำวันที่ท้องถิ่นของแถวล่าสุด)
7. **ท้าทาย:** เพิ่มคำสั่งที่พิมพ์ค่าเฉลี่ย/ต่ำสุด/สูงสุดของอุณหภูมิจากไฟล์ log ปัจจุบัน (อ่านไฟล์ทีละบรรทัดแล้วแยกคอลัมน์)

## ปัญหาที่พบบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| `NO CARD` ทั้งที่ใส่การ์ดแล้ว | ใส่ไม่สุด/ด้านผิด, การ์ดเสีย, ไม่ใช่ FAT32 (เช่น exFAT ของการ์ด 64 GB ขึ้นไป) ลองฟอร์แมตเป็น FAT32 จากคอมพิวเตอร์ (ข้อมูลในการ์ดจะหาย) แล้วพิมพ์ `r` |
| `ERROR` ระหว่างบันทึก | ถอดการ์ดโดยไม่ได้สั่ง `e`, การ์ดเต็ม, หรือสัมผัสไม่ดี โปรแกรมจะลองเมาท์ใหม่ทุก 5 วินาทีและสร้างไฟล์ใหม่เมื่อสำเร็จ |
| ถอดการ์ดแล้วไฟล์เปิดไม่ได้/ข้อมูลหาย | ถอดตอนกำลังเขียน ครั้งต่อไปให้พิมพ์ `e` ก่อน ตรวจสแกนการ์ดด้วยคอมพิวเตอร์ (เช่น "Check and repair") |
| เวลาในไฟล์เป็น `NOT_SYNCED` | ยังไม่ได้ตั้ง WiFi หรือยังไม่ sync ดู Lab 7 ตอนเริ่มเครื่อง ~10 วินาทีแรกอาจเป็น `NOT_SYNCED` ได้ถ้า WiFi ช้า |
| Excel แสดงเวลาไม่มีวินาที | เป็นรูปแบบเริ่มต้น จัดรูปแบบเซลล์เป็น `yyyy-mm-dd hh:mm:ss` |
| นาฬิกา/จอสะดุดทุก 5 วินาที ตอนไม่มีการ์ด | การเมาท์ล้มเหลวใช้ ≈ 0.6 วินาที (ดูแบบฝึกหัดข้อ 4) |
| ไม่ลบไฟล์ที่ไม่ใช่ `log_####.csv` | ตั้งใจ โปรแกรมลบเฉพาะไฟล์ที่ตัวเองสร้าง ถ้าจะลบไฟล์อื่นให้ใช้คอมพิวเตอร์ |
| upload ไม่ผ่าน | ปิด Serial Monitor / กด BOOT ค้างตอน `Connecting......` / ถอด-เสียบสาย USB ใหม่ |

## สิ่งที่ยังไม่ได้ยืนยัน (ผู้ทดสอบ/ผู้สอนควรตรวจและบันทึก)

| ข้อ | สถานะ |
|---|---|
| โปรแกรม build ผ่าน | ยืนยันแล้ว (ไม่มี warning จากโค้ดของ Lab นี้) |
| เมาท์การ์ด SDHC 7.4 GB, สร้างไฟล์ใหม่เลขถัดไป (`log_0001` → `0002` → …), หัวตาราง CSV, บันทึกแถวพร้อมเวลาจริง `REAL` | **ยืนยันแล้ว** จากบอร์ดจริง (Serial และภาพ Excel ของผู้พัฒนา) |
| เวลาเขียน 1 แถว ≈ 14.4–16.8 ms, เมาท์ ≈ 10–148 ms | **วัดแล้ว** จากบอร์ดจริง (ตัวอย่างที่เก็บ การ์ดตัวเดียว) |
| คำสั่ง `i`, `l`, `p`, `e`, `r` | **ยืนยันแล้ว** (ระหว่าง `EJECTED` ข้ามไป 2 แถว นับใน `skipped`) |
| คำสั่ง `x` → `y` (ลบ), `x` → ปุ่มอื่น (ยกเลิก), `y` โดยไม่มี `x` ไม่ทำอะไร, ไม่แตะโฟลเดอร์ `System Volume Information` | **ยืนยันแล้ว** จากบอร์ดจริง |
| เส้นทาง "ไม่พบการ์ด": ทดสอบโดยเปลี่ยนขา CS ไปขาที่ว่าง (GPIO22) → `NO CARD`, ลองใหม่ทุก 5 วินาที, เมาท์ล้มเหลวใช้ ≈ 625 ms | **ยืนยันแล้ว** (เป็นการจำลอง ไม่ได้ถอดการ์ดจริง) |
| ไม่มี WiFi → แถวเป็น `NOT_SYNCED` (พร้อม `uptime_s`) | **ยืนยันแล้ว** จากบอร์ดจริง |
| หน้าจอ: เวลา, ป้าย SYNCED, REAL, `SD READY SDHC 7.4GB`, `log_0002.csv rows 3 wr 14ms`, `WiFi -60dBm` | **ยืนยันแล้ว** จากภาพถ่ายของผู้พัฒนา (ภาพเล็ก ตรวจได้ว่าครบและไม่ชนกัน) |
| ป้ายสถานะ SD แบบ `NO CARD` / `ERROR` / `EJECTED` และข้อความ `insert FAT32 card` / `safe to remove` บนจอ | **ยังไม่มีหลักฐานภาพ** (ตรวจแค่ Serial) |
| ถอดการ์ดขณะกำลังบันทึกโดยไม่สั่ง `e` (เส้นทาง `WriteError` และเมาท์ใหม่เอง) | **ยังไม่ได้ทดสอบ** ผู้เขียนถอดการ์ดเองไม่ได้ โค้ดมีเส้นทางนี้ไว้ |
| ใส่การ์ดภายหลังขณะเปิดเครื่อง (`NoCard` → `Ready` เอง) | **ยังไม่ได้ทดสอบจริง** (ทดสอบเฉพาะการเมาท์ใหม่ด้วย `r` และการเปลี่ยนขา CS) |
| การ์ดเต็ม, การ์ดความจุ ≥ 32 GB (exFAT), การ์ดยี่ห้อ/ชนิดอื่น | **ยังไม่ได้ทดสอบ** |
| ความทนทานเมื่อไฟดับขณะเขียน | **ยังไม่ได้ทดสอบ** (ออกแบบให้ปิดไฟล์ทุกแถวเพื่อลดความเสี่ยง) |
| `SD_SPI_HZ` ที่ 10 MHz และ 20 MHz | **ตรวจแล้ว** บนการ์ดตัวนี้เมาท์ผ่านและเขียนได้ปกติ เวลาเขียนลดจาก ≈ 14–17 ms เหลือ ≈ 12–14 ms (10 MHz) และ ≈ 12–13 ms (20 MHz) (ตัวอย่างเล็ก การ์ดตัวเดียว ตัวอย่างหนึ่งที่ 10 MHz วัดได้ 30.6 ms ผิดปกติ) การ์ดอื่นอาจไม่ผ่าน |
| LED เขียว, ปุ่ม BOOT | **ยังไม่ได้เห็น/กดเอง** |
| ขนาดไฟล์ ≈ 0.38 MB ต่อวัน (380,160 ไบต์) | คำนวณจากแถวละ 44 ไบต์ที่วัดจากขนาดไฟล์ ที่ 1 แถวต่อ 10 วินาที |

**หมายเหตุเรื่องการ์ดของคุณ:** การทดสอบสร้างไฟล์ `log_0001`–`log_0004.csv` บนการ์ดของผู้พัฒนา (และผมลบไฟล์ `log_0001`–`log_0002` ชุดแรกไปในการทดสอบคำสั่ง `x`/`y`)
ถ้าไม่ต้องการ ให้ใช้ `x` แล้ว `y` ลบไฟล์ log ทั้งหมด (ไม่แตะไฟล์อื่น) หรือลบจากคอมพิวเตอร์
