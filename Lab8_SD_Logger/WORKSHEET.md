## 1. เป้าหมายการเรียนรู้

เมื่อจบใบงานนี้ ผู้เรียนต้องทำได้ทุกข้อ

1. อธิบายได้ว่า data logger คืออะไร ทำไมต้องบันทึกลงการ์ด และข้อมูลใน RAM กับในการ์ดต่างกันอย่างไร
2. ต่อ/ใช้ microSD ผ่าน SPI ชุดแยก และอธิบายบทบาทของ CS, MOSI, SCK, MISO และเหตุผลที่จอกับการ์ดใช้ SPI คนละชุด
3. ใช้ไลบรารี `SD` เมาท์การ์ด สร้าง/ต่อท้าย/อ่าน/ลบไฟล์ และอธิบายความต่างของ `FILE_WRITE` กับ `FILE_APPEND`
4. อธิบายได้ว่าทำไมต้อง "เปิด-เขียน-ปิดไฟล์" ทุกครั้ง และทำไมต้องพิมพ์ `e` ก่อนถอดการ์ด
5. วัดเวลาที่ใช้เขียนการ์ดจริง คำนวณสัดส่วนเวลาที่ `loop()` ถูกบล็อก และตัดสินใจเลือกช่วงบันทึกที่เหมาะสม
6. ออกแบบการรับมืออุปกรณ์ที่ถอดได้: ไม่มีการ์ด, เขียนไม่สำเร็จ, สั่งถอด, ลองเมาท์ใหม่ โดยโปรแกรมไม่ค้าง
7. ออกแบบรูปแบบข้อมูล CSV (คอลัมน์ `source`, `NOT_SYNCED`) และเปิดวิเคราะห์ใน Excel ได้
8. คำนวณขนาดไฟล์/ความจุ และดัดแปลงโปรแกรมตามแบบฝึกหัดได้

## 3. ความรู้พื้นฐานที่ต้องเข้าใจก่อนลงมือ

### 3.1 data logger และทำไมต้องใช้การ์ด

| หน่วยความจำ | เก็บข้อมูลเมื่อไฟดับ? | ใช้ทำอะไร |
|---|---|---|
| **RAM** (ตัวแปรในโปรแกรม) | ไม่ เมื่อไฟดับหายหมด | ค่าที่กำลังใช้งาน |
| **flash ภายในของ ESP32** | ใช่ | เก็บโปรแกรม (ไม่ควรเขียนบ่อยๆ เพราะมีจำนวนครั้งเขียนจำกัด) |
| **microSD card** | **ใช่** ความจุเป็นกิกะไบต์ ถอดไปอ่านในคอมพิวเตอร์ได้ | เก็บข้อมูลยาวนาน (log) |

**data logger** คือเครื่องที่วัดค่าเป็นระยะแล้วจดลงที่เก็บถาวร เพื่อให้ย้อนดูภายหลังได้ ข้อมูลที่มีเวลาจริงกำกับ (จาก Lab 7) จึงจะวิเคราะห์ได้ เช่น "เมื่อวานตอนบ่ายอุณหภูมิสูงสุดเท่าไร"

### 3.2 การ์ด microSD

| ชนิด | ขนาดโดยทั่วไป | ระบบไฟล์ที่ใช้ | ใช้กับ Lab นี้ |
|---|---|---|---|
| SDSC | ≤ 2 GB | FAT16 | ได้ (อาจหายาก) |
| **SDHC** | 2–32 GB | **FAT32** | **ใช่ (แนะนำ)** การ์ดที่ทดสอบคือ SDHC |
| SDXC | > 32 GB | exFAT | **ยังไม่ได้ทดสอบ** ต้องฟอร์แมตเป็น FAT32 ก่อนถึงน่าจะใช้ได้ |

ตัวอย่าง: การ์ดที่ผู้เขียนทดสอบ ฉลากเขียน "8 GB" แต่โปรแกรมรายงาน `size 7.4 GB` เพราะผู้ผลิตนับ 1 GB = 1,000,000,000 ไบต์ ส่วนคอมพิวเตอร์นับ 1 GB = 1,073,741,824 ไบต์ (2³⁰):
8,000,000,000 ÷ 1,073,741,824 ≈ **7.45 GB** (โปรแกรมแสดง 7.4 เพราะตัดทศนิยม)

### 3.3 SPI และการใช้บัสร่วมกัน

การ์ดคุยกับบอร์ดผ่าน **SPI** (เหมือนจอใน Lab 4) ซึ่งมี 4 สาย

| สาย | หน้าที่ | ขาบนบอร์ดนี้ (การ์ด) |
|---|---|---|
| CS (Chip Select) | เลือกอุปกรณ์ที่จะคุยด้วย (ดึงลง LOW = คุยกับตัวนี้) | GPIO5 |
| MOSI | บอร์ดส่งข้อมูลไปการ์ด | GPIO23 |
| SCK | สัญญาณนาฬิกา | GPIO18 |
| MISO | การ์ดส่งข้อมูลกลับบอร์ด | GPIO19 |

ESP32 มี SPI หลายชุด จอ TFT ใช้ชุด **HSPI** (ขา 12, 13, 14, 15) ส่วนการ์ดใช้ชุด **VSPI** (ขา 18, 19, 23, 5) จึงใช้งานพร้อมกันได้โดยไม่ชนกัน
ในโค้ด `SPIClass sdSpi(VSPI);` สร้างตัวแทนของ SPI ชุดการ์ด แล้วส่งให้ `SD.begin(cs, sdSpi, ความเร็ว)` ความเร็วเริ่มต้นของ Lab นี้คือ **4 MHz** (`SD_SPI_HZ`)

### 3.3.1 คำนวณเวลาส่งข้อมูลบริสุทธิ์

ที่ 4 MHz ส่งได้ 4,000,000 บิตต่อวินาที แถว log ยาว 44 ไบต์ = 352 บิต ใช้เวลา 352 ÷ 4,000,000 = **88 ไมโครวินาที** ส่วนการ์ดเขียนเป็นบล็อกละ 512 ไบต์ (4,096 บิต) = **≈ 1.0 มิลลิวินาที** ต่อบล็อก
แต่ผลที่วัดจริงคือ **ราว 14–17 มิลลิวินาที** ต่อ 1 แถว มากกว่ามาก เพราะเวลาส่วนใหญ่หมดไปกับงานของระบบไฟล์ (เปิดไฟล์ หาตำแหน่งต่อท้าย อัปเดตตารางไฟล์ FAT ปิดไฟล์) และการรอการ์ดเขียนเสร็จ (ดูผลการทดลองความเร็ว SPI ในแบบฝึกหัดข้อ 5)

### 3.4 ไฟล์และระบบไฟล์ FAT

ลำดับการเขียนไฟล์ในโปรแกรม

```cpp
File file = SD.open("/log_0001.csv", FILE_APPEND);   // 1) เปิดไฟล์ (ต่อท้าย)
file.println("...");                                  // 2) เขียนลง buffer
file.close();                                         // 3) ปิด: ข้อมูลและตารางไฟล์ถูกบันทึกลงการ์ดจริง
```

| คำสั่ง | ทำอะไร |
|---|---|
| `SD.open(path, FILE_WRITE)` | เปิดไฟล์เพื่อเขียน ถ้ายังไม่มีไฟล์จะสร้างใหม่ (ใช้ตอนสร้างไฟล์ log พร้อมหัวตาราง) |
| `SD.open(path, FILE_APPEND)` | เปิดและเขียนต่อท้ายไฟล์เดิม (ใช้ตอนบันทึกแต่ละแถว) |
| `SD.open(path, FILE_READ)` | เปิดอ่าน |
| `file.println(text)` | เขียนข้อความแล้วต่อด้วยขึ้นบรรทัดใหม่ (`\r\n` = 2 ไบต์ ซึ่ง Windows/Excel ใช้) |
| `SD.remove(path)` | ลบไฟล์ |
| `SD.open("/")` + `openNextFile()` | เปิดโฟลเดอร์หลักแล้วอ่านรายชื่อไฟล์ทีละตัว |

**ทำไมต้อง "เปิด-เขียน-ปิด" ทุกครั้ง:** ข้อมูลที่ `println` อาจค้างอยู่ใน buffer ใน RAM และตารางไฟล์ (FAT) บนการ์ดจะถูกอัปเดตเมื่อปิดไฟล์
ถ้าไฟดับหรือถอดการ์ดก่อนปิดไฟล์ ข้อมูลล่าสุดอาจหายหรือไฟล์เสียหาย การปิดทุกแถวจึงปลอดภัยกว่า แลกกับเวลาที่ช้ากว่า
เมื่อจะถอดการ์ดจริง ให้สั่ง `e` (ปล่อยการ์ด) ก่อนเสมอ

### 3.5 รูปแบบข้อมูล CSV

CSV (Comma-Separated Values) = ข้อความที่คั่นแต่ละคอลัมน์ด้วยคอมมา บรรทัดแรกเป็นหัวตาราง

```
timestamp,uptime_s,source,temp_c,hum_pct,fan_duty_pct,mode
2026-10-09 20:14:19,11,REAL,27.4,93,0,AUTO
```

| คอลัมน์ | ตัวอย่าง | ความหมาย |
|---|---|---|
| `timestamp` | `2026-10-09 20:14:19` | เวลาจริง UTC+7 หรือ `NOT_SYNCED` |
| `uptime_s` | `11` | วินาทีตั้งแต่เปิดเครื่อง (`millis() / 1000`) มีเสมอ |
| `source` | `REAL` | `REAL` / `SIM-RANDOM` / `SIM-SWEEP` (ไม่ให้ค่าจำลองปนกับค่าจริง) |
| `temp_c` | `27.4` | อุณหภูมิ (ทศนิยม 1 ตำแหน่ง) |
| `hum_pct` | `93` | ความชื้น |
| `fan_duty_pct` | `0` | duty ของพัดลมจำลอง |
| `mode` | `AUTO` | AUTO / MANUAL |

**ขนาดต่อแถว (ตัวอย่างแถว `2026-10-09 20:14:19,11,REAL,27.4,93,0,AUTO`)**

| ส่วน | ไบต์ |
|---|---|
| `2026-10-09 20:14:19` | 19 |
| `,11` `,REAL` `,27.4` `,93` `,0` `,AUTO` | 3 + 5 + 5 + 3 + 2 + 5 = 23 |
| ขึ้นบรรทัดใหม่ `\r\n` | 2 |
| **รวม** | **44** (ตรวจแล้วจากขนาดไฟล์จริงบนการ์ด: หัวตาราง 60 ไบต์ + 44 ไบต์ต่อแถว) |

**ขนาดที่โตต่อวัน**: ทุก 10 วินาที = 8,640 แถวต่อวัน × 44 = **380,160 ไบต์** (≈ 371 KiB ≈ 0.38 MB) ต่อวัน ต่อปี ≈ 138.8 MB
การ์ดที่ทดสอบมีพื้นที่ 7,592 MiB ใช้ได้ราว 7,592 ÷ 0.363 ≈ 20,900 วัน (กว่า 50 ปี) ที่ช่วงบันทึก 10 วินาที

### 3.6 สถานะของ SD (state machine)

| สถานะ | ความหมาย | ไปสถานะถัดไปเมื่อ |
|---|---|---|
| `NoCard` | ไม่พบการ์ด/เมาท์ไม่สำเร็จ | ลองเมาท์ใหม่ทุก 5 วินาที สำเร็จ → `Ready` |
| `Ready` | บันทึกได้ | เขียนไม่สำเร็จ → `WriteError` / สั่ง `e` → `Ejected` |
| `WriteError` | เขียนไม่สำเร็จ (ถอดการ์ดโดยไม่สั่ง `e`, การ์ดเต็ม ฯลฯ) | ปล่อยการ์ด แล้วลองเมาท์ใหม่ทุก 5 วินาที |
| `Ejected` | ผู้ใช้สั่ง `e` (ถอดได้) | สั่ง `r` → เมาท์ใหม่ |

เมื่อไม่พร้อมบันทึก แถวที่ถึงเวลาจะถูกข้ามและนับใน `skipped` (ไม่เก็บค้างไว้เขียนทีหลัง เพื่อไม่ให้หน่วยความจำเต็มและไม่ให้เวลาในแถวผิด)

**ผลวัดจากบอร์ดจริง (การ์ดตัวเดียว)**

| เหตุการณ์ | เวลา |
|---|---|
| เมาท์การ์ดที่มีอยู่ | ≈ 7–148 ms (ครั้งแรกหลังเปิดเครื่องนานกว่า) |
| เขียน 1 แถว ที่ 4 MHz | ≈ 14.4–16.8 ms |
| **เมาท์ล้มเหลว (ไม่มีการ์ด)** | ≈ **625 ms** และ `loop()` หยุดรอตลอดช่วงนี้ |

สัดส่วนเวลาที่ `loop()` ถูกบล็อก: เขียนแถว ≈ 16 ms ทุก 10,000 ms = **0.16%** (น้อยมาก) แต่เมื่อไม่มีการ์ดลองเมาท์ทุก 5 วินาที: 625 ms ÷ (5,000 + 625) ms ≈ **11%** (นาฬิกา/จอสะดุดเป็นช่วงๆ)

### 3.7 ความปลอดภัยของข้อมูล

| หลักการ | ในโปรแกรมนี้ |
|---|---|
| ไม่ฟอร์แมตการ์ดเอง | `SD.begin()` ใช้ค่าเริ่มต้น `format_if_empty = false` |

### 3.8 ทางเลือกเมื่อยังไม่ sync เวลา (`NOT_SYNCED`)

| ทางเลือก | ข้อดี | ข้อเสีย |
|---|---|---|
| **A. บันทึกแถวพร้อม `NOT_SYNCED`** (ที่โปรแกรมเลือก) | ไม่เสียข้อมูล มี `uptime_s` กำกับ รู้ว่าแถวไหนไม่มีเวลาจริง | ข้อมูลช่วงแรกไม่มีเวลาจริง (ต้องคำนวณย้อนจาก uptime ถ้าต้องการ) |
| B. รอจน sync แล้วค่อยเริ่มบันทึก | ทุกแถวมีเวลาจริง | เสียข้อมูลช่วงแรก; ถ้าไม่มี WiFi จะไม่บันทึกเลย |

## 6. แบบฝึกหัด

ก่อนแก้ทุกข้อให้จดสภาพเดิมไว้เทียบ ทำทีละข้อ (แก้ → build/upload → ดูผล → ย้อนกลับ) **ใช้การ์ดสำหรับทดลอง**

### ระดับ 1 — พื้นฐาน (ข้อละ 5 คะแนน)

**ข้อ 1 — ช่วงบันทึกและขนาดไฟล์:** ตั้ง `LOG_INTERVAL_MS = 2000` ดูว่าบันทึกเร็วขึ้นตามที่ตั้ง จากนั้นคำนวณด้วยมือ (แถวละ 44 ไบต์): (ก) กี่แถวต่อวัน (ข) กี่ไบต์ต่อวัน (ค) ถ้าการ์ดมีพื้นที่ว่าง 7,592 MiB จะเต็มในกี่วัน/กี่ปี เทียบกับที่ 10 วินาที (หัวข้อ 3.5)

**ข้อ 2 — เพิ่มคอลัมน์ `wifi_rssi`:** เพิ่มคอลัมน์ความแรงสัญญาณ WiFi (`WiFi.RSSI()` เมื่อเชื่อมต่ออยู่ ถ้าไม่เชื่อมต่อให้เขียน `NA`) ต้องแก้ทั้งหัวตารางใน `createLogFile()` และ `snprintf` ใน `appendLogRow()` ตรวจในไฟล์ว่ามี 8 คอลัมน์ และคำนวณขนาดแถวใหม่

**ข้อ 3 — รอ sync ก่อนบันทึก:** เปลี่ยนให้ไม่บันทึกจนกว่า `timeValid()` เป็นจริง (แถวที่ถึงเวลาแต่ยังไม่ sync นับใน `logSkipped`) ตอบ: เปรียบเทียบข้อดี/ข้อเสียกับการเขียน `NOT_SYNCED` (หัวข้อ 3.8) และถ้าไม่มี WiFi เลยจะเกิดอะไร

### ระดับ 2 — ทดลองเข้าใจหลักการ (ข้อละ 7 คะแนน)

**ข้อ 4 — ลดการสะดุดเมื่อไม่มีการ์ด:** ตั้ง `SD_RETRY_MS = 30000` ถอดการ์ดออก (ตอนปิดไฟ) แล้วสังเกตว่านาฬิกาบนจอลื่นขึ้นไหม คำนวณสัดส่วนที่ถูกบล็อกใหม่ และบอกข้อเสียของการตั้งค่านี้ (เมื่อใส่การ์ดแล้วต้องรอนานแค่ไหนกว่าจะบันทึกต่อ)

**ข้อ 5 — ความเร็ว SPI:**

1. **ทำนายก่อน:** ถ้าเพิ่ม `SD_SPI_HZ` จาก 4 MHz เป็น 20 MHz (เร็วขึ้น 5 เท่า) เวลาเขียน 1 แถวจะลดลง 5 เท่าหรือไม่ เพราะอะไร (คำใบ้: หัวข้อ 3.3.1)
2. ลอง `10000000` และ `20000000` ทีละค่า จด `mount took` และ `write took` อย่างน้อย 5 แถวของแต่ละค่า (การ์ด/สายบางแบบอาจเมาท์ไม่ผ่านที่ความเร็วสูง ถ้าไม่ผ่านให้ย้อนกลับค่าเดิมและบันทึกว่าไม่ผ่าน)
3. สรุปผลและอธิบาย

**ข้อ 6 — ไฟล์ใหม่ทุกวัน:** เมื่อวันที่ท้องถิ่นเปลี่ยน (เที่ยงคืนเวลาไทย) ให้สร้างไฟล์ log ใหม่ (คำใบ้: จำเลขวันที่ของแถวล่าสุด `lastLogDay` จาก `(time + GMT_OFFSET_SEC) / 86400` ตามที่ Lab 7 ใช้แสดงวันที่ แล้วเรียก `createLogFile()` เมื่อเปลี่ยน) ตอบ: ทดสอบอย่างไรโดยไม่ต้องรอเที่ยงคืน? (คำใบ้: เปลี่ยน `GMT_OFFSET_SEC` ชั่วคราว หรือจำลองเลขวัน)

### ระดับ 3 — ออกแบบเอง (ข้อละ 10 คะแนน)

**ข้อ 7 — สถิติจากไฟล์:** เพิ่มคำสั่ง `a` ที่อ่านไฟล์ log ปัจจุบันทีละบรรทัด (ห้ามโหลดทั้งไฟล์ลง RAM) แล้วพิมพ์ค่าต่ำสุด/สูงสุด/เฉลี่ยของ `temp_c` เช่น `[STATS] 3 rows: min=29.7 max=29.8 avg=29.8 C`
ข้อกำหนด: ข้ามหัวตาราง, แยกคอลัมน์ที่ 4 (หลังคอมมาที่ 3), ไม่ใช้ `String`, จัดการไฟล์ที่ยังไม่มีแถวข้อมูล (พิมพ์ `no data rows yet`)

**ข้อ 8 (โบนัส +10) — ท้าทาย:** เลือกอย่างใดอย่างหนึ่ง
(ก) ตั้งชื่อไฟล์ตามวันที่ เช่น `log_20261009.csv` เมื่อมีเวลาจริง (ยังไม่ sync ให้ถอยกลับไปใช้ชื่อเลขลำดับ) และบันทึกต่อท้ายไฟล์วันเดิมถ้ามีอยู่แล้ว
(ข) แสดงค่าต่ำสุด/สูงสุดของอุณหภูมิวันนี้บนจอ (หาที่ว่างเอง)
ส่งโค้ดที่เพิ่มและภาพถ่ายผล
