ต่อจาก [Lab 2](../Lab2_Template_ADC_LDR/README.md) (ค่าแสง LDR) และ [Lab 3](../Lab3_WiFiConnecting/README.md) (WiFi)
โดยเปลี่ยนจากการอ่านตัวเลขใน Serial Monitor มาเป็น **หน้าจอสี TFT ขนาด 320×240** ของบอร์ดเอง

**หน้า 1 — Calibrate (6 วินาทีแรกหลังเปิดเครื่อง)** ให้ครอบเซนเซอร์แล้วเปิดมือ เหมือน Lab 2 แต่ตอนนี้มีหน้าจอบอก

```
┌──────────────────────────────────────┐

│       COVER the light sensor         │
│    with your hand for a moment,      │
│         then UNCOVER it.             │
│                                      │
│  [██████████░░░░░░░░░░░░░░░░░░░░]    │  ← แถบความคืบหน้า
│    raw  132    min  131    max  250  │  ← ค่าสด

```

**หน้า 2 — หน้าหลัก**

```
┌──────────────────────────────────────┐
│ Lab 4 - TFT Display                  │  ← แถบหัว
├──────────────────────────────────────┤
│ LIGHT                      raw 132   │
│ 97%               BRIGHT             │  ← ตัวเลขใหญ่ + ระดับ (สีตามระดับ)
│ [██████████████████████████████░]    │  ← แถบความสว่าง
├──────────────────────────────────────┤
│ WIFI                          ▂▄▆█   │  ← ไอคอนสัญญาณ 4 แท่ง
│ ● CONNECTED                          │  ← จุดสี + สถานะ
│ SSID: <ชื่อ WiFi ของคุณ>              │
│ IP: 192.168.x.x   -48 dBm            │
├──────────────────────────────────────┤
│ uptime 00:03:12                    ● │  ← เวลาเปิดเครื่อง + จุดกะพริบ
└──────────────────────────────────────┘
```

(ภาพข้างบนวาดแทนคร่าวๆ ให้เห็นตำแหน่ง ของจริงเป็นสีและขนาดตามโค้ด)

| ส่วนบนจอ | แสดงอะไร |
|---|---|
| ตัวเลข % และคำ `DARK` / `NORMAL` / `BRIGHT` | ความสว่าง: ต่ำกว่า 35% = DARK (น้ำเงิน), สูงกว่า 65% = BRIGHT (เหลือง), ระหว่างนั้น = NORMAL (ส้ม) |
| แถบกราฟ | เติมตามเปอร์เซ็นต์ความสว่าง สีเปลี่ยนตามระดับ |
| `raw 132` | ค่าดิบจาก ADC (ตัวเล็ก ไว้ดูประกอบ) |
| จุดสี + ข้อความ WiFi | แดง = `NOT CONFIGURED` / `FAILED`, น้ำเงิน = `CONNECTING...`, เขียว = `CONNECTED` |
| ไอคอนแท่ง | ความแรงสัญญาณ (ดู RSSI): ≥ −55 = 4 แท่ง, ≥ −65 = 3, ≥ −75 = 2, ≥ −85 = 1, ต่ำกว่านั้น 0 |
| uptime และจุดกะพริบมุมล่างขวา | เวลาที่เปิดเครื่อง และถ้าจุดกะพริบอยู่ แปลว่าโปรแกรมยังทำงานปกติ |

RGB LED ยังบอกสถานะ WiFi ด้วย: **เขียว = ต่อแล้ว, น้ำเงิน = กำลังต่อ, แดง = มีปัญหา/ยังไม่ตั้งค่า** (ติดค้าง ไม่กะพริบ)
ช่วง calibrate LED เป็นสีขาวกะพริบ

## ความรู้ใหม่ใน Lab นี้

### พิกัดบนจอ

จอมี 320 × 240 **พิกเซล** (จุดภาพ) ใช้ระบบพิกัด x,y โดย **(0, 0) = มุมซ้ายบน** x เพิ่มไปทางขวา y เพิ่มลงล่าง
(ต่างจากกราฟคณิตศาสตร์ที่ y ขึ้นบน) ตำแหน่งทุกอย่างในโค้ดใช้พิกเซลนี้ และใช้ `tft.setRotation(1)` ให้จอเป็นแนวนอน

### สี RGB565

จอใช้สี 16 บิตต่อพิกเซล (แดง 5 บิต, เขียว 6 บิต, น้ำเงิน 5 บิต) ฟังก์ชัน `rgb565(r, g, b)` ในโค้ดแปลงสีแบบปกติ (0–255) เป็นค่าที่จอเข้าใจ
เช่น `rgb565(240, 85, 85)` = สีแดง ค่านิยมเหล่านี้ตั้งชื่อไว้ที่ต้นไฟล์ (`COLOR_BG`, `COLOR_GREEN` ฯลฯ) แก้ที่เดียวเปลี่ยนทั้งจอ

### ไลบรารี TFT_eSPI และคำสั่งวาดที่ใช้

| คำสั่ง | ทำอะไร |
|---|---|
| `tft.init()`, `tft.setRotation(1)` | เริ่มจอ และตั้งแนวนอน |
| `cyd::enableBacklight()` | เปิดไฟหลังจอ (ไฟหลังจอต้องติดจึงจะเห็นภาพ; ไลบรารี TFT_eSPI ก็เปิดให้เองตอน `tft.init()` เพราะกำหนด `TFT_BL` ไว้ ในโค้ดนี้สั่งซ้ำให้ชัดเจน) |
| `tft.fillScreen(color)` | ระบายสีทั้งจอ |
| `tft.fillRect(x, y, w, h, color)` | สี่เหลี่ยมทึบ (ใช้ทำแถบหัว แถบกราฟ แท่งสัญญาณ) |
| `tft.drawRect(...)` | กรอบสี่เหลี่ยม |
| `tft.fillRoundRect` / `drawRoundRect` | สี่เหลี่ยมมุมมน (การ์ด) |
| `tft.fillCircle(x, y, r, color)` | วงกลมทึบ (จุดสถานะ, heartbeat) |
| `tft.drawString(text, x, y, font)` | วาดข้อความ ฟอนต์ที่เปิดไว้ใน `platformio.ini`: 2 (16 พิกเซลสูง), 4 (26 พิกเซลสูง) |
| `tft.setTextColor(fg, bg)` | สีตัวอักษรและสีพื้นหลังของตัวอักษร |
| `tft.setTextSize(2)` | ขยายตัวอักษรเป็น 2 เท่า (ใช้ทำเลข % ตัวใหญ่) |
| `tft.setTextDatum(TL_DATUM)` | บอกว่า (x, y) ที่ให้คือมุมไหนของข้อความ: `TL` = ซ้ายบน, `TC` = กลางบน |
| `tft.setTextPadding(w)` | บอกความกว้างที่ต้องลบข้อความเก่าทิ้งก่อนวาดใหม่ (กันตัวเลขเก่าค้างบนจอ) |

### หลักสำคัญ: วาดส่วนที่ไม่เปลี่ยนครั้งเดียว อัปเดตเฉพาะส่วนที่เปลี่ยน

ถ้าล้างจอทั้งหน้า (`fillScreen`) แล้ววาดใหม่ทุกครั้งที่ค่าเปลี่ยน จอจะ **กะพริบ** โปรแกรมนี้จึงแยกเป็น 2 ส่วน

| ส่วน | ฟังก์ชัน | วาดเมื่อไร |
|---|---|---|
| ส่วนที่ไม่เปลี่ยน (พื้นหลัง การ์ด ป้ายชื่อ กรอบแถบ) | `drawMainScreenStatic()` | ครั้งเดียว ตอนเข้าหน้าหลัก |
| ค่าแสง (เลข %, ระดับ, แถบ, raw) | `updateLightCard()` | ทุก 100 ms **เฉพาะเมื่อ % เปลี่ยน** |
| WiFi, IP, สัญญาณ, uptime | `updateStatusCards()` | ทุก 1 วินาที หรือเมื่อสถานะ WiFi เปลี่ยน |
| จุดกะพริบ | `updateHeartbeat()` | ทุก 500 ms |

### การแยกหน้าจอด้วย state

ตัวแปร `phase` (`Calibrating` / `Running`) บอกว่ากำลังอยู่หน้าไหน `loop()` ทำงานต่างกันตามหน้านั้น เหมือน Lab 2
เมื่อ calibrate เสร็จ เรียก `drawMainScreenStatic()` เพื่อเปลี่ยนไปหน้าหลัก

```powershell

```

(เปลี่ยน `COM3` ตามเครื่องคุณ ปิด Serial Monitor ก่อน upload ทุกครั้ง)

- **build ครั้งแรกนานกว่า Lab ก่อนๆ** เพราะต้องดาวน์โหลดและคอมไพล์ไลบรารี `TFT_eSPI`
- ตอน build จะเห็นคำเตือน `TOUCH_CS pin not defined, TFT_eSPI touch functions will not be available!` เป็นเรื่องปกติและไม่มีผลเสีย
  (เราใช้จอสัมผัสใน Lab ถัดไปด้วยไลบรารีอื่น)

ทดลองดู

1. **6 วินาทีแรก** เห็นหน้า Calibrate ให้ครอบเซนเซอร์ LDR (ตัวเล็กใกล้ขอบจอ ป้าย R21) แล้วเปิดมือ ดูแถบและค่า min/max ขยับ
2. หลังจากนั้นเข้าหน้าหลัก ครอบมืออีกครั้ง เห็น % ลด แถบหดสั้นลง คำเปลี่ยนเป็น `DARK` และสีแถบเปลี่ยนเป็นน้ำเงิน เปิดมือ/ส่องไฟฉายเห็นกลับเป็น `BRIGHT` สีเหลือง
3. ดูส่วน WiFi: ถ้าตั้ง `secrets.h` แล้วควรเห็นจุดสีน้ำเงินช่วงสั้นๆ แล้วเป็นเขียว `CONNECTED` พร้อม IP และไอคอนสัญญาณ

## ตัวอย่างข้อความ Serial

ผลจริงจากบอร์ดต้นแบบตอนเชื่อม WiFi สำเร็จ (บรรทัดสรุปทุก 1 วินาที)

```
[LDR] raw= 132 smooth= 132.1 light= 97%   [WIFI] CONNECTED
[LDR] raw= 132 smooth= 131.9 light= 97%   [WIFI] CONNECTED
```

ข้อความช่วงเปิดเครื่อง (รูปแบบตามโค้ด ตัวเลขของคุณจะต่างไป)

```
[CAL] cover the LDR for a moment within 6 s, then uncover it.
[CAL] raw min (brightest) = 131, raw max (darkest) = 250, range = 119
[CAL] OK: using the range measured in this room.
[WIFI] connecting to "ชื่อ WiFi ของคุณ" ...
[WIFI] NOT CONFIGURED -> CONNECTING...
[WIFI] connected, IP 192.168.x.x, RSSI -48 dBm
[WIFI] CONNECTING... -> CONNECTED
```

ถ้า calibrate ไม่สำเร็จ (ไม่ได้ครอบเซนเซอร์) จะขึ้น `range too small: using defaults ...` และบรรทัดสรุปท้ายจะมี `(default range)`
ค่าสำรอง (`DEFAULT_RAW_BRIGHT`/`DEFAULT_RAW_DARK`) เป็นค่าประมาณเท่านั้น ห้องที่สว่างต่างกันอาจได้เปอร์เซ็นต์ไม่ตรงความรู้สึก
ให้ calibrate ใหม่ (กด EN/RESET) เพื่อผลที่แม่นกว่า

## สังเกตจากการทดสอบจริง

- ภาพถ่ายจากบอร์ดต้นแบบแสดงหน้าหลักครบทุกส่วนตามที่ออกแบบ (ค่าแสง 83% และ 97% ระดับ `BRIGHT` แถบสีเหลือง, สถานะ `CONNECTED`,
  ชื่อ WiFi, IP, RSSI พร้อมไอคอนสัญญาณ 4 แท่ง, uptime และจุดกะพริบ) ใช้ได้ทั้งแนวนอนและเมื่อหมุนบอร์ดตั้ง (หมุนบอร์ดไม่ได้เปลี่ยนโค้ด ภาพจึงหมุนตามตัวบอร์ด)
- **ค่า `raw` ของแต่ละครั้งที่เปิดเครื่องไม่เท่ากัน** (เช่นภาพหนึ่ง 157 อีกภาพ 280 แต่ทั้งคู่เป็น `BRIGHT`) เพราะทุกครั้งที่บูตโปรแกรมจะ calibrate ใหม่
  เปอร์เซ็นต์จึงเป็น "ความสว่างเทียบกับช่วงมืด–สว่างของรอบนั้น" ไม่ใช่ค่าสัมบูรณ์ ให้ดู **% เป็นหลัก** และอย่าเอา raw ข้ามรอบมาเทียบกัน
- สีพื้นหลังของจอในรูปถ่ายอาจดูเป็นไล่โทนสีน้ำเงินสว่างกว่าสีที่ตั้งไว้ (เกือบดำ) เพราะจอ TN มุมมองแคบ สีเข้มจะดูจางลงเมื่อถ่ายหรือมองเฉียง
  ถ้ามองตรงๆ แล้วพื้นหลังดำกว่าในรูป ถือว่าปกติ

## ค่าที่ปรับได้ใน `app_config.h`

| ค่า | ค่าเริ่มต้น | ผลเมื่อปรับ |
|---|---|---|
| `LIGHT_REFRESH_MS` | 100 | ความถี่อัปเดตส่วนค่าแสงบนจอ |
| `STATUS_REFRESH_MS` | 1000 | ความถี่อัปเดตส่วน WiFi / uptime |
| `HEARTBEAT_MS` | 500 | จังหวะกะพริบของจุดมุมล่างขวา |
| `LIGHT_DARK_BELOW` / `LIGHT_BRIGHT_ABOVE` | 35 / 65 | เกณฑ์ตัดสิน DARK / BRIGHT (%) |
| `CALIBRATION_MS` | 6000 | เวลา calibrate |
| `SMOOTH_ALPHA` | 0.25 | ความไวของตัวกรองค่าแสง |
| `CONNECT_TIMEOUT_MS` / `RETRY_DELAY_MS` | 15000 / 5000 | เวลารอต่อ WiFi / รอก่อนลองใหม่ |

สีและตำแหน่งแก้ได้ที่ต้นไฟล์ `src/main.cpp` (ชุดค่า `COLOR_...` และ `..._X`, `..._Y`, `..._W`, `..._H`)

## แบบฝึกหัด

1. **เปลี่ยนสี:** แก้ `COLOR_HEADER` และ `COLOR_CARD` ให้เป็นโทนสีที่ชอบ แล้ว upload ดู
2. **ใส่ชื่อตัวเอง:** เพิ่มชื่อของคุณที่แถบหัว (แก้ข้อความใน `drawHeader("Lab 4 - TFT Display")`)
3. **เปลี่ยนเกณฑ์:** ตั้ง `LIGHT_DARK_BELOW = 20` และ `LIGHT_BRIGHT_ABOVE = 80` ดูว่าคำ `NORMAL` ปรากฏบ่อยขึ้นหรือน้อยลง
4. **ทดลอง "ผี" ตัวเลข:** ลองลบ `tft.setTextPadding(paddingW)` ใน `drawText()` (ให้ padding เป็น 0 เสมอ) แล้วดูตอนเปอร์เซ็นต์ลดจาก 100% เหลือ 9% ว่ามีอะไรผิดปกติ เพราะอะไร
5. **ทดลองวาดซ้ำทั้งหน้า:** เพิ่ม `drawMainScreenStatic();` เป็นบรรทัดแรกใน `updateLightCard()` แล้วสังเกตอาการจอกะพริบ เปรียบเทียบกับของเดิม แล้วลบออก (ลองคิดด้วยว่าถ้าใส่แค่ `tft.fillScreen(COLOR_BG)` จะเกิดอะไรกับการ์ดและ header เพราะอะไร)
6. **ย้ายตำแหน่ง:** ย้ายแถบกราฟขึ้นไปไว้เหนือเลข % (ต้องคำนวณพิกัดใหม่ให้ไม่ทับกัน)
7. **ท้าทาย:** วาดกราฟย้อนหลังของค่าแสงล่าสุด 60 ค่าไว้บนจอ (คำใบ้: เก็บค่าในอาร์เรย์แบบวนรอบ แล้วใช้ `tft.drawLine` ต่อจุด และต้องมีพื้นที่ว่างบนจอเพิ่ม เช่นลดขนาดการ์ด WIFI)

| จอขาว/เป็นเส้นสุ่ม | ตั้งค่าไดรเวอร์หรือ pin จอผิด อย่าแก้ `build_flags` ใน `platformio.ini` |
| สีเพี้ยน (แดงกลายเป็นน้ำเงิน) | ค่าสีไม่ใช่ RGB565 ให้ใช้ฟังก์ชัน `rgb565()` ที่มีให้ |
| ตัวเลขเก่าค้างทับกับตัวเลขใหม่ | ลืม `setTextPadding` หรือกว้างไม่พอ (หัวข้อแบบฝึกหัด 4) |
| จอกะพริบมาก | ล้างจอทั้งหน้าบ่อยเกินไป ให้อัปเดตเฉพาะส่วนที่เปลี่ยน |
| ข้อความล้นการ์ด/ทับกัน | ข้อความยาวเกิน หรือตำแหน่งชิดกัน เว้นระยะอย่างน้อย 8 พิกเซลและตัดข้อความ (เช่น `%.24s`) |
| WiFi ไม่ต่อ | ดู Lab 3 (2.4 GHz, ชื่อ/รหัสต้องตรง, upload ใหม่ทุกครั้งที่แก้ `secrets.h`) |
| upload ไม่ผ่าน `Access is denied` | ปิด Serial Monitor ก่อน upload |
| build ช้า/ดาวน์โหลดไลบรารีไม่ได้ | ครั้งแรกต้องใช้อินเทอร์เน็ต ลอง build ซ้ำ |
