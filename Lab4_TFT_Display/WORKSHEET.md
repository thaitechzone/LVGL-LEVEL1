## 1. เป้าหมายการเรียนรู้

เมื่อจบใบงานนี้ ผู้เรียนต้องทำได้ทุกข้อ

1. อธิบายระบบพิกัดของจอ (มุม (0,0), แกน x/y, หน่วยพิกเซล) และอ่านตำแหน่งในโค้ดแล้วบอกได้ว่าอะไรอยู่ตรงไหนบนจอ
2. อธิบายสี RGB565 และแปลงสี `rgb565(r, g, b)` เป็นเลขฐานสิบหกด้วยมือได้
3. ใช้คำสั่งวาดพื้นฐานของ TFT_eSPI ได้: สี่เหลี่ยม วงกลม ข้อความ (ฟอนต์ ตำแหน่งอ้างอิง สี ความกว้างลบทับ)
4. อธิบายได้ว่าทำไมจึง "วาดส่วนที่ไม่เปลี่ยนครั้งเดียว แล้วอัปเดตเฉพาะส่วนที่เปลี่ยน" และเห็นผลเสียของการวาดทั้งจอซ้ำๆ
5. อ่านโค้ดที่แยกหน้าจอเป็นหลายหน้า (calibrate / หน้าหลัก) ด้วยตัวแปรสถานะ และตัวจับเวลา `millis()` หลายตัวที่ทำงานพร้อมกันได้
6. ดัดแปลงโปรแกรมตามแบบฝึกหัด (สี ข้อความ เกณฑ์ ตำแหน่ง กราฟย้อนหลัง) ได้ด้วยตัวเอง

```
┌──────────────────────────────────────┐

│ ┌──────────────────────────────────┐ │
│ │ LIGHT                    raw 132 │ │  ← การ์ดค่าแสง
│ │ 97%                  BRIGHT      │ │
│ │ [██████████████████████████████] │ │  ← แถบ (เติมตาม %)
│ └──────────────────────────────────┘ │
│ ┌──────────────────────────────────┐ │
│ │ WIFI                      ▂▄▆█   │ │  ← การ์ด WiFi + ไอคอนสัญญาณ
│ │ ● CONNECTED                      │ │
│ │ SSID: MyHomeWiFi                 │ │
│ │ IP: 192.168.1.45   -48 dBm       │ │
│ └──────────────────────────────────┘ │
│ uptime 00:03:27                    ● │  ← เวลาเปิดเครื่อง + จุดกะพริบ
└──────────────────────────────────────┘
```

| ส่วนบนจอ | แสดงอะไร |
|---|---|
| เลข % ตัวใหญ่ + คำ `DARK` / `NORMAL` / `BRIGHT` | ความสว่าง: < 35% = DARK (น้ำเงิน), > 65% = BRIGHT (เหลือง), นอกนั้น NORMAL (ส้ม) |
| แถบกราฟ | เติมตามเปอร์เซ็นต์ สีเปลี่ยนตามระดับ |
| `raw N` | ค่าดิบจาก ADC ไว้ดูประกอบ |
| จุดสี + ข้อความ WiFi | แดง = `NOT CONFIGURED` / `FAILED - will retry`, น้ำเงิน = `CONNECTING...`, เขียว = `CONNECTED` |
| ไอคอนแท่ง 4 แท่ง | ความแรงสัญญาณ (จาก RSSI) |
| `uptime` + จุดกะพริบ | เวลาตั้งแต่เปิดเครื่อง / ถ้าจุดกะพริบ แปลว่า `loop()` ยังทำงาน |

RGB LED ยังบอกสถานะ WiFi อยู่ (เขียว = ต่อแล้ว, น้ำเงิน = กำลังต่อ, แดง = มีปัญหาหรือยังไม่ตั้งค่า, ติดค้างไม่กะพริบ) ช่วง calibrate เป็นสีขาวกะพริบ

## 3. ความรู้พื้นฐานที่ต้องเข้าใจก่อนลงมือ

### 3.1 จอ TFT และพิกเซล

จอของบอร์ดคือ **ILI9341** ขนาด **320 × 240 พิกเซล** (กว้าง × สูง เมื่อวางแนวนอน) พิกเซลคือจุดภาพเล็กๆ ที่เปลี่ยนสีได้ทีละจุด
จอมี 320 × 240 = **76,800 พิกเซล** แต่ละพิกเซลเก็บสี 16 บิต (2 ไบต์) ดังนั้นภาพเต็มจอมีขนาด 76,800 × 2 = **153,600 ไบต์**

บอร์ดคุยกับจอผ่านสาย **SPI** (ส่งข้อมูลทีละบิตแบบซิงโครไนซ์ด้วยสัญญาณนาฬิกา) ในโปรเจกต์นี้ตั้งความเร็วไว้ **40 MHz** (`SPI_FREQUENCY=40000000`)
ขั้นต่ำเชิงทฤษฎีในการส่งภาพเต็มจอหนึ่งภาพคือ 153,600 × 8 ÷ 40,000,000 ≈ **0.031 วินาที (31 มิลลิวินาที)** ยังไม่รวมเวลาเตรียมคำสั่งอื่นๆ
(ตัวเลขนี้คำนวณเอง ไม่ได้วัดจากบอร์ด) จึงเห็นว่า **ยิ่งวาดพื้นที่มาก ยิ่งใช้เวลามาก** — เป็นเหตุผลของหลักการในหัวข้อ 3.6

| สายที่ใช้กับจอ (กำหนดใน `platformio.ini` และ `board_config.h`) | GPIO |
|---|---|
| MOSI (ส่งข้อมูลไปจอ) | 13 |
| SCLK (สัญญาณนาฬิกา) | 14 |
| CS (เลือกจอ) | 15 |
| DC (แยก "คำสั่ง" / "ข้อมูล") | 2 |
| MISO | 12 |
| Backlight (ไฟหลังจอ) | 21 |

> **ข้อควรจำ:** GPIO21 คือไฟหลังจอ **ห้ามนำไปต่อเซนเซอร์อื่น** ไม่เช่นนั้นไฟหลังจอจะกะพริบ (ดูเอกสารบอร์ด)
> ไฟหลังจอต้องติดจึงจะเห็นภาพ ใน `setup()` มี `cyd::enableBacklight()` สั่งเปิดไว้ให้ชัดเจน (ในโปรเจกต์นี้ไลบรารี TFT_eSPI ก็เปิดให้เองตอน `tft.init()`
> เพราะเรากำหนด `TFT_BL` กับ `TFT_BACKLIGHT_ON` ไว้ใน `platformio.ini` จึงเป็นการเปิดซ้ำที่ไม่เสียหาย)

### 3.2 ระบบพิกัด

```
(0,0) ─────────────────► x   (เพิ่มไปทางขวา สูงสุด 319)
  │
  │
  ▼
  y   (เพิ่มลงล่าง สูงสุด 239)
```

- **(0, 0) คือมุมซ้ายบน** ต่างจากกราฟในวิชาคณิตศาสตร์ที่ y เพิ่มขึ้นด้านบน
- หน่วยเป็นพิกเซล วัตถุหนึ่งชิ้นระบุด้วย "มุมซ้ายบน" + "กว้าง × สูง"
- `tft.setRotation(1)` ทำให้จอเป็นแนวนอน กว้าง 320 สูง 240 (ค่า 0 = แนวตั้งปกติ ค่าอื่นหมุนต่อไปอีก)

ตัวอย่าง `tft.fillRect(8, 34, 304, 92, color)` = สี่เหลี่ยมทึบ มุมซ้ายบนอยู่ที่ x=8, y=34 กว้าง 304 สูง 92 จึงครอบคลุม x = 8…311 และ y = 34…125
(ชิดขอบซ้ายห่าง 8 พิกเซล และชิดขอบขวาห่าง 320 − 312 = 8 พิกเซล เท่ากันสองข้าง)

### 3.3 สีแบบ RGB565

สีปกติบนคอมพิวเตอร์ใช้ 8 บิตต่อสี (0–255) รวม 24 บิต แต่จอนี้ใช้ **16 บิต** ต่อพิกเซลเพื่อประหยัดหน่วยความจำและเวลาส่ง

| ช่องสี | จำนวนบิต | ตำแหน่งบิต | ระดับสีที่ละเอียดได้ |
|---|---|---|---|
| แดง (R) | 5 | บิต 15–11 | 32 ระดับ |
| เขียว (G) | 6 | บิต 10–5 | 64 ระดับ (ตาเรามองเห็นเขียวไวที่สุด จึงให้มากสุด) |
| น้ำเงิน (B) | 5 | บิต 4–0 | 32 ระดับ |

ฟังก์ชันในโค้ด

```cpp
constexpr uint16_t rgb565(uint8_t r, uint8_t g, uint8_t b)
{
    return static_cast<uint16_t>(((r & 0xF8) << 8) | ((g & 0xFC) << 3) | (b >> 3));
}
```

อ่านทีละส่วน (`& 0xF8` คือ "เก็บเฉพาะ 5 บิตบน" ของ 8 บิต, `<< 8` คือเลื่อนไปอยู่ตำแหน่งบิต 15–11)

**ตัวอย่างคำนวณ `rgb565(240, 85, 85)` (สีแดงที่ใช้บอกข้อผิดพลาด)**

| ขั้น | ค่า |
|---|---|
| R: 240 = 0xF0, `& 0xF8` = 0xF0, `<< 8` | **0xF000** |
| G: 85 = 0x55, `& 0xFC` = 0x54, `<< 3` | **0x02A0** |
| B: 85 = 0x55, `>> 3` = 0x0A | **0x000A** |
| รวมด้วย OR | 0xF000 \| 0x02A0 \| 0x000A = **0xF2AA** |

ค่าที่ควรจำ: ขาว `rgb565(255,255,255)` = **0xFFFF**, เขียวสด `rgb565(0,255,0)` = **0x07E0**, ดำ = 0x0000

> สังเกต: เพราะตัดบิตล่างทิ้ง สี 85 กับ 87 (R หรือ B) จะกลายเป็นสีเดียวกันบนจอ ไม่ใช่ข้อผิดพลาด เป็นข้อจำกัดของ 16 บิต
> และถ้าใส่เลขสีดิบ 24 บิตตรงๆ จะได้สีเพี้ยน จึงต้องผ่าน `rgb565()` เสมอ

### 3.4 คำสั่งวาดของ TFT_eSPI ที่ใช้ใน Lab นี้

| คำสั่ง | ทำอะไร | ใช้ที่ไหนในโปรแกรม |
|---|---|---|
| `tft.init()` | เริ่มจอ | `setup()` |
| `tft.setRotation(1)` | แนวนอน 320×240 | `setup()` |
| `tft.fillScreen(c)` | ระบายสีทั้งจอ | เริ่มหน้าจอใหม่ |
| `tft.fillRect(x,y,w,h,c)` | สี่เหลี่ยมทึบ | header, แถบกราฟ, แท่งสัญญาณ |
| `tft.drawRect(x,y,w,h,c)` | กรอบสี่เหลี่ยม | กรอบแถบกราฟ, กรอบแถบ calibrate |
| `tft.fillRoundRect(x,y,w,h,r,c)` / `drawRoundRect` | สี่เหลี่ยมมุมมน (รัศมี r) | การ์ด |
| `tft.fillCircle(x,y,r,c)` | วงกลมทึบ (x,y = จุดศูนย์กลาง) | จุดสถานะ WiFi, heartbeat |
| `tft.drawString(text,x,y,font)` | วาดข้อความ | ทุกข้อความ |
| `tft.setTextColor(fg,bg)` | สีตัวอักษร / สีพื้นหลังของตัวอักษร | `drawText()` |
| `tft.setTextSize(2)` | ขยายตัวอักษร 2 เท่า | เลข % ตัวใหญ่ |
| `tft.setTextDatum(...)` | จุดอ้างอิงของข้อความ | `TL_DATUM` = มุมซ้ายบน, `TC_DATUM` = กึ่งกลางด้านบน |
| `tft.setTextPadding(w)` | ความกว้างที่ต้องลบทับ | กันตัวเลขเก่าค้าง |

**ฟอนต์:** เลือกด้วยเลขท้ายใน `drawString` ฟอนต์ที่เปิดไว้ใน `platformio.ini` คือ `LOAD_GLCD` (ฟอนต์ 1), `LOAD_FONT2` (สูง 16 พิกเซล), `LOAD_FONT4` (สูง 26 พิกเซล)
ถ้าใช้เลขฟอนต์ที่ไม่ได้เปิด ข้อความจะไม่ขึ้นหรือเพี้ยน ไม่ได้ใช้ฟอนต์ภาษาไทย (ข้อความบนจอจึงเป็นภาษาอังกฤษทั้งหมด)

**สีพื้นหลังของตัวอักษร (`setTextColor(fg, bg)`):** เมื่อ fg ≠ bg ไลบรารีจะระบายพื้นหลังรอบตัวอักษรด้วยสี bg ให้ด้วย (ทับของเก่า)

**ความกว้างลบทับ (`setTextPadding`):** ถ้าข้อความใหม่ **สั้นกว่า** ข้อความเก่า ส่วนท้ายของข้อความเก่าจะค้างอยู่
`setTextPadding(w)` สั่งให้ลบ (ระบายสีพื้นหลัง) ไปจนครบความกว้าง w พิกเซลนับจากจุดเริ่มข้อความ ต้องตั้ง **ไม่น้อยกว่าความกว้างของข้อความที่ยาวที่สุดที่เป็นไปได้**

ตัวอย่างการเลือกค่า padding ของเลข % (ฟอนต์ 4 ขยาย 2 เท่า): จากตารางความกว้างตัวอักษรของไลบรารี ตัวเลขแต่ละตัวกว้าง 14 พิกเซล เครื่องหมาย % กว้าง 21 พิกเซล
ข้อความ `100%` กว้างที่สุด = (14 + 14 + 14 + 21) × 2 = **126 พิกเซล** โปรแกรมตั้ง padding **130** ซึ่งพอดี (เหลือ 4 พิกเซล)
และเลข % เริ่มที่ x=16 จบที่ x=146 ไม่ชนคำ `BRIGHT` ที่เริ่ม x=178

### 3.5 ฟังก์ชัน `drawText()` ที่เราเขียนเอง

```cpp
void drawText(const char *text, int16_t x, int16_t y, uint8_t font, uint16_t fg, uint16_t bg, uint16_t paddingW = 0)
{
    tft.setTextColor(fg, bg);
    tft.setTextPadding(paddingW);
    tft.drawString(text, x, y, font);
    tft.setTextPadding(0);       // ล้างค่า เพื่อไม่ให้กระทบข้อความอื่นที่วาดทีหลัง
}
```

รวม 4 อย่าง (ตั้งสี, ตั้งความกว้างลบทับ, วาด, คืนค่า) ไว้ที่เดียว ทำให้โค้ดที่เรียกใช้สั้นลงและไม่ลืมคืนค่า padding

### 3.6 หลักสำคัญ: วาดส่วนที่ไม่เปลี่ยนครั้งเดียว อัปเดตเฉพาะส่วนที่เปลี่ยน

วิธีที่ง่ายที่สุดในการอัปเดตจอคือ "ล้างจอแล้ววาดทุกอย่างใหม่" แต่จะมีปัญหา

1. ใช้เวลามาก (หัวข้อ 3.1 แค่ส่งภาพเต็มจอก็ ≥ 31 ms) CPU จึงเหลือเวลาทำอย่างอื่นน้อยลง
2. จอ **กะพริบ** เพราะมีช่วงสั้นๆ ที่ส่วนหนึ่งเป็นสีพื้นหลังก่อนจะถูกวาดทับ ตาเรามองเห็นเป็นการสั่นไหว

โปรแกรมนี้จึงแบ่งงานเป็น 2 กลุ่ม

| กลุ่ม | ฟังก์ชัน | วาดเมื่อไร |
|---|---|---|
| **ส่วนที่ไม่เปลี่ยน** (พื้นหลัง การ์ด ป้ายชื่อ กรอบแถบ) | `drawMainScreenStatic()` | **ครั้งเดียว** ตอนเข้าหน้าหลัก |
| **ส่วนที่เปลี่ยน** — ค่าแสง | `updateLightCard()` | ทุก 100 ms แต่ **วาดจริงเฉพาะเมื่อ % เปลี่ยน** |
| **ส่วนที่เปลี่ยน** — WiFi / IP / สัญญาณ / uptime | `updateStatusCards()` | ทุก 1 วินาที หรือเมื่อสถานะ WiFi เปลี่ยน |
| **ส่วนที่เปลี่ยน** — จุดกะพริบ | `updateHeartbeat()` | ทุก 500 ms |

ขณะอัปเดตส่วนที่เปลี่ยน ใช้ `setTextColor(fg, bg)` + `setTextPadding` ทับของเก่าเฉพาะที่ ไม่ต้องแตะส่วนอื่น

### 3.7 การแยกหน้าจอด้วยตัวแปรสถานะ

```cpp
enum class Phase { Calibrating, Running };
```

`loop()` ตรวจ `phase` แล้วทำงานคนละแบบ: ถ้า `Calibrating` ก็อัปเดตเฉพาะหน้า calibrate แล้ว `return;` ถ้า `Running` ก็ทำงานของหน้าหลัก
เมื่อ calibrate ครบ 6 วินาที `finishCalibration()` เปลี่ยนเป็น `Running` และเรียก `drawMainScreenStatic()` เพื่อวาดโครงหน้าหลักหนึ่งครั้ง

### 3.9 ค่าแสงจาก LDR (ทบทวน Lab 2 แบบสั้น)

- บอร์ดนี้ raw **สูง = มืด**, raw **ต่ำ = สว่าง** (กลับกับที่คนมักคิด)
- ช่วง 6 วินาทีแรก โปรแกรมจดค่า raw ต่ำสุด (`calMin` = สว่างสุด) และสูงสุด (`calMax` = มืดสุด) ที่เห็น
- ถ้าช่วงห่างกัน ≥ 8 (`MIN_CALIBRATION_RANGE`) ใช้ค่าที่วัดได้ มิฉะนั้นใช้ค่าสำรอง (สว่าง = 0, มืด = 120) และบรรทัด Serial จะมี `(default range)`
- แปลงเป็น % ด้วย `map(raw, rawDark, rawBright, 0, 100)` แล้ว `constrain` ให้อยู่ใน 0–100

**ตัวอย่างคำนวณ** สมมติ calibrate ได้ min = 131 (สว่างสุด), max = 250 (มืดสุด) แล้วอ่าน raw เฉลี่ย 190

`map` ของ Arduino ใช้เลขจำนวนเต็ม: `(190 − 250) × (100 − 0) ÷ (131 − 250) + 0 = (−60 × 100) ÷ (−119) = 50.42` → ตัดทศนิยมเป็น **50%**

ถ้า raw = 132 จะได้ (−118 × 100) ÷ (−119) = 99.16 → **99%**

**ผลสำคัญ:** เปอร์เซ็นต์คือ "ความสว่างเทียบกับช่วงของรอบ calibrate นั้น" ไม่ใช่ค่าสัมบูรณ์ ทุกครั้งที่ reset จะ calibrate ใหม่
ค่า raw ที่ได้จึงต่างกันในแต่ละรอบ (เช่นรอบหนึ่งสว่างสุดเป็น 157 อีกรอบเป็น 280 แต่ทั้งคู่แสดงเป็น BRIGHT) ห้ามเอา raw ข้ามรอบมาเทียบกัน

ค่าที่ใช้กรองสัญญาณ: อ่านซ้ำ 8 ครั้งต่อตัวอย่างแล้วเฉลี่ย (oversampling) และใช้ตัวกรอง EMA `smooth += (raw − smooth) × 0.25`
หลังแสงเปลี่ยนแบบกระทันหัน ค่ากรองจะเข้าใกล้ค่าใหม่ 90% ภายใน 9 ตัวอย่างโดยประมาณ (ที่ 50 ms ต่อตัวอย่าง ≈ 0.4–0.5 วินาที) เพราะ 0.75⁸ ≈ 0.100 และ 0.75⁹ ≈ 0.075
จึงเห็นเปอร์เซ็นต์ค่อยๆ ไหลไป ไม่กระโดดทันที

### 3.10 ความแรงสัญญาณ WiFi เป็นแท่ง

อ่านค่า RSSI (dBm ติดลบ ยิ่งใกล้ 0 ยิ่งแรง) แล้วแปลงเป็น 0–4 แท่งด้วย `rssiToBars()`

| RSSI | จำนวนแท่ง |
|---|---|
| ≥ −55 dBm | 4 |
| ≥ −65 | 3 |
| ≥ −75 | 2 |
| ≥ −85 | 1 |
| ต่ำกว่า −85 | 0 |

### 5.3 `loop()` — โครงสร้างหลัก

```
loop():
  now = millis()
  ทุก 50 ms        → อ่าน LDR (และถ้าอยู่ใน Calibrating → จด min/max)
  ถ้า phase == Calibrating:
      ทุก 250 ms   → สลับ LED ขาว
      ทุก 100 ms   → อัปเดตแถบความคืบหน้า + ตัวเลข raw/min/max
      ครบ 6 วินาที  → finishCalibration() แล้วเริ่มต่อ WiFi (ถ้ามี SSID)
      return        ← ไม่ทำส่วนล่าง
  ถ้า phase == Running:
      updateWifi(now)
      ทุก 100 ms   → updateLightCard()   (วาดเมื่อ % เปลี่ยน)
      ทุก 1000 ms  → updateStatusCards() (หรือเมื่อสถานะ WiFi เปลี่ยน)
      ทุก 500 ms   → updateHeartbeat()
      ทุก 1000 ms  → พิมพ์ Serial
```

**ข้อ 7 — ย้ายแถบกราฟขึ้นไปเหนือเลข %:**

- เก็บค่า % ล่าสุด **65 ค่า** (กว้างแท่งละ 2 พิกเซล = 130) ในอาร์เรย์ ทุก 1 วินาที เมื่อเต็มให้เลื่อนค่าเก่าทิ้ง
- ความสูงแท่ง = % × 18 ÷ 100 (อย่างน้อย 1 พิกเซล) สีแท่งตามเกณฑ์เดียวกับแถบหลัก (`lightColor()`)
- ห้ามใช้ `delay()` ห้ามล้างจอทั้งหน้า

คำใบ้: เพิ่มฟังก์ชัน `pushHistory(int percent)` (เก็บค่าลงอาร์เรย์ + วาดกราฟ) แล้วเรียกท้าย `updateStatusCards()`

## 11. เช็คลิสต์ผ่าน Lab

- [ ] build และ upload สำเร็จ เห็นหน้า Calibrate แล้วเข้าหน้าหลักเอง
- [ ] ค่าแสงบนจอเปลี่ยนตามการครอบมือ (ตัวเลข แถบ คำ DARK/NORMAL/BRIGHT และสีเปลี่ยน)
