## คำถามระหว่างอ่านโค้ด

| ข้อ | เฉลย |
|---|---|
| 5.1 | ช่องตัวอักษรเริ่ม y=56 สูง 52 → แถวสุดท้าย y = 56 + 52 − 1 = **107** กรอบแถบเริ่มที่ BAR_Y−1 = **109** แถวว่างคั่น **1 แถว** (y=108) แถบเริ่มที่ y=110 |
| 5.2 | บรรทัด `cyd::enableBacklight()` ใน `setup()` และ `tft.init()` (เพราะกำหนด `TFT_BL` ใน `platformio.ini`) ถ้าไฟหลังจอไม่ติด **จอจะดำ/มืด แต่โปรแกรมและ Serial ยังทำงานปกติ** (เพราะไฟหลังจอเป็นวงจรแยกจากข้อมูลภาพ) |
| 5.3 | จุดกะพริบเร็วขึ้นเป็นทุก 100 ms (10 ครั้ง/วินาที) ยังคงทำงานได้เพราะ `loop()` ไม่ถูกบล็อก ใช้เวลาวาดวงกลมเล็กมาก |

## แบบฝึกหัด

### ข้อ 1 — เปลี่ยนสี

```cpp
constexpr uint16_t COLOR_HEADER = rgb565(120, 40, 140);   // ม่วง
constexpr uint16_t COLOR_CARD   = rgb565(40, 24, 50);     // ม่วงเข้ม
```
(build ผ่านแล้ว)

คำนวณ `rgb565(120, 40, 140)`: R 120 = 0x78 → `& 0xF8` = 0x78 → `<< 8` = **0x7800**; G 40 = 0x28 → `& 0xFC` = 0x28 → `<< 3` = **0x0140**; B 140 → `>> 3` = 17 = **0x0011**
รวม = 0x7800 | 0x0140 | 0x0011 = **0x7951** (ตรวจด้วยสคริปต์แล้ว) ตัวอย่างอื่นที่ใช้ในโค้ด: `rgb565(20, 70, 120)` = 0x122F, `rgb565(240, 85, 85)` = 0xF2AA
ให้คะแนนเต็มถ้าเปลี่ยนสีได้และคำนวณ RGB565 ถูก (ตัวเลขจะต่างตามสีที่นักเรียนเลือก) ตรวจว่าตัวอักษรขาวยังอ่านออก

### ข้อ 2 — ใส่ชื่อ

```cpp
drawHeader("Lab 4 - TFT Display : Somchai");
```
(build ผ่านแล้ว) จำนวนตัวอักษรที่พอดีขึ้นกับตัวอักษรที่ใช้ (ฟอนต์สัดส่วนไม่เท่ากัน) ให้ถือคำตอบที่นักเรียนทดลองจริงเป็นหลัก ไม่ตัดคะแนนเมื่อตัวเลขต่างกัน

### ข้อ 3 — เปลี่ยนเกณฑ์

```cpp
constexpr uint8_t LIGHT_DARK_BELOW = 20;
constexpr uint8_t LIGHT_BRIGHT_ABOVE = 80;
```
(build ผ่านแล้ว) **`NORMAL` ปรากฏบ่อยขึ้น** เพราะช่วง NORMAL กว้างขึ้นจาก 35–65 (31 ค่า) เป็น 20–80 (61 ค่า) ค่าที่ต้องจึงจะเป็น DARK/BRIGHT มากขึ้นกว่าเดิม

### ข้อ 4 — "ผี" ตัวเลข

```cpp
void drawText(...)
{
    tft.setTextColor(fg, bg);
    tft.setTextPadding(0);        // แก้จาก paddingW
    tft.drawString(text, x, y, font);
    tft.setTextPadding(0);
}
```
(build ผ่านแล้ว)

**คำอธิบายที่ถูก (จากการอ่านโค้ดและไลบรารี ยังไม่ได้ดูบนบอร์ด):** `drawString` วาดเฉพาะพื้นที่ของตัวอักษรที่ส่งเข้าไป ส่วนที่ข้อความเก่ายาวกว่าไม่ถูกลบ
`100%` ที่ขนาด 2 เท่ากว้าง (14+14+14+21)×2 = 126 พิกเซล แต่ `9%` กว้างแค่ (14+21)×2 = 70 พิกเซล พื้นที่ x ≈ 86–142 ของข้อความเก่าจึงค้างอยู่
คือเศษของเลข 0 ตัวที่สามและเครื่องหมาย `%` เดิม ทำนองเดียวกัน `BRIGHT` → `DARK` (91 → 68 พิกเซล) และ `raw 132` → `raw 98` จะมีส่วนท้ายของข้อความเก่าค้าง
**รับคำตอบที่ถูก** ถ้านักเรียนอธิบายว่า "ข้อความใหม่สั้นกว่า ส่วนท้ายของข้อความเก่าไม่ถูกลบ" และ `setTextPadding` แก้ได้โดยบอกให้ลบพื้นที่กว้างเท่าข้อความที่ยาวที่สุด

### ข้อ 5 — วาดทั้งหน้าซ้ำ

```cpp
void updateLightCard()
{
    drawMainScreenStatic();     // ← เพิ่ม
    const int percent = lightPercent();
    ...
```
(build ผ่านแล้ว)

**วิเคราะห์จากโค้ด:** `drawMainScreenStatic()` เรียก `fillScreen` + วาด header/การ์ด และตั้ง `lastDrawnPercent = -1` ทำให้เงื่อนไข `percent == lastDrawnPercent` ไม่เป็นจริงเลย
ทุกครั้งที่ `updateLightCard()` ถูกเรียก (ทุก 100 ms) จึงล้างจอแล้ววาดทั้งหน้า และยังตั้ง `lastStatusDrawAt = 0` ทำให้ส่วน WiFi / uptime ถูกวาดซ้ำทุกรอบของ `loop()` ที่ตามมา
การล้างจอเต็มจอส่งข้อมูลอย่างน้อย ~31 ms (ค่าทางทฤษฎี) × 10 ครั้ง/วินาที = ใช้เวลาราว 30% ของทุกวินาทีกับการล้างจออย่างเดียว คาดว่าจะ **เห็นการกะพริบหรือส่วนของจอวูบ**
(ความรุนแรงที่แท้จริงขึ้นกับสายตาและกล้อง ผมยังไม่ได้ดูจากบอร์ด ให้ผู้สอนลองก่อน)

**คำถามเสริม — ใส่แค่ `tft.fillScreen(COLOR_BG)` ที่ต้นฟังก์ชัน:** header และการ์ดทั้งสองใบ **หายไปถาวร** เพราะวาดไว้ครั้งเดียวใน `drawMainScreenStatic()` และไม่มีใครวาดซ้ำ
นอกจากนี้ล้างจอทุก 100 ms แต่ค่าแสงวาดใหม่เฉพาะตอน % เปลี่ยน (เพราะ `fillScreen` อยู่ก่อนการเช็ค `return`) จอส่วนค่าแสงจึงว่างเกือบตลอดเวลา
สรุปคือถ้าล้างจอ ต้องวาด "ทุกอย่าง" ที่อยู่บนหน้านั้นใหม่ ซึ่งเป็นเหตุผลที่โปรแกรมเลือกไม่ล้างจอ

### ข้อ 6 — ปรับความถี่การวาด

```cpp
constexpr uint32_t LIGHT_REFRESH_MS = 1000;
```
(เปลี่ยนค่าคงที่ตัวเดียว ไม่ได้ build แยก) % บนจออัปเดตวินาทีละครั้ง จึงรู้สึกหน่วงเวลาครอบ/เปิดมือเร็วๆ
ค่าบน Serial ไม่ช้าลงเพราะ Serial ใช้ตัวจับเวลา `SERIAL_PRINT_MS` และใช้ `lightPercent()` ที่คำนวณทันทีจากค่ากรอง ไม่ขึ้นกับการวาดจอ
ค่าที่เหมาะส่วนใหญ่อยู่ราว 100–250 ms ที่ 50 ms ไม่ต่างจาก 100 ms มาก เพราะค่าแสงถูกกรองด้วย EMA ที่ไหลช้ากว่านั้นอยู่แล้ว (ตอบตามเหตุผลที่นักเรียนอธิบาย)

### ข้อ 7 — ย้ายแถบกราฟขึ้นเหนือเลข %

ตัวอย่างค่าที่ใช้ได้ (build ผ่านแล้ว)

```cpp
constexpr int16_t BAR_X = 16, BAR_Y = 56, BAR_W = 288, BAR_H = 12;      // เดิม BAR_Y = 110
...
// ใน updateLightCard():
drawText(text, LIGHT_CARD_X + 8, LIGHT_CARD_Y + 38, 4, COLOR_TEXT, COLOR_CARD, 130);   // เดิม + 22
drawText(lightLabel(percent), LIGHT_CARD_X + 170, LIGHT_CARD_Y + 50, 4, color, COLOR_CARD, 120);  // เดิม + 36
```

วิธีคิด (การ์ดอยู่ y 34–125)

| ส่วน | y เริ่ม | y สุดท้าย |
|---|---|---|
| ป้าย `LIGHT` / `raw` | 38 | 53 |
| กรอบแถบ (BAR_Y−1 ถึง BAR_Y+BAR_H) | 55 | 68 |
| เลข % (สูง 52) | 72 (= 34+38) | 123 |
| คำระดับ (สูง 26) | 84 (= 34+50) | 109 |

เลข % จบที่ y=123 ไม่เกินขอบการ์ด y=125 และไม่ซ้อนกรอบแถบ ค่าอื่นที่ถูกก็ได้ ขอแค่เป็นไปตามเงื่อนไข ("ลำดับ ป้าย → แถบ → เลข", ไม่ล้น, ไม่ทับ)
ข้อผิดพลาดที่พบบ่อย: ลืมว่าเลข % สูง 52 (ไม่ใช่ 26) ทำให้ล้นล่างการ์ด หรือย้าย `BAR_Y` แต่ไม่ย้ายเลข % จึงซ้อนกัน

### ข้อ 8 — ท้าทาย: กราฟย้อนหลัง

โค้ดเฉลย (build ผ่านแล้ว) เพิ่มตัวแปรหลัง `lastDrawnPercent`

```cpp
constexpr int16_t GRAPH_X = 164, GRAPH_Y = 220, GRAPH_W = 130, GRAPH_H = 18;
constexpr uint8_t GRAPH_POINTS = GRAPH_W / 2;   // 65 แท่ง แท่งละ 2 พิกเซล
uint8_t history[GRAPH_POINTS];
uint8_t historyCount = 0;
```

เพิ่มฟังก์ชันก่อน `updateStatusCards()`

```cpp
void drawHistoryGraph()
{
    tft.fillRect(GRAPH_X, GRAPH_Y, GRAPH_W, GRAPH_H, COLOR_BG);
    for (uint8_t i = 0; i < historyCount; i++) {
        const int16_t h = max<int16_t>(1, history[i] * GRAPH_H / 100);
        tft.fillRect(GRAPH_X + i * 2, GRAPH_Y + GRAPH_H - h, 2, h, lightColor(history[i]));
    }
}

void pushHistory(int percent)
{
    if (historyCount < GRAPH_POINTS) {
        history[historyCount++] = static_cast<uint8_t>(percent);
    } else {
        memmove(history, history + 1, GRAPH_POINTS - 1);          // เลื่อนค่าเก่าทิ้ง
        history[GRAPH_POINTS - 1] = static_cast<uint8_t>(percent);
    }
    drawHistoryGraph();
}
```

และท้าย `updateStatusCards()` เรียก `pushHistory(lightPercent());`

ข้อสังเกตสำหรับผู้สอน
- `updateStatusCards()` ถูกเรียกทุก 1 วินาที และเมื่อสถานะ WiFi เปลี่ยน (ผ่าน `lastStatusDrawAt = 0`) จึงอาจมีจุดเพิ่มเป็นครั้งคราว ถือว่ายอมรับได้ ถ้าต้องการให้เว้นจังหวะเป๊ะ ให้ใช้ตัวจับเวลาแยก
- กราฟล้างพื้นที่เล็ก 130×18 แล้ววาดใหม่ทุกวินาที ส่งข้อมูลน้อยกว่าล้างทั้งจอมาก แต่ถ้ามองใกล้ๆ อาจเห็นกะพริบเล็กน้อยที่กราฟ (ยังไม่ได้ดูบนบอร์ด)
- เฉลยของนักเรียนอาจใช้ `drawLine` ต่อจุด หรือวางตำแหน่งต่างจากนี้ ก็ถูกถ้าไม่ใช้ `delay()` ไม่ล้างจอทั้งหน้า และไม่ทับส่วนอื่น

## ข้อควรระวังและข้อสังเกตสำหรับผู้สอน

1. **ภาพหน้าจอ:** ในภาพถ่ายจากบอร์ดต้นแบบ พื้นหลังอาจดูเป็นโทนน้ำเงินสว่างกว่าสีที่ตั้งไว้ (เกือบดำ) เพราะจอ TN มุมมองแคบ ยังไม่ได้ยืนยันเรื่องนี้กับผู้ทดสอบ จึงถือเป็นข้อสันนิษฐาน
2. **ความเป็นส่วนตัว:** ภาพจริงของหน้าหลักแสดง SSID และ IP กำชับให้นักเรียนปิดทับก่อนส่ง และไม่ส่ง `secrets.h` (ถูก `.gitignore` ไว้แล้ว)
3. **ข้อ 5 ในเอกสารเวอร์ชันแรกของ README** เคยใช้ `fillScreen` เพียงอย่างเดียว ซึ่งให้ผลคนละแบบกับที่คาด (การ์ดหาย ไม่ใช่เพียงกะพริบ) จึงเปลี่ยนเป็น `drawMainScreenStatic()` และเก็บ `fillScreen` เป็นคำถามเสริม
4. **ข้อ 4 และ 5 คือหัวใจของ Lab** ถ้านักเรียนอธิบายเหตุผลของ "วาดเฉพาะที่เปลี่ยน" ได้ ถือว่าบรรลุเป้าหมายหลัก
