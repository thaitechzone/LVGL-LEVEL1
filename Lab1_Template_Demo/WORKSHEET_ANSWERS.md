# เฉลยใบงาน Level 1 / Lab 1 — Template Demo (สำหรับผู้สอนเท่านั้น)

> อย่าแจกก่อนผู้เรียนทำเสร็จ ใบงานฉบับนักเรียนอยู่ที่ [WORKSHEET.md](WORKSHEET.md)

## สถานะการตรวจสอบเฉลย

| รายการ | สถานะ |
|---|---|
| โค้ดเฉลยแบบฝึกหัดข้อ 3, 4, 5, 6 | build ผ่าน และอัปโหลดขึ้นบอร์ดจริงแล้ว |
| ข้อความ Serial ของข้อ 3, 4, 5 (ลำดับสี เลข GPIO uptime) | ตรวจจากบอร์ดจริงแล้ว ตรงตามเฉลย |
| ช่วงเวลาเปลี่ยนสี 2.0 วินาที | วัดจากเวลาที่ Serial Monitor (`--filter time`) ได้ 2.000 วินาที คลาดเคลื่อนไม่เกิน ~2 มิลลิวินาที |
| LED แดง/เขียว/น้ำเงิน ตรงกับ Serial | ผู้ใช้ยืนยันด้วยตาบนบอร์ดจริงแล้ว |
| ลักษณะการกะพริบของข้อ 6 | โค้ดทำงานและ build ผ่าน แต่ **ผู้สอนควรดูด้วยตา** ว่ากะพริบทุก ~0.25 วินาที |
| คำตอบข้อ 7 (สีเมื่อกลับ Active-LOW) | **คำนวณจากตรรกะ ยังไม่ได้ทดสอบบนบอร์ด** ให้ผู้สอนลองยืนยันเอง |

## ตารางบันทึกผล (หัวข้อ 4 ขั้นที่ 7)

| ข้อความใน Serial | สีที่ต้องเห็น |
|---|---|
| `LED = RED (GPIO4)` | แดง |
| `LED = GREEN (GPIO16)` | เขียว |
| `LED = BLUE (GPIO17)` | น้ำเงิน |

ขั้นที่ 8: ระยะเวลาระหว่างบรรทัด ≈ **2.0 วินาที** (ตรงกับ `LED_STEP_MS = 2000`)

## ตารางในหัวข้อ 5.3 (ledSet)

| `red` | `red == LED_ACTIVE_LOW` | ส่งระดับ | ผลที่ LED สีแดง |
|---|---|---|---|
| `true` | true | LOW | ติด |
| `false` | false | HIGH | ดับ |

## แบบฝึกหัด

### ข้อ 1 — ปรับความเร็ว
แก้ `LED_STEP_MS = 500;` ระยะห่างระหว่างบรรทัดที่วัดได้ ≈ **0.5 วินาที**

### ข้อ 2 — เปลี่ยนข้อความ
แก้ `HELLO_TEXT[] = "ชื่อตัวเอง";` (ภาษาอังกฤษ) ข้อความเปลี่ยนทั้งแบนเนอร์และทุกบรรทัด `... #N  LED = ...`
เพราะทั้งสองจุดอ้างถึงค่าคงที่ตัวเดียวกัน `app::HELLO_TEXT` (แก้ที่เดียวเปลี่ยนทุกที่)

### ข้อ 3 — สลับลำดับสี
```cpp
const LedStep steps[] = {
    {"BLUE", cyd::LED_PIN_B, false, false, true},
    {"GREEN", cyd::LED_PIN_G, false, true, false},
    {"RED", cyd::LED_PIN_R, true, false, false},
};
```
ผล Serial (ตรวจจากบอร์ดจริงแล้ว): `#1 LED = BLUE (GPIO17)`, `#2 LED = GREEN (GPIO16)`, `#3 LED = RED (GPIO4)`
**ไม่ต้องแก้ตัวเลข 3 ที่ไหนเลย** เพราะ `STEP_COUNT = sizeof(steps) / sizeof(steps[0])` คำนวณจำนวนสมาชิกให้อัตโนมัติ

### ข้อ 4 — เพิ่มสีเหลือง
```cpp
{"YELLOW", cyd::LED_PIN_R, true, true, false},
```
ผล Serial ที่ตรวจแล้ว: `LED = YELLOW (GPIO4)` (แสดงเลข GPIO ของแดง) และ LED จริงติดทั้งแดงและเขียวพร้อมกัน
เหตุผล: ช่อง `pin` เป็นตัวเลขเดียว จึงเก็บ GPIO ได้แค่ขาเดียวต่อขั้น สีที่ผสมจาก 2 ขาจึงแสดงได้ไม่ครบ
(ผู้เรียนที่เก่งอาจเสนอให้เปลี่ยนเป็นพิมพ์ข้อความแทนเลขเดียว หรือเก็บเป็นชุดของ pin ซึ่งเป็นการออกแบบที่ดีกว่า)

### ข้อ 5 — แสดง uptime
```cpp
Serial.printf("%s #%lu  LED = %s (GPIO%u)  uptime = %lu s\n", app::HELLO_TEXT,
              static_cast<unsigned long>(helloCount), step.name, step.pin,
              static_cast<unsigned long>(millis() / 1000));
```
ผลที่ตรวจแล้ว (เมื่อ `LED_STEP_MS = 2000`): `uptime = 0 s`, `2 s`, `4 s`, `6 s` ตามลำดับ

### ข้อ 6 — กะพริบภายในแต่ละสี
เพิ่มตัวแปรสองตัว (ไว้ข้างตัวแปรอื่นใน namespace ไม่มีชื่อ) และแก้ `loop()`
```cpp
uint32_t lastBlinkAt = 0;
bool blinkOn = true;

void loop()
{
    const uint32_t now = millis();
    if (now - lastStepAt >= app::LED_STEP_MS) {
        lastStepAt = now;
        currentStep = (currentStep + 1) % STEP_COUNT;
        showStep(steps[currentStep]);
        blinkOn = true;          // เริ่มสีใหม่ด้วยสถานะ "ติด"
        lastBlinkAt = now;
    }

    if (now - lastBlinkAt >= 250) {
        lastBlinkAt = now;
        blinkOn = !blinkOn;
        const LedStep &step = steps[currentStep];
        cyd::ledSet(blinkOn && step.red, blinkOn && step.green, blinkOn && step.blue);
    }
}
```
อธิบาย: `millis()` แค่อ่านเวลาโดยไม่หยุดโปรแกรม จึงมีตัวจับเวลาได้หลายตัวในรอบ `loop()` เดียวกัน
(ตัวหนึ่งเปลี่ยนสีทุก 2000 ms อีกตัวสลับติด/ดับทุก 250 ms) ส่วน `delay()` หยุดทุกอย่างจนกว่าจะครบเวลา
จึงทำสองจังหวะที่ไม่เท่ากันพร้อมกันไม่ได้

### ข้อ 7 — กลับค่า Active-LOW (ผลที่ทำนายจากตรรกะ)
เมื่อ `LED_ACTIVE_LOW = false` ฟังก์ชัน `ledSet` จะส่ง HIGH เมื่อ "ติด" และ LOW เมื่อ "ดับ" แต่ฮาร์ดแวร์จริงของบอร์ดนี้ติดเมื่อได้ LOW
ผลจึงกลับกันทุกขา (สีที่ควรติดจะดับ สีที่ควรดับจะติด) → ทำนาย

| ข้อความใน Serial | ขาที่ติดจริง | สีที่คาดว่าจะเห็น |
|---|---|---|
| `LED = RED` | G และ B | ฟ้าอมเขียว (cyan) |
| `LED = GREEN` | R และ B | ม่วงแดง (magenta) |
| `LED = BLUE` | R และ G | เหลือง |

(ยังไม่ได้ทดสอบบนบอร์ด ให้ผู้สอนลองยืนยัน แล้วอย่าลืมเปลี่ยนกลับเป็น `true`)

## คำถามทบทวน

1. `setup()` ทำครั้งเดียวตอนเริ่ม ใช้ตั้งค่าเริ่มต้น; `loop()` ทำซ้ำไม่สิ้นสุดหลังจากนั้น ใช้ทำงานต่อเนื่อง
2. Baud rate คือความเร็วส่งข้อมูลทางสาย Serial ถ้าสองฝั่งตั้งไม่เท่ากัน ข้อความที่เห็นจะเป็นตัวอักษรเพี้ยน/อ่านไม่ออก
3. Active-LOW คือ LED ติดเมื่อส่ง LOW ดับเมื่อส่ง HIGH ในบอร์ดนี้ต้องส่ง **LOW** ที่ขา GPIO4 ให้ LED สีแดงติด
4. ซ่อนเรื่องกลับระดับสัญญาณไว้ในฟังก์ชันเดียว เรียกใช้ด้วย true/false อ่านง่าย ลดโอกาสผิด และถ้าบอร์ดเปลี่ยนก็แก้ที่เดียว (`LED_ACTIVE_LOW`)
5. `board_config.h` คือข้อเท็จจริงของฮาร์ดแวร์ (pin ฯลฯ) ไม่ควรแก้; `app_config.h` คือค่าที่ปรับเล่นได้ของแต่ละ Lab; เปลี่ยนความเร็ว LED แก้ที่ `app_config.h` (`LED_STEP_MS`)
6. `delay()` หยุดโปรแกรมทั้งหมดระหว่างรอ ส่วน `millis()` ให้เช็คเวลาโดยไม่หยุด `loop()` จึงยังทำงานอื่นได้ และเป็นนิสัยที่จำเป็นเมื่อเริ่มใช้จอ/LVGL ใน Lab ถัดไป
7. คำนวณขั้นถัดไปแบบวนกลับ เมื่อ `STEP_COUNT = 3` และ `currentStep = 2` → `(2 + 1) % 3 = 0` (กลับไปสีแรก)
8. `%s` = ข้อความ, `%lu` = จำนวนเต็มบวกยาว (unsigned long), `%u` = จำนวนเต็มบวก (unsigned int)
9. ตรวจเลข GPIO ที่ Serial แสดงมาเทียบกับสีที่เห็นจริง แล้วตรวจ `LED_PIN_R/G/B` ใน `board_config.h` (ต้องเป็น 4 / 16 / 17)
10. Serial Monitor จองพอร์ต COM ไว้ ตัว upload จึงเปิดพอร์ตเดียวกันไม่ได้ (ขึ้น `Access is denied` หรือ `port is busy`)

## ข้อควรตรวจเมื่อให้คะแนน

- ผู้เรียนที่ข้อความ Serial ถูกแต่สี LED ผิด: ตรวจ `LED_PIN_R/G/B` และ `LED_ACTIVE_LOW` ก่อน
- ให้ถามปากเปล่า 1–2 ข้อจากคำถามทบทวน (เช่นข้อ 6 และ 7) เพื่อดูว่าเข้าใจจริง ไม่ได้แค่ลอกโค้ด
- ผู้เรียนที่ทำข้อ 4 แล้วบอกว่า "GPIO ของเหลืองคือ 4" ให้ชี้ให้เห็นว่าเลขนี้เป็นแค่ GPIO ของแดงที่ใส่ในช่อง `pin` ไม่ใช่ "ขาของสีเหลือง"
