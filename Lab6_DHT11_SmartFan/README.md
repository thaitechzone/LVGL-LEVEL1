# Level 1 / Lab 6 — DHT11 Smart Fan: ต่อเซนเซอร์ภายนอก แล้วสั่งพัดลมจำลองด้วย PWM

Lab นี้เป็น **วงจรภายนอกตัวแรก** ของคอร์ส: ต่อเซนเซอร์อุณหภูมิ/ความชื้น **DHT11** เข้ากับบอร์ด แล้วใช้อุณหภูมิสั่ง "พัดลมจำลอง"
(LED น้ำเงินที่คุมความสว่างด้วย PWM จาก Lab 5) พร้อมแสดงผลบนจอและ Serial

> **สถานะการตรวจสอบ (อ่านก่อน):** โปรแกรม build ผ่านและทดสอบบนบอร์ดจริงแล้ว ทั้งเส้นทาง "ไม่พบเซนเซอร์", ค่าจำลอง (SIM), ตรรกะพัดลมพร้อม hysteresis, คำสั่ง MANUAL
> และ **การอ่าน DHT11 จริง** (ผู้พัฒนาต่อเซนเซอร์แล้ว ส่งภาพถ่ายหน้าจอที่ป้าย `REAL` และผมอ่าน Serial ยืนยันค่าและเวลาอ่าน)
> **ส่วนที่ยังไม่ได้ตรวจ:** ความแม่นยำของเซนเซอร์เทียบเครื่องวัดอื่น, สี LED น้ำเงิน/แดง และปุ่ม BOOT ดูตาราง "สิ่งที่ยังไม่ได้ยืนยัน" ท้ายไฟล์
> ภาพ ASCII วาดประกอบ ตัวอย่างข้อความ Serial ที่ระบุว่าเป็นของจริงมาจากบอร์ดต้นแบบ

## สิ่งที่จะได้เรียน

1. **ต่อวงจรภายนอก:** แหล่งจ่าย 3.3 V, GND, ขาข้อมูล และตัวต้านทานดึงขึ้น (pull-up)
2. **เลือกขา GPIO:** ทำไมใช้ GPIO27 และ **ห้ามใช้ GPIO21** (เป็นขาไฟหลังจอ)
3. **เซนเซอร์สายเดียว (single-wire):** อ่านได้ไม่ถี่กว่า ~1 ครั้งต่อวินาที และอ่านพลาดได้เสมอ
4. **รับมือข้อมูลเซนเซอร์ที่เชื่อถือไม่ได้:** `NaN`, อ่านพลาดติดกัน, แสดง `SENSOR ERROR`, ไม่ใช้ค่าเก่าสั่งงาน
5. **เซนเซอร์ → ตัดสินใจ → ควบคุม:** อุณหภูมิ → duty ของ PWM พร้อมแนวคิด **hysteresis** (ช่วงหน่วงกันสวิตช์สั่น)

## วงจร (ใช้โมดูล DHT11 แบบ 3 ขา ที่มีตัวต้านทาน pull-up มาในตัว)

```
   โมดูล DHT11                    บอร์ด CYD (ช่องต่อ Expansion IO2)
   ┌───────────┐
   │ VCC (+)   ├──────────────── 3.3V
   │ DATA (S/OUT)├────────────── GPIO27
   │ GND (-)   ├──────────────── GND
   └───────────┘
```

| ขาโมดูล | ต่อกับ | หมายเหตุ |
|---|---|---|
| VCC / `+` | **3.3V** ของบอร์ด | ใช้ 3.3 V เพื่อให้สัญญาณข้อมูลไม่เกิน 3.3 V ที่ขา ESP32 รับได้ (หลักการทั่วไป ไม่ต้องเสี่ยงจ่าย 5 V) |
| DATA / `S` / `OUT` | **GPIO27** | ชื่อขานี้ต่างกันตามโมดูล |
| GND / `-` | GND | |

- **ลำดับขาของโมดูลแต่ละยี่ห้อไม่เหมือนกัน** อ่านตัวหนังสือที่พิมพ์บนแผ่นวงจรเสมอ อย่าเดาจากตำแหน่ง
- **ปิดไฟ (ถอดสาย USB) ก่อนต่อหรือย้ายสายทุกครั้ง**
- ถ้าเป็นเซนเซอร์เปล่า 4 ขา (ไม่ใช่โมดูล) ต้องต่อตัวต้านทาน **4.7–10 kΩ** ระหว่าง DATA กับ VCC เอง (pull-up) ขาที่ 3 ของเซนเซอร์ไม่ใช้
- **ทำไม GPIO27 ไม่ใช่ GPIO21:** GPIO21 คือขาไฟหลังจอ เคยทดสอบกับบอร์ดนี้ใน `labs/Lab14_DHT11_Test` แล้วพบว่าต่อ DHT11 ที่ GPIO21 ทำให้จอกะพริบตามจังหวะอ่านค่า
  ส่วน GPIO27 ใช้ต่อเซนเซอร์ได้ปกติ (ดู `ESP32-2432S028_CYD_Knowledge_Base.md`)

## สิ่งที่จะเห็นบนจอ

```
┌──────────────────────────────────────┐
│ Lab 6 - DHT11 Smart Fan              │
│ ┌────────────────┐┌────────────────┐ │
│ │ TEMP     REAL  ││ HUMIDITY  REAL │ │
│ │ 29.0 C         ││ 62 %           │ │
│ └────────────────┘└────────────────┘ │
│ ┌──────────────────────────────────┐ │
│ │ FAN (PWM)              MODE: AUTO│ │
│ │ 45%                RUNNING       │ │
│ │ [████████░░░░░░░░░░░░░░░░░░░░░░] │ │
│ │ ON >= 30C  OFF <= 28C  MAX 36C   │ │
│ └──────────────────────────────────┘ │
│ OK 128  FAIL 2  last 3s ago        ● │
└──────────────────────────────────────┘
```

| ส่วนบนจอ | ความหมาย |
|---|---|
| `TEMP` / `HUMIDITY` | อุณหภูมิและความชื้น ตัวเลขอุณหภูมิเป็นสีส้มเมื่อถึงเกณฑ์เปิดพัดลม ค่าที่ไม่มีให้แสดง `--` |
| **ป้ายมุมขวาบนของการ์ด** | **`REAL`** (เขียว) = ค่าจาก DHT11 จริง, **`SIM`** (เหลือง) = ค่าจำลอง (สุ่มหรือไล่ขึ้น-ลง) ไม่ใช่ค่าจริง, `N/A` (เทา) = ยังไม่มีค่า (กำลังรออ่านครั้งแรก) |
| `FAN` + เลข % + แถบ | duty ที่สั่ง LED น้ำเงิน (ความเร็วพัดลมจำลอง) แถบเติมตาม duty |
| `RUNNING` / `STOPPED` | พัดลมหมุนอยู่ (duty > 0) หรือหยุด |
| `MODE: AUTO / MANUAL` | พัดลมตามอุณหภูมิ หรือเรากำหนดเอง |
| บรรทัดเกณฑ์ | `ON` เกณฑ์เปิด, `OFF` เกณฑ์ปิด, `MAX` อุณหภูมิที่ duty 100% (จาก `app_config.h`) |
| บรรทัดล่าง | `REAL OK 128 FAIL 2 last 3s` (ใช้ค่าจริง: จำนวนอ่านสำเร็จ/พลาด และผ่านมากี่วินาทีจากครั้งล่าสุด), `SIM: no sensor - check wiring` (ไม่พบเซนเซอร์ จึงใช้ค่าจำลองให้เอง), `SIM random` / `SIM sweep` (เลือกใช้ค่าจำลองด้วย `s`), `SENSOR ERROR - check wiring` (แดง ถ้าปิดการใช้ค่าจำลองอัตโนมัติ) |
| จุดกะพริบมุมล่างขวา | `loop()` ยังทำงานอยู่ |

LED บนบอร์ด: **น้ำเงิน** = พัดลมจำลอง (สว่างมาก = หมุนเร็ว), **แดง** = เซนเซอร์มีปัญหา (อ่านพลาดติดกัน 3 ครั้ง) แม้จะใช้ค่า SIM แทนอยู่ก็ตาม ยกเว้นเมื่อคุณเลือก SIM ด้วยมือ
หมายเหตุ: ฟอนต์ที่เปิดไว้ไม่มีสัญลักษณ์ ° จึงแสดงหน่วยเป็นตัว `C`

## ความรู้ใหม่ใน Lab นี้

### DHT11 คืออะไร

เซนเซอร์ราคาถูกที่วัด **อุณหภูมิ** และ **ความชื้นสัมพัทธ์** ส่งข้อมูลเป็นพัลส์ตามจังหวะเวลาบนสายข้อมูลเส้นเดียว (single-wire)
ไลบรารี `DHT sensor library` ของ Adafruit จัดการจังหวะให้ เราเรียก `dht.readTemperature()` / `dht.readHumidity()`

| เรื่อง | ข้อมูล |
|---|---|
| อ่านถี่สุด | ประมาณ 1 ครั้งต่อวินาที โปรแกรมนี้อ่านทุก 2.5 วินาที (`DHT_READ_INTERVAL_MS`) |
| ความแม่นยำ / ช่วงวัด | ตามข้อมูลเอกสารทั่วไปของ DHT11 คือประมาณ ±2 °C และ ±5 %RH ช่วงอุณหภูมิ 0–50 °C ความชื้น 20–90 % (**ไม่ได้ทดสอบกับตัวของคุณ** ถือเป็นค่าประมาณ ไม่ใช่เครื่องมือวัดจริง) |
| ความละเอียด | ตามข้อมูลทั่วไปของ DHT11 คือ 1 °C / 1 %RH แต่ตัวที่ทดสอบกับไลบรารีนี้ **รายงานอุณหภูมิมีทศนิยมได้** (เช่น `30.5`, `33.8` จากบอร์ดจริง) ส่วนความชื้นโปรแกรมแสดงเป็นจำนวนเต็ม |
| เมื่ออ่านพลาด | ไลบรารีคืน `NaN` (ไม่ใช่ตัวเลข) ต้องตรวจด้วย `isnan()` เสมอ |
| เวลาที่ใช้อ่าน | การอ่านหนึ่งครั้งทำให้ `loop()` หยุดรอ **วัดจากบอร์ดจริง:** เมื่ออ่านสำเร็จ ≈ **25.2 ms** (`read took 25147–25239 us`) เมื่อเซนเซอร์ไม่ตอบ ≈ **59.5 ms** (`read took 59513 us`) |

### ค่าจริง (REAL) กับค่าจำลอง (SIM)

ทุกครั้งที่แสดงตัวเลข โปรแกรมจะบอกเสมอว่ามาจากไหน (ป้าย `REAL` / `SIM` บนจอ และ `src=` ใน Serial) เพื่อไม่ให้เข้าใจผิดว่าค่าจำลองเป็นค่าที่วัดได้จริง

| แหล่ง | ป้าย | ค่ามาจาก | เมื่อไหร่ใช้ |
|---|---|---|---|
| **REAL** | `REAL` (เขียว) | DHT11 จริง | อ่านสำเร็จ และไม่ได้เลือก SIM |
| **SIM random** | `SIM` (เหลือง) | **สุ่ม** (random walk): ทุก 1 วินาที อุณหภูมิเปลี่ยนสุ่มไม่เกิน ±1.5 °C ความชื้นไม่เกิน ±3 % ในช่วง 24–38 °C และ 40–90 % | **อัตโนมัติเมื่อไม่พบเซนเซอร์** (อ่านพลาดติดกัน 3 ครั้ง) หรือกด `s` |
| **SIM sweep** | `SIM` (เหลือง) | ไล่ขึ้น-ลงสม่ำเสมอ อุณหภูมิ 24 → 38 → 24 °C รอบละ 60 วินาที ความชื้นไล่สวนทาง | กด `s` สองครั้ง (ผลทำซ้ำได้ เหมาะดู hysteresis ชัดๆ) |
| ไม่มีค่า | `N/A` (เทา) | — | ช่วง ~7 วินาทีแรกก่อนอ่านพลาดครบ 3 ครั้ง หรือปิดการใช้ SIM อัตโนมัติไว้ |

- ถ้า**ต่อเซนเซอร์ภายหลัง** ขณะใช้ SIM อัตโนมัติอยู่ เมื่ออ่านสำเร็จโปรแกรมจะกลับไปใช้ `REAL` เอง (ข้อความ `[SRC] data source: SIM-RANDOM -> REAL`) ผลที่เห็นจริง: ผู้พัฒนาต่อเซนเซอร์ระหว่างที่บอร์ดทำงานอยู่ (ตัวนับ `FAIL 666` ที่ยังค้างอยู่แสดงว่าบอร์ดไม่ได้รีเซ็ต) แล้วจอและ Serial เปลี่ยนเป็น `REAL` เอง (ผมไม่ได้เห็นบรรทัด `[SRC]` ตอนเปลี่ยน แต่เห็นผลลัพธ์) ใบงานยังแนะนำให้ **ปิดไฟก่อนต่อสายทุกครั้ง**
- ปิดการใช้ SIM อัตโนมัติได้ที่ `SIM_WHEN_NO_SENSOR = false` ใน `app_config.h` (เมื่อเซนเซอร์เสียจะขึ้น `--` และพัดลมหยุด)
- ค่า SIM แบบสุ่มเดินสุ่มแล้ว "ชนขอบ" ได้ (เช่นค้างที่ 38.0 °C ชั่วคราวเพราะถูกบีบให้อยู่ในช่วง) เป็นเรื่องปกติของวิธีนี้

### hysteresis: ทำไมต้องมีเกณฑ์ "เปิด" กับ "ปิด" ต่างกัน

ถ้าใช้เกณฑ์เดียว (เช่นเปิดเมื่อ ≥ 30 ปิดเมื่อ < 30) พออุณหภูมิแกว่งรอบ 30 °C พัดลมจะเปิด-ปิดสลับไปมาถี่ๆ (สั่น)
โปรแกรมจึงใช้ **เปิดที่ ≥ 30 °C, ปิดที่ ≤ 28 °C** ช่วง 28–30 °C พัดลม "คงสถานะเดิม" (ตัวแปร `fanOn` จดจำไว้)

ตรวจจากบอร์ดจริงด้วยอุณหภูมิจำลอง 1 รอบ (ข้อความ Serial จริง):

| ขณะอุณหภูมิ… | สิ่งที่เห็น |
|---|---|
| ขึ้นถึง 30.1 °C | `[FAN] OFF -> ON at 30.1 C` |
| ขึ้นผ่านช่วง 28–30 (เช่น 29.1 °C ขณะพัดลมยังหยุด) | พัดลมยัง **หยุด** (`fan=STOP`) |
| ลงมาถึง 28.2 °C | พัดลมยังหมุนที่ duty ต่ำสุด 30% |
| ลงถึง 28.0 °C | `[FAN] ON -> OFF at 28.0 C` |

### duty ของพัดลมตามอุณหภูมิ

เมื่อพัดลมเปิด: `duty = 30 + (T − 30) ÷ (36 − 30) × 70` (บีบให้อยู่ใน 30–100%)

| อุณหภูมิ | duty ที่ได้ |
|---|---|
| 30 °C (เพิ่งเปิด) | 30% (`FAN_MIN_DUTY_PERCENT`) |
| 33 °C | 65% |
| 36 °C ขึ้นไป | 100% |

(การแปลง % เป็นค่า `value` 0–255 ใช้สูตรเดียวกับ Lab 5)

### เมื่อเซนเซอร์มีปัญหา

อ่านพลาดติดกัน 3 ครั้ง (`DHT_FAIL_LIMIT`) → ถือว่า `SENSOR ERROR` และ LED แดงติด จากนั้นมี 2 ทางตาม `SIM_WHEN_NO_SENSOR`

- `true` (ค่าเริ่มต้น): ใช้ค่า **SIM** แทน ป้ายบนจอเป็น `SIM` สีเหลือง และบรรทัดล่างบอก `SIM: no sensor - check wiring` เหมาะกับการสาธิตตอนยังไม่ได้ต่อเซนเซอร์
- `false`: จอแสดง `--` สีแดง และ **พัดลมหยุด** (ไม่ใช้ค่าเก่าสั่งงาน)

ข้อควรคิด: การใช้ค่า SIM สั่งพัดลมเหมาะกับการเรียนรู้ ไม่เหมาะกับงานจริง ในงานจริงเมื่อเซนเซอร์เสีย ควรหยุดหรือเข้าสู่สถานะปลอดภัย (ดูแบบฝึกหัด)

ลองตามลำดับนี้

1. **ยังไม่ต่อเซนเซอร์ก็ทดสอบได้:** เปิดเครื่อง รอ ~8 วินาที โปรแกรมจะสลับไปใช้ค่า **SIM random** ให้เอง จอแสดงอุณหภูมิ/ความชื้นที่เปลี่ยนแบบสุ่ม ป้ายเป็น `SIM` สีเหลือง LED แดงติด และพัดลม (LED น้ำเงิน) เริ่มหมุนเมื่ออุณหภูมิ SIM ถึง 30 °C (ที่ตรวจแล้วจาก Serial)
2. **ทดสอบพัดลมด้วย SIM sweep:** พิมพ์ `s` สองครั้งให้เป็น `SIM-SWEEP` ดูอุณหภูมิขึ้น-ลงสม่ำเสมอ พัดลมเริ่มหมุนที่ ≥ 30 °C สว่างขึ้นตามอุณหภูมิ และหยุดที่ ≤ 28 °C พิมพ์ `s` อีกครั้งเพื่อกลับไปแหล่งข้อมูลปกติ (REAL หรือ SIM อัตโนมัติ)
3. **ทดสอบ MANUAL:** พิมพ์ `5` แล้ว `+` ดู duty เพิ่ม ตรงกับตัวเลขบนจอและ Serial
4. **ต่อ DHT11 จริง** (ปิดไฟก่อนต่อ): เปิดเครื่อง ควรเห็นค่าอุณหภูมิ/ความชื้นภายใน ~3 วินาที ป้ายเป็น `REAL` สีเขียว และ LED แดงดับ
5. **ทดสอบกับความร้อนจริง:** เป่าลมอุ่นหรือหายใจรดเซนเซอร์เบาๆ (ห้ามใช้ความร้อนสูงหรือน้ำ) ความชื้นควรขึ้นก่อน อุณหภูมิจะขึ้นช้ากว่า (ผลจริงที่เห็นจากบอร์ดต้นแบบดูหัวข้อ "สังเกตจากการทดสอบจริง")

## ตัวอย่างข้อความ Serial

ผลจริงจากบอร์ดต้นแบบ (ขณะไม่ได้ต่อเซนเซอร์ แล้วสลับไปใช้ SIM ให้เอง)

```
[DHT11] data pin = GPIO27 (do NOT use GPIO21: it is the TFT backlight)
[STATUS] src=NONE       temp=-- C hum=-- % | mode=AUTO fan=STOP duty=  0% value=  0/255 | dht ok=0 fail=2
[DHT11] #3 FAILED (checksum/timeout) fails in a row=3  -> SENSOR ERROR: check wiring (VCC/DATA/GND)  (read took 59517 us)
[SRC] data source: NONE -> SIM-RANDOM
[FAN] OFF -> ON at 30.3 C
[STATUS] src=SIM-RANDOM temp=31.9 C hum=58 % | mode=AUTO fan=RUN  duty= 52% value=133/255 | dht ok=0 fail=6  SENSOR ERROR
[SIM] sweep: simulated temperature/humidity (smooth up-down cycle)
[SRC] data source: SIM-RANDOM -> SIM-SWEEP
[FAN] ON -> OFF at 28.0 C
[FAN] manual duty = 60% (value 153/255)
```

(ตัวเลข SIM random จะต่างกันทุกครั้งที่เปิดเครื่อง เพราะเป็นค่าสุ่ม)

รูปแบบบรรทัดเมื่ออ่านสำเร็จตามโค้ด (ตัวเลขเป็นตัวอย่าง **ไม่ได้มาจากบอร์ด** เพราะยังไม่ได้ต่อเซนเซอร์ตอนทดสอบ)

```
[DHT11] #5 OK     temp=29.0 C  hum=62 %  (read took 25000 us)
```

## สังเกตจากการทดสอบจริง

ภาพถ่ายจากบอร์ดต้นแบบ (ขณะไม่ได้ต่อเซนเซอร์ ใช้ค่า SIM อัตโนมัติ) แสดงครบ: `TEMP 38.0 C` สีส้ม (เกินเกณฑ์เปิดพัดลม) และ `HUMIDITY 43 %` พร้อมป้าย **`SIM` สีเหลือง**
ที่มุมขวาบนของทั้งสองการ์ด, การ์ดพัดลม `MODE: AUTO` สีเขียว `100%` `RUNNING` แถบเต็ม, บรรทัดเกณฑ์ `ON >= 30C OFF <= 28C MAX 36C`,
บรรทัดล่าง `SIM: no sensor - check wiring` สีเหลือง และจุดกะพริบสีเขียว (ภาพถ่ายตอนหมุนบอร์ดตั้ง ซึ่งไม่ได้เปลี่ยนโค้ด)

**ภาพถ่ายตอนต่อ DHT11 จริง (ป้าย `REAL`)** แสดง `TEMP 30.5 C` สีส้ม และ `HUMIDITY 80 %` พร้อมป้าย **`REAL` สีเขียว** ที่ทั้งสองการ์ด,
การ์ดพัดลม `MODE: AUTO`, `36%`, `RUNNING` (หัวการ์ดอ่าน `FAN (PWM)` ไม่ชนกับ `MODE: AUTO` แล้ว), บรรทัดล่าง `REAL OK 112 FAIL 666 last 0s`
และจุดกะพริบสีเขียว ตัวเลขตรงกับสูตร: ที่ 30.5 °C duty = 30 + (0.5 ÷ 6) × 70 = 35.8 → **36%** ✓

ข้อมูลจาก Serial (อ่านอย่างเดียว) ขณะต่อเซนเซอร์จริง เช่น

```
[DHT11] #804 OK     temp=33.8 C  hum=68 %  (read took 25151 us)
[STATUS] src=REAL       temp=33.8 C hum=68 % | mode=AUTO fan=RUN  duty= 74% value=189/255 | dht ok=139 fail=666
[STATUS] src=REAL       temp=33.5 C hum=68 % | mode=AUTO fan=RUN  duty= 71% value=181/255 | dht ok=142 fail=666
```

ตรวจสูตร: 33.8 °C → 30 + (3.8 ÷ 6) × 70 = 74.3 → **74%**, `value` = (74×255+50)÷100 = **189** ✓ และ 33.5 °C → 70.8 → **71%**, `value` **181** ✓

ข้อสังเกต: (1) **ตัวนับ `FAIL` เป็นค่าสะสมตั้งแต่เปิดเครื่อง** ไม่ถูกรีเซ็ตเมื่อเซนเซอร์กลับมาอ่านได้ (666 มาจากช่วงที่ยังไม่ได้ต่อเซนเซอร์) (2) DHT11 ตัวนี้รายงานอุณหภูมิมีทศนิยม (เช่น 30.5, 33.8)
(3) ภาพถ่ายตอนหมุนบอร์ดตั้ง ซึ่งไม่ได้เปลี่ยนโค้ด

ข้อบกพร่องที่พบจากภาพ (ภาพตอนใช้ค่า SIM): หัวการ์ดพัดลมเดิมเขียนว่า `FAN (PWM on blue LED)` ยาวจนชนกับ `MODE: AUTO` อ่านติดกัน จึงย่อเป็น `FAN (PWM)` (ภาพถ่ายตอนต่อเซนเซอร์จริงแสดงว่าหลังแก้อ่านชัดแล้ว)

## แบบฝึกหัด

1. **ปรับเกณฑ์:** ตั้ง `FAN_ON_TEMP_C = 27` และ `FAN_OFF_TEMP_C = 25` ให้เหมาะกับห้องของคุณ ทดสอบด้วยอุณหภูมิจำลอง (`s`)
2. **ลบ hysteresis:** ตั้ง `FAN_OFF_TEMP_C = FAN_ON_TEMP_C` (เช่นทั้งคู่ 30) ในอุณหภูมิจำลอง ดูข้อความ `[FAN]` ว่าสลับถี่ขึ้นไหมเมื่ออุณหภูมิจำลองผ่าน 30 (ลองเพิ่มสัญญาณรบกวนเล็กน้อยให้จำลองด้วยเพื่อให้เห็นชัด)
3. **ความเร็วพัดลมไม่เป็นเส้นตรง:** แก้ `dutyForTemp()` ให้พัดลมเร่งเร็วขึ้นช่วงอุณหภูมิสูง (เช่นยกกำลังสอง)
4. **Fail-safe:** เปลี่ยนให้เมื่อ `SENSOR ERROR` ในโหมด AUTO พัดลม "เปิดที่ 60%" แทนการหยุด (คิดว่าเมื่อไหร่ควรเลือกแบบไหน)
5. **เปลี่ยนเป็น DHT22:** เปลี่ยน `DHT dht(cyd::DHT11_PIN, DHT11)` เป็น `DHT22` (ไลบรารีเดียวกัน) แล้วดูว่าได้ทศนิยมละเอียดขึ้นไหม (ถ้ามีเซนเซอร์)
6. **ท้าทาย:** วาดไอคอนพัดลมหมุนบนจอ (ความเร็วหมุนตาม duty) หรือกราฟอุณหภูมิย้อนหลัง

| ข้อ | สถานะ |
|---|---|
| โปรแกรม build ผ่าน | ยืนยันแล้ว (ไม่มี warning จากโค้ดของ Lab นี้) |
| เส้นทาง "ไม่พบเซนเซอร์": อ่านพลาด 3 ครั้ง → `SENSOR ERROR`, พัดลมหยุด, ข้อความ Serial | **ยืนยันแล้ว** จากบอร์ดจริง (ยังไม่ได้ต่อ DHT11 ตอนตรวจ) |
| ตรรกะพัดลม AUTO + hysteresis ครบ 1 รอบด้วย SIM sweep; ค่า duty/`value` ตามสูตร | **ยืนยันแล้ว** จาก Serial (รอบแรกที่ตรวจ ก่อนเพิ่มโหมด SIM random) |
| ไม่พบเซนเซอร์ → สลับเป็น SIM random อัตโนมัติ (`[SRC] ... NONE -> SIM-RANDOM`), ค่าสุ่มอยู่ในช่วง 24–38 °C / 40–90 %, `s` สลับ SIM random → SIM sweep → กลับ (fallback) | **ยืนยันแล้ว** จาก Serial |
| คำสั่ง MANUAL (`+ - 0-9 m h`) | **ยืนยันแล้ว** จาก Serial (รอบแรกที่ตรวจ ก่อนเพิ่มโหมด SIM random) |
| ป้าย `SIM` และข้อความบรรทัดล่าง `SIM: no sensor - check wiring` บนจอ | **ยืนยันแล้ว** จากภาพถ่ายของผู้พัฒนา (ดู "สังเกตจากการทดสอบจริง") |
| ป้าย `REAL` (สีเขียว) และข้อความ `REAL OK … FAIL … last …s` บนจอ | **ยืนยันแล้ว** จากภาพถ่ายของผู้พัฒนา (ดู "สังเกตจากการทดสอบจริง") |
| กลับจาก SIM อัตโนมัติเป็น `REAL` เองเมื่อต่อเซนเซอร์ภายหลัง | **ยืนยันผลลัพธ์แล้ว** (เห็นว่ากลับเป็น `REAL` เอง) ยังไม่ได้เห็นบรรทัด `[SRC] ... -> REAL` ตอนเปลี่ยน |
| อ่านค่า DHT11 จริงสำเร็จ, เวลาที่ใช้อ่านเมื่อสำเร็จ | **ยืนยันแล้ว** จาก Serial: อ่านสำเร็จต่อเนื่อง ค่า `read took` ≈ 25.2 ms |
| ความแม่นยำของ DHT11 ตัวที่คุณมี (เทียบเครื่องวัดอื่น) | **ยังไม่ได้ทดสอบ** (เห็นแต่ว่าค่าเปลี่ยนตามสภาพจริง) |
| หน้าตาจอ (ตำแหน่ง ข้อความ สี ความพอดีของตัวเลขในการ์ด) | **ยืนยันแล้วจากภาพถ่ายในโหมด SIM** (ตัวเลขอุณหภูมิ/ความชื้นพอดีการ์ด) พบข้อความหัวการ์ดพัดลมชนกันครั้งหนึ่ง แก้แล้ว แต่ **ยังไม่ได้เห็นภาพหลังแก้** |
| LED น้ำเงินสว่างตาม duty และ LED แดงติดเมื่อ ERROR | **ยังไม่ได้เห็นเอง** (คาดจากโค้ดและ Lab 5) |
| ปุ่ม BOOT สลับโหมดได้ | **ยังไม่ได้ยืนยัน** (คำสั่ง `m` ผ่านแล้ว) |
| การอ่าน DHT11 (ปิด interrupt ช่วงสั้นๆ) ไม่ทำให้ PWM ของ LED กระตุก | **ยังไม่ได้ตรวจ** (PWM ทำงานด้วยฮาร์ดแวร์ จึงคาดว่าไม่กระตุก) |
