## คำถามระหว่างอ่านโค้ด

## แบบฝึกหัด

### ข้อ 1 — แผนผังการต่อสาย (กระดาษ)
คำตอบที่ถูกต้องต้องมี: VCC โมดูล → 3V3, DATA → IO27 (GPIO27), GND → GND และมีเครื่องหมาย ✗ ที่ GPIO21 พร้อมเหตุผล "เป็นขาไฟหลังจอ ต่อแล้วจอกะพริบตามจังหวะอ่านค่า (ทดสอบแล้วในโปรเจกต์)"
เซนเซอร์เปล่า 4 ขา: ต้องเพิ่มตัวต้านทาน pull-up 4.7–10 kΩ ระหว่าง DATA กับ VCC (ขาที่ 3 ของเซนเซอร์ไม่ใช้)

### ข้อ 2 — ปรับเกณฑ์
```cpp
constexpr float FAN_ON_TEMP_C = 27.0f;
constexpr float FAN_OFF_TEMP_C = 25.0f;
```
(build ผ่านแล้ว) คำนวณ SIM sweep ที่ ON=27, OFF=25 (ช่วง 24–38, ครึ่งรอบ 30 วินาที): เปิดที่ (27−24)÷14 × 30 ≈ **6.4 s**, ปิดที่ 60 − (25−24)÷14 × 30 ≈ **57.9 s**
เมื่อเปลี่ยนเกณฑ์ duty ตอน 36 °C ยังเต็ม 100% หรือไม่ ขึ้นกับ `FAN_FULL_TEMP_C` (ถ้า ON=27 แล้ว FULL ยัง 36 ช่วงเร่งจะยาวขึ้นเป็น 9 °C)

### ข้อ 3 — คำนวณ duty (ON 30, FULL 36, MIN 30)

| T | (T−30)÷6 | duty | `value` |
|---|---|---|---|
| 31 | 0.167 | 30 + 11.67 → **42%** | (42×255+50)÷100 = **107** |
| 32 | 0.333 | 30 + 23.3 → **53%** | **135** |
| 34 | 0.667 | 30 + 46.7 → **77%** | **196** |
| 35 | 0.833 | 30 + 58.3 → **88%** | **224** |

ใน Serial อาจเห็นต่างกัน ±1% เพราะอุณหภูมิที่พิมพ์ปัดทศนิยม 1 ตำแหน่ง (ตัวอย่างจริงที่ตรวจ: `temp=31.0 → duty=41%`, `value=105/255` เพราะอุณหภูมิจริงเล็กน้อยกว่า 31.0)

### ข้อ 4 — ลบ hysteresis
```cpp
constexpr float FAN_ON_TEMP_C = 30.0f;
constexpr float FAN_OFF_TEMP_C = 30.0f;   // เดิม 28
```
(build ผ่านแล้ว)

คำทำนายที่ถูก: พัดลมสลับสถานะ **บ่อยขึ้น** เพราะเมื่ออุณหภูมิแกว่งรอบ 30 °C จะผ่านเกณฑ์ขึ้น-ลงซ้ำๆ โดยไม่มีช่วงคงสถานะ
**แบบจำลองบนคอมพิวเตอร์ (ไม่ใช่ผลวัดบนบอร์ด):** จำลองตรรกะเดียวกันบน SIM random 300 วินาที 2000 รอบ ได้ค่าเฉลี่ย **ราว 6 ครั้ง** (30/28) เทียบกับ **ราว 16 ครั้ง** (30/30) ผลบนบอร์ดจริงจะสุ่มต่างกันทุกครั้ง ให้ผู้เรียนทำ 2–3 รอบแล้วเฉลี่ย และรับคำตอบที่แสดงแนวโน้ม "ไม่มี hysteresis สลับถี่กว่า" ได้ (จำนวนเป๊ะไม่ใช่เกณฑ์ตัดสิน)
**ผลบนบอร์ดจริงยังไม่ได้ทดสอบ**

### ข้อ 5 — ความเร็วพัดลมแบบยกกำลังสอง
```cpp
const float fraction = constrain((tempC - app::FAN_ON_TEMP_C) / span, 0.0f, 1.0f);
const float shaped = fraction * fraction;
return app::FAN_MIN_DUTY_PERCENT + static_cast<int>(lroundf(shaped * (100 - app::FAN_MIN_DUTY_PERCENT)));
```
(build ผ่านแล้ว)

| T | fraction | fraction² | duty ใหม่ | duty เดิม (เส้นตรง) |
|---|---|---|---|---|
| 31 | 0.167 | 0.028 | 32% | 42% |
| 32 | 0.333 | 0.111 | 38% | 53% |
| 33 | 0.5 | 0.25 | **48%** (30 + 17.5 → 18) | 65% |
| 34 | 0.667 | 0.444 | 61% | 77% |
| 35 | 0.833 | 0.694 | 79% | 88% |
| 36 | 1 | 1 | 100% | 100% |

คำทำนายข้อ 33 °C ได้ **48%** (เดิม 65%) ผลบนบอร์ดจริงยังไม่ได้ทดสอบ

### ข้อ 6 — Fail-safe
```cpp
// app_config.h
constexpr bool SIM_WHEN_NO_SENSOR = false;

// updateFanAuto():
if (isnan(tempC)) {
    fanOn = sensorError;                 // เมื่อ sensorError = true ให้ถือว่า "เปิด"
} else if ...

applyFanDuty(isnan(tempC) ? (sensorError ? 60 : 0) : (fanOn ? dutyForTemp(tempC) : 0));
```
(build ผ่านแล้ว)

(ก) ผลที่คาด: หลังพลาดติดกัน 3 ครั้ง ขึ้น `SENSOR ERROR`, จอ `--` สีแดง, LED แดงติด, `[FAN] OFF -> ON (no valid temperature)` และพัดลม duty 60% ในขณะที่ยังไม่ถึง 3 ครั้ง (ช่วง `NONE` ตอนเริ่มเครื่อง) พัดลมยังหยุด (ผลบนบอร์ดยังไม่ได้ทดสอบ)
(ข) ตัวอย่างที่ควร "เปิดไว้เมื่อเสีย": พัดลมระบายความร้อนของเครื่องจักร/ตู้อุปกรณ์ (ร้อนเกินเสียหายหนักกว่าการเปลืองไฟ) ตัวอย่างที่ควร "ปิดไว้เมื่อเสีย": ปั๊มน้ำรดต้นไม้ หรือฮีตเตอร์ (เปิดค้างอาจน้ำท่วม/ไฟไหม้) รับคำตอบอื่นที่มีเหตุผลสอดคล้อง

### ข้อ 7 — ค่าต่ำสุด/สูงสุด
```cpp
float minTemp = NAN;   // ใกล้ๆ ตัวแปรอื่น
float maxTemp = NAN;

void trackMinMax(float tempC)
{
    if (isnan(tempC)) return;
    if (isnan(minTemp) || tempC < minTemp) minTemp = tempC;
    if (isnan(maxTemp) || tempC > maxTemp) maxTemp = tempC;
}

// ใน loop() ช่วงตรรกะพัดลม (ทุก FAN_UPDATE_MS):
trackMinMax(effectiveTemp(now));

// ใน printStatus() เพิ่มบรรทัด:
Serial.printf("[MINMAX] min=%.1f C max=%.1f C", minTemp, maxTemp);   // + ขึ้นบรรทัดใหม่

// ใน handleSerialInput() เพิ่มคำสั่ง r:
} else if (c == 'r' || c == 'R') {
    minTemp = NAN;
    maxTemp = NAN;
}
```
(build ผ่านแล้ว) ผลที่คาด: `[MINMAX] min=24.0 C max=38.0 C` เมื่อใช้ SIM sweep ครบรอบ (ค่าที่พิมพ์ก่อนมีค่าแรกคือ `nan`) ข้อสังเกต: ถ้านับค่าจาก `effectiveTemp` ค่าจะรวมค่า SIM ด้วย ผู้เรียนอาจเลือกนับเฉพาะ `REAL` ก็ได้ ถ้าอธิบายเหตุผลได้ (ผลบนบอร์ดยังไม่ได้ทดสอบ)

### ข้อ 8 (โบนัส) — ท้าทาย
ไม่มีโค้ดเฉลยตายตัว **ไม่ได้ทดสอบโค้ดตัวอย่าง** ให้ตรวจตามข้อกำหนด: ลบ/วาดเฉพาะพื้นที่ที่เปลี่ยน ไม่ล้างจอทั้งหน้า ไม่ใช้ `delay()` และไม่ทับส่วนอื่น
คำใบ้สำหรับ (ก) ไอคอนพัดลมหมุน: วาดใบพัด 3 ใบด้วยเส้นหรือสามเหลี่ยมในพื้นที่เล็กคงที่ (เช่น 40×40 พิกเซล) เปลี่ยนมุมเพิ่มตาม duty ทุกๆ 50–100 ms และลบพื้นที่นั้นด้วยสีการ์ดก่อนวาดใหม่ สำหรับ (ข) กราฟย้อนหลัง: ใช้อาร์เรย์วนรอบ (ring buffer) เก็บ 60 ค่า วาดแท่ง/เส้นในพื้นที่ที่ว่าง

| 4 | Not a Number: ค่าที่ไลบรารีคืนเมื่ออ่านพลาด เปรียบเทียบด้วย `==` ไม่ได้ผล (NaN ไม่เท่ากับอะไรแม้แต่ตัวมันเอง) ต้องใช้ `isnan()` |
| 5 | เซนเซอร์เตรียมค่าใหม่ได้ช้า (ราว 1 ครั้ง/วินาที) อ่านถี่เกินได้ค่าเก่า/ผิด โปรแกรมใช้ `millis()` จับเวลาให้อ่านทุก 2.5 วินาที ไม่ใช้ `delay()` |

| 9 | duty = 30 + (T−30)÷(36−30) × 70 (บีบ 30–100%) แปลงเป็น `value` ด้วยสูตรเดียวกับ Lab 5; LED น้ำเงิน GPIO17 ใช้ PWM เป็นพัดลมจำลอง, LED แดง GPIO4 ใช้ `digitalWrite` บอกเซนเซอร์มีปัญหา (LED เขียว GPIO16 ไม่ใช้) |

## ข้อควรระวังและข้อสังเกตสำหรับผู้สอน

1. **ทดสอบกับ DHT11 จริงก่อนสอน** โดยเฉพาะ: ค่าที่ได้, เวลาที่ใช้อ่านเมื่อสำเร็จ, ป้าย `REAL`, การกู้คืนจาก SIM, สี LED และปุ่ม BOOT
2. **ความปลอดภัยของบอร์ด:** ย้ำให้ถอดไฟก่อนต่อสาย ใช้ 3.3 V และตรวจตัวหนังสือบนช่อง Expansion IO2 ก่อนต่อ (ลำดับขาในใบงานมาจากเอกสาร ยังไม่ได้ตรวจกับตัวบอร์ดจริง) ระวังไม่ให้ DATA เข้า GPIO21
3. **ค่า SIM ต้องมีป้ายเสมอ** ถ้านักเรียนแก้โค้ดจนป้ายหาย ให้ชี้ให้เห็นว่าเป็นข้อผิดพลาดเชิงการออกแบบ
4. **ความแม่นยำของ DHT11 ต่ำ** อย่าให้นักเรียนสรุปว่าเซนเซอร์เสียเพียงเพราะค่าต่างจากเครื่องวัดอื่น 1–2 °C
5. **ผู้เรียนที่ไม่มีเซนเซอร์:** ทำได้ถึงขั้นที่ 5 (ใช้ SIM) และตอบคำถามเรื่องการต่อวงจรจากเอกสาร (เกณฑ์ผ่านกำหนดไว้ให้แล้ว)
6. **แบบฝึกหัดข้อ 4:** ค่าสุ่มทำให้ผลต่างกันทุกครั้ง ผู้เรียนควรทำซ้ำหลายรอบ และให้คะแนนจากเหตุผลและแนวโน้มมากกว่าตัวเลข
