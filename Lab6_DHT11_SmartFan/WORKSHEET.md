## 1. เป้าหมายการเรียนรู้

เมื่อจบใบงานนี้ ผู้เรียนต้องทำได้ทุกข้อ

1. ต่อวงจรเซนเซอร์ภายนอกให้ถูกต้อง: เลือกขาจ่ายไฟ ขา GND และขาข้อมูล และอธิบายได้ว่า pull-up resistor มีไว้ทำไม
2. อธิบายได้ว่าทำไมต่อ DHT11 ที่ GPIO27 ได้ แต่ **ห้ามต่อที่ GPIO21**
3. อ่านอุณหภูมิ/ความชื้นจาก DHT11 และอธิบายได้ว่าทำไมต้องตรวจ `isnan()` และห้ามอ่านถี่เกิน ~1 ครั้งต่อวินาที
4. ออกแบบโปรแกรมที่ "รับมือเซนเซอร์เสีย" ได้: นับการอ่านพลาดติดกัน, แยกแหล่งข้อมูล **REAL / SIM**, ไม่นำค่าที่เชื่อถือไม่ได้ไปสั่งงาน
5. อธิบายและคำนวณ **hysteresis** ของเกณฑ์เปิด/ปิดพัดลม และคำนวณ duty ที่ได้ตามอุณหภูมิ
6. อ่านโค้ดที่เชื่อมเซนเซอร์ → ตรรกะตัดสินใจ → PWM → จอ/Serial ได้ครบสาย
7. ดัดแปลงโปรแกรมตามแบบฝึกหัด (เกณฑ์, ความเร็วพัดลม, fail-safe, ค่าต่ำสุด/สูงสุด) ได้

## 2. ภาพรวมสิ่งที่จะสร้าง

```
   โมดูล DHT11                               บอร์ด CYD
   ┌───────────┐                       ┌───────────────────────────────┐
   │ VCC  (+)  ├── 3.3V ───────────────┤ Expansion IO2                 │
   │ DATA (S)  ├── GPIO27 ─────────────┤   ┌── อ่านอุณหภูมิ/ความชื้น   │
   │ GND  (-)  ├── GND ────────────────┤   ▼                            │
   └───────────┘                       │ ตัดสินใจ: เกณฑ์ ON/OFF         │
                                       │   │ (hysteresis)               │
                                       │   ▼                            │
                                       │ PWM ──► GPIO17 LED น้ำเงิน     │ ← พัดลมจำลอง
                                       │ digital ► GPIO4  LED แดง       │ ← เซนเซอร์มีปัญหา
                                       │ SPI ──► จอ TFT: ค่า/สถานะ      │
                                       └───────────────────────────────┘
```

**หน้าจอ** (หน้าเดียว ใช้หลัก "วาดเฉพาะส่วนที่เปลี่ยน" จาก Lab 4)

```
┌──────────────────────────────────────┐
│ Lab 6 - DHT11 Smart Fan              │
│ ┌────────────────┐┌────────────────┐ │
│ │ TEMP     REAL  ││ HUMIDITY  REAL │ │
│ │ 29.0 C         ││ 62 %           │ │
│ └────────────────┘└────────────────┘ │
│ ┌──────────────────────────────────┐ │
│ │ FAN (PWM)              MODE: AUTO│ │
│ │ 45%                RUNNING       │ │
│ │ [████████░░░░░░░░░░░░░░░░░░░░░░] │ │
│ │ ON >= 30C  OFF <= 28C  MAX 36C   │ │
│ └──────────────────────────────────┘ │
│ REAL OK 128 FAIL 2 last 3s         ● │
└──────────────────────────────────────┘
```

| ส่วนบนจอ | ความหมาย |
|---|---|
| `TEMP` / `HUMIDITY` | อุณหภูมิและความชื้น (อุณหภูมิเป็นสีส้มเมื่อถึงเกณฑ์เปิดพัดลม) ถ้าไม่มีค่าแสดง `--` |
| **ป้ายมุมขวาบนของการ์ด** | **`REAL`** (เขียว) = ค่าจากเซนเซอร์จริง, **`SIM`** (เหลือง) = ค่าจำลอง ไม่ใช่ค่าที่วัดได้, `N/A` (เทา) = ยังไม่มีค่า |
| การ์ด `FAN` | duty ของพัดลมจำลอง (เลข %, แถบ, `RUNNING`/`STOPPED`) และโหมด `AUTO`/`MANUAL` |
| บรรทัดเกณฑ์ | เกณฑ์ ON, OFF และ MAX ที่ตั้งไว้ใน `app_config.h` |
| บรรทัดล่าง | สถานะเซนเซอร์: `REAL OK … FAIL … last …s`, `SIM: no sensor - check wiring`, `SIM random`/`SIM sweep`, `SENSOR ERROR - check wiring` |
| จุดกะพริบมุมล่างขวา | `loop()` ยังทำงานอยู่ |

**LED บนบอร์ด:** น้ำเงิน (GPIO17, PWM) = พัดลมจำลอง สว่างมาก = หมุนเร็ว, แดง (GPIO4) = เซนเซอร์มีปัญหา

## 3. ความรู้พื้นฐานที่ต้องเข้าใจก่อนลงมือ

### 3.1 ไฟฟ้าเบื้องต้นสำหรับการต่อเซนเซอร์

| คำ | ความหมาย |
|---|---|
| **VCC / 3.3V** | ขาจ่ายไฟบวกของเซนเซอร์ ESP32 ทำงานที่ **3.3 V** จึงจ่ายเซนเซอร์ที่ 3.3 V เพื่อให้สัญญาณข้อมูลไม่เกิน 3.3 V ที่ขา ESP32 รับได้ (หลักการทั่วไป) |
| **GND** | ขากราวด์ ระดับอ้างอิง 0 V ของวงจรทั้งหมด ต้องต่อร่วมกันเสมอ |
| **DATA** | ขาสัญญาณที่เซนเซอร์ส่งข้อมูลมาให้บอร์ด (และบอร์ดส่งสัญญาณ "เริ่มอ่าน" ไปที่เซนเซอร์) |
| **Pull-up resistor** | ตัวต้านทาน (ประมาณ 4.7–10 kΩ) ต่อระหว่าง DATA กับ VCC ทำให้เส้น DATA อยู่ที่ระดับ HIGH เมื่อไม่มีใครขับสัญญาณ เส้นสายเดียวใช้ร่วมกันทั้งสองทาง (บอร์ดส่งคำสั่ง แล้วเซนเซอร์ตอบกลับ) ช่วงที่ปล่อยเส้นว่าง ต้องมีตัวต้านทานดึงให้ค้างที่ HIGH ไม่ให้สัญญาณลอยจนอ่านผิด |
| **โมดูล vs เซนเซอร์เปล่า** | โมดูล 3 ขามี pull-up บนแผ่นวงจรแล้ว ต่อสายได้เลย ส่วนเซนเซอร์เปล่า 4 ขา (ขาที่ 3 ไม่ใช้) ต้องต่อตัวต้านทาน pull-up เอง |

### 3.2 เลือกขา GPIO ให้ถูก

| ขา | ใช้กับ DHT11 ได้ไหม | เหตุผล |
|---|---|---|
| **GPIO27** | **ได้ (ใช้ใน Lab นี้)** | ขา GPIO ทั่วไปที่ทดสอบกับบอร์ดนี้แล้วว่าใช้ต่อเซนเซอร์ได้ ไม่ชนกับวงจรอื่น (อยู่ที่ Expansion IO2) |
| GPIO21 | **ไม่ได้** | เป็นขาไฟหลังจอ เคยทดสอบกับบอร์ดนี้ใน `labs/Lab14_DHT11_Test` แล้วว่า ต่อ DHT11 ที่ขานี้ทำให้จอกะพริบตามจังหวะอ่านค่า |
| GPIO34, 35, 36, 39 | ไม่ได้ | เป็นขา input-only (อ่านได้อย่างเดียว) แต่ DHT11 ต้องให้บอร์ด "ส่ง" สัญญาณเริ่มต้นด้วย จึงต้องใช้ขาที่เป็น output ได้ |
| ขาที่จอ/จอสัมผัส/SD ใช้ | ไม่ควร | ชนกับอุปกรณ์บนบอร์ด (ดู `board_config.h`) |

**ช่อง Expansion IO2 บนบอร์ด** (ตามเอกสารของโปรเจกต์ ขั้วต่อ 4 ขา ระยะห่าง 1.25 mm)

| ลำดับขา | สัญญาณ | ต่อกับขาของโมดูล DHT11 |
|---|---|---|
| 1 | GND | GND (`-`) |
| 2 | GPIO22 | ไม่ใช้ |
| 3 | **GPIO27** | **DATA** (`S` / `OUT`) |
| 4 | 3.3V | VCC (`+`) |

> **ก่อนต่อจริงให้ตรวจตัวหนังสือที่พิมพ์ข้างขั้วต่อบนบอร์ด** (GND, IO22, IO27, 3V3) เทียบกับตารางนี้ ถ้าไม่ตรงกัน ให้ยึดตัวหนังสือบนบอร์ด
> และลำดับขาของโมดูล DHT11 แต่ละยี่ห้อไม่เหมือนกัน ให้อ่านตัวหนังสือบนแผ่นวงจรของโมดูลเสมอ

### 3.3 DHT11 ทำงานอย่างไร

DHT11 วัดอุณหภูมิและความชื้นสัมพัทธ์ และส่งข้อมูลทางสายเดียว (single-wire) ตามจังหวะเวลาที่กำหนด ตามข้อมูลทั่วไปของ DHT11:

1. บอร์ดดึงเส้น DATA ลง LOW ค้างไว้สักครู่เพื่อสั่ง "เริ่มอ่าน" แล้วปล่อยให้เป็น HIGH
2. เซนเซอร์ตอบกลับด้วยพัลส์ แล้วส่งข้อมูล 40 บิต = 5 ไบต์ (ความชื้นส่วนจำนวนเต็ม + ทศนิยม, อุณหภูมิส่วนจำนวนเต็ม + ทศนิยม, และ **checksum** = ผลบวกของ 4 ไบต์แรก)
3. ไลบรารีตรวจ checksum ถ้าไม่ตรงหรือเซนเซอร์ไม่ตอบ ถือว่าอ่านพลาด

| คุณสมบัติ (ข้อมูลทั่วไปของ DHT11 ไม่ได้วัดกับตัวของคุณ) | ค่า |
|---|---|
| ช่วงวัดอุณหภูมิ / ความชื้น | 0–50 °C / 20–90 %RH |
| ความแม่นยำ | ประมาณ ±2 °C / ±5 %RH |
| ความละเอียด | ตามข้อมูลทั่วไปของ DHT11 คือ 1 °C / 1 %RH แต่ตัวที่ทดสอบกับไลบรารีนี้รายงาน **อุณหภูมิเป็นทศนิยมได้** (เช่น `30.5`, `33.8` จากบอร์ดจริง) ความชื้นโปรแกรมแสดงเป็นจำนวนเต็ม |
| อ่านถี่สุด | ประมาณ 1 ครั้งต่อวินาที (โปรแกรมนี้อ่านทุก 2.5 วินาที) |

**ข้อสรุป:** DHT11 เหมาะกับการเรียนรู้และงานที่ไม่ต้องแม่นมาก ไม่ใช่เครื่องวัดที่เชื่อถือได้ ค่าที่ได้เป็นค่าประมาณ

### 3.4 อ่านค่าในโปรแกรม

```cpp
DHT dht(cyd::DHT11_PIN, DHT11);    // บอกขาข้อมูลและชนิดเซนเซอร์
dht.begin();                        // เตรียมขา (เรียกใน setup)
float h = dht.readHumidity();       // ความชื้น (%)
float t = dht.readTemperature();    // อุณหภูมิ (°C)
if (isnan(h) || isnan(t)) { /* อ่านพลาด */ }
```

| จุดควรรู้ | รายละเอียด |
|---|---|
| ค่าตอนอ่านพลาด | ไลบรารีคืน `NaN` (Not a Number) ซึ่งเอาไปเปรียบเทียบ (เช่น `t > 30`) ไม่ได้ผลที่ถูก ต้องตรวจด้วย `isnan()` ก่อนใช้เสมอ |
| อ่านพลาดเป็นปกติ | DHT11 อ่านพลาดเป็นครั้งคราวได้แม้ต่อถูก ดูจากแนวโน้ม ไม่ใช่ครั้งเดียว โปรแกรมนี้ถือว่า "เซนเซอร์มีปัญหา" เมื่อพลาด **ติดกัน 3 ครั้ง** (`DHT_FAIL_LIMIT`) |
| อ่านถี่เกินไป | ไลบรารีจะคืนค่าเก่าถ้าอ่านซ้ำเร็วกว่าที่เซนเซอร์รับได้ จึงใช้ตัวจับเวลา `millis()` ให้อ่านทุก 2.5 วินาที ไม่ใช้ `delay()` |
| **เวลาที่ใช้อ่าน** | การอ่านเป็นการ "รอ" สัญญาณจากเซนเซอร์ ระหว่างนั้น `loop()` หยุดทำอย่างอื่น **ผลวัดจากบอร์ดจริง:** เมื่ออ่านสำเร็จ ≈ **25.2 ms** (Serial แสดง `read took 25147–25239 us`) เมื่อเซนเซอร์ไม่ตอบ ≈ **59.5 ms** (`read took 59513 us`) |

### 3.5 แหล่งข้อมูล REAL / SIM / NONE: ไม่เอาค่าที่เชื่อถือไม่ได้ไปสั่งงาน

ปัญหา: ถ้าเซนเซอร์เสียหรือหลุด แล้วโปรแกรมยังใช้ "ค่าเก่า" หรือค่าที่ไม่รู้ที่มา สั่งงานต่อ อาจเกิดอันตรายหรือความเข้าใจผิด
โปรแกรมนี้จึงแยก **แหล่งข้อมูล** ชัดเจน และแสดงให้ผู้ใช้เห็นเสมอ

| แหล่ง | ป้าย | ความหมาย | ตัดสินใจใช้เมื่อ (`currentSource()`) |
|---|---|---|---|
| **REAL** | `REAL` (เขียว) | ค่าจากเซนเซอร์ที่อ่านสำเร็จ | อ่านสำเร็จ และผู้ใช้ไม่ได้เลือก SIM |
| **SIM random** | `SIM` (เหลือง) | ค่าจำลองแบบสุ่ม | ผู้ใช้กด `s`, หรือ **อัตโนมัติเมื่อเซนเซอร์ไม่ตอบ** (พลาดติดกัน 3 ครั้ง) ถ้า `SIM_WHEN_NO_SENSOR = true` |
| **SIM sweep** | `SIM` (เหลือง) | ค่าจำลองไล่ขึ้น-ลงสม่ำเสมอ | ผู้ใช้กด `s` สองครั้ง |
| **NONE** | `N/A` (เทา) | ยังไม่มีค่าที่ใช้ได้ | ยังไม่เคยอ่านสำเร็จ และยังไม่ถึงเกณฑ์ ERROR (ช่วง ~7 วินาทีแรก) หรือเซนเซอร์เสียและปิด SIM อัตโนมัติ |

ลำดับการตัดสินใจ: (1) ผู้ใช้เลือก SIM ด้วย `s`? → ใช้ SIM (2) เซนเซอร์ใช้ได้? → REAL (3) เซนเซอร์เสียและเปิด fallback? → SIM random (4) นอกนั้น → NONE

**หลักคิดสำคัญ:** ค่าจำลองต้องมีป้ายบอกเสมอ ไม่ให้ใครเข้าใจผิดว่าเป็นค่าที่วัดจริง (และ Serial ก็พิมพ์ `src=REAL` หรือ `src=SIM-RANDOM` ทุกบรรทัดสถานะ)

**SIM random (เดินสุ่ม)**: ทุก 1 วินาที อุณหภูมิเปลี่ยนไปสุ่มระหว่าง −1.5 ถึง +1.5 °C ความชื้น ±3 % แล้วบีบให้อยู่ในช่วง 24–38 °C และ 40–90 %
แต่ละก้าวมีส่วนเบี่ยงเบนมาตรฐานราว 1.5 ÷ √3 ≈ 0.87 °C หลัง 60 ก้าวอุณหภูมิเปลี่ยนจากจุดเริ่มต้นได้ราว ±6.7 °C (คำนวณจากทฤษฎีการเดินสุ่ม) จึงผ่านเกณฑ์พัดลมได้ภายในไม่กี่นาที ค่า "ชนขอบ" (เช่นค้าง 38.0 °C) เกิดได้เพราะถูกบีบให้อยู่ในช่วง

**SIM sweep (คลื่นสามเหลี่ยม)**: อุณหภูมิ = 24 + f × (38 − 24) เมื่อ f ไล่ 0 → 1 → 0 รอบละ 60 วินาที (ความชื้นไล่สวนทาง)

| เหตุการณ์ใน 1 รอบ (60 s) | เวลาที่คำนวณ |
|---|---|
| ขึ้นถึง 30 °C (พัดลมเริ่มหมุน) | f = 6 ÷ 14 → 0.4286 × 30 s ≈ **12.9 s** |
| ขึ้นถึง 36 °C (duty 100%) | 12 ÷ 14 × 30 ≈ **25.7 s** |
| ลงถึง 28 °C (พัดลมหยุด) | 60 − (4 ÷ 14 × 30) ≈ **51.4 s** |

(ตรวจแล้วจากบอร์ดจริงว่าพัดลมเปิดที่ ≈ 30.1 °C และปิดที่ 28.0 °C ในรอบ sweep)

### 3.6 ตรรกะพัดลมและ hysteresis

**ปัญหา:** ถ้าใช้เกณฑ์เดียว (เปิดเมื่อ ≥ 30, ปิดเมื่อ < 30) พออุณหภูมิแกว่งรอบ 30 °C พัดลมจะเปิด-ปิดสลับถี่ๆ (สั่น) ทำให้ LED/พัดลมจริง/รีเลย์เสียหายหรือน่ารำคาญ

**แก้ด้วย hysteresis:** ใช้ **เกณฑ์เปิดกับเกณฑ์ปิดต่างกัน** (`ON = 30`, `OFF = 28`) ช่วง 28–30 °C พัดลม "คงสถานะเดิม" (ตัวแปร `fanOn` จดจำ)

```
อุณหภูมิ
 36 ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ duty 100% (MAX)
 30 ─ ─ ─ ─ ─ ─ ─ ┌── ถึงจุดนี้ พัดลม "เปิด" (duty เริ่ม 30%)
 29               │   ช่วง hysteresis: คงสถานะเดิม
 28 ─ ─ ─ ─ ─ ─ ─ └── ลงถึงจุดนี้ พัดลม "ปิด"
```

| สถานะก่อนหน้า | อุณหภูมิ | ผลลัพธ์ |
|---|---|---|
| ปิด | 29 °C | ยังปิด (ยังไม่ถึง 30) |
| ปิด | 30 °C | **เปิด** |
| เปิด | 29 °C | ยังเปิด (ยังไม่ลงถึง 28) |
| เปิด | 28 °C | **ปิด** |

**ผลวัดจากบอร์ดจริง (SIM sweep 1 รอบ):** `[FAN] OFF -> ON at 30.1 C` … ขณะขาขึ้นผ่าน 29.1 °C พัดลมยังหยุด … ลงมาถึง 28.2 °C พัดลมยังหมุนที่ duty ต่ำสุด 30% … `[FAN] ON -> OFF at 28.0 C`

**ผลของ hysteresis (จากแบบจำลองบนคอมพิวเตอร์ ไม่ใช่การวัดบนบอร์ด):** เมื่อจำลองตรรกะเดียวกันกับ SIM random เป็นเวลา 300 วินาที 2000 รอบ
ค่าเฉลี่ยจำนวนครั้งที่พัดลมเปลี่ยนสถานะคือ **ราว 6 ครั้ง** เมื่อ `ON=30, OFF=28` และ **ราว 16 ครั้ง** เมื่อ `ON=OFF=30` (ไม่มี hysteresis) ตัวเลขนี้ขึ้นกับการสุ่มและเป็นเพียงภาพรวม

**ความเร็วพัดลมตามอุณหภูมิ** (เมื่อเปิด): `duty = 30 + (T − 30) ÷ (36 − 30) × 70` บีบให้อยู่ใน 30–100%

| อุณหภูมิ T | (T−30)÷6 | duty | `value` = (duty×255+50)÷100 |
|---|---|---|---|
| 30 °C | 0 | 30% | 77 |
| 31 | 0.167 | 42% | 107 |
| 32 | 0.333 | 53% | 135 |
| 33 | 0.5 | 65% | 166 |
| 34 | 0.667 | 77% | 196 |
| 35 | 0.833 | 88% | 224 |
| 36 ขึ้นไป | 1 | 100% | 255 |

(ตัวเลข duty ที่บอร์ดแสดงอาจต่าง ±1 เพราะอุณหภูมิบนจอปัดทศนิยม 1 ตำแหน่ง)

## 6. แบบฝึกหัด

ก่อนแก้ทุกข้อให้จดสภาพเดิมไว้เทียบ ทำทีละข้อ (แก้ → build/upload → ดูผล → ย้อนกลับ) ใช้ SIM ช่วยทดสอบได้ถ้าไม่มีความร้อนจริง

### ระดับ 1 — พื้นฐาน (ข้อละ 5 คะแนน)

**ข้อ 1 — วาดแผนผังการต่อสาย (บนกระดาษ):** วาดแผนผังวงจร DHT11 ต่อกับบอร์ด ระบุชื่อขา สีสาย และ **ขีดฆ่าขา GPIO21 พร้อมเขียนเหตุผล** ตอบเพิ่ม: ถ้าใช้เซนเซอร์เปล่า 4 ขาแทนโมดูล ต้องเพิ่มอะไรเข้าไปในวงจร?

**ข้อ 2 — ปรับเกณฑ์ให้เหมาะกับห้องของคุณ:** ตั้ง `FAN_ON_TEMP_C = 27` และ `FAN_OFF_TEMP_C = 25` (หรือค่าที่เหมาะกับอุณหภูมิห้องของคุณ) ทดสอบด้วย SIM sweep จดเวลาที่พัดลมเปิด/ปิดใหม่ (คำนวณล่วงหน้าด้วยวิธีหัวข้อ 3.5 แล้วเทียบ)

**ข้อ 3 — คำนวณ duty:** ใช้ค่าเริ่มต้น (ON 30, FULL 36, MIN 30%) หา duty และ `value` ของ 31, 32, 34, 35 °C (ตารางหัวข้อ 3.6 มีให้บางค่า) แล้วตรวจกับ SIM sweep ว่าตัวเลขใน Serial ตรงกันหรือไม่ (ต่างกันได้ ±1)

### ระดับ 2 — ทดลองเข้าใจหลักการ (ข้อละ 7 คะแนน)

**ข้อ 4 — ลบ hysteresis:**

1. **ทำนายก่อน:** ถ้าตั้ง `FAN_OFF_TEMP_C = FAN_ON_TEMP_C = 30` และใช้ SIM random พัดลมจะเปลี่ยนสถานะบ่อยขึ้นหรือน้อยลง เพราะอะไร?
2. แก้ค่า upload ใช้ SIM random (พิมพ์ `s` ให้เป็น `SIM-RANDOM` หรือปล่อยให้ fallback เอง) นับจำนวนบรรทัด `[FAN] ... -> ...` ใน 5 นาที
3. คืนค่าเดิม (30 / 28) แล้วนับอีกครั้ง 5 นาที (ค่าสุ่มจึงได้ตัวเลขไม่เท่ากันทุกครั้ง ทำ 2–3 รอบแล้วเฉลี่ย)
4. อธิบายสาเหตุ และเปรียบเทียบกับตัวเลขจากแบบจำลองในหัวข้อ 3.6 (ราว 6 ครั้งเทียบกับ 16 ครั้ง ต่อ 300 วินาที)

**ข้อ 5 — ความเร็วพัดลมแบบไม่เป็นเส้นตรง:** แก้ `dutyForTemp()` ให้ใช้ `fraction × fraction` (ยกกำลังสอง) แทน `fraction` เพื่อให้ช่วงอุณหภูมิต่ำเร่งช้า ช่วงสูงเร่งเร็ว
ทำนายก่อน: T = 33 °C ได้ duty เท่าไร (เดิม 65%)? แล้วทดสอบด้วย SIM sweep เทียบ

**ข้อ 6 — Fail-safe:** ตั้ง `SIM_WHEN_NO_SENSOR = false` แล้วแก้ `updateFanAuto()` ให้เมื่อ `sensorError` เป็นจริงในโหมด AUTO พัดลม **เปิดที่ duty 60%** แทนการหยุด (ค่าปลอดภัยแบบเปิดไว้)
ทดสอบโดยไม่ต่อสาย DATA ผล: ตอบ (ก) ผลที่เห็นหลังพลาดติดกัน 3 ครั้ง (ข) ยกตัวอย่างงานที่ควรเลือก "เปิดไว้เมื่อเสีย" 1 งาน และ "ปิดไว้เมื่อเสีย" 1 งาน พร้อมเหตุผล

### ระดับ 3 — ออกแบบเอง (ข้อละ 10 คะแนน)

**ข้อ 7 — ค่าต่ำสุด/สูงสุด:** เพิ่มตัวแปรเก็บอุณหภูมิ **ต่ำสุดและสูงสุด** ที่เห็นตั้งแต่เปิดเครื่อง พิมพ์ลง Serial ทุกครั้งที่พิมพ์สถานะ (บรรทัด `[MINMAX] min=… max=…`) และเพิ่มคำสั่ง `r` ล้างค่า
ข้อกำหนด: ไม่นับค่า `NaN`, ไม่ใช้ `delay()`, ตัวแปรเริ่มต้นเป็น `NAN` แล้วถูกกำหนดค่าเมื่อเห็นค่าแรก
คำใบ้: เขียนฟังก์ชัน `trackMinMax(float t)` แล้วเรียกในช่วงเดียวกับ `updateFanAuto`

**ข้อ 8 (โบนัส +10) — ท้าทาย:** เลือกอย่างใดอย่างหนึ่ง
(ก) วาดไอคอนพัดลมหมุนบนจอ โดยความเร็วหมุนตาม duty (ต้องลบ/วาดเฉพาะพื้นที่ไอคอน ห้ามล้างจอทั้งหน้า)
(ข) วาดกราฟอุณหภูมิย้อนหลัง 60 ค่าไว้บนจอ (ต้องหาพื้นที่ว่างเอง เช่นลดขนาดการ์ดพัดลม)
ส่งโค้ดที่เพิ่มและภาพถ่ายจอ

## 11. เช็คลิสต์ผ่าน Lab

- [ ] ต่อ DHT11 ถูกต้อง (VCC → 3.3V, GND → GND, DATA → GPIO27) และอธิบายได้ว่าทำไมไม่ใช้ GPIO21
- [ ] เห็นค่าอุณหภูมิและความชื้นบนจอและ Serial และบอกได้ว่าเป็น `REAL` หรือ `SIM` จากป้าย
- [ ] ทดสอบพัดลมด้วย SIM sweep และอธิบายได้ว่าเกณฑ์ ON/OFF ต่างกันเพื่ออะไร (hysteresis)
- [ ] คำนวณ duty ของพัดลมตามอุณหภูมิด้วยมือได้ถูกต้อง
- [ ] ดูผลเมื่อเซนเซอร์ไม่ตอบ และอธิบายได้ว่าโปรแกรมรับมืออย่างไร (นับพลาดติดกัน, ป้าย SIM/NONE, LED แดง)
- [ ] สลับ AUTO / MANUAL ได้ และบอกได้ว่า duty มาจากไหนในแต่ละโหมด
- [ ] ทำแบบฝึกหัดอย่างน้อยระดับ 1–2 ครบ
