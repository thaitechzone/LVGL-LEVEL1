## 1. เป้าหมายการเรียนรู้

เมื่อจบใบงานนี้ ผู้เรียนต้องทำได้ทุกข้อ

1. อธิบายได้ว่า NTP คืออะไร ทำไมบอร์ดที่ไม่มีนาฬิกา (RTC) ต้องขอเวลาจากอินเทอร์เน็ต
2. อธิบาย epoch (Unix time), UTC และเขตเวลา UTC+7 และแปลง epoch ↔ วันเวลาด้วยมือได้
3. ใช้ `configTime()`, `time()`, `localtime_r()`, `strftime()` ได้ และเลือกรูปแบบวันเวลาที่ต้องการได้
4. อธิบายได้ว่าทำไมก่อน sync ต้องไม่แสดงหรือบันทึกเวลา (ปี 1970) และโปรแกรมตรวจความน่าเชื่อถือของเวลาอย่างไร
5. อ่านโค้ด state machine ของ WiFi และ NTP รวมถึง callback และตัวแปร `volatile` ได้
6. ทดสอบเส้นทางสำเร็จ / ไม่มี WiFi / ขอเวลาไม่สำเร็จ และอ่านผลจากจอและ Serial ได้
7. ดัดแปลงโปรแกรมตามแบบฝึกหัด (รูปแบบเวลา, เขตเวลา, STALE, timestamp, ปีพุทธศักราช) ได้
8. เข้าใจการเตรียมเวลาจริงสำหรับ Lab ถัดไป (บันทึกข้อมูลลง SD card)

## 3. ความรู้พื้นฐานที่ต้องเข้าใจก่อนลงมือ

### 3.1 ทำไมต้องใช้ NTP

บอร์ด ESP32 ไม่มีนาฬิกาที่มีแบตเตอรี่ (RTC) เมื่อไฟดับ เวลาหายไปหมด ตอนเปิดเครื่องใหม่นาฬิกาในตัวเริ่มที่ **1 มกราคม 1970**
ถ้าจะรู้ว่า "ตอนนี้กี่โมง" ต้องขอจากภายนอก วิธีที่นิยมคือ **NTP (Network Time Protocol)** ขอเวลาจากเซิร์ฟเวอร์ผ่านอินเทอร์เน็ต

| เรื่อง | ข้อมูล |
|---|---|
| โปรโตคอล / พอร์ต | NTP ใช้ UDP พอร์ต **123** บางเครือข่าย (เช่นองค์กรหรือโรงเรียน) บล็อกพอร์ตนี้ ทำให้ต่อ WiFi ได้แต่ขอเวลาไม่ได้ |
| เซิร์ฟเวอร์ที่ใช้ | `pool.ntp.org` (หลัก) และ `time.nist.gov` (สำรอง) เป็นชื่อโดเมน ต้องมี DNS ทำงาน |
| เวลาที่ได้ | เป็นเวลา **UTC** (เวลาอ้างอิงสากล) ต้องแปลงเป็นเวลาท้องถิ่นเอง |
| ความแม่นยำ | ตามข้อมูลทั่วไป NTP ผ่านอินเทอร์เน็ตให้ความคลาดเคลื่อนในระดับไม่กี่สิบมิลลิวินาที (ผู้เขียนไม่ได้วัดความแม่นยำละเอียดระดับนี้ ที่ตรวจคือบอร์ดต่างจากนาฬิกาคอมพิวเตอร์ไม่เกิน ~1 วินาที ซึ่งเป็นความละเอียดของการเทียบ) |

### 3.2 epoch, UTC และเขตเวลา

| คำ | ความหมาย |
|---|---|
| **epoch (Unix time)** | จำนวนวินาทีนับจาก 1 มกราคม 1970 00:00:00 UTC เก็บในตัวแปรชนิด `time_t` |
| **UTC** | เวลาอ้างอิงสากล ไม่ขึ้นกับประเทศ |
| **เขตเวลา** | ส่วนต่างจาก UTC ไทยคือ **+7 ชั่วโมง** = 7 × 3600 = **25,200 วินาที** ไทยไม่มีเวลาออมแสง (DST) |
| **เวลาท้องถิ่น** | UTC + ส่วนต่างเขตเวลา |

**ตัวอย่างการแปลง** (คำนวณแล้ว)

| epoch | UTC | UTC+7 (ไทย) |
|---|---|---|
| 1,700,000,000 | 2023-11-14 22:13:20 | 2023-11-15 05:13:20 |
| 1,760,000,000 | 2025-10-09 08:53:20 | 2025-10-09 15:53:20 |

สังเกต: 1,700,000,000 คือค่า `SANE_EPOCH` ในโปรแกรม เวลาที่ต่ำกว่านี้ (ก่อนพฤศจิกายน 2023) ถือว่า "ยังไม่ได้ตั้งเวลา" เพราะเวลาจริงตอนใช้งานไม่มีทางเก่าขนาดนั้น
ก่อน sync นาฬิกาในตัวจะอยู่ใกล้ epoch 0 (ปี 1970) ซึ่งต่ำกว่าค่านี้มาก

ข้อมูลที่ใช้คำนวณ: 1 วัน = 86,400 วินาที, 1 ชั่วโมง = 3,600 วินาที, 1 ปี (365 วัน) = 31,536,000 วินาที

### 3.3 ตั้งเขตเวลาและจัดรูปแบบเวลาในโปรแกรม

```cpp
configTime(7 * 3600, 0, "pool.ntp.org", "time.nist.gov");  // เขตเวลา +7, ไม่มี DST, เซิร์ฟเวอร์หลัก/สำรอง
time_t t = time(nullptr);          // epoch ตอนนี้
struct tm local;
localtime_r(&t, &local);           // แปลงเป็นเวลาท้องถิ่น (UTC+7)
strftime(text, sizeof(text), "%H:%M:%S", &local);   // จัดรูปแบบเป็นข้อความ
```

| รหัสใน `strftime` | ความหมาย | ตัวอย่าง |
|---|---|---|
| `%H` `%M` `%S` | ชั่วโมง (00–23) นาที วินาที | `19:49:08` |
| `%I` `%p` | ชั่วโมงแบบ 12 ชั่วโมง และ AM/PM | `07:49:08 PM` |
| `%Y` `%m` `%d` | ปี (ค.ศ.) เดือน (01–12) วัน | `2026-10-09` |
| `%a` `%b` | ชื่อวัน / เดือนแบบย่อ (ภาษาอังกฤษ) | `Fri`, `Oct` |

ฟอนต์บนจอไม่มีอักษรไทย จึงแสดงชื่อวัน/เดือนเป็นภาษาอังกฤษ และปีเป็นตัวเลข

### 3.4 สถานะ WiFi และ NTP (state machine สองตัวทำงานคู่กัน)

| สถานะ WiFi | ความหมาย | ไปสถานะถัดไปเมื่อ |
|---|---|---|
| `NotConfigured` | ไม่มี `secrets.h` หรือ SSID ว่าง | (ไม่ไปไหน) |
| `Connecting` | กำลังต่อ | ต่อสำเร็จ → `Connected` / เกิน 15 วินาที → `Failed` |
| `Connected` | ต่อแล้ว | หลุด → ต่อใหม่ (`Connecting`) |
| `Failed` | ต่อไม่สำเร็จ | รอ 5 วินาที แล้วลองใหม่ |

| สถานะ NTP | ความหมาย | ไปสถานะถัดไปเมื่อ |
|---|---|---|
| `Idle` | ยังไม่ได้ขอเวลา (รอ WiFi) | WiFi ต่อแล้ว → เริ่มขอเวลา (`Syncing`) |
| `Syncing` | ขอเวลาแล้ว รอคำตอบ | ได้เวลา → `Synced` / เกิน 20 วินาที → `Failed` |
| `Synced` | ได้เวลาแล้ว | (ไลบรารีขอซ้ำเองเป็นระยะ ได้เวลาใหม่ก็นับ `syncCount` เพิ่ม) |
| `Failed` | ขอไม่สำเร็จ | รอ 30 วินาที แล้วขอใหม่ |

**callback:** ไลบรารี SNTP เรียกฟังก์ชัน `onTimeSync()` ทุกครั้งที่ได้เวลาจากเซิร์ฟเวอร์ ฟังก์ชันนี้ทำงานใน **task ของเครือข่าย** (คนละ task กับ `loop()`)
จึงทำแค่ตั้งธง `syncEvent = true` แล้วให้ `loop()` มาจัดการต่อ ธงนี้ประกาศเป็น `volatile` เพราะมีสอง task อ่าน/เขียนร่วมกัน (บอกคอมไพเลอร์ว่าค่าเปลี่ยนได้ตลอดเวลา อย่าแคชไว้)

### 3.5 เวลาที่ "น่าเชื่อถือ": ก่อน sync ต้องไม่ใช้

```cpp
bool timeValid() { return syncCount > 0 && time(nullptr) >= SANE_EPOCH; }
```

ใช้ **สองเงื่อนไขร่วมกัน** คือ (1) เคย sync สำเร็จแล้ว (2) เวลาในเครื่องไม่ใช่ค่าเริ่มต้นแบบ 1970
หลักคิดเดียวกับ REAL/SIM ใน Lab 6: อย่านำค่าที่เชื่อถือไม่ได้ไปแสดงหรือบันทึกเหมือนเป็นค่าจริง ก่อน sync หน้าจอแสดง `--:--:--` และ Serial บอก `NOT SYNCED`

**STALE (เก่าเกินไป):** เมื่อ sync ล่าสุดเก่ากว่า `NTP_RESYNC_MS × NTP_STALE_FACTOR` (ค่าเริ่มต้น 1 ชั่วโมง × 2 = 2 ชั่วโมง) ป้ายเป็น `STALE` สีเหลือง เพราะนาฬิกาในตัวอาจคลาดเคลื่อนสะสม (ผู้เขียนยังไม่ได้วัดว่าคลาดเคลื่อนเท่าไร)

### 3.6 นาฬิกาเดินต่อเอง และ uptime ต่างจากเวลาจริง

- หลัง sync แล้ว **ไม่ต้องขอเวลาทุกวินาที** นาฬิกาในตัวเดินต่อเอง จึงเดินต่อได้แม้ WiFi หลุด ไลบรารีขอเวลาซ้ำเองเป็นระยะ (ค่าเริ่มต้นทุก 1 ชั่วโมง) เพื่อแก้ความคลาดเคลื่อนที่สะสม
- `millis()` คือ **uptime** (เวลาตั้งแต่เปิดเครื่อง) รีเซ็ตเป็น 0 เมื่อไฟดับ ใช้บอก "ผ่านไปนานเท่าไร" แต่บอก "ตอนนี้กี่โมง" ไม่ได้

| | `millis()` | เวลาจริง (`time()`) |
|---|---|---|
| ตอบคำถาม | ผ่านไปนานเท่าไรแล้ว | ตอนนี้กี่โมง วันที่เท่าไร |
| หลังไฟดับ | เริ่มนับใหม่ที่ 0 | ต้องขอ NTP ใหม่ |
| ใช้ใน Lab นี้ | จับเวลางานย่อย (อ่านเซนเซอร์ วาดจอ) | แสดงนาฬิกา, ติด timestamp |

### 3.7 `makeTimestamp()` — เตรียมสำหรับ Lab ถัดไป

```cpp
char stamp[24];
bool ok = makeTimestamp(stamp, sizeof(stamp));
// ok = true  -> stamp = "2026-10-09 19:55:54"
// ok = false -> stamp = "NOT_SYNCED"
```

Lab นี้ใช้ติดเวลาจริงให้บรรทัดเหตุการณ์พัดลมใน Serial เช่น `[FAN] OFF -> ON at 30.7 C  @ 2026-10-09 19:55:54` (ตัวอย่างจริงจากบอร์ดต้นแบบ)
Lab ถัดไป (SD datalogger) จะใช้ฟังก์ชันนี้ติดเวลาจริงให้ทุกแถวของไฟล์ log ต้องตัดสินใจไว้ล่วงหน้าว่าถ้า `NOT_SYNCED` จะทำอย่างไร (บันทึกพร้อมเครื่องหมาย หรือรอ ไม่ทิ้งเวลาปี 1970 ลงไฟล์)

## 6. แบบฝึกหัด

### ระดับ 1 — พื้นฐาน (ข้อละ 5 คะแนน)

**ข้อ 1 — รูปแบบวันที่:** แก้รูปแบบวันที่ในการ์ดนาฬิกาเป็น `DD/MM/YYYY` (เช่น `09/10/2026`) แล้วตอบเพิ่ม (คำนวณด้วยมือ ไม่ต้องลองบนบอร์ด): ถ้าเปลี่ยนเวลาเป็นแบบ 12 ชั่วโมง `%I:%M:%S %p` (เช่น `07:49:08 PM`) ที่ฟอนต์ 4 ขยาย 2 เท่า ข้อความกว้างกี่พิกเซล และจะชนกับป้ายสถานะ (เริ่มที่ x = 220 โดยเวลาเริ่มที่ x = 16) หรือไม่? (ใช้ความกว้างตัวอักษรในหัวข้อ 3.8)

**ข้อ 2 — เขตเวลา:** ตั้ง `GMT_OFFSET_SEC = 9 * 3600` (ญี่ปุ่น) ดูว่าเวลาเปลี่ยนไปกี่ชั่วโมง ข้อสังเกต: ป้ายชื่อการ์ดยังเขียนว่า `TIME (UTC+7)` อยู่หรือไม่? ถ้ายัง ให้แก้ให้ป้ายชื่อคำนวณจาก `GMT_OFFSET_SEC` เอง (คำใบ้: `snprintf` กับ `%+ld` และ `GMT_OFFSET_SEC / 3600`) แล้วคืนค่าเป็น 7 ชั่วโมง

**ข้อ 3 — คำนวณ epoch ด้วยมือ:** (ก) แปลง epoch 1,760,000,000 เป็นวันเวลา UTC และ UTC+7 (ตารางหัวข้อ 3.2 มีค่าอื่นให้เทียบวิธีคิด) โดยใช้ว่า 1 วัน = 86,400 วินาที (ข) ถ้าบอร์ดแสดงเวลา 19:49:08 (UTC+7) นั่นคือกี่โมงเวลา UTC (ค) 7 ชั่วโมงเท่ากับกี่วินาที (ง) ถ้า sync ล่าสุดเมื่อ millis() = 600,000 และตอนนี้ millis() = 3,900,000 sync เมื่อกี่นาทีก่อน

### ระดับ 2 — ทดลองเข้าใจหลักการ (ข้อละ 7 คะแนน)

**ข้อ 4 — ขอเวลาไม่สำเร็จ:**

1. **ทำนายก่อน:** ถ้าเปลี่ยน `NTP_SERVER_1` และ `NTP_SERVER_2` เป็นชื่อที่ไม่มีอยู่จริง (เช่น `no-such-ntp.invalid`) สถานะ NTP จะวนอย่างไร จอแสดงอะไร และ Serial พิมพ์อะไร
2. แก้ค่า (แนะนำลด `NTP_TIMEOUT_MS` เหลือ 8000 และ `NTP_RETRY_MS` เหลือ 12000 เพื่อไม่ต้องรอนาน) แล้ว upload ดูผล 1–2 นาที
3. คืนค่าเดิม

**ข้อ 5 — ป้าย STALE:** ตั้ง `NTP_RESYNC_MS = 60000` และ `NTP_STALE_FACTOR = 1` ทำนายก่อนว่า ถ้า WiFi ใช้งานได้ปกติ ป้ายจะเป็น STALE หรือไม่ และถ้าปิด WiFi ของเราเตอร์ไว้ 2 นาที ป้ายและสีเวลาจะเป็นอย่างไร แล้วทดลอง (ผลจริงขึ้นกับว่ารอบ sync ของไลบรารีเกิดขึ้นเมื่อไร ให้บันทึกที่เห็น) คืนค่าเดิม

**ข้อ 6 — จำเวลาที่พัดลมเปิดล่าสุด:** เพิ่มตัวแปร `lastFanOnStamp` (ข้อความเวลาจริงที่พัดลมเปิดล่าสุด เริ่มต้น `"-"`) บันทึกค่าเมื่อพัดลมเปลี่ยนจากปิดเป็นเปิด และให้คำสั่ง `t` พิมพ์บรรทัด `[TIME] fan last turned ON at …` เพิ่ม (คำใบ้: `makeTimestamp()` ใน `updateFanAuto()`) ทดสอบด้วย `s` สองครั้ง (SIM sweep) แล้วพิมพ์ `t`

### ระดับ 3 — ออกแบบเอง (ข้อละ 10 คะแนน)

**ข้อ 7 — บรรทัดล่างสลับแสดง uptime:** แก้ `updateStatusLine()` ให้บรรทัดล่างสุดสลับระหว่างสถานะ WiFi/NTP เดิม กับ `uptime HH:MM:SS` ทุก 5 วินาที (คำใบ้: `(now / 5000) % 2`) โดยไม่ใช้ `delay()` ตอบเพิ่ม: uptime กับเวลาจริงต่างกันอย่างไร และถ้ากด RESET แล้ว uptime ที่แสดงจะเป็นอย่างไร ส่วนเวลาจริงจะเป็นอย่างไร (ต้องรอ sync ก่อนหรือไม่)

**ข้อ 8 (โบนัส +10) — วันที่แบบพุทธศักราช:** แสดงวันที่เป็นรูปแบบ `DD/MM/พ.ศ.` (เช่น `09/10/2569`) โดย พ.ศ. = ค.ศ. + 543 (ฟอนต์ไม่มีอักษรไทยจึงแสดงเฉพาะตัวเลข) คำใบ้: ใช้ `localtime_r` แล้วอ่าน `tm_mday`, `tm_mon + 1`, `tm_year + 1900 + 543` ส่งโค้ดที่เพิ่มและภาพถ่ายจอ
