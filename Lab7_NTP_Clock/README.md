# Level 1 / Lab 7 — NTP Clock: เวลาจริงจากอินเทอร์เน็ต พร้อมค่า DHT11 และพัดลมจาก Lab 6

Lab นี้ต่อยอดจาก Lab 6 โดยเพิ่ม **นาฬิกาเวลาจริง**: ต่อ WiFi แล้วขอเวลาจากเซิร์ฟเวอร์ **NTP** แสดงวัน-เวลาไทย (UTC+7) บนจอ
ในขณะที่ยังแสดงอุณหภูมิ/ความชื้น (ป้าย REAL/SIM) และควบคุมพัดลมจำลองด้วย PWM เหมือน Lab 6 บอร์ดไม่มีนาฬิกา (RTC) เวลาจึงหายทุกครั้งที่ไฟดับ
เมื่อได้เวลาจริงแล้ว Lab 8 (บันทึกข้อมูลลง SD card) จะติดเวลาจริงให้ทุกแถวของ log ได้

> **สถานะการตรวจสอบ (อ่านก่อน):** โปรแกรม build ผ่านและทดสอบบนบอร์ดจริงแล้ว: เส้นทางไม่มี WiFi, ต่อ WiFi + sync เวลาจริง (เทียบกับนาฬิกาคอมพิวเตอร์ ต่างกันไม่เกิน ~1 วินาที),
> คำสั่ง `n`/`t`, เส้นทาง "ขอเวลาไม่สำเร็จแล้วลองใหม่", การ sync ซ้ำอัตโนมัติ (ทดสอบด้วยรอบสั้น) และ **หน้าจอ** (ผู้พัฒนาส่งภาพถ่ายยืนยันว่าทุกอย่างแสดงครบถูกต้อง)
> **ส่วนที่ยังไม่ได้ตรวจ:** LED เขียว, ปุ่ม BOOT, พฤติกรรมเมื่อ WiFi หลุดระหว่างใช้งาน, ป้าย STALE, รอบ sync จริง 1 ชั่วโมง และการคลาดเคลื่อนของนาฬิกา ดูตาราง "สิ่งที่ยังไม่ได้ยืนยัน" ท้ายไฟล์
> ภาพ ASCII วาดประกอบ ข้อความ Serial ที่ระบุว่าเป็นของจริงมาจากบอร์ดต้นแบบ (ปิดบังชื่อ WiFi แล้ว)

## สิ่งที่จะได้เรียน

1. **NTP คืออะไร:** โปรโตคอลขอเวลาจากเซิร์ฟเวอร์ผ่านอินเทอร์เน็ต เวลาอ้างอิงเป็น UTC (ใช้ UDP พอร์ต 123)
2. **epoch และเขตเวลา:** เวลาในคอมพิวเตอร์เก็บเป็น "วินาทีนับจาก 1 ม.ค. 1970 (UTC)" แล้วแปลงเป็นเวลาท้องถิ่น (UTC+7) ตอนแสดง
3. **ใช้ `configTime()`, `time()`, `localtime_r()`, `strftime()`** จัดรูปแบบวันเวลา
4. **ตรวจว่าเวลาเชื่อถือได้ก่อนใช้:** ก่อน sync เวลาในเครื่องเป็นปี 1970 ต้องไม่นำไปแสดงหรือบันทึก (ต่อเนื่องจากหลักคิด REAL/SIM ใน Lab 6)
5. **สถานะการ sync:** ยังไม่ sync / กำลัง sync / sync แล้ว / ล้มเหลวแล้วลองใหม่ / เก่าเกินไป (STALE) พร้อม callback เมื่อได้เวลา
6. **uptime ต่างจากเวลาจริง:** `millis()` นับตั้งแต่เปิดเครื่อง ส่วนเวลาจริงต้องมาจากภายนอก
7. เตรียมฟังก์ชัน `makeTimestamp()` ไว้ใช้ติดเวลาจริงให้ข้อมูล (Lab 8)

## วงจร

| ส่วนบนจอ | ความหมาย |
|---|---|
| เวลาตัวใหญ่ + วันที่ | เวลาท้องถิ่น UTC+7 ถ้ายังไม่ sync แสดง `--:--:--` สีเทา (ไม่แสดงปี 1970) ถ้า STALE เป็นสีเหลือง |
| ป้ายสถานะ | `SYNCED` (เขียว) sync แล้ว, `SYNCING` (น้ำเงิน) กำลังขอเวลา, `WIFI...` (น้ำเงิน) กำลังต่อ WiFi, `NO SYNC` (แดง) ขอเวลาไม่สำเร็จ จะลองใหม่เอง, `NO WIFI` (แดง) ไม่ได้ตั้งค่าหรือต่อไม่ได้, `STALE` (เหลือง) sync ล่าสุดเก่าเกิน 2 ชั่วโมง |
| `sync #N` | sync สำเร็จมาแล้วกี่ครั้ง |
| การ์ด TEMP / HUMIDITY | ค่าจาก DHT11 พร้อมป้าย `REAL` (เขียว) หรือ `SIM` (เหลือง) เหมือน Lab 6 |
| การ์ด FAN | duty ของพัดลมจำลอง, `RUNNING`/`STOPPED`, โหมด `AUTO`/`MANUAL`, แถบ duty |
| บรรทัดล่าง | `WiFi -45dBm  synced 12s ago`, `WiFi connecting...`, `WiFi failed - retrying`, `Set WIFI_SSID in include/secrets.h` |
| จุดกะพริบมุมล่างขวา | `loop()` ยังทำงานอยู่ |

**LED บนบอร์ด** (ขาจริงใน `board_config.h`): **เขียว** (GPIO16) = sync เวลาสำเร็จแล้ว, **น้ำเงิน** (GPIO17, PWM) = พัดลมจำลอง, **แดง** (GPIO4) = เซนเซอร์มีปัญหา

## วิธีควบคุม

| วิธี | ทำอะไร |
|---|---|
| ปุ่ม **BOOT** หรือ `m` | สลับ AUTO ↔ MANUAL (พัดลม) |
| `+` / `-` / `0`–`9` | MANUAL: ปรับ duty ของพัดลม |

| `h` | แสดงวิธีใช้ |

## ความรู้ใหม่ใน Lab นี้

### เวลาในคอมพิวเตอร์: epoch, UTC และเขตเวลา

| คำ | ความหมาย |
|---|---|
| **epoch (Unix time)** | จำนวนวินาทีนับจาก 1 มกราคม 1970 00:00:00 UTC (`time_t`) ก่อนตั้งเวลา ESP32 จะเป็นค่าใกล้ 0 = ปี 1970 |
| **UTC** | เวลาอ้างอิงสากล ไม่ขึ้นกับประเทศ |
| **เขตเวลา (timezone)** | ส่วนต่างจาก UTC: ไทย = **+7 ชั่วโมง** (+25,200 วินาที) ไม่มีเวลาออมแสง (DST) |
| `configTime(7*3600, 0, server1, server2)` | ตั้งเขตเวลา และเริ่มขอเวลาจากเซิร์ฟเวอร์ |
| `time(nullptr)` | เวลาปัจจุบัน (epoch) |
| `localtime_r()` + `strftime()` | แปลง epoch เป็นเวลาท้องถิ่น และจัดรูปแบบ เช่น `%H:%M:%S`, `%a %d %b %Y` |

### การทำงานของโปรแกรม

1. ต่อ WiFi (state machine แบบย่อจาก Lab 3: ต่อ → ถ้าไม่สำเร็จใน 15 วินาที ลองใหม่ทุก 5 วินาที)
2. เมื่อ WiFi ต่อแล้ว เรียก `configTime()` ขอเวลาจาก `pool.ntp.org` (สำรอง `time.nist.gov`) สถานะเป็น `SYNCING`
3. ไลบรารี SNTP เรียก **callback** `onTimeSync()` เมื่อได้เวลา (ทำงานใน task ของเครือข่าย จึงแค่ตั้งธง `syncEvent`) แล้ว `loop()` มาจัดการ: นับ `syncCount`, จดเวลา sync, สถานะเป็น `SYNCED`
4. ถ้าไม่ได้เวลาภายใน 20 วินาที → `NO SYNC` แล้วขอใหม่ทุก 30 วินาที
5. ไลบรารีขอเวลาซ้ำเองทุก 1 ชั่วโมง (`sntp_set_sync_interval`) ถ้า sync ล่าสุดเก่ากว่า 2 ชั่วโมง ป้ายเป็น `STALE`
6. นาฬิกา**เดินต่อเอง**ด้วยนาฬิกาในตัว ไม่ต้องขอ NTP ทุกวินาที จึงเดินต่อแม้ WiFi หลุด (ความคลาดเคลื่อนสะสม ดูหัวข้อสิ่งที่ยังไม่ได้ยืนยัน)
7. `timeValid()` เป็นจริงเมื่อเคย sync แล้วและเวลาไม่ใช่ค่าเริ่มต้น (≥ `SANE_EPOCH` ≈ พ.ย. 2023) จึงไม่เคยแสดงหรือบันทึกเวลาปี 1970

### `makeTimestamp()` — เตรียมไว้สำหรับ Lab 8

```cpp
char stamp[24];
if (makeTimestamp(stamp, sizeof(stamp))) { /* stamp = "2026-10-09 19:38:08" */ }
else                                      { /* stamp = "NOT_SYNCED" */ }
```

Lab 7 ใช้ฟังก์ชันนี้ติดเวลาจริงให้บรรทัด `[FAN] ... -> ...` ใน Serial ส่วน Lab 8 จะใช้ติดเวลาจริงให้ทุกแถวของไฟล์ log บน SD card

### uptime กับเวลาจริง

`millis()` คือเวลาตั้งแต่เปิดเครื่อง รีเซ็ตเป็น 0 ทุกครั้งที่ไฟดับ ใช้วัด "ผ่านไปนานเท่าไร" ได้ แต่บอก "ตอนนี้กี่โมง" ไม่ได้
เวลาจริงต้องขอจากภายนอก (NTP) โปรแกรมนี้ใช้ทั้งสองอย่าง: `millis()` จับเวลางานย่อย ส่วนเวลาจริงใช้แสดงและติด timestamp

## วิธีรันและทดสอบ

```powershell
pio run -t upload --upload-port COM3
pio device monitor -b 115200 --port COM3
```

(เปลี่ยน `COM3` ตามเครื่องคุณ ปิด Serial Monitor ก่อน upload ถ้าไม่มีคำสั่ง `pio` ให้ใช้ `python -m platformio` ถ้า upload ไม่ผ่านด้วย `No serial data received` ให้กดปุ่ม BOOT ค้างตอน `Connecting......`)

ลองตามลำดับนี้

1. **ยังไม่ตั้งค่า WiFi:** จอแสดง `--:--:--` ป้าย `NO WIFI` Serial บอก `NOT SYNCED` (ตรวจแล้วจากบอร์ดจริง) ส่วนเซนเซอร์และพัดลมทำงานปกติ
2. **ตั้งค่า WiFi แล้ว:** หลังเปิดเครื่อง ไม่กี่วินาที ป้ายเปลี่ยน `WIFI...` → `SYNCING` → `SYNCED` เวลาขึ้นบนจอ (ตรวจแล้วจาก Serial และภาพถ่ายหน้าจอ; LED เขียวติดยังไม่ได้ตรวจ)
3. **เทียบกับนาฬิกาอื่น:** เทียบเวลาบนจอกับนาฬิกามือถือ/คอมพิวเตอร์ ต่างกันได้ไม่เกินราวหนึ่งวินาทีหรือสองวินาที
4. **ขอเวลาใหม่:** พิมพ์ `n` ใน Serial ดู `sync #` เพิ่มขึ้น (ตรวจแล้ว: `synced #2` ภายใน ~1 วินาที) พิมพ์ `t` เพื่อดูเวลาและเวลาที่ sync ล่าสุด
5. **ทดสอบ WiFi หลุด:** ปิด WiFi ของเราเตอร์/hotspot ชั่วคราว ดูว่านาฬิกายังเดินต่อและบรรทัดล่างเปลี่ยนเป็น `WiFi connecting...` (**ยังไม่ได้ทดสอบ**)

```
[NTP] requesting time from pool.ntp.org / time.nist.gov ...
[NTP] synced #2: 2026-10-09 19:39:11 (UTC+7)

[NTP] requesting time from no-such-ntp.invalid / no-such-ntp2.invalid ...
[TIME] NOT SYNCED  (wifi=CONNECTED ntp=SYNCING)
[NTP] no reply within 8 s (UDP port 123 blocked? DNS problem?) - will retry
[TIME] NOT SYNCED  (wifi=CONNECTED ntp=FAILED)
```

(ตัวอย่างหลังใช้เวลา timeout 8 วินาทีเพื่อทดสอบให้เร็ว ค่าเริ่มต้นคือ 20 วินาที)

## ค่าที่ปรับได้ใน `app_config.h`

| ค่า | ค่าเริ่มต้น | ผลเมื่อปรับ |
|---|---|---|
| `NTP_SERVER_1` / `NTP_SERVER_2` | `pool.ntp.org` / `time.nist.gov` | เซิร์ฟเวอร์ NTP หลัก/สำรอง |
| `GMT_OFFSET_SEC` | `7 * 3600` | เขตเวลา (วินาทีจาก UTC) |
| `DAYLIGHT_OFFSET_SEC` | 0 | เวลาออมแสง |
| `NTP_TIMEOUT_MS` / `NTP_RETRY_MS` | 20000 / 30000 | รอเวลานานเท่าไรถึงถือว่าล้มเหลว / รอก่อนขอใหม่ |
| `NTP_RESYNC_MS` | 3600000 | ขอเวลาใหม่เป็นระยะทุกกี่ ms |
| `NTP_STALE_FACTOR` | 2 | sync ล่าสุดเก่ากว่า `NTP_RESYNC_MS` × ค่านี้ = ป้าย STALE |
| `SANE_EPOCH` | 1700000000 | เวลาที่เก่ากว่านี้ถือว่ายังไม่ได้ตั้ง |
| `CONNECT_TIMEOUT_MS` / `RETRY_DELAY_MS` | 15000 / 5000 | WiFi: รอต่อนานเท่าไร / รอก่อนลองใหม่ |
| (ค่าของ Lab 6) | | เกณฑ์พัดลม, ค่า SIM, ช่วงอ่าน DHT11 ฯลฯ |

## แบบฝึกหัด

1. **เปลี่ยนรูปแบบเวลา:** แก้ `strftime` ให้แสดงเวลา 12 ชั่วโมง (`%I:%M:%S %p`) หรือวันที่แบบ `DD/MM/YYYY`
2. **เปลี่ยนเขตเวลา:** ตั้ง `GMT_OFFSET_SEC` เป็น `9 * 3600` (ญี่ปุ่น) หรือ `0` (UTC) ดูเวลาเปลี่ยนไปกี่ชั่วโมง แล้วคืนค่า
3. **เซิร์ฟเวอร์อื่น:** เปลี่ยน `NTP_SERVER_1` เป็นเซิร์ฟเวอร์อื่น (เช่นที่โรงเรียนกำหนด) ดู `[NTP] synced` เร็วหรือช้ากว่าเดิม
4. **ทดสอบความล้มเหลว:** ใส่ชื่อเซิร์ฟเวอร์ที่ไม่มีอยู่จริงทั้งสองตัว ดูสถานะ `SYNCING → FAILED → ลองใหม่` ใน Serial และป้ายบนจอ ย้อนกลับ
5. **วัดการคลาดเคลื่อน (drift):** จดเวลาบนจอเทียบกับนาฬิกาที่แม่นยำ ตอนเพิ่ง sync และอีกครั้งหลังตั้ง `NTP_RESYNC_MS` ให้ยาว (เช่น 6 ชั่วโมง) แล้วดูว่าต่างกันกี่วินาที (**ไม่มีค่าเฉลย** ผู้เขียนยังไม่ได้วัด)
6. **ทำป้าย STALE ให้เร็วขึ้น:** ตั้ง `NTP_RESYNC_MS` เหลือ 60000 และ `NTP_STALE_FACTOR` เป็น 1 ลองถอด WiFi เพื่อดูป้าย `STALE`
7. **ท้าทาย:** แสดง "เวลาที่เครื่องเปิดอยู่" (uptime) เป็นบรรทัดเล็กในการ์ดนาฬิกา หรือแสดงเวลาที่พัดลมเปิดล่าสุด (ใช้ `makeTimestamp()`)

## สิ่งที่ยังไม่ได้ยืนยัน (ผู้ทดสอบ/ผู้สอนควรตรวจและบันทึก)

| ข้อ | สถานะ |
|---|---|
| โปรแกรม build ผ่าน | ยืนยันแล้ว (ไม่มี warning จากโค้ดของ Lab นี้) |
| ไม่มี `secrets.h`: `NOT CONFIGURED`, `NOT SYNCED`, เซนเซอร์ทำงานปกติ | **ยืนยันแล้ว** จากบอร์ดจริง (Serial) |
| ต่อ WiFi และ sync เวลา: `connected, RSSI -45 dBm` แล้ว `synced #1` | **ยืนยันแล้ว** จากบอร์ดจริง (Serial) **เวลาที่วัดจากการรีเซ็ต:** ต่อ WiFi สำเร็จที่ ≈ 2.0 วินาที (หลังเริ่มต่อ ≈ 0.8 วินาที) และ sync เวลาได้ที่ ≈ 2.3 วินาที (หลังขอเวลา ≈ 0.3 วินาที) ในเครือข่ายที่ทดสอบ เครือข่ายอื่นอาจช้ากว่านี้มาก |
| ความถูกต้องของเวลาและเขตเวลา UTC+7 | **ยืนยันแล้ว** บอร์ดแสดง `19:38:28` ขณะนาฬิกาคอมพิวเตอร์แสดง `19:38:29` (ผมไม่ได้ตรวจว่านาฬิกาคอมพิวเตอร์เองแม่นแค่ไหน) |
| คำสั่ง `n` (ขอเวลาใหม่ → `synced #2`) และ `t` | **ยืนยันแล้ว** จากบอร์ดจริง |
| ขอเวลาไม่สำเร็จ: `SYNCING → no reply → FAILED → ขอใหม่` และไม่พิมพ์เวลาปี 1970 | **ยืนยันแล้ว** จากบอร์ดจริง (ทดลองใช้เซิร์ฟเวอร์ปลอมและ timeout สั้น) |
| อ่าน DHT11 ได้ปกติขณะ WiFi ทำงาน (`read took` ≈ 25.8 ms) | **ยืนยันแล้ว** ในตัวอย่างที่เก็บ ไม่เห็นการอ่านพลาด (ยังไม่ได้ทดสอบระยะยาว) |
| หน้าจอ: ป้าย SYNCED, เวลา/วันที่ตัวใหญ่, ตำแหน่งและความพอดีของทุกข้อความในการ์ด | **ยืนยันแล้ว** จากภาพถ่ายของผู้พัฒนา (ดู "สังเกตจากการทดสอบจริง") ป้าย `SYNCING`, `NO SYNC`, `NO WIFI`, `WIFI...` และ `--:--:--` ตอนยังไม่ sync **ยังไม่มีหลักฐานภาพ** (ตรวจเฉพาะข้อความ Serial) |
| LED เขียวติดเมื่อ sync, LED น้ำเงิน/แดง, ปุ่ม BOOT | **ยังไม่ได้เห็น/กดเอง** |
| WiFi หลุดระหว่างใช้งาน: นาฬิกาเดินต่อ, ป้ายและข้อความ | **ยังไม่ได้ทดสอบ** |
| sync ซ้ำอัตโนมัติทุก `NTP_RESYNC_MS` (ตั้งด้วย `sntp_set_sync_interval`) | **ยืนยันแล้วด้วยรอบสั้น:** ตั้งเป็น 30 วินาทีชั่วคราว ได้ `synced #2` ที่ +30 วินาที และ `#3` ที่อีก +45 วินาทีต่อมา (ช่วงห่างจริงไม่เท่ากันเป๊ะ ไลบรารีเป็นผู้กำหนดจังหวะ) ค่าเริ่มต้น 1 ชั่วโมง **ยังไม่ได้รอจนครบ** และป้าย `STALE` **ยังไม่ได้ทดสอบ** |
| การคลาดเคลื่อน (drift) ของนาฬิกาในตัว | **ยังไม่ได้วัด** |
| เครือข่ายที่บล็อก UDP 123 | **ยังไม่ได้ทดสอบ** (ทดสอบเฉพาะเซิร์ฟเวอร์ที่ไม่มีอยู่จริง) |
