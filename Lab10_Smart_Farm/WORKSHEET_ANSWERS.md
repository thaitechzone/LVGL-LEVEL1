| `LIGHT_THRESHOLD_PERCENT` / `LIGHT_HYSTERESIS_PERCENT` / `LIGHT_FROM_HOUR` / `LIGHT_TO_HOUR` | 40 / 5 / 6 / 18 |

### ขั้นที่ 2 — Build / calibrate

- `[SUCCESS]` ; คำเตือน `TOUCH_CS pin not defined` ปกติ
- Lab นี้เก็บ calibrate ใน namespace `lab10` (แยกจาก Lab 9) ครั้งแรกจึงขึ้นหน้า calibrate (`[CAL] no saved calibration`) แล้วหลังแตะครบ 4 จุด `[CAL] saved to flash` เข้า DASH
- `[LDR] range: dark=raw 300, bright=raw 0 (defaults from app_config.h)` และ `[CFG] fan 30/28 C, light <40% 06-18 h, soil <35%, water 07:00 + 17:00 for 10 s`

### ขั้นที่ 3 — เซนเซอร์

- TEMP/HUM ป้าย `REAL` (ถ้ามี DHT11) ; ตัวอย่างบอร์ดต้นแบบ 27.1–27.6 °C / 92–95%
- LIGHT ป้าย `LDR` ; SOIL ป้าย `SIM` เริ่ม 60% แล้วลดช้าๆ (ประมาณ 1% ทุก 5 วินาที)
- ครอบมือบัง LDR : raw **ลดลง**หรือเพิ่ม? ในบอร์ดต้นแบบตอนกลางคืน ห้องมืด raw ≈ 270–340 (LIGHT ≈ 0–10%) แต่ตอนส่องไฟ/มีแสงมาก raw ≈ 0 (LIGHT ≈ 95–100%) ดังนั้น **มืด = raw สูง, สว่าง = raw ต่ำ** (แปรผกผัน) ถ้าห้องของนักเรียนสว่างอยู่แล้ว ครอบมือจะทำให้ raw เพิ่มขึ้น
- ป้ายนาฬิกา: `SYNCED` เมื่อมี WiFi ; `NO WIFI` ถ้าไม่มี `secrets.h`

### ขั้นที่ 4 — calibrate LDR

- กด `SET DARK` ตอนมืดสุด (raw สูง) แล้ว `SET BRIGHT` ตอนสว่าง (raw ต่ำ) ; Serial `[LDR] DARK end set to raw=… (dark=… bright=…) saved`
- raw ที่ตรงกับ 40% และ 45% : `raw = dark − pct × (dark − bright) ÷ 100` ตัวอย่าง dark = 300, bright = 0 : 40% → 180, 45% → 165 ; dark = 250, bright = 40 : 40% → 166, 45% → ≈ 155.5 (ใช้ `map` จำนวนเต็ม raw 155 ได้ 45%, raw 156 ได้ 44%)
- กด `SET BRIGHT` ให้ค่าสูงกว่าฝั่งมืดหรือห่างน้อยกว่า 20 : ถูกปฏิเสธ Serial `[LDR] refused: BRIGHT raw=… but the other end is …` และค่าไม่เปลี่ยน
- หลังรีเซ็ตต้องเห็น `[LDR] range: dark=…, bright=… (saved by SET DARK/BRIGHT)` (สถานะ: **ยังไม่ได้ยืนยันบนบอร์ด** เพราะผู้พัฒนาไม่ได้บันทึกช่วงนี้ในการทดสอบ ค่ายังเป็น defaults)

### ขั้นที่ 5 — พัดลม AUTO

- เริ่มที่ ≈ 30 °C (ตัวอย่างวัด: `ON 31% … at 30.1 C` เพราะตรวจทุก 200 ms) ; หยุดที่ ≈ 28 °C (ตัวอย่างวัด `OFF … at 27.9 C`) ไม่ใช่ 30 : เพราะ hysteresis (เกณฑ์ปิดต่ำกว่าเกณฑ์เปิด 2 °C ช่วง 28–30 คงสถานะเดิม)
- duty : 33 °C → 65% (คำนวณ) ; 36 °C ขึ้นไป → 100% ตัวอย่างวัดที่ SIM: 68% ที่ 33.3 °C, 95% ที่ 35.7 °C, 100% ที่ 38.0 °C
- LED น้ำเงินสว่างขึ้นตามอุณหภูมิ ; ตอนวัดผ่าน Serial ผมไม่ได้ดูความสว่างจริงของ LED (ผู้พัฒนาแจ้งผลถูกต้องโดยรวม)

### ขั้นที่ 6 — ไฟปลูก

### ขั้นที่ 7 — ปั๊มตามดินแห้ง

- เริ่มที่ดิน 20% (reason `SOIL DRY`) ; หยุดเมื่อดินถึง 55% (ตัวอย่างวัดหยุดที่ 56% ใน 23 วินาที) เหตุผล `soil wet enough`
- คำนวณ : (55 − 20) ÷ 1.5 = 23.3 วินาที (ตรงกับที่วัด)
- หลังหยุด : `REST` นับถอยหลัง 20 วินาที
- ดินลดลงช้าๆ เพราะโปรแกรมจำลองการระเหย 0.2% ต่อวินาที (ตัวอย่างวัดลดประมาณ 1% ทุก 5 วินาที)

### ขั้นที่ 8 — ปั๊มตามตาราง

- เริ่มเมื่อเวลาท้องถิ่นเข้า HH:00 (ภายในไม่เกิน HH:04) ; reason `SCHEDULE` ; รดตาม `RUN TIME` (10 วินาที) ; ดินเพิ่ม 10 × 1.5 = 15% (ตัวอย่างวัด 59 → 74%)
- ผ่าน HH:04 ไปแล้ว : รอบนั้นพลาด ไม่เริ่ม (ออกแบบตาม `WATER_SLOT_GRACE_MIN`)
- รีเซ็ตบอร์ดในช่วง HH:00–HH:04 : รดซ้ำ เพราะ `slotDoneDay` อยู่ใน RAM และหายตอนรีเซ็ต (ตัวอย่างวัด: หลังเปิดเครื่องและ sync เวลาในช่วงผ่อนผัน ปั๊มเริ่มทันทีที่ sync เสร็จ)
- นักเรียนที่ไม่มี WiFi : ยอมรับคำตอบเป็นการคำนวณ (เช่นสำหรับ H = 7: นาทีของวันตั้งแต่ 420 ถึง 424)

### ขั้นที่ 9 — MANUAL / ความปลอดภัย

| ทดสอบ | เฉลย |
|---|---|
| แตะ `ON` ของพัดลมใน AUTO | MANUAL ON, duty 100% |
| แตะปุ่มโหมดกลับเป็น AUTO | อุปกรณ์ทำตามกฎ |
| MANUAL ON ปั๊มแล้วไม่ทำอะไร | ดับเองที่ **30 วินาที** (`MAX RUN watchdog`) ตัวอย่างวัด 30 วินาทีพอดี |
| สั่ง ON อีกทันที | ปฏิเสธ จอขึ้น `REST` ปุ่มกลับเป็น OFF Serial `[PUMP] refused: resting for N more s` |
| ปุ่ม BOOT | ทุกอุปกรณ์เป็น MANUAL + OFF (ตรวจจอ CTRL / Serial `EMERGENCY STOP`) — สถานะ: ยังไม่ได้กดปุ่ม BOOT ระหว่างทดสอบ จึงยืนยันจากโค้ดเท่านั้น |
| `a` | ทุกอุปกรณ์กลับเป็น AUTO (ตัวอย่างวัด `[MODE] all devices -> AUTO`) |

### ขั้นที่ 10 — SETUP และการจำค่า

- Serial ขึ้น `[CFG] saved to flash` ตอน**ปล่อยนิ้ว** (ขณะกดค้างจะเห็นเฉพาะ `[CFG] <ชื่อ> = <ค่า>` ที่เปลี่ยนทีละขั้น)
- หลังรีเซ็ต : ค่าที่ตั้งยังอยู่ (`[CFG] …` แสดงค่าที่โหลด) ; โหมดกลับเป็น AUTO เสมอ เพราะไม่ได้บันทึกโหมด (ความปลอดภัยไว้ก่อน)
- ปุ่ม `-` ของ `FAN ON >=` ลงได้ต่ำสุด = `FAN OFF + 1` (เช่น 29 เมื่อ OFF = 28)
- สถานะ: ขั้นนี้ **ยังไม่ได้ยืนยันบนบอร์ด** (ไม่พบการปรับค่าใน Serial)

## เฉลยคำถามอ่านโค้ด (หัวข้อ 5)

**5.1** (ก) ไม่เปลี่ยน : `toggleDeviceMode` ไป MANUAL แล้วตั้ง `manualOn = currentlyOn` (คงสถานะเดิม พัดลมยังทำงานอยู่) (ข) พัดลมหยุดอยู่ใน AUTO แตะ `ON/OFF` → `toggleDeviceManual` : เป็น MANUAL และ `manualOn = !currentlyOn = true` พัดลมเปิด 100% (ค) กลับไป AUTO ให้กฎตัดสินใจเอง (ถ้าอุณหภูมิต่ำกว่าเกณฑ์ พัดลมดับ)

**5.2** ตาราง `fanAutoOn` : 27 → false ; 29 → false (ยังไม่ถึง 30) ; 30.5 → **true** ; 29 → true (ยังไม่ถึง ≤ 28) ; 28.5 → true ; 28 → **false** ; 29 → false

**5.3** (ก) span = 36 − 32 = 4 ; fraction = (34 − 32) ÷ 4 = 0.5 ; duty = 30 + round(0.5 × 70) = 30 + 35 = **65%** (ข) value = (65 × 255 + 50) ÷ 100 = 16,625 ÷ 100 = 166 ; active-LOW เขียน 255 − 166 = **89** (ค) fraction = constrain(−1 ÷ 6, 0, 1) = 0 → duty = **30%** (ค่าต่ำสุด ขณะ `fanAutoOn` ยังเป็น true เพราะยังไม่ถึงเกณฑ์ปิด 28)

**5.4** ช่วงมืด 250, สว่าง 40 : `pct = (raw − 250) × 100 ÷ (40 − 250)` (ก) raw 145 : (−105 × 100) ÷ (−210) = **50%** (ข) raw 300 : (50 × 100) ÷ (−210) = −23 → `constrain` = **0%** ; raw 20 : (−230 × 100) ÷ (−210) = 109 → **100%** ; `constrain` กันค่าหลุดช่วง 0–100 (ค) 40% → raw 166 ; 45% → raw ≈ 155–156 (ใช้สูตร `raw = 250 − pct × 2.1`)

**5.5** เริ่มดับ : 50 → ดับ ; 42 → ดับ (ยังไม่ < 40) ; 38 → **ติด** ; 43 → ติด (ยัง < 45) ; 44 → ติด ; 45 → **ดับ** (ไม่ < 45) ; 41 → ดับ (ต้อง < 40 ถึงจะติดใหม่)

**5.6** (ก) (55 − 30) ÷ 1.5 = 16.7 → ปั๊มทำงาน ≈ **17 วินาที** (ข) ไม่ได้ : 30 วินาที × 0.5 = +15% (30 → 45 < 55) ต้องหยุดด้วย watchdog (ค) soil ลดเร็ว (1.0%/s) กว่าขึ้น (0.8%/s ขณะปั๊มทำงาน) : ปั๊มรดจาก 35 ถึง 55 ใช้ 25 วินาที ( < 30 ) หลังหยุดพัก 20 วินาทีดินลดกลับถึง 35 พอดี ปั๊มจึงเริ่มใหม่ทันที → ทำงานประมาณ 25 วินาทีต่อรอบ 45 วินาที (≈ 56% ของเวลา) หมายถึงดินแห้งเร็วเกินกว่าปั๊มจะตามทัน เสี่ยงปั๊มร้อนเกิน

**5.7** (ก) 07:03 = 423 นาที อยู่ใน [420, 425) → **0** (ข) 07:06 = 426 ≥ 425 → **−1** (เลยช่วงผ่อนผัน) (ค) **−1** (รอบ 0 ทำแล้ววันนี้ และ 07:03 ยังไม่ถึงรอบ 1) (ง) **1** (17:00 ถึงรอบ 1) (จ) **−1** (ไม่มีเวลาจริง `timeValid()` เป็น false)

**5.8** (ก) เพื่อให้ MANUAL ก็ถูกจำกัดเหมือนกัน ถ้าตรวจหลังแยกโหมดอาจลืมใส่ในบางเส้นทาง ทำให้ MANUAL ข้ามด่านความปลอดภัยได้ (ข) ให้ปุ่ม/สถานะ MANUAL สอดคล้องกับของจริง (ปั๊มดับแล้ว) ถ้าไม่ล้าง `manualOn` ยังเป็น true ค้างอยู่ เมื่อพักปั๊มครบ 20 วินาที โค้ดส่วน MANUAL จะเห็นว่า "ผู้ใช้สั่ง ON" และเริ่มปั๊มใหม่เองโดยผู้ใช้ไม่ได้สั่งซ้ำ (อันตราย) (ค) ไม่ทำงาน : `pumpResting` เป็นจริง → ตั้ง `manualOn = false` และพิมพ์ `refused`

**5.9** (ก) ข้อความที่แสดง `RUN 7s` / `REST 12s` เปลี่ยนทุกวินาที ถ้าไม่รวมวินาทีในคีย์ จอจะไม่อัปเดตตัวเลขเวลา (ข) เปลี่ยนโหมด AUTO↔MANUAL โดยที่สถานะไม่เปลี่ยน (เช่นพัดลมกำลังหยุด) คีย์ไม่เปลี่ยน → ป้ายโหมดบนจอไม่อัปเดต

**5.10** `normalizeSettings()` : `fanOn` = constrain(30, 16, 35) = 30 ; `fanOff` = constrain(40, 15, 29) = **29** ต้องมีเพราะค่าใน flash อาจเสียหาย, มาจากเฟิร์มแวร์เวอร์ชันอื่น หรือผู้ใช้เขียนผิด การตรวจตอนโหลดช่วยให้ระบบไม่เริ่มด้วยค่าที่ขัดแย้งกันแม้ UI ป้องกันไว้แล้ว (defense in depth)

## เฉลยแบบฝึกหัด

### ข้อ 1 — ช่วงแสงของห้อง (5 คะแนน)

สูตร `raw = dark − pct × (dark − bright) ÷ 100` ตัวอย่าง dark = 250, bright = 40 : 40% → 250 − 84 = **166**, 45% → 250 − 94.5 = **155.5** (ใน `map` จำนวนเต็ม raw 155 ได้ 45%, 156 ได้ 44%) ตรวจกับจอ: บังแสงจนได้ค่าใกล้ 40% ดู raw ใน Serial `k` เทียบ ให้คะแนนเมื่อวิธีคำนวณถูกและเทียบผลจริงได้ (คลาดเคลื่อน ±5 raw ยอมรับ เพราะ EMA และ oversampling)

### ข้อ 2 — ระบบดินชื้น (5 คะแนน)

- (ก) แห้งจาก 55 → 35 : 20 ÷ 0.2 = **100 วินาที** (ข) รดจาก 35 → 55 : 20 ÷ 1.5 ≈ **13.3 วินาที** (ค) รอบเต็ม ≈ **113 วินาที** (ปั๊มทำงาน ≈ 11.8%)
- ข้อมูลจากบอร์ดต้นแบบ: การรด 20 → 56 ใช้ 23 วินาที ; อัตราแห้ง ≈ 0.2%/s (ประมาณ 1% ต่อ 5 วินาที)
- หมายเหตุ: ช่วง `REST` 20 วินาทีหลังรดไม่กระทบรอบนี้ เพราะดินยังเปียกอยู่

### ข้อ 3 — ค่าคงที่ (5 คะแนน) — ทดสอบบนบอร์ดแล้ว

ตั้ง `PUMP_MAX_RUN_SEC = 15` และ `SOIL_WET_RATE = 0.5f` ทำนาย: แตะ SOIL (20%) ปั๊มเริ่ม รดได้ 15 × 0.5 = +7.5% → ≈ 28% ปั๊มหยุดด้วย **watchdog** (ไม่ใช่ดินชื้นพอ) พัก 20 วินาที (ดินลดลง ≈ 4% เหลือ ≈ 23%) ดินยังต่ำกว่า 35% จึงเริ่มรอบใหม่ทันทีที่พักครบ วนซ้ำจนดินสูงถึง 35%+
ผลวัดจริง (Serial): `ON reason=SOIL DRY limit=15 s soil=20%` → `OFF (MAX RUN watchdog) ran 15 s … soil=28%` → `ON … soil=23%` (หลังพัก 20 วินาที) → `OFF (MAX RUN watchdog) … soil=31%`
สิ่งที่เรียนรู้: watchdog ป้องกันปั๊มเดินนานเมื่อ "น้ำน้อยกว่าปกติ" ได้ แต่ถ้าปัญหาจริง (ไม่มีน้ำ) ปั๊มจะวนไปเรื่อยๆ จึงนำไปสู่ข้อ 7 (FAULT)

### ข้อ 4 — ถ่วงเวลาขั้นต่ำของไฟปลูก (7 คะแนน) — compile ผ่านเท่านั้น

```cpp
// ใน updateLight() ก่อนบล็อก if (want != lightOn) { setLightOutput(want); ... }
static uint32_t lightChangedAt = 0;
if (lightDev.mode == Mode::Auto && want != lightOn && lightChangedAt != 0 && now - lightChangedAt < 5000UL) {
    want = lightOn;  // ต้องคงสถานะอย่างน้อย 5 วินาที กันไฟติด-ดับถี่
}
if (want != lightOn) lightChangedAt = now;
```

- ข้อดี: ลดการติด-ดับถี่เมื่อแสงแกว่ง (หลอดไฟจริงอายุยาวขึ้น) ข้อเสีย: ตอบสนองช้า ถ้าแสงเปลี่ยนจริงต้องรอ 5 วินาที ; ไม่ใช้กับ MANUAL เพราะผู้ใช้ต้องสั่งได้ทันที
- ข้อควรสังเกต: ตัวแปร `static` ในฟังก์ชันเก็บค่าข้ามรอบ ; ค่าเริ่ม 0 หมายถึงยังไม่เคยเปลี่ยน อนุญาตการเปลี่ยนครั้งแรกทันที
- สถานะ: ยังไม่ได้ทดสอบพฤติกรรมบนบอร์ด

### ข้อ 5 — กฎความชื้นของพัดลม (7 คะแนน) — ทดสอบบนบอร์ดแล้ว

```cpp
// ใน updateFan() ในส่วนที่อุณหภูมิถูกต้อง แทนบรรทัด duty = fanAutoOn ? dutyForTemp(tempC) : 0;
static bool humidHigh = false;
const float hum = effectiveHumidity(now);
if (!isnan(hum)) {
    if (!humidHigh && hum >= 85.0f) humidHigh = true;
    else if (humidHigh && hum <= 80.0f) humidHigh = false;
}
duty = fanAutoOn ? dutyForTemp(tempC) : (humidHigh ? app::FAN_MIN_DUTY_PERCENT : 0);
```

ผลวัดจริงด้วย SIM sweep (ความชื้น = 90 − fraction × 50, อุณหภูมิ = 24 + fraction × 14) : `FAN ON 30% (AUTO) at 25.3 C` (ความชื้น ≈ 85) พัดลมหมุนทั้งที่อุณหภูมิต่ำกว่าเกณฑ์ 30 → `FAN OFF at 26.8 C` (ความชื้น ≈ 80) → ต่อมา `FAN ON 31% at 30.1 C` ตามอุณหภูมิ
การออกแบบ: ใช้ hysteresis ของความชื้นเอง (85/80) ไม่ผสมกับ `fanAutoOn` ; ใช้ duty ต่ำสุด (30%) เพราะเป้าหมายคือระบายความชื้น ไม่ใช่ลดอุณหภูมิ ; ตรวจ `isnan` กรณีไม่มีค่าความชื้น

### ข้อ 6 — ตัวนับรอบรดน้ำต่อวัน (7 คะแนน) — ทดสอบบนบอร์ดแล้ว

```cpp
int pumpRunsToday = 0;
long pumpRunsDay = -1;
// ที่ต้น startPump():
if (timeValid()) {
    const long day = (static_cast<long>(time(nullptr)) + app::GMT_OFFSET_SEC + app::DAYLIGHT_OFFSET_SEC) / 86400;
    if (day != pumpRunsDay) { pumpRunsDay = day; pumpRunsToday = 0; }  // ขึ้นวันใหม่ตามเวลาท้องถิ่น
}
pumpRunsToday++;
Serial.printf("[PUMP] runs today: %d\n", pumpRunsToday);
```

ผลวัดจริง: สั่ง `p` (MANUAL ON) ได้ `[PUMP] runs today: 1` ก่อน `[PUMP] ON …`
ประเด็น: ต้องใช้เลขวันตามเวลาท้องถิ่น (บวก 7 ชั่วโมงก่อนหาร 86,400) ไม่ใช่ UTC (บทเรียนจาก Lab 7) ; ถ้าไม่มีเวลาจริง ตัวนับจะไม่รีเซ็ตเมื่อขึ้นวันใหม่ (ไม่รู้วัน) ควรนับต่อและแจ้งว่าไม่แน่ใจ หรือไม่นับแบบแยกวัน ; ตัวนับอยู่ใน RAM (หายเมื่อรีเซ็ต) นับรวมการสั่ง MANUAL ด้วย ตามที่โค้ดนี้นับตอนเริ่ม

### ข้อ 7 — FAULT ของปั๊ม (10 คะแนน) — ไม่มีเฉลยที่ทดสอบ

แนวคิดที่ยอมรับได้:

- ตัวนับ `watchdogTrips` เพิ่มทุกครั้งที่ `stopPump(..., "MAX RUN watchdog")` ถูกเรียก ; ล้างเป็น 0 เมื่อปั๊มหยุดด้วยเหตุผลปกติ (ดินชื้นพอ หรือครบเวลารด)
- เมื่อ `watchdogTrips >= 2` และดินยังต่ำกว่า `SOIL DRY + 10` → `pumpFault = true` ; โหมด AUTO ไม่เรียก `startPump` (ตรวจใน `updatePump` ก่อนเงื่อนไขเริ่ม)
- แสดง `FAULT` สีแดงใน `drawTile()` และ `updateControlPage()` ; Serial `[PUMP] FAULT`
- ปลดล็อก: ปุ่ม BOOT (ใน `emergencyStop`) หรือ `setAllAuto()` ล้าง `pumpFault` และ `watchdogTrips`
- เหตุผลของค่าที่เลือก: "2 ครั้ง" กันกรณีรอบเดียวที่น้ำน้อยชั่วคราว ; "+10" กันความคลาดเคลื่อนของเซนเซอร์/การจำลอง
- ทดสอบ: ตั้ง `SOIL_WET_RATE` ต่ำมาก (เช่น 0.1) แล้วแตะ SOIL ต้องเห็น watchdog 2 รอบแล้ว FAULT
- ตรวจ: ปุ่ม MANUAL ยังสั่งปั๊มได้หรือไม่ (ควรยังสั่งได้ภายใต้ watchdog/cooldown ถ้านักเรียนอธิบายเหตุผล)

### ข้อ 8 (โบนัส) — เซนเซอร์ดินจริง (+10) — ไม่มีเฉลยที่ทดสอบ

แนวทางที่ถูกต้อง : เลือกขา ADC1 ที่ว่างตาม pinout (GPIO34/35/36/39 อ่านได้อย่างเดียว แต่ GPIO34 ใช้กับ LDR, GPIO36/39 ใช้กับจอสัมผัส) ต้องตรวจว่าขานั้นมีบนคอนเน็กเตอร์ของบอร์ดนี้จริง (ผู้สอนยังไม่ได้ทดสอบขา GPIO35 กับบอร์ดนี้) ; calibrate แห้ง/เปียกเหมือน LDR (เซนเซอร์แบบ capacitive ส่วนใหญ่ raw สูง = แห้ง) ; อย่าใช้ ADC2 ขณะเปิด WiFi ; เซนเซอร์ที่จ่ายไฟต่อเนื่องในดินกัดกร่อนเร็ว ควรจ่ายไฟเฉพาะตอนอ่านถ้าทำได้

## เฉลยคำถามทบทวน

1. อ่าน (sense: `readDht`, `readLdr`, `ambientPercent`, `updateSoil`, เวลา NTP) → ตัดสินใจ (decide: `updateFan`, `updateLight`, `updatePump`) → สั่งงาน (act: `applyFanDuty`, `setLightOutput`, `setPumpOutput`)
2. ใช้สองเกณฑ์ที่ห่างกันเพื่อให้การเปลี่ยนสถานะไม่เกิดถี่ที่เกณฑ์เดียว ถ้าไม่มี อุปกรณ์จะเปิด-ปิดถี่ (กะพริบ เสียงรบกวน อายุสั้น)
3. raw แปรผกผันกับแสง (มืดสูง) จึงใส่ช่วงขาเข้า "มืดก่อน" ; ช่วงค่าขึ้นกับห้อง/เวลา/บอร์ด (บอร์ดต้นแบบกลางคืน raw ≈ 270–340 ไม่ใช่ 120) จึงต้อง calibrate
4. ลดการเขียน flash (มีจำนวนรอบจำกัดและเขียนช้า) และไม่ให้ UI ช้าลงขณะกดค้าง/ลาก
5. กันอุปกรณ์ค้างอยู่ในโหมดสั่งมือหลังไฟดับ/รีเซ็ต (เช่นปั๊มค้าง ON) ; เริ่มจากสถานะปลอดภัยที่ระบบตัดสินเอง
6. watchdog กันปั๊มเดินนานเกิน (น้ำล้น/มอเตอร์ร้อน เมื่อโปรแกรมหรือเซนเซอร์ผิดพลาด) ; cooldown กันเปิดปิดถี่เกิน ; ใช้กับ MANUAL ด้วยเพราะความผิดพลาดของผู้ใช้ (ลืมปิด) ก็ทำให้เกิดความเสียหายแบบเดียวกัน
7. ตัวควบคุมจริงไม่ควรตัดสินใจจากข้อมูลปลอมโดยผู้ใช้ไม่รู้ ; แสดง ERR ให้เห็นชัด และหมุนพัดลมครึ่งหนึ่งเพราะการปล่อยให้โรงเรือนร้อนเสียหายกว่าการสิ้นเปลืองไฟเล็กน้อย
8. ไม่มีเวลาจริง : ข้ามตารางเวลา ไฟปลูกใช้แสงอย่างเดียว ปั๊มใช้ดินแห้งอย่างเดียว เพราะเวลาที่ผิด (เช่นปี 1970) จะสั่งงานผิดเวลา ; อย่าเดาเวลาเอง
9. ดินแห้ง → ปั๊มทำงาน → ดินชื้นขึ้น → ปั๊มหยุด → ดินแห้งอีก (วงจรปิด) ; เกณฑ์เปิด/ปิดห่าง 20% เพื่อให้ปั๊มไม่เปิด-ปิดถี่ และรดให้ถึงระดับที่ชื้นพอจริง
10. ขาของ ESP32 จ่ายกระแสน้อย (หลัก mA) และเป็นไฟเลี้ยง 3.3 V ; ไฟบ้านอันตรายถึงชีวิตและทำลายบอร์ดได้ ต้องใช้วงจรขับ (ทรานซิสเตอร์/MOSFET + ไดโอดป้องกัน) หรือรีเลย์/โซลิดสเตตรีเลย์ที่แยกไฟ และฟิวส์ ผ่านการตรวจโดยผู้สอน
