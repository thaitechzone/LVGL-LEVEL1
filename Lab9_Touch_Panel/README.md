# Level 1 / Lab 9 — Touch Panel: ควบคุมทุกอย่างด้วยจอสัมผัส

Lab นี้ต่อยอดจาก Lab 7 (NTP Clock + DHT11 + พัดลมจำลอง PWM) โดยเพิ่ม **จอสัมผัส XPT2046**: แตะปุ่ม ลากแถบเลื่อน และกดค้าง แทนการพิมพ์คำสั่งใน Serial
มี 3 แท็บ (DASH / FAN / SYSTEM) หน้า TOUCH TEST สำหรับดูค่าจริงของจอสัมผัส และหน้า calibrate ที่แตะเป้า 4 มุม (เก็บค่าถาวร ไม่ต้องทำใหม่ทุกครั้ง)

> **สถานะการตรวจสอบ (อ่านก่อน):** โปรแกรมนี้ build ผ่านและทดสอบบนบอร์ดจริงครบแล้ว ผู้พัฒนาทดสอบ calibrate, ปุ่ม/แท็บทั้ง 3 หน้า, แถบเลื่อน, ปุ่ม `+` `-` (auto-repeat), ปุ่ม RECALIBRATE กดค้าง 1 วินาที,
> หน้า TOUCH TEST และแถบความสว่างจอ แล้วยืนยันว่า **ทุกอย่างทำงานถูกต้องปกติ** พร้อมภาพถ่ายของทุกหน้า ผมตรวจจาก Serial เพิ่มว่าค่า calibrate และความสว่างจอถูกบันทึกและ **โหลดกลับมาหลังรีเซ็ตบอร์ด**
> **ส่วนที่ยังไม่ได้ตรวจ:** ความแม่นยำเชิงตัวเลขของพิกัดที่มุมจอ (ผู้พัฒนาแจ้งว่า "ผ่าน" โดยไม่ได้ระบุเป็นพิกเซล), การอ่านจอสัมผัสทับกับ DHT11/WiFi ระยะยาว และการรวมกับ SD card (Lab ถัดไป)
> ดูตาราง "สิ่งที่ยังไม่ได้ยืนยัน" ท้ายไฟล์ ภาพ ASCII วาดประกอบ

## สิ่งที่จะได้เรียน

1. **จอสัมผัสแบบ resistive** ทำงานอย่างไร และต่างจากจอมือถือ (capacitive) อย่างไร
2. **อ่านชิป XPT2046 ผ่าน SPI** ด้วยโค้ดของเราเอง (ส่งคำสั่ง รับค่า 12 บิต คำนวณแรงกด)
3. **calibration:** แปลงค่าดิบ (0–4095) เป็นพิกัดพิกเซล ด้วยการแตะเป้า 4 มุม รวมถึงแกนสลับ/กลับด้าน
4. **กันสัญญาณรบกวน (debounce)** และสร้างเหตุการณ์ กดลง / กำลังกด / ปล่อย / คลิก
5. **hit test:** จุดที่แตะอยู่ในปุ่มไหน และปุ่มจะ "ทำงานเมื่อปล่อยนิ้วบนปุ่มเดิม" (เหมือนปุ่มบนมือถือ)
6. **แถบเลื่อน (slider) ลากนิ้ว**, **กดค้างเพื่อยืนยัน (long press)**, **กดค้างเพื่อเพิ่มต่อเนื่อง (auto-repeat)**
7. **เก็บค่าถาวร** ด้วย `Preferences` (ค่า calibrate และความสว่างจอ)
8. **ควบคุมฮาร์ดแวร์จริงจากหน้าจอ:** ความเร็วพัดลม (PWM), เกณฑ์ hysteresis, ความสว่างจอ (PWM ที่ GPIO21), การขอเวลา NTP

- จอสัมผัสใช้ SPI ชุด **VSPI** ซึ่งเป็นชุดเดียวกับที่ SD card ใช้ใน Lab 8 (ขา 18/19/23/5) จึง **Lab นี้ไม่รวม SD card** (ESP32 มี SPI ฮาร์ดแวร์ที่ใช้ได้แค่ 2 ชุด: HSPI สำหรับจอ, VSPI สำหรับจอสัมผัส) การรวม SD กับจอสัมผัสต้องหาทางแก้เพิ่มใน Lab ถัดไป

- **จอ resistive ต้องกดให้แรงพอ** เล็บมือหรือปากกาปลายมนแม่นกว่านิ้ว และไม่ไวเท่าจอมือถือ

## หน้าจอและสิ่งที่แตะได้

### หน้า Calibrate (เปิดเครื่องครั้งแรก / สั่งใหม่)

แสดงเครื่องหมายกากบาทสีเขียว 4 จุด (มุมบนซ้าย → บนขวา → ล่างขวา → ล่างซ้าย ห่างขอบ 20 พิกเซล) **แตะกลางกากบาททีละจุด กดค้างจนจุดทึบขึ้น แล้วปล่อย** จุดถัดไปจึงจะขึ้น
ครบ 4 จุด โปรแกรมคำนวณและบันทึกค่า แล้วเข้าหน้า DASH ถ้าแตะผิด (ค่าไม่เป็นสี่เหลี่ยมผืนผ้า) จะขึ้น `Calibration FAILED` และเริ่มใหม่

### แท็บ FAN

| ปุ่ม/ส่วน | แตะแล้วทำอะไร |
|---|---|
| `AUTO` / `MANUAL` | เลือกโหมดพัดลม (ปุ่มที่เลือกอยู่เป็นสีเข้ม) |
| แถบเลื่อน `FAN DUTY` | **ลากนิ้ว** ตั้ง duty 0–100% (ลากแล้วสลับเป็น MANUAL ให้เอง) ใน AUTO แถบแสดง duty ที่โปรแกรมคำนวณ |
| `ON >=` ปุ่ม `-` `+` | เกณฑ์อุณหภูมิ "เปิดพัดลม" ทีละ 1 °C **กดค้างเพื่อเพิ่ม/ลดต่อเนื่อง** |
| `OFF <=` ปุ่ม `-` `+` | เกณฑ์ "ปิดพัดลม" (ต้องต่ำกว่าเกณฑ์เปิดอย่างน้อย 1 °C = hysteresis) |

ค่าเกณฑ์ที่ปรับจากจอใช้เฉพาะรอบนั้น (รีเซ็ตกลับค่าใน `app_config.h` เมื่อเปิดเครื่องใหม่)

### แท็บ SYSTEM

| ปุ่ม/ส่วน | แตะแล้วทำอะไร |
|---|---|
| แถบเลื่อน `BACKLIGHT` | **ลาก** ปรับความสว่างจอ 10–100% (PWM ที่ GPIO21 เหมือน Lab 5) แล้ว **จำค่าไว้** เมื่อปล่อยนิ้ว (ต่ำสุด 10% กันจอมืดจนแตะไม่เห็น) |
| `SYNC NTP` | ขอเวลา NTP ใหม่ทันที |
| `TOUCH TEST` | เข้าหน้าทดสอบจอสัมผัส |
| `RECALIBRATE (hold 1 s)` | **กดค้าง 1 วินาที** (มีแถบสีเขียวเติมขณะกด) เพื่อ calibrate ใหม่ ต้องกดค้างกันกดพลาด |
| บรรทัดล่าง | WiFi RSSI, จำนวน sync และเวลาที่ sync ล่าสุด |

### หน้า TOUCH TEST

แสดง **ค่าดิบ** (`RAW x y z`) และ **พิกัดพิกเซล** (`PIXEL x y`) ของนิ้วที่แตะ พร้อมสถานะ `DOWN`/`UP` และกล่องวาดภาพ (ลากนิ้วแล้วมีจุดสีเขียวตามนิ้ว) ปุ่ม `CLEAR` ล้างกล่อง ปุ่ม `BACK` กลับหน้า SYSTEM
ใช้ดูว่าแตะที่ไหน ค่าดิบเป็นเท่าไร และ calibrate แม่นแค่ไหน (ลองแตะที่มุมจอทั้ง 4)

### พฤติกรรมของปุ่ม

- ปุ่มเปลี่ยนสีขณะถูกกด และ **ทำงานเมื่อปล่อยนิ้วบนปุ่มเดิม** (ถ้ากดแล้วเลื่อนนิ้วออกนอกปุ่มก่อนปล่อย จะไม่ทำงาน)
- แถบเลื่อนตามนิ้วทันทีที่กดลง และลากต่อได้
- ปุ่ม `+` `-` ทำงานทันทีที่กดลง แล้วกดค้างเกิน 0.5 วินาทีจะเพิ่ม/ลดซ้ำทุก 0.15 วินาที
- ระหว่างอ่าน DHT11 (ครั้งละ ≈ 25 ms ทุก 2.5 วินาที) โปรแกรมไม่ได้อ่านจอสัมผัส การแตะสั้นมากๆ ที่บังเอิญตรงช่วงนั้นอาจพลาดได้

## ความรู้ใหม่ใน Lab นี้

### จอสัมผัส resistive และชิป XPT2046

จอสัมผัสแบบ resistive ประกอบด้วยแผ่นนำไฟฟ้าสองชั้นที่มีช่องว่างคั่น เมื่อกด สองชั้นแตะกัน ชิป **XPT2046** วัดแรงดันที่จุดแตะบนแต่ละแกนด้วย ADC 12 บิต (ค่า 0–4095)
และวัด "แรงกด" (Z) ได้ ซึ่งใช้ตัดสินว่ามีการแตะจริงหรือไม่ ชิปคุยกับบอร์ดผ่าน **SPI** (SCK, MISO, MOSI, CS) ที่ 2.5 MHz

| คำสั่ง (ไบต์ที่ส่ง) | วัดอะไร |
|---|---|
| `0xB1` | เริ่มวัด Z1 |
| `0xC1` | เริ่มวัด Z2 (ผล Z1 จะมาในรอบส่งนี้) |
| `0x91`, `0xD1` | วัดแกนหนึ่ง/อีกแกนหนึ่ง (โปรแกรมเรียกค่าที่ได้ว่า x ดิบ และ y ดิบ) |
| `0xD0` | วัดครั้งสุดท้ายและสั่งชิปพักการวัด |

**แรงกด** `z = Z1 + 4095 − Z2` ถ้า `z ≥ 400` (`TOUCH_Z_MIN`) ถือว่ามีการแตะ ผลวัดจากบอร์ดต้นแบบขณะไม่มีใครแตะได้ `z ≈ 7–13` (ต่ำกว่าเกณฑ์มาก จึงไม่มีการแตะหลอก)
เมื่อมีการแตะ โปรแกรมวัดแกน x, y หลายครั้งแล้วเลือก "สองค่าที่ใกล้กันที่สุด" มาเฉลี่ย เพื่อตัดค่าที่เพี้ยนเป็นครั้งคราว

### calibration: ค่าดิบ → พิกเซล

ค่าดิบของจอสัมผัสไม่ใช่พิกเซล ต้องแปลงด้วยสมการเส้นตรงแยกแต่ละแกน: **`พิกัดจอ = a + b × ค่าดิบ`** (เหมือน `map()` ของ LDR ใน Lab 2)
โปรแกรมหา `a`, `b` จากเป้า 4 มุม (บนซ้ายที่ (20, 20), ล่างขวาที่ (299, 219)):

1. ตรวจว่าแกนดิบสลับกับแกนจอหรือไม่ (ดูว่าเมื่อเลื่อนจากมุมบนซ้ายไปบนขวา แกนดิบไหนเปลี่ยนมากกว่า) ถ้าเป็นแกน Y ดิบ ถือว่าสลับ (`swapXY`)
2. หาค่าดิบเฉลี่ยของขอบซ้าย/ขวา (`leftU`, `rightU`) และขอบบน/ล่าง (`topV`, `bottomV`)
3. `b = (ตำแหน่งขวา − ตำแหน่งซ้าย) ÷ (rightU − leftU)` และ `a = ตำแหน่งซ้าย − b × leftU` (ถ้าแกนกลับด้าน `b` จะเป็นลบเอง)
4. ตรวจย้อนกลับ: นำค่าดิบของทั้ง 4 เป้ามาแปลงกลับเป็นพิกัดจอ ต้องคลาดเคลื่อนจากเป้าไม่เกิน 25 พิกเซล และช่วงดิบต้องกว้างพอ (`CAL_MIN_SPAN` = 300) มิฉะนั้นถือว่าแตะผิด

**ตัวอย่างคำนวณ (ตัวเลขสมมุติ ไม่ใช่ค่าจริงจากบอร์ด):** ขอบซ้ายดิบ 480 ขอบขวาดิบ 3,600 → `b = (299 − 20) ÷ (3,600 − 480) = 0.0894 พิกเซลต่อหน่วย`, `a = 20 − 0.0894 × 480 = −22.9`
ค่าดิบ 2,040 จึงได้ `−22.9 + 0.0894 × 2,040 ≈ 159.5` (กลางจอพอดีในแกน x)

### เหตุการณ์สัมผัสและการกันสัญญาณรบกวน

| ขั้น | ความหมาย |
|---|---|
| อ่านทุก 10 ms | `TOUCH_POLL_MS` |
| **กดลง (press)** | เห็นแรงกดพอติดกัน **2 ครั้ง** (`TOUCH_PRESS_SAMPLES`) ≈ 20 ms กันสัญญาณรบกวน |
| กำลังกด (hold) | พิกัดผ่านตัวกรอง EMA (`TOUCH_SMOOTH_ALPHA`) ให้นิ่งขึ้นขณะลาก |
| **ปล่อย (release)** | ไม่เห็นแรงกดติดกัน **3 ครั้ง** (`TOUCH_RELEASE_SAMPLES`) ≈ 30 ms |
| **คลิก (click)** | ปล่อยนิ้วบน widget เดียวกับที่กดลง |

### เก็บค่าถาวรด้วย `Preferences`

ค่า calibrate (`swapXY`, `xa`, `xb`, `ya`, `yb`) และความสว่างจอเก็บในหน่วยความจำ flash แบบ key-value (namespace `lab9`) ไม่หายเมื่อไฟดับ
เปิดเครื่องครั้งต่อไปโหลดค่ากลับมาและเข้าหน้า DASH ทันที ถ้ายังไม่มีค่าที่บันทึกไว้ จะเข้าหน้า calibrate

ลองตามลำดับนี้

1. เปิดเครื่อง (ครั้งแรก) จะเข้าหน้า calibrate แตะ 4 จุดตามที่บอก ดู Serial: `[CAL] point 1 raw = (…)` … และ `[CAL] swapXY=… worst target error … px` แล้ว `saved`
2. เข้าหน้า DASH: แตะการ์ดต่างๆ ดูผล (สลับ REAL/SIM, AUTO/MANUAL, ขอเวลา NTP) ดู Serial ว่ามีบรรทัด `[TOUCH] down … target=…` ตรงกับที่แตะ
3. ไปแท็บ FAN: ลากแถบเลื่อน ดูพัดลม (LED น้ำเงิน) สว่างตาม ลอง `+` `-` กดค้าง
4. ไปแท็บ SYSTEM: ลากแถบความสว่างจอ (จอควรสว่าง/หรี่ตาม) แล้ว **รีเซ็ตบอร์ด (ปุ่ม EN)** ตรวจว่าความสว่างและ calibrate ยังจำค่าเดิม
5. กดปุ่ม `TOUCH TEST` แตะที่ 4 มุมจอและกลางจอ ดูว่า `PIXEL` ใกล้ตำแหน่งที่แตะ แล้วลองวาดภาพ
6. กด `RECALIBRATE` ค้าง 1 วินาที ดูแถบเขียวเติมและเข้าหน้า calibrate

## สังเกตจากการทดสอบจริง

ค่า calibrate ที่ได้จากบอร์ดต้นแบบ (อ่านด้วยคำสั่ง `k` และยืนยันว่าโหลดกลับมาหลังรีเซ็ต):

```
[TOUCH] calibration: valid  swapXY=no  x: 0.0861*u-16.5  y: 0.0673*v-17.9
[CAL] loaded from flash: swapXY=no x: 0.0861*u-16.5  y: 0.0673*v-17.9
```

แปลความหมาย: แกนดิบไม่สลับกับแกนจอ (`swapXY=no`) และเป็นเส้นตรงเดียวกับที่คำนวณได้จากเป้า 4 มุม ถ้าย้อนกลับ เป้าซ้าย (x = 20) ตรงกับค่าดิบ ≈ (20 + 16.5) ÷ 0.0861 ≈ **424**
และเป้าขวา (x = 299) ≈ (299 + 16.5) ÷ 0.0861 ≈ **3,664** ส่วนแกน y: เป้าบน (y = 20) ≈ 563 และเป้าล่าง (y = 219) ≈ 3,520
ช่วงนี้ใกล้เคียงค่าประมาณเริ่มต้นในไฟล์ `board_config.h` (x 480–3600, y 600–3530) ซึ่งบอกว่าค่าที่วัดจริงสมเหตุสมผล และยังยืนยันว่าค่าในไฟล์นั้นเป็นเพียงค่าประมาณ แต่ละบอร์ดต้อง calibrate เอง
(ตัวเลขชุดนี้เป็นของบอร์ดต้นแบบตัวเดียว ของคุณจะต่างออกไป)

ค่าดิบล่าสุดที่เห็นหลังนิ้วปล่อย `(828, 3393)` แปลงด้วยค่าข้างบนได้ประมาณ x = 0.0861 × 828 − 16.5 ≈ **55**, y = 0.0673 × 3,393 − 17.9 ≈ **210** ซึ่งอยู่ในปุ่มแท็บ `DASH` (x 4–103, y 202–237)
สอดคล้องกับที่ผู้พัฒนากดแท็บนั้น (ผมไม่ได้เห็นตอนกด เป็นการอนุมานจากค่าดิบล่าสุดที่ค้างอยู่)

### ค่า calibrate ครั้งที่ 2 (ผู้พัฒนากด RECALIBRATE แล้วทำใหม่)

```
[CAL] loaded from flash: swapXY=no x: 0.0909*u-25.2  y: 0.0715*v-30.3
```

ย้อนกลับเป็นค่าดิบของเป้า: ซ้าย (x = 20) ≈ (20 + 25.2) ÷ 0.0909 ≈ **497**, ขวา (x = 299) ≈ **3,567**, บน (y = 20) ≈ (20 + 30.3) ÷ 0.0715 ≈ **703**, ล่าง (y = 219) ≈ **3,486**
เทียบกับครั้งแรก (ซ้าย ≈ 424, ขวา ≈ 3,664, บน ≈ 563, ล่าง ≈ 3,520) ค่าต่างกันได้ราว 70–140 หน่วยดิบ (ประมาณ 6–10 พิกเซล) เพราะ **calibrate แต่ละครั้งขึ้นกับตำแหน่งและแรงที่แตะ**
ข้อสังเกตที่ใช้สอนได้: แตะกลางกากบาทอย่างนิ่งๆ และกดแรงสม่ำเสมอ (หรือใช้ปากกาปลายมน) ให้ผลที่ซ้ำได้ดีกว่า (ตัวเลขชุดนี้เป็นของบอร์ดต้นแบบตัวเดียว)

### สิ่งที่เห็นในภาพถ่ายของผู้พัฒนา

| ภาพ | สิ่งที่เห็น |
|---|---|
| หน้า Calibrate | ชื่อ `Touch calibration`, คำอธิบาย 3 บรรทัด, `Point 1 / 4` สีเหลือง และกากบาทสีเขียวที่มุมบนซ้าย |
| หน้า DASH | เวลา `21:11:38` ตัวใหญ่ พร้อมป้าย `SYNCED`, `09/10/26`, `sync #2`, การ์ด `TEMP 29.4 C REAL` และ `HUMIDITY 85 % REAL`, การ์ดพัดลม `FAN 30% RUNNING` โหมด `MANUAL` พร้อมแถบ, แท็บ `DASH` ถูกเน้น, เวลาและจุด heartbeat ที่แถบหัว |
| หน้า FAN | ปุ่ม `AUTO`/`MANUAL` (MANUAL ถูกเน้น), `FAN DUTY 30%` กับแถบเลื่อน, `ON >= 35 C` และ `OFF <= 28 C` พร้อมปุ่ม `-` `+` สองแถว |
| หน้า SYSTEM | `BACKLIGHT 100%` กับแถบเลื่อน, ปุ่ม `SYNC NTP` / `TOUCH TEST`, ปุ่ม `RECALIBRATE (hold 1 s)`, บรรทัด `WiFi -54dBm sync #2 1m ago`, แท็บ `SYSTEM` ถูกเน้น |
| หน้า SYSTEM (หลังปรับความสว่าง) | `BACKLIGHT 29%` แถบเลื่อนเติมสีเหลืองถึงตำแหน่งที่สัมพันธ์กับ 29% (ช่วงปรับ 10–100%), `WiFi -46dBm sync #2 1m ago` |
| หน้า TOUCH TEST | `RAW - -  z= 9` (ขณะไม่แตะ แรงกดต่ำ ตรงกับที่ Serial เห็น), `PIXEL last x=231 y=151  UP`, เส้นที่ลากวาดเป็นจุดสีเขียวต่อเนื่องในกล่อง, ปุ่ม `BACK` / `CLEAR` |

หลังรีเซ็ตบอร์ด เกณฑ์พัดลมกลับเป็นค่าใน `app_config.h` (`on>=30 off<=28` ใน Serial) ตามที่ออกแบบไว้ (ส่วนค่า calibrate และความสว่างจอเท่านั้นที่จำถาวร)

## แบบฝึกหัด

1. **เปลี่ยนสีปุ่ม:** แก้ `COLOR_BUTTON`, `COLOR_PRESSED`, `COLOR_ACTIVE` ให้เป็นโทนสีที่ชอบ
2. **ปรับความไว:** ตั้ง `TOUCH_Z_MIN = 700` แล้วดูว่าต้องกดแรงขึ้นแค่ไหน (ใช้หน้า TOUCH TEST ดูค่า `z` ตอนกดเบา/แรง) แล้วลอง 200 ดูว่าเกิดการแตะหลอกไหม
3. **ปรับ calibrate:** ตั้ง `CAL_MARGIN = 30` แล้ว calibrate ใหม่ เทียบความแม่นที่มุมจอด้วยหน้า TOUCH TEST
4. **กดค้าง:** ตั้ง `LONG_PRESS_MS = 2000` แล้วดูแถบเติมช้าลง และตอบ: ทำไมปุ่มที่ทำให้เกิดผลใหญ่ (เช่น recalibrate) จึงต้องกดค้าง
5. **เพิ่มปุ่มบนหน้า DASH:** เพิ่มปุ่มเล็กสั่ง "ปิดพัดลมทันที" (MANUAL, duty 0%) ต้องเพิ่ม `Widget` ใหม่ สี่เหลี่ยมของปุ่ม และจัดการใน `hitTest()`, `redrawWidget()`, `onActivate()`
6. **ใช้ขา IRQ:** ดัดแปลงให้ใช้ขา GPIO36 (IRQ) ตรวจว่ามีการแตะก่อนอ่านชิปเต็มรอบ (ลดเวลา SPI ตอนไม่มีการแตะ)
7. **ท้าทาย:** เพิ่มการปัดนิ้ว (swipe) ซ้าย/ขวา เพื่อสลับแท็บ (คำใบ้: เทียบพิกัดตอนกดลงกับตอนปล่อย)

## ปัญหาที่พบบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| แตะแล้วตำแหน่งเพี้ยน/กลับด้าน | calibrate ไม่ดี (แตะไม่กลางกากบาท หรือกดไม่นิ่ง) ให้ `RECALIBRATE` หรือพิมพ์ `c` ใหม่ ใช้เล็บ/ปากกาปลายมน |
| ขึ้น `Calibration FAILED` | แตะผิดมุม/ผิดลำดับ ช่วงค่าดิบแคบเกินไป ให้ทำใหม่โดยแตะกลางกากบาททีละจุด ตามลำดับ |
| แตะแล้วไม่ตอบสนอง | กดเบาเกินไป (z ต่ำกว่า 400 ดูที่หน้า TOUCH TEST), เล็บ/นิ้วแห้งหรือมีฟิล์มกันรอย, ลดค่า `TOUCH_Z_MIN` |
| แตะเองทั้งที่ไม่มีใครแตะ | `TOUCH_Z_MIN` ต่ำเกินไป หรือสาย/ขา SPI ของจอสัมผัสผิด ดู `z` ใน Serial (`k`) ขณะไม่แตะ ควรต่ำกว่า 400 |
| ปุ่มกดแล้วไม่ทำงาน | ปล่อยนิ้วนอกปุ่ม (ปุ่มทำงานเมื่อปล่อยบนปุ่มเดิม) |
| ลากแถบเลื่อนแล้วสะดุด | อ่าน DHT11 แย่งเวลา ~25 ms ทุก 2.5 วินาที เป็นเรื่องปกติ |
| จอมืดจนไม่เห็น | ลดความสว่างต่ำสุดไม่ได้ต่ำกว่า 10% ถ้ายังมืด ตรวจ `bl=` ใน Serial หรือรีเซ็ตเก็บค่าใหม่ (ลบค่าที่จำไว้ได้โดยอัปโหลดใหม่และลากแถบสว่างสุด) |
| ไม่มีเวลาจริง | ดู Lab 7 (WiFi/`secrets.h`) จอสัมผัสยังใช้ได้ปกติ |
| upload ไม่ผ่าน | ปิด Serial Monitor / กด BOOT ค้างตอน `Connecting......` / ถอด-เสียบสาย USB ใหม่ |

| ความสว่างจอ (PWM ที่ GPIO21) ปรับได้จริงและจำค่าหลังรีเซ็ต | **ยืนยันแล้ว** ภาพหน้า SYSTEM แสดง `BACKLIGHT 29%` พร้อมแถบเลื่อนตามค่า และผมตรวจจาก Serial ว่าความสว่างที่ตั้งไว้ (`bl=93%`) ยังเท่าเดิมหลังรีเซ็ตบอร์ด (ผมมองจอเองไม่ได้ว่าหรี่ตามสัดส่วนหรือไม่ แต่ผู้พัฒนาแจ้งว่าทำงานถูกต้อง) |
| ตำแหน่ง/ขนาดข้อความและปุ่มของหน้าใหม่ (ไม่ชน ไม่ล้น) | **ยืนยันแล้วจากภาพถ่าย** ของหน้า calibrate, DASH, FAN, SYSTEM และ TOUCH TEST (ข้อความพอดี ปุ่มไม่ชนกัน) |
| ปุ่ม RECALIBRATE กดค้าง 1 วินาที เข้าหน้า calibrate และบันทึกค่าใหม่ | **ยืนยันแล้ว** ผู้พัฒนาแจ้งว่าทำงานถูกต้อง และผมตรวจจาก Serial ว่าค่า calibrate ที่โหลดหลังรีเซ็ตต่างจากค่าแรก (เปลี่ยนจาก `x: 0.0861*u-16.5` เป็น `x: 0.0909*u-25.2`) แสดงว่ามีการ calibrate ใหม่และบันทึกจริง |
| หน้า TOUCH TEST แสดงค่าดิบ/พิกเซล/แรงกดและวาดตามนิ้ว | **ยืนยันแล้วจากภาพถ่ายของผู้พัฒนา** (ดู "สิ่งที่เห็นในภาพถ่าย") |
| การอ่านจอสัมผัสทับกับการอ่าน DHT11 และ WiFi ไม่ทำให้พลาดการแตะบ่อย | **ยังไม่ได้ทดสอบ** |
| ภาพ ASCII และตัวอย่างบรรทัด `[TOUCH]` | วาดประกอบ/ตามรูปแบบในโค้ด ไม่ใช่ผลจริง |
