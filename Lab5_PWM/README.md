# Level 1 / Lab 5 — PWM: ปรับความสว่างจอและ LED ด้วย Duty Cycle

Lab นี้เรียนรู้ **PWM (Pulse Width Modulation)** โดยใช้ PWM ปรับความสว่างของ **ไฟหลังจอ** (GPIO21) และ **LED สีเขียว** บนบอร์ด
พร้อมแสดง **ค่า duty / ความถี่ / รูปคลื่น PWM** บนจอ และรายงานผ่าน Serial

> **สถานะการตรวจสอบ (อ่านก่อน):** โปรแกรมนี้ build ผ่าน และผู้พัฒนาทดสอบบนบอร์ดจริงแล้วแจ้งว่าผลถูกต้อง (มีภาพถ่ายหน้าจอโหมด BREATHE ที่ duty 29%
> ตัวเลขบนจอตรงกับสูตรในโค้ดทุกค่า) ส่วนที่ผมยังไม่ได้เห็นผลเองหรือยังไม่มีหลักฐาน แยกไว้ในหัวข้อ "สิ่งที่ยังไม่ได้ยืนยัน" ท้ายไฟล์
> ตัวอย่างข้อความ Serial ในเอกสารนี้คำนวณจากสูตร ไม่ได้คัดลอกจากบอร์ด

## ตอบคำถามที่ถามมา

| คำถาม | คำตอบ |
|---|---|
| ปรับ duty cycle ไปควบคุมแสงของจอได้ไหม | **ได้** ไฟหลังจอต่ออยู่ที่ GPIO21 ใช้ PWM ของ ESP32 (LEDC) สร้างสัญญาณที่ขานี้ได้ duty มาก = สว่างมาก |
| แสดงรูปคลื่น PWM บนจอได้ไหม | **ได้ แต่เป็นรูปประกอบ** ความถี่จริง (100 Hz – 20 kHz) เร็วเกินกว่าจอจะวาดตามได้ โปรแกรมจึงวาดคลื่น 3 รอบให้เห็น "รูปร่าง" โดยความกว้างช่วง HIGH เป็นสัดส่วนตาม duty จริง พร้อมตัวเลขคาบ เวลา ON/OFF และแรงดันเฉลี่ย |
| แสดงค่าบน Serial ได้ไหม | ได้ ทุก 1 วินาทีและทุกครั้งที่เปลี่ยนค่า |

> **หมายเหตุเรื่อง GPIO21:** เอกสารบอร์ดเตือนว่า **ห้ามเอา GPIO21 ไปต่อเซนเซอร์** เพราะเป็นขาไฟหลังจอ ใน Lab นี้เราใช้ขานี้ตามหน้าที่จริงของมัน (ควบคุมไฟหลังจอ) จึงไม่ขัดกับคำเตือน

## วิธีควบคุม

| วิธี | ทำอะไร |
|---|---|
| ปุ่ม **BOOT** บนบอร์ด | สลับโหมด MANUAL → BREATHE → AUTO → MANUAL |
| พิมพ์ `+` / `-` ใน Serial Monitor | เพิ่ม/ลด duty ทีละ 5% (สลับเป็น MANUAL ให้เอง) |
| พิมพ์ `0`–`9` | ตั้ง duty เป็น 0,10,…,90% (ขั้นต่ำถูกบังคับที่ 5%) |
| พิมพ์ `f` | สลับความถี่ PWM: 100 → 500 → 1000 → 5000 → 20000 Hz |
| พิมพ์ `m` | สลับโหมด (เหมือนปุ่ม BOOT) |
| พิมพ์ `h` | แสดงวิธีใช้ |

| โหมด | duty มาจากไหน |
|---|---|
| **MANUAL** | คุณกำหนดเองผ่าน Serial |
| **BREATHE** | ไล่ขึ้น-ลงนุ่มๆ เองด้วยฟังก์ชัน cos รอบละ 4 วินาที (ค่า `BREATHE_PERIOD_MS`) |
| **AUTO (LDR)** | ตามแสงห้อง ห้องสว่าง → จอสว่าง ห้องมืด → จอหรี่ (เหมือน auto-brightness ของมือถือ) |

LED สีเขียวบนบอร์ดจะ "ทำตาม" duty เดียวกับไฟหลังจอ (หลังเข้าหน้าหลัก) เพื่อให้เห็นผลของ PWM บน LED ด้วย

> ทำไมขั้นต่ำ 5%: ถ้าตั้ง 0% ไฟหลังจอดับสนิท ดูไม่ออกว่าโปรแกรมยังทำงานอยู่ ปรับได้ที่ `MIN_DUTY_PERCENT` ใน `app_config.h`

## ความรู้ใหม่ใน Lab นี้

### PWM คืออะไร

บอร์ดไม่มีขาที่ส่งแรงดัน "2 โวลต์" หรือ "1.5 โวลต์" ได้โดยตรง ขาดิจิทัลมีแค่ HIGH (3.3 V) กับ LOW (0 V)
PWM แก้ปัญหานี้ด้วยการ **สลับ HIGH/LOW เร็วมากซ้ำๆ** แล้วปรับสัดส่วนเวลาที่เป็น HIGH ใน 1 รอบ

```
duty 25%:  ┌─┐      ┌─┐      ┌─┐        เฉลี่ยแล้ว  ~0.25 × 3.3 V ≈ 0.83 V
           │ └──────┘ └──────┘ └─
duty 75%:  ┌──────┐ ┌──────┐ ┌──────┐   เฉลี่ยแล้ว  ~0.75 × 3.3 V ≈ 2.48 V
           │      └─┘      └─┘      └─
```

| คำ | ความหมาย | สูตร / ตัวอย่าง |
|---|---|---|
| **คาบ (Period, T)** | เวลา 1 รอบ | T = 1 ÷ f   (5000 Hz → 200 µs) |
| **ความถี่ (f)** | จำนวนรอบต่อวินาที | หน่วย Hz |
| **Duty cycle** | สัดส่วนเวลา HIGH ใน 1 รอบ | duty = เวลา ON ÷ T (เป็น %) |
| **แรงดันเฉลี่ย** | ระดับที่ LED/ตาเรา "รู้สึก" | ≈ duty × 3.3 V |
| **ความละเอียด (resolution)** | แบ่ง 1 รอบเป็นกี่ระดับ | 8 บิต = 256 ระดับ (ค่า 0–255) |

ตาเรามองไม่ทันเมื่อกะพริบเร็วเกินราว 100 ครั้ง/วินาทีขึ้นไป จึงเห็นเป็นความสว่างคงที่ที่ลดลง
ความถี่ต่ำๆ (เช่น 100 Hz ที่ duty ต่ำ) อาจทำให้เห็นหรือถ่ายภาพแล้วเห็นเป็นแถบกะพริบ ลองสลับความถี่ด้วย `f` เพื่อสังเกต (ดูหัวข้อสิ่งที่ยังไม่ได้ยืนยัน)

### แปลง % เป็นค่าที่เขียนเข้า PWM

โค้ดคำนวณ `value = (duty% × 255 + 50) ÷ 100` (บวก 50 เพื่อปัดเศษ)

| duty ที่สั่ง | `value` | duty จริง = value ÷ 255 | แรงดันเฉลี่ย (3.3 V × duty จริง) |
|---|---|---|---|
| 5% | 13 | 5.1% | 0.17 V |
| 25% | 64 | 25.1% | 0.83 V |
| 50% | 128 | 50.2% | 1.66 V |
| 100% | 255 | 100% | 3.30 V |

สังเกต: 50% แปลงเป็น 128 จาก 255 ซึ่งเป็น 50.2% ไม่ใช่ 50.0% เพราะมีแค่ 256 ระดับ นี่คือผลของ "ความละเอียด"

### 3 ขั้นตอนใช้ PWM บน ESP32 (LEDC)

```cpp
ledcSetup(channel, frequency, resolutionBits);   // 1) ตั้งค่าช่อง: ความถี่ + ความละเอียด
ledcAttachPin(gpio, channel);                    // 2) ผูกขา GPIO เข้ากับช่อง
ledcWrite(channel, value);                       // 3) เขียนค่า duty (0 ถึง 2^bits − 1)
```

ใน Lab นี้ช่อง 0 ผูกกับ GPIO21 (ไฟหลังจอ) ช่อง 1 ผูกกับ GPIO16 (LED เขียว) ทั้งสองช่องใช้ความถี่เดียวกัน
`ledcSetup()` คืนค่าความถี่ที่ฮาร์ดแวร์ตั้งให้จริง (โปรแกรมพิมพ์เป็น `actual` ใน Serial) ถ้าความถี่/ความละเอียดที่ขอทำไม่ได้ จะคืนค่า 0

> **จุดสังเกต:** `tft.init()` ของไลบรารีจอจะเปิดไฟหลังจอด้วย `digitalWrite(GPIO21, HIGH)` ก่อน เมื่อเรียก `ledcAttachPin()` ทีหลัง
> ขา GPIO21 จะถูกคุมด้วย PWM แทน (ถ้าลำดับกลับกัน คาดว่า `pinMode`/`digitalWrite` ของไลบรารีจอจะตั้งขาเป็น GPIO ธรรมดาทับ PWM ผู้เขียนยังไม่ได้ลองสลับลำดับเพื่อยืนยัน)

### LED บนบอร์ดเป็นแบบ active-LOW

LED ติดเมื่อขาเป็น LOW ดังนั้น PWM duty 70% (HIGH 70%) จะทำให้ LED ติดเพียง 30% ของเวลา โค้ดจึงกลับค่าก่อนเขียน
`writeLed(v)` ส่ง `255 − v` เมื่อ `LED_ACTIVE_LOW = true` แล้ว LED จะสว่างตาม duty ที่สั่ง

### รูปคลื่นบนจอ

`drawWave(percent, color)` วาด 3 รอบ รอบละ 80 พิกเซล ช่วงที่เป็น HIGH ยาว `percent × 80 ÷ 100` พิกเซล ช่วงที่เหลือเป็น LOW
เวลาเปลี่ยนค่า ใช้เทคนิค "ลบด้วยสีพื้นหลังแล้ววาดใหม่" (เรียก `drawWave` ด้วยสีการ์ดเพื่อลบของเก่า) ไม่ล้างทั้งจอ ตามหลักของ Lab 4

| duty | ความกว้างช่วง HIGH (พิกเซล) จาก 80 |
|---|---|
| 5% | 4 |
| 25% | 20 |
| 50% | 40 |
| 75% | 60 |
| 100% | 80 (เส้นตรงระดับสูง ไม่มีขอบ) |

### โหมด BREATHE และโหมด AUTO

- **BREATHE:** `level = 0.5 − 0.5 × cos(2π × t / T)` ค่า `level` ไล่ 0 → 1 → 0 นุ่มๆ (ช้าตรงปลายทาง) แล้วแปลงเป็น duty ระหว่าง 5% – 100%
- **AUTO:** `duty = 5 + lightPercent × 95 ÷ 100` โดย `lightPercent` ได้จากการ calibrate แบบเดียวกับ Lab 4

## วิธีรันและทดสอบ

```powershell
pio run -t upload --upload-port COM3
pio device monitor -b 115200 --port COM3
```

(เปลี่ยน `COM3` ตามเครื่องคุณ ปิด Serial Monitor ก่อน upload ทุกครั้ง ถ้าไม่มีคำสั่ง `pio` ให้ใช้ `python -m platformio`)

ถ้า upload ไม่ผ่านด้วยข้อความ `Failed to connect to ESP32: No serial data received` (ผู้เขียนเคยเจอครั้งหนึ่ง ก่อนที่ผู้พัฒนาจะอัปโหลดสำเร็จเอง):
กดปุ่ม **BOOT ค้างไว้** ตอนที่ขึ้น `Connecting......` แล้วปล่อยเมื่อเริ่มเขียนไฟล์ หรือถอดแล้วเสียบสาย USB ใหม่ แล้วลองอีกครั้ง

ลองทำตามลำดับนี้

1. ครอบมือ → เปิดมือ ตอน calibrate 6 วินาทีแรก
2. หน้าหลักขึ้นที่ MANUAL 50% ใน Serial Monitor พิมพ์ `+` หลายครั้ง ดูจอสว่างขึ้น เลข % ใน Serial และบนจอตรงกัน และรูปคลื่นส่วน HIGH กว้างขึ้น
3. พิมพ์ `1` (10%) ดูจอหรี่ลงมาก และสังเกตว่าตัวเลขบนจอยังอ่านออกหรือไม่
4. พิมพ์ `f` สลับความถี่ ดูว่าความสว่างเฉลี่ยของจอเปลี่ยนหรือไม่ และสังเกตการกะพริบที่ 100 Hz
5. กดปุ่ม BOOT ไป BREATHE แล้วดูจอและ LED เขียวไล่แสงขึ้น-ลง
6. กด BOOT อีกครั้งเป็น AUTO ใช้มือบังเซนเซอร์/ส่องไฟฉาย ดู duty เปลี่ยนตามแสง

## ตัวอย่างข้อความ Serial

ผลจริงจากบอร์ดต้นแบบ (บรรทัดสรุปทุก 1 วินาที และบรรทัดที่เกิดจากคำสั่ง)

```
[MODE] -> MANUAL
[PWM] duty  mode=MANUAL duty= 50% value=128/255 freq=5000 Hz (actual 5000) period=200us ON=100us OFF=100us | LDR raw= 268 light=100%
[PWM] freq  mode=MANUAL duty= 50% value=128/255 freq=100 Hz (actual 100) period=10.0ms ON=5.0ms OFF=5.0ms | LDR raw= 269 light=100%
[PWM]       mode=BREATHE duty= 79% value=201/255 freq=5000 Hz (actual 5000) period=200us ON=158us OFF=42us | LDR raw= 269 light=100%
```

ความหมายของแต่ละช่อง: `duty` = % ที่สั่ง, `value` = ค่าที่เขียนเข้า LEDC (จาก 255), `freq` = ความถี่ที่ขอ, `actual` = ความถี่ที่ฮาร์ดแวร์ตั้งให้จริง,
`period` = คาบ, `ON`/`OFF` = เวลา HIGH/LOW ต่อรอบ, `LDR raw`/`light` = ค่าเซนเซอร์แสง คำนำหน้า (`duty`, `freq`, `mode`, `start`) บอกว่าบรรทัดนั้นเกิดจากเหตุการณ์อะไร
บรรทัดที่ไม่มีคำนำหน้าคือสรุปรายวินาที

## ค่าที่ปรับได้ใน `app_config.h`

| ค่า | ค่าเริ่มต้น | ผลเมื่อปรับ |
|---|---|---|
| `PWM_RESOLUTION_BITS` | 8 | ความละเอียดของ duty (8 → 0–255) |
| `PWM_FREQUENCIES[]` | 100, 500, 1000, 5000, 20000 | รายการความถี่ที่สลับด้วย `f` |
| `DEFAULT_FREQUENCY_INDEX` | 3 | ความถี่เริ่มต้น (3 = 5000 Hz) |
| `MIN_DUTY_PERCENT` | 5 | duty ต่ำสุดที่อนุญาต |
| `DEFAULT_DUTY_PERCENT` | 50 | duty เริ่มต้นของหน้าหลัก |
| `DUTY_STEP_PERCENT` | 5 | ขั้นของ `+` `-` |
| `BREATHE_PERIOD_MS` | 4000 | ความเร็วของโหมด breathe |
| `DISPLAY_REFRESH_MS` | 50 | วาดจอได้ไม่เกินความถี่นี้ |

## แบบฝึกหัด

1. **เปลี่ยนความเร็ว breathe:** ตั้ง `BREATHE_PERIOD_MS` เป็น 1500 และ 8000 ดูความรู้สึกต่างกันอย่างไร
2. **เปลี่ยน duty ต่ำสุด:** ตั้ง `MIN_DUTY_PERCENT = 0` ดูว่าเกิดอะไรขึ้นที่ 0% (ระวังจอดับ ใช้ Serial กด `5` เพื่อกลับ)
3. **ความละเอียด:** ตั้ง `PWM_RESOLUTION_BITS = 4` (16 ระดับ) แล้วสั่ง duty 50% ดูค่า `value` และ duty จริงใน Serial เทียบกับ 8 บิต
4. **ความถี่ใหม่:** เพิ่มความถี่ 50 และ 10000 ใน `PWM_FREQUENCIES` (จำนวนนับให้อัตโนมัติ แต่ต้องดูว่า `DEFAULT_FREQUENCY_INDEX` ยังชี้ความถี่ที่ต้องการ) ดูค่า `actual` ใน Serial
5. **Gamma:** ตาเรารับรู้ความสว่างแบบไม่เป็นเส้นตรง ลองแปลง duty ด้วย `level^2.2` ในโหมด BREATHE แล้วเทียบว่าไล่แสงดู "สม่ำเสมอ" ขึ้นหรือไม่
6. **เลือก LED สี:** เปลี่ยนจาก LED เขียว (GPIO16) เป็นสีน้ำเงิน (GPIO17)
7. **ท้าทาย:** เพิ่มโหมดที่ 4 "PULSE" กะพริบ duty 100% / 5% สลับกันทุก 500 ms แสดงชื่อโหมดบนจอ

| จอดับสนิท | ตั้ง duty ต่ำเกินไป (ถ้าตั้ง `MIN_DUTY_PERCENT` เป็น 0) พิมพ์ `9` ใน Serial เพื่อเพิ่มความสว่าง |
| กดปุ่ม BOOT แล้วไม่เปลี่ยนโหมด | ใช้ Serial พิมพ์ `m` แทน และแจ้งผู้สอนเพื่อตรวจ pin ของปุ่ม (ดูหัวข้อสิ่งที่ยังไม่ได้ยืนยัน) |
| พิมพ์ใน Serial แล้วไม่มีผล | Serial Monitor ต้องตั้งส่ง "No line ending" หรือ "Newline" ก็ได้ แต่ต้องกดส่งหลังพิมพ์ ตรวจว่าเลือกพอร์ตถูก |
| AUTO แล้วจอสว่าง/หรี่ไม่สัมพันธ์กับแสง | calibrate ไม่สำเร็จ (ไม่ได้ครอบมือ) กด EN/RESET ครอบมือใหม่ |
| ตัวเลขเก่าค้างบนจอ | `setTextPadding` ไม่พอ (ดู Lab 4) |

## สังเกตจากการทดสอบจริง

ภาพถ่ายจากบอร์ดต้นแบบแสดงหน้าหลักครบทุกส่วน: โหมด `BREATHE` ที่ `FREQ: 5000 Hz`, duty 29%, `VALUE: 74/255`, `ON 58us OFF 142us AVG 0.96V`,
รูปคลื่น 3 รอบ (ช่วง HIGH สั้นกว่า LOW ตรงกับ duty 29%) และจุดกะพริบมุมล่างขวา ตัวเลขตรวจกับสูตรแล้วถูกต้อง
(74 = (29×255+50)÷100, ON = 200 µs × 0.29 = 58 µs, AVG = 3.3 × 74 ÷ 255 = 0.96 V)
ภาพนิ่งบอกไม่ได้ว่าจอหรี่จริงเมื่อ duty ต่ำ (ผู้ทดสอบแจ้งว่าผลถูกต้อง แต่ไม่ได้แนบหลักฐานเรื่องความสว่างเฉพาะ)

ผู้เขียนตรวจเพิ่มผ่าน Serial กับบอร์ดตัวเดียวกัน (ส่งคำสั่งและอ่านข้อความตอบกลับ ไม่ได้อัปโหลดโปรแกรมใหม่) ผลคือ

- `+` `-` และ `0`–`9` ทำงานถูกต้อง: ค่า `value` ตรงสูตรทุกค่าที่ลอง (10% → 26, 50% → 128, 90% → 230, 95% → 242, 100% → 255) `+` ที่ 100% ค้างอยู่ที่ 100% และ `0` ถูกบังคับเป็น 5% (`value` 13)
- `f` สลับความถี่ครบ 5 ค่า ค่า `actual` ตรงกับที่ขอทุกค่า (20000, 100, 500, 1000, 5000 Hz) รวม **100 Hz ที่ 8 บิตก็ตั้งได้**
- ที่ duty 100% Serial รายงาน `ON=200us OFF=0us` (ไม่มีช่วง LOW)
- โหมด BREATHE → AUTO → MANUAL → BREATHE สลับได้ด้วยคำสั่ง `m` ในโหมด AUTO ตอนแสงห้องสว่างได้ duty 100% และเมื่อมีสิ่งบังเซนเซอร์ (ค่า `raw` พุ่งเป็นราว 2200–2900) duty ลดลงเหลือ 5%
- ค่า `LDR raw` ในโหมด MANUAL ขณะแสงห้องคงที่ อยู่ราว 264–274 ทั้งที่ duty ต่างกันมาก (5%, 10%, 50%, 90%, 100%) จึง **ไม่พบการรั่วของแสงจากไฟหลังจอเข้า LDR ที่ชัดเจน** ในสภาพห้องที่ทดสอบ (ห้องมืดอาจต่าง)

## สิ่งที่ยังไม่ได้ยืนยัน (ผู้ทดสอบ/ผู้สอนควรตรวจและบันทึก)

| ข้อ | สถานะ |
|---|---|
| โปรแกรม build ผ่าน | ยืนยันแล้ว (ไม่มี warning จากโค้ดของ Lab นี้) |
| หน้าหลักและโหมด BREATHE บนบอร์ดจริง | ยืนยันแล้วจากภาพถ่ายและคำยืนยันของผู้ทดสอบ |
| MANUAL (คำสั่ง Serial), AUTO, ความถี่ทั้ง 5 ค่า | ยืนยันแล้วจากข้อความ Serial (ดูด้านบน) |
| ปุ่ม BOOT (GPIO0) สลับโหมดได้ | **ยังไม่ได้ยืนยัน** (คำสั่ง `m` ผ่านแล้ว แต่ผู้เขียนกดปุ่มบนบอร์ดเองไม่ได้) |
| PWM ที่ GPIO21 หรี่ไฟหลังจอได้ชัดเจนด้วยตา และจอไม่รวนตอนสลับความถี่ | **ยังไม่มีหลักฐาน** (ผู้เขียนมองจอไม่ได้ ผู้ทดสอบแจ้งแต่ว่า "ถูกต้อง") |
| ที่ความถี่ใดจึงเห็นการกะพริบ | **ยังไม่ได้ยืนยัน** ขึ้นกับตาและกล้อง |
| ลำดับ `tft.init()` ก่อน `ledcAttachPin()` สำคัญจริง | **ยังไม่ได้ทดลองสลับลำดับ** |
| ภาพ ASCII และข้อความ Serial ตัวอย่างในหัวข้อ "ตัวอย่างข้อความ Serial" | วาดประกอบ/คำนวณจากสูตร (ข้อความที่อ้างในหัวข้อนี้ด้านบนเป็นของจริง) |
