## 2. ภาพรวมสิ่งที่จะสร้าง

PWM คือการ "เปิด-ปิดเร็วมากซ้ำๆ" แล้วปรับสัดส่วนเวลาที่เปิด เพื่อให้ได้ความสว่างที่ต้องการ โปรแกรมนี้ใช้ PWM คุมสิ่งสองอย่าง

```
                    ┌──────────────────────────────┐
  Serial (+ - 0-9 f m)│                              │──► GPIO21 ──► ไฟหลังจอ (ความสว่างของจอ)
  ปุ่ม BOOT ─────────►│  ESP32  (LEDC: PWM 2 ช่อง)   │
  LDR (แสงห้อง) ─────►│                              │──► GPIO16 ──► LED สีเขียว (ทำตาม duty เดียวกัน)
                    └──────────────┬───────────────┘
                                   │ SPI
                                   ▼
                      จอ TFT: แสดง duty, ความถี่, ค่า, รูปคลื่น
```

**หน้า 1 — Calibrate ค่าแสง (6 วินาทีแรก)** เหมือน Lab 4: ครอบมือเหนือ LDR แล้วเปิดมือ เพื่อใช้กับโหมด AUTO (ระหว่างนี้จอสว่างเต็มที่ 100%)

**หน้า 2 — หน้าหลัก**

```
┌──────────────────────────────────────┐
│ Lab 5 - PWM                          │
│ ┌──────────────────────────────────┐ │
│ │ DUTY CYCLE                       │ │
│ │ 50%            MODE: MANUAL      │ │
│ │                FREQ: 5000 Hz     │ │
│ │                VALUE: 128/255    │ │
│ └──────────────────────────────────┘ │
│ ┌──────────────────────────────────┐ │
│ │ PWM WAVEFORM (3 periods)         │ │
│ │ 3.3V  ┌────┐    ┌────┐    ┌────┐ │ │
│ │       │    │    │    │    │    │ │ │
│ │ 0V ───┘    └────┘    └────┘    └─│ │
│ │ ON 100us OFF 100us AVG 1.66V     │ │
│ └──────────────────────────────────┘ │
│ BOOT=mode  Serial: + - 0-9 f       ● │
└──────────────────────────────────────┘
```

| ส่วนบนจอ | แสดงอะไร |
|---|---|
| เลข % ตัวใหญ่ | duty cycle ที่สั่งอยู่ |
| `MODE` | MANUAL / BREATHE / AUTO (LDR) (สีฟ้า / เขียว / เหลือง) |
| `FREQ` | ความถี่ PWM ที่ขอ (Hz) |
| `VALUE` | ค่าที่เขียนเข้า PWM จริง (จาก 255 เมื่อความละเอียด 8 บิต) |
| รูปคลื่น 3 รอบ | ช่วง HIGH (สูง) ยาวตาม duty — ดูหัวข้อ 3.7 ว่าทำไมเป็นรูปประกอบ |
| `ON … OFF … AVG …` | เวลาที่เป็น HIGH / LOW ต่อรอบ และแรงดันเฉลี่ย |
| จุดกะพริบมุมล่างขวา | `loop()` ยังทำงานอยู่ |

| โหมด | duty มาจากไหน |
|---|---|
| **MANUAL** | เรากำหนดเองผ่าน Serial |
| **BREATHE** | โปรแกรมไล่ขึ้น-ลงนุ่มๆ เอง รอบละ 4 วินาที |
| **AUTO (LDR)** | ตามแสงห้อง: สว่าง → จอสว่าง, มืด → จอหรี่ |

## 3. ความรู้พื้นฐานที่ต้องเข้าใจก่อนลงมือ

### 3.1 ปัญหา: ขาดิจิทัลมีแค่ HIGH กับ LOW

ขา GPIO ของ ESP32 ส่งออกได้แค่ HIGH (3.3 V) หรือ LOW (0 V) ไม่มี "1.5 V" แต่เราอยากให้ LED หรือไฟหลังจอ "สว่างครึ่งหนึ่ง"
วิธีแก้คือ **PWM (Pulse Width Modulation = การปรับความกว้างของพัลส์)** สลับ HIGH/LOW เร็วมากซ้ำๆ แล้วปรับว่าใน 1 รอบ เป็น HIGH นานเท่าไร

```
duty 25%:   ┌─┐      ┌─┐      ┌─┐        HIGH 1 ใน 4 ของรอบ  → เฉลี่ย ≈ 0.25 × 3.3 V ≈ 0.83 V
            │ └──────┘ └──────┘ └─
duty 50%:   ┌───┐    ┌───┐    ┌───┐      HIGH ครึ่งหนึ่งของรอบ → เฉลี่ย ≈ 1.65 V
            │   └────┘   └────┘   └─
duty 75%:   ┌─────┐  ┌─────┐  ┌─────┐    HIGH 3 ใน 4 ของรอบ   → เฉลี่ย ≈ 2.48 V
            │     └──┘     └──┘     └─
```

ถ้าสลับเร็วพอ ตาเรามองไม่ทัน (เห็นเป็นความสว่างคงที่ที่ลดลง) LED หรือไฟหลังจอ "เฉลี่ย" ความสว่างให้เอง duty มาก = สว่างมาก

### 3.2 คำศัพท์และสูตร

| คำ | ความหมาย | สูตร / ตัวอย่าง |
|---|---|---|
| **ความถี่ f** | จำนวนรอบต่อวินาที | หน่วย Hz เช่น 5000 Hz = 5000 รอบ/วินาที |
| **คาบ T** | เวลา 1 รอบ | T = 1 ÷ f   (5000 Hz → 0.0002 s = **200 µs**) |
| **เวลา ON** | เวลาที่เป็น HIGH ใน 1 รอบ | ON = T × duty |
| **เวลา OFF** | เวลาที่เป็น LOW ใน 1 รอบ | OFF = T − ON |
| **Duty cycle** | สัดส่วนเวลา HIGH ต่อ 1 รอบ | duty = ON ÷ T × 100 (%) |
| **แรงดันเฉลี่ย** | ระดับที่อุปกรณ์ "รู้สึก" | V เฉลี่ย ≈ duty × 3.3 V |
| **ความละเอียด** | แบ่ง 1 รอบเป็นกี่ระดับ | n บิต = 2ⁿ ระดับ (8 บิต = 256 ระดับ ค่า 0–255) |

หน่วยเวลา: 1 ms = 1,000 µs  และ 1 s = 1,000,000 µs

**ตัวอย่างคำนวณ** ความถี่ 5000 Hz, duty 29% (ค่าที่เห็นบนจอจริงจากภาพถ่ายของบอร์ดต้นแบบ)

| ขั้น | คำนวณ | ผล |
|---|---|---|
| คาบ | 1,000,000 ÷ 5000 | 200 µs |
| ON | 200 × 0.29 | **58 µs** |
| OFF | 200 − 58 | **142 µs** |
| ค่าที่เขียนเข้า PWM | (29 × 255 + 50) ÷ 100 | **74** |
| แรงดันเฉลี่ย | 3.3 × 74 ÷ 255 | **0.96 V** |

(ทั้งหมดตรงกับ `ON 58us OFF 142us AVG 0.96V` และ `VALUE 74/255` ที่แสดงบนจอ)

### 3.3 ความถี่ต้องสูงแค่ไหน

- **ต่ำเกินไป** (เช่น 100 Hz ที่ duty ต่ำ) ตาอาจเห็นการกะพริบ หรือกล้องมือถือจับได้เป็นแถบ
- **สูงขึ้น** (หลักพัน Hz) ตาเห็นเป็นความสว่างคงที่ จึงเป็นค่าที่นิยมใช้กับ LED/ไฟหลังจอ
- ความถี่ไม่เกี่ยวกับ "ความสว่าง" โดยตรง ความสว่างขึ้นกับ duty เท่านั้น ความถี่ที่เปลี่ยนมีผลเรื่องกะพริบและเสียงรบกวน
  (ผู้เขียนยังไม่ได้ยืนยันว่าความถี่ใดเริ่มเห็นกะพริบบนบอร์ดนี้ ให้ผู้เรียนสังเกตและบันทึกเองในขั้นที่ 7)

### 3.4 PWM บน ESP32: LEDC

ESP32 มีวงจรสร้าง PWM ในตัวชื่อ **LEDC** (LED Controller) ทำงานด้วยฮาร์ดแวร์ ไม่กิน CPU เมื่อตั้งค่าแล้ว

```cpp
ledcSetup(channel, frequency, resolutionBits);   // 1) ตั้งช่อง: ความถี่ + ความละเอียด
ledcAttachPin(gpio, channel);                    // 2) ผูกขา GPIO เข้ากับช่อง
ledcWrite(channel, value);                       // 3) เขียนค่า duty (0 ถึง 2^bits − 1)
```

| จุดควรรู้ | รายละเอียด |
|---|---|
| ช่องกับ timer | ช่อง (channel) ถูกจับคู่กับ timer ทีละ 2 ช่อง: ช่อง 0 และ 1 ใช้ timer 0 ร่วมกัน (อ่านจากซอร์สของ Arduino-ESP32 แล้ว) ดังนั้น **ช่อง 0 และ 1 ต้องใช้ความถี่และความละเอียดเดียวกัน** โปรแกรมนี้จึงเรียก `ledcSetup` ทั้งสองช่องด้วยค่าเดียวกัน |
| ค่าคืนของ `ledcSetup` | คืน "ความถี่ที่ตั้งได้จริง" (คืน 0 ถ้าตั้งไม่ได้) โปรแกรมพิมพ์เป็น `actual` ใน Serial ดูได้ว่าตรงกับที่ขอไหม (ในการทดสอบจริง 100, 500, 1000, 5000 และ 20000 Hz ที่ 8 บิต ได้ `actual` ตรงกับที่ขอทุกค่า) |
| ค่าสูงสุดของ `ledcWrite` | ถ้าเขียนค่าสูงสุด (255 เมื่อ 8 บิต) ไลบรารีจะสั่ง "เปิดตลอด" ให้ (ไม่มีช่วง LOW เลย) จึงเป็น duty 100% จริงๆ (อ่านจากซอร์สแล้ว) ซึ่งตรงกับที่ Serial รายงาน `ON=200us OFF=0us` ที่ 100% |
| หลัง `ledcSetup` ใหม่ | ต้องเขียน duty ซ้ำ (โปรแกรมทำใน `nextFrequency()`) |
| ขา GPIO21 | ปกติเป็นขาไฟหลังจอ `tft.init()` ของไลบรารีจอเปิดไฟหลังจอให้ด้วย `digitalWrite(HIGH)` จากนั้นเราค่อย `ledcAttachPin` เพื่อให้ PWM คุมขานี้ **เอกสารบอร์ดห้ามเอา GPIO21 ไปต่อเซนเซอร์** แต่ใน Lab นี้เราใช้ตามหน้าที่จริงของมัน |

### 3.5 แปลง % เป็นค่าที่เขียนเข้า PWM

โปรแกรมใช้สูตร `value = (duty% × 255 + 50) ÷ 100` (หารจำนวนเต็ม ตัดเศษ การบวก 50 ก่อนหารทำให้ปัดเศษเป็นค่าที่ใกล้ที่สุด)

| duty ที่สั่ง | `value` | duty จริง = value ÷ 255 | แรงดันเฉลี่ย 3.3 V × duty จริง |
|---|---|---|---|
| 5% | 13 | 5.1% | 0.17 V |
| 10% | 26 | 10.2% | 0.34 V |
| 25% | 64 | 25.1% | 0.83 V |
| 29% | 74 | 29.0% | 0.96 V |
| 50% | 128 | **50.2%** | 1.66 V |
| 75% | 191 | 74.9% | 2.47 V |
| 90% | 230 | 90.2% | 2.98 V |
| 100% | 255 | 100% | 3.30 V |

สังเกต: 50% ได้ 128 ไม่ใช่ 127.5 เพราะค่าที่เขียนเข้า PWM ต้องเป็น **จำนวนเต็ม** จึงเกิดความคลาดเคลื่อนเล็กน้อย (สูงสุดครึ่งหนึ่งของ 1 ระดับ = 0.5 ÷ 255 ≈ 0.2%)
ถ้าลดความละเอียดเหลือ 4 บิต (16 ระดับ ค่า 0–15) ความคลาดเคลื่อนจะใหญ่ขึ้นมาก: 50% → (50 × 15 + 50) ÷ 100 = 8 → 8 ÷ 15 = **53.3%** (ดูแบบฝึกหัดข้อ 4)

### 3.6 LED บนบอร์ดเป็นแบบ active-LOW

LED บนบอร์ดติดเมื่อขาเป็น **LOW** (เหมือน Lab 1) ถ้าส่ง PWM ที่ duty 70% (HIGH 70% ของเวลา) ตรงๆ LED จะติดแค่ 30%
โปรแกรมจึงกลับค่าก่อนเขียน: ส่ง `255 − value` เมื่อ `LED_ACTIVE_LOW = true` ทำให้ LED สว่างตาม duty ที่สั่ง
ตัวอย่าง: duty 25% → value 64 → เขียนเข้า LED ช่องนั้น 255 − 64 = **191**

### 3.7 รูปคลื่นบนจอ: ทำไมเป็น "รูปประกอบ"

ความถี่จริง 100–20,000 Hz หมายถึง 100–20,000 รอบ **ต่อวินาที** จอวาดภาพใหม่ได้ไม่เร็วขนาดนั้น และตาเราก็ตามไม่ทัน
โปรแกรมจึงวาด "ลักษณะของคลื่น" 3 รอบ โดยให้ **สัดส่วน** ช่วงสูงต่อ 1 รอบตรงกับ duty จริง (ไม่ได้สัมพันธ์กับความถี่ที่ตั้ง รูปจะดูเหมือนกันทุกความถี่)

แต่ละรอบกว้าง 80 พิกเซล ช่วง HIGH ยาว `percent × 80 ÷ 100` พิกเซล

| duty | ความกว้างช่วง HIGH จาก 80 พิกเซล |
|---|---|
| 5% | 4 |
| 25% | 20 |
| 29% | 23 |
| 50% | 40 |
| 75% | 60 |
| 100% | 80 (เส้นตรงระดับสูง ไม่มีขอบ) |

การอัปเดตจอใช้หลักเดียวกับ Lab 4: "ลบของเก่า (วาดซ้ำด้วยสีพื้นการ์ด) แล้ววาดของใหม่" เฉพาะส่วนที่เปลี่ยน ไม่ล้างทั้งจอ

### 3.8 โหมด BREATHE: ไล่แสงนุ่มด้วยฟังก์ชัน cos

```
level = 0.5 − 0.5 × cos(2π × t ÷ T)       t = เวลาในรอบ, T = BREATHE_PERIOD_MS (4000 ms)
duty  = 5 + level × (100 − 5)
```

`cos` ทำให้ `level` ไล่จาก 0 → 1 → 0 โดยเปลี่ยนช้าตรงปลายทาง เปลี่ยนเร็วตรงกลาง จึงดูนุ่ม เหมือนการหายใจ

| เวลาในรอบ (T = 4000 ms) | phase = t÷T | level | duty โดยประมาณ |
|---|---|---|---|
| 0 ms | 0 | 0 | 5% |
| 1000 ms | 0.25 | 0.5 | ≈ 52–53% |
| 2000 ms | 0.5 | 1 | 100% |
| 3000 ms | 0.75 | 0.5 | ≈ 52–53% |

(ที่ level = 0.5 ได้ 5 + 47.5 ซึ่งอยู่ตรงกึ่งกลางการปัดเศษ จึงอาจได้ 52 หรือ 53 ตามการปัดเศษของ `float`)

### 3.9 โหมด AUTO: เหมือน auto-brightness ของมือถือ

```
duty = 5 + lightPercent × 95 ÷ 100        (หารจำนวนเต็ม)
```

`lightPercent` คือเปอร์เซ็นต์ความสว่างห้อง 0–100 จากการ calibrate (เหมือน Lab 4) ได้ duty 5%–100%

| lightPercent | duty |
|---|---|
| 0 (มืด) | 5% |
| 33 | 36% |
| 50 | 52% |
| 70 | 71% |
| 100 (สว่าง) | 100% |

ในการทดสอบจริง เมื่อแสงห้องสว่าง (`light=100%`) โหมด AUTO ได้ duty 100% และเมื่อมือบังเซนเซอร์ (raw พุ่งเป็นราว 2200–2900) duty ลดเหลือ 5%
ข้อสังเกต: ไฟหลังจอและเซนเซอร์อยู่ใกล้กัน ในทางทฤษฎีแสงจากจออาจรั่วเข้าเซนเซอร์ได้ (ทำให้เกิด "วงป้อนกลับ") ผู้เขียนวัดแล้วในห้องที่สว่าง
พบว่า `raw` ไม่เปลี่ยนชัดเจนเมื่อ duty เปลี่ยน (264–274 ทุกระดับ) แต่ยังไม่ได้ทดสอบในห้องมืด ให้ผู้เรียนลองเองในขั้นที่ 10

### 3.10 รับคำสั่ง Serial และปุ่ม BOOT แบบไม่บล็อก

- `handleSerialInput()` อ่านทีละตัวอักษรที่มีอยู่ใน buffer แล้วทำงานทันที ไม่รอ ไม่ใช้ `delay()`
- ปุ่ม BOOT ต่อกับ GPIO0 (กด = LOW) โปรแกรมเปิดตัวต้านทานดึงขึ้นภายใน (`INPUT_PULLUP`) ให้ปล่อยปุ่มแล้วอ่านได้ HIGH ฟังก์ชัน `bootButtonPressed()` ตรวจ "เพิ่งเปลี่ยนจากปล่อยเป็นกด" และกันปุ่มเด้ง (debounce) 40 ms
- (ข้อควรระวังเรื่องปุ่ม BOOT: อย่ากดค้างตอนกด RESET/เสียบสาย เพราะ ESP32 จะเข้าโหมดดาวน์โหลดโปรแกรม ไม่ใช่รันโปรแกรมปกติ)

### ระดับ 1 — ปรับค่าและคำนวณ (ข้อละ 5 คะแนน)

**ข้อ 2 — ค่าเริ่มต้นและขั้น:** ตั้ง `DEFAULT_DUTY_PERCENT = 20` และ `DUTY_STEP_PERCENT = 10` ดูว่าหน้าหลักเริ่มที่เท่าไร และ `+` เพิ่มทีละเท่าไร

**ข้อ 3 — คำนวณบนกระดาษ (ไม่ต้องใช้บอร์ด):** ความถี่ 1000 Hz, ความละเอียด 8 บิต สำหรับ duty 20% และ 60% ให้หา (ก) คาบ (ข) ON (ค) OFF (ง) `value` (จ) duty จริง = value ÷ 255 (ฉ) แรงดันเฉลี่ย ตรวจคำตอบด้วยการตั้งบนบอร์ดแล้วดู Serial (ใช้ `f` สลับเป็น 1000 Hz และพิมพ์ `2`, `6`)

### ระดับ 2 — ทดลองเข้าใจหลักการ (ข้อละ 7 คะแนน)

**ข้อ 4 — ความละเอียดต่ำ:**

1. **ทำนายก่อน:** ถ้าตั้ง `PWM_RESOLUTION_BITS = 4` สั่ง duty 50% จะได้ `value` เท่าไร (ช่วง 0–15) และ duty จริงกี่ %?
2. แก้ค่าแล้ว upload สั่ง duty 25%, 50%, 75% ดู `VALUE` บนจอและ Serial เทียบกับคำทำนาย
3. อธิบาย: ทำไมค่าบนจอ (`duty%`) ยังเป็น 50% แต่ duty จริงไม่ใช่ 50%? ความละเอียดต่ำมีข้อเสียอะไร?

**ข้อ 5 — Gamma:** ตาคนรับรู้ความสว่างแบบไม่เป็นเส้นตรง (ที่ duty ต่ำแสงเปลี่ยนไวกว่า) เพื่อให้ไล่แสงดู "สม่ำเสมอ" ให้ปรับ `level` ในฟังก์ชัน `breatheDuty()` เป็น `level = powf(level, 2.2f);` ก่อนคำนวณ duty
ทำนายก่อน: ที่ phase 0.25 (t = 1000 ms) ได้ duty เท่าไร (เทียบกับเดิมประมาณ 52–53%)? แล้วลองรัน เปรียบเทียบความรู้สึกกับเดิม (ผลที่เห็นด้วยตาเป็นความรู้สึกส่วนตัว บันทึกตามจริง)

**ข้อ 6 — เปลี่ยน LED:** เปลี่ยนจาก LED เขียว (`LED_PIN_G`) เป็น LED น้ำเงิน (`LED_PIN_B`) ในฟังก์ชัน `pwmBegin()` ผลที่เห็นเป็นอย่างไร? (คำใบ้: ต้องแก้ตำแหน่งเดียวที่ `ledcAttachPin`)

### ระดับ 3 — ออกแบบเอง (ข้อละ 10 คะแนน)

**ข้อ 7 — โหมดใหม่ "PULSE":** เพิ่มโหมดที่ 4 ที่ duty สลับ 100% / 5% ทุก 500 ms (กะพริบช้าๆ ให้เห็นด้วยตา) ต้องแก้
(ก) `enum class Mode` เพิ่ม `Pulse` (ข) `modeName()` และ `modeColor()` เพิ่มชื่อ/สี (ค) `nextMode()` เปลี่ยน `% 3` เป็น `% 4` (ง) ใน `loop()` ส่วนคำนวณ duty ของโหมดอัตโนมัติ
คำใบ้ (ง): `((now / 500) % 2 == 0) ? 100 : app::MIN_DUTY_PERCENT` ถ้าต้องการสี ให้เพิ่มค่าคงที่สีใหม่ที่ต้นไฟล์ด้วย `rgb565(...)`

**ข้อ 8 — ท้าทาย: พิมพ์ค่า duty เป็นเลขใดก็ได้:** เพิ่มคำสั่ง Serial ให้พิมพ์ `d37` แล้วกด Enter = ตั้ง duty 37% (ปัจจุบันตั้งได้เฉพาะ 0,10,20,...,90 และ +/-5)
ข้อกำหนด: ห้ามใช้ `delay()` หรือ `Serial.parseInt()` ที่บล็อก ให้ใช้ตัวแปร `static` เก็บสถานะ "กำลังพิมพ์ตัวเลข" และค่าที่สะสมใน `handleSerialInput()`
(Serial Monitor ต้องตั้งให้ส่ง Newline เมื่อกด Enter) ผลลัพธ์: `d37` ตามด้วย Enter → `[PWM] duty ... duty= 37% value= 94/255 ...`

## 9. ปัญหาที่พบบ่อย

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| upload แล้วขึ้น `No serial data received` | กดปุ่ม BOOT ค้างตอน `Connecting......` หรือถอด/เสียบสาย USB ใหม่ หรือลองสายอื่น |
| upload ไม่ผ่าน `Access is denied` | ปิด Serial Monitor ก่อน upload |
| พิมพ์ใน Serial แล้วไม่มีผล | เลือกพอร์ตผิด หรือยังไม่ได้กดส่ง ตรวจว่าตั้ง baud 115200 และโปรแกรมเข้าหน้าหลักแล้ว (หลัง calibrate 6 วินาที) |
| จอดับสนิท | `MIN_DUTY_PERCENT` ถูกแก้เป็น 0 และตั้ง duty ต่ำ พิมพ์ `9` เพื่อเพิ่มความสว่าง |
| กดปุ่ม BOOT แล้วไม่เปลี่ยนโหมด | ใช้ Serial พิมพ์ `m` แทน และแจ้งผู้สอน (ตรวจ `BOOT_BUTTON_PIN`) |
| AUTO แล้วจอสว่าง/หรี่ไม่สัมพันธ์กับแสง | calibrate ไม่สำเร็จ (ไม่ได้ครอบมือ) ดูข้อความ `[CAL] range too small` ใน Serial แล้วกด EN/RESET ลองใหม่ |
| ค่า `actual` ไม่ตรงกับ `freq` | ฮาร์ดแวร์ปัดความถี่ (ปกติเมื่อความถี่/ความละเอียดสูงมาก) ถ้า `actual` เป็น 0 แปลว่าตั้งไม่ได้ |
| ตัวเลขเก่าค้างบนจอ | `setTextPadding` ไม่พอ (ดู Lab 4) |
| build ไม่ผ่านหลังเพิ่ม enum ใหม่ | `switch` ใน `modeName()`/`modeColor()` ต้องมี `case` ครบทุกค่า |
