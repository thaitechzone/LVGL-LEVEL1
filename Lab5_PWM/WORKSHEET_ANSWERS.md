## แบบฝึกหัด

### ข้อ 1 — ความเร็ว breathe
แก้ `BREATHE_PERIOD_MS = 1500` / `8000` ค่ารอบจริงควรใกล้ค่าที่ตั้ง (1.5 วินาที / 8 วินาที) ไม่ตัดคะแนนตามความคลาดเคลื่อนของการจับเวลาด้วยมือ ความรู้สึก (ถี่/ช้า) ตอบตามที่ผู้เรียนสังเกต

### ข้อ 2 — ค่าเริ่มต้นและขั้น
```cpp
constexpr int DEFAULT_DUTY_PERCENT = 20;
constexpr int DUTY_STEP_PERCENT = 10;
```
(build ผ่านแล้ว) เริ่มที่ 20% และ `+` เพิ่มทีละ 10% (20 → 30 → 40 …)

### ข้อ 3 — คำนวณบนกระดาษ (1000 Hz, 8 บิต)

| รายการ | duty 20% | duty 60% |
|---|---|---|
| (ก) คาบ = 1,000,000 ÷ 1000 | 1000 µs (1.0 ms) | 1000 µs |
| (ข) ON = T × duty | 200 µs | 600 µs |
| (ค) OFF = T − ON | 800 µs | 400 µs |
| (ง) `value` = (duty × 255 + 50) ÷ 100 | (20×255+50)÷100 = 5150÷100 = **51** | (60×255+50)÷100 = 15350÷100 = **153** |
| (จ) duty จริง = value ÷ 255 | 20.0% | 60.0% |
| (ฉ) แรงดันเฉลี่ย 3.3 × value ÷ 255 | 0.66 V | 1.98 V |

บนจอ/Serial ที่ 1000 Hz จะแสดงคาบเป็น `1.0ms`, ON `200us` / `600us` ตามรูปแบบของ `formatMicros()`

### ข้อ 4 — ความละเอียดต่ำ
```cpp
constexpr uint8_t PWM_RESOLUTION_BITS = 4;   // PWM_MAX_VALUE = 15 (คำนวณจาก 2^4 − 1 อัตโนมัติ)
```
(build ผ่านแล้ว)

| duty ที่สั่ง | `value` = (duty × 15 + 50) ÷ 100 | duty จริง = value ÷ 15 | AVG บนจอ = 3.3 × value ÷ 15 |
|---|---|---|---|
| 25% | (375+50)÷100 = **4** | 26.7% | 0.88 V |
| 50% | (750+50)÷100 = **8** | **53.3%** | 1.76 V |
| 75% | (1125+50)÷100 = **11** | 73.3% | 2.42 V |

บนจอ `VALUE` จะแสดง `8/15` เป็นต้น ส่วนเลข `%` ตัวใหญ่และรูปคลื่นยังใช้ duty ที่ "สั่ง" (50%) จึงไม่ตรงกับ duty จริง (53.3%) — จุดที่ควรให้ผู้เรียนสังเกต
ข้อเสีย: มีแค่ 16 ระดับ ควบคุมละเอียดไม่ได้ (ความคลาดเคลื่อนสูงสุดครึ่งระดับ = 0.5 ÷ 15 ≈ 3.3%) และโหมด BREATHE จะเห็นเป็นขั้นบันไดหยาบ (ส่วนหลังนี้คาดจากตัวเลข ยังไม่ได้เห็นบนบอร์ด)
(ผู้สอนตรวจ `actual` ใน Serial ด้วยว่าที่ 4 บิตความถี่ยังตั้งได้ เพราะยังไม่ได้ลองบนบอร์ด)

### ข้อ 5 — Gamma
```cpp
float level = 0.5f - 0.5f * cosf(2.0f * PI * phaseFraction);
level = powf(level, 2.2f);                                    // เพิ่มบรรทัดนี้
return app::MIN_DUTY_PERCENT + static_cast<int>(lroundf(level * (100 - app::MIN_DUTY_PERCENT)));
```
(build ผ่านแล้ว; ต้องเปลี่ยน `const float level` เป็น `float level`)

คำทำนาย: ที่ t = 1000 ms `level` เดิม 0.5 → 0.5^2.2 = 0.218 → duty = 5 + round(0.218 × 95) = 5 + 21 = **26%** (เดิมประมาณ 52–53%) กล่าวคือ duty ต่ำนานขึ้น และไล่ขึ้นเร็วขึ้นช่วงท้าย
ความรู้สึก (ไล่แสงดูสม่ำเสมอกว่าเดิมหรือไม่) เป็นการรับรู้ของแต่ละคน ผมยังไม่ได้ดูบนบอร์ด ยอมรับคำตอบที่สมเหตุผลตามที่ผู้เรียนเห็น

### ข้อ 6 — LED น้ำเงิน

| 5 | LED ติดเมื่อขาเป็น LOW (active-LOW) ถ้าไม่กลับค่า duty ที่สั่งจะกลายเป็นด้านตรงข้าม (สั่งมาก = LED หรี่) จึงส่ง 255 − value |

## ข้อควรระวังและข้อสังเกตสำหรับผู้สอน

1. **ยืนยันด้วยตัวเองก่อนสอน:** กดปุ่ม BOOT, สังเกตความสว่างจริงของจอที่ duty ต่ำ/สูง, ลองสลับความถี่ดูว่าจอไม่รวน, และถ่ายภาพที่ 100 Hz ดูว่าเห็นแถบหรือไม่
2. **รูปคลื่นเป็นรูปประกอบ** อธิบายนักเรียนให้เข้าใจตั้งแต่ต้น เพื่อไม่ให้เข้าใจผิดว่าเป็นการวัดสัญญาณ (ถ้ามีออสซิลโลสโคปควรให้ดูของจริงที่ GPIO21 หรือ GPIO16 เทียบ แต่อย่าต่อโพรบแล้วทำให้ GPIO21 ถูกโหลด)
3. **ห้ามเอา GPIO21 ไปต่อเซนเซอร์** (ตามเอกสารบอร์ด) ใน Lab นี้ใช้ตามหน้าที่จริงของขา
4. **แบบฝึกหัดข้อ 8 (`dNN`)** เป็นทักษะการเขียนโค้ดแบบ state machine ในการรับข้อความ ควรชื่นชมแนวทางที่ไม่ใช้ `Serial.parseInt()` เพราะบล็อกการทำงาน
5. **คะแนนข้อ 5.x และข้อ 7:** ถ้านักเรียนตอบได้เหตุผลถูกแต่ตัวเลขต่างจากเฉลย 1–2 หน่วย (จากการปัดเศษ) ให้ตรวจวิธีคิด ไม่ตัดคะแนนเต็ม
